# TrainingMirror 전신거울 외형 2종 전달 기록

제작일: 2026-11-10 (한국 시간). Blender 5.2.1 LTS에서 메시 제작·FBX 내보내기·재반입·렌더 미리보기 수행.

## 납품 구성

- `../K1_MirrorFrame.fbx`: K1 방독면용 외형.
- `../PC_MirrorFrame.fbx`: 보호의용 외형.
- `TrainingMirror.blend`: 두 모델을 각각 별도 컬렉션에 보관한 원본.
- `Previews/`: 모델별 정면·측면·후면·사선 PNG 8개 및 4방향 종합 미리보기 2개.
- `validation.json`: 원본/FBX 재반입 비교와 메시/개구부/FBX 원시 데이터 검사 결과.
- `build_training_mirror.py`, `audit_and_preview.py`, `label_previews.py`: 제작·검사·미리보기 재현 스크립트.
- `workspace_before.json`, `workspace_after.json`, `workspace_audit.py`: 납품 폴더 밖 기존 파일 보존 확인 기록.

## 실측 치수

단위는 m. 전체 외곽은 받침대를 포함한 AABB이며 크기 순서는 X 폭 × Y 높이 × Z 깊이.

| 항목 | K1 | 보호의(PC) |
|---|---:|---:|
| 기존 Surface 폭 × 높이 | 0.800 × 1.800 | 0.900 × 1.900 |
| 기존 Surface 중심의 바닥 높이 | 0.950 | 0.980 |
| 기존 Surface 하단의 바닥 높이 | 0.050 | 0.030 |
| 개구부 공칭 폭 × 높이 | 0.802 × 1.802 | 0.902 × 1.902 |
| 프레임 외곽 폭 × 높이 | 0.842 × 1.842 | 0.942 × 1.942 |
| 프레임 폭 / 깊이 | 0.020 / 0.028 | 0.020 / 0.028 |
| 전체 외곽 폭 × 높이 × 깊이 | 0.842 × 1.871 × 0.160 | 0.942 × 1.951 × 0.160 |
| 전체 X 범위 | −0.421 ~ +0.421 | −0.471 ~ +0.471 |
| 전체 Y 범위 | −0.950 ~ +0.921 | −0.980 ~ +0.971 |
| 전체 Z 범위 | −0.010 ~ +0.150 | −0.010 ~ +0.150 |
| 바닥 접점 Y | −0.950 | −0.980 |
| 프레임 최하단의 바닥 여유 | 0.029 | 0.009 |
| 삼각형 수 | 1,148 | 1,212 |
| 메시 부품 수 / 사용 재질 수 | 8 / 1 | 8 / 1 |

개구부 치수는 둥근 모서리를 포함한 공칭 경계 치수다. 각 변에 1mm씩 여유를 두었으며, 요구된 **정확한 사각 Surface 전체**가 모서리까지 노출되는지는 모든 삼각형을 Surface 사각 영역과 클리핑하여 별도로 확인했다. 프레임의 안쪽 모서리가 요구 사각 영역을 가리지 않는다.

전방 돌출은 Surface 기준 10mm, 후방 돌출은 최대 150mm다. 측방 받침대는 프레임 밖으로 나오지 않는다. 받침대는 전부 Surface 뒤쪽 Z=+0.014~+0.150에 있으며 높이는 8mm다. K1 받침대 중심 X=±0.340, PC는 ±0.390이며 각 발의 폭은 70mm다.

## 구조와 마감

두 모델은 동일한 디자인의 수직 금속 프레임, 2mm 뒤판, 후면 세로 지지대 2개, 삼각 보강대 2개, 낮은 받침대 2개로 구성했다. 후방 보강대는 바닥 위 약 600mm까지 이어진다. 프레임은 외곽 모서리 반경 4mm, 개구부 모서리 반경 2mm, 모서리 베벨 0.8mm를 적용했다. 나머지 부품에는 0.5~1mm 베벨을 적용했다. 로고·문자·장식·바퀴·손잡이는 없다.

뒤판의 앞면은 Z=+0.018, 뒷면은 +0.020이다. 기존 Surface와 18mm 떨어져 있으며 Z=0에 중첩되는 별도 평면이나 유리는 없다. 프레임·뒤판·지지대는 부피가 겹치지 않도록 맞댄 구조다. 각 부품은 닫힌 입체이며 독립 메시로 구분된다.

이름은 각 모델의 `K1_` 또는 `PC_` 접두사와 `Frame`, `Backplate`, `RearSupport_L/R`, `RearBrace_L/R`, `Foot_L/R`를 조합했다.

공유 재질은 `TrainingMirror_MatteDarkGrayMetal` 한 개다. Blender Principled 기본색 linear RGB=(0.065, 0.075, 0.082), Metallic=0.8, Roughness=0.68이다. 텍스처·반사 셰이더·외부 재질 파일은 제작하지 않았다. FBX에는 단순 금속 재질 정의만 포함되며 Unity 재질 파일은 생성/수정하지 않았다. Unity에서의 재질 해석 및 연결은 검증 범위 밖이다.

## 원점·축·내보내기

- 모든 부품의 원점은 기존 반사면 중심 (0,0,0)이다. 오브젝트 이동/회전은 0, 배율은 1이다.
- 설계 및 FBX 메시 좌표는 X=가로, +Y=위, −Z=사용자 쪽, +Z=뒤판/지지대 쪽이다. Surface는 XY 평면 Z=0이다.
- Blender 원본에서는 (X,Y,Z)=(Unity X, −Unity Z, Unity Y)로 제작했다. 따라서 Blender의 +Z가 위, +Y가 앞쪽이다.
- Blender 단위 METRIC, unit scale=1.0. FBX global scale=1.0, Forward=−Z, Up=Y, Apply Unit Scale=true, Apply Scalings=FBX Units Scale, Bake Space Transform=true로 내보냈다.
- FBX 7400의 원시 메시 좌표가 요구된 미터 수치 및 축과 일치함을 파서로 확인했다. FBX `UnitScaleFactor=100`은 1 FBX 좌표 단위=100cm=1m라는 표준 단위 메타데이터이며, 모델 확대 100배를 뜻하지 않는다. 모든 FBX Mesh 노드의 로컬 이동/회전=0, 배율=(1,1,1)을 확인했다.
- 카메라·조명·가이드·Surface·애니메이션·아마추어·추가 루트 Empty 없이 각 파일당 Mesh 노드 8개만 내보냈다.
- 향후 기존 `K1_Mirror` 또는 `PC_Mirror` 루트의 별도 자식으로 모델을 추가하고 로컬 위치/회전 0, 배율 1로 맞추는 구성이다. 기존 Surface/Camera의 자식으로 넣거나 교체할 필요가 없다. 이번 작업에서 실제 Unity 적용은 하지 않았다.

Blender 원본의 두 컬렉션은 동일한 요구 원점에 있으므로 겹쳐 있다. 초기에는 K1만 표시하고 PC는 뷰포트/렌더 표시를 꺼 두었다. 다른 크기를 확인할 때 K1을 숨기고 PC 컬렉션의 모니터/렌더 표시를 켜면 된다. 모델 오브젝트 자체를 옮길 필요는 없다. 이 컬렉션 표시 설정은 이미 내보낸 PC FBX에 영향을 주지 않는다.

## 검증 결과

1. **개구부/반사면 비침범**: 원본과 FBX 재반입의 모든 삼각형 위치가 0.01mm 정밀도로 일치한다. 정확한 Surface 사각 영역 내 Z≤0의 메시 교차는 0건이다. 따라서 베벨·프레임·지지대가 Surface를 가리지 않는다. 뒤판은 +Z에만 있다.
2. **원점/축/실측/바닥**: 원본과 재반입의 전체 외곽, 삼각형, 부품 수가 일치한다. FBX 원시 좌표·단위·노드 변환도 별도 검사했다. 최하단 Y는 각각 −0.950 / −0.980이고 바닥 아래 메시가 없다. 프레임은 수직이다.
3. **메시 건강 상태**: 원본 및 재반입에서 열린 경계, 비다양체 모서리, 사용되지 않은 정점, 중복 정점/면은 0개다. 각 부품의 signed volume은 양수다. 원본의 모든 면을 바깥 방향으로 재계산해 비교한 법선 변경은 0개다. 재반입은 동일한 삼각형 형상과 바깥 부피를 유지했다. 부품 간 중복 면 0개, 양의 부피를 갖는 AABB 겹침 0개로 내부 관통 부품도 없다. 맞댐 경계의 닫힌 캡은 각 부품의 독립성을 위해 유지했다.
4. **부품/재질/예산**: 파일당 8개 부품 모두 재반입되었으며 재질 1개, 2,000삼각형 이하를 충족한다. 이름별 상세값은 `validation.json`에 있다.
5. **시각 확인**: 실제 Blender 렌더의 정면·측면·후면·사선에서 베벨, 수직 구조, 후면 보강, 낮은 받침대를 확인했다. 청회색 중앙 면은 기존 Surface 위치를 설명하는 임시 가이드이며 납품 FBX/원본 모델에는 없다. 미리보기 바닥·카메라·조명도 납품 FBX/원본 모델에는 없다.
6. **기존 파일 보존**: 작업 시작 시 납품 폴더 밖 Git 추적 파일 및 ignore되지 않은 미추적 파일 4,303개를 기록했다. 작업 후 같은 4,303개 파일의 크기/수정시각(ns) 비교에서 변경 경로는 0개다(`workspace_after.json`). 시작 전부터 있던 폰트 1개·Docs/B 문서 4개의 수정 및 미추적 문서 1개는 본 작업과 무관하며 그대로 보존했다. 모든 작성 스크립트와 결과 파일의 저장 경로는 `Assets/B/Models/TrainingMirror/` 내부로 한정했다.

   작업 전부터 실행 중이던 Unity 프로세스가 새 자산을 감지하여 FBX의 `.meta` 2개(납품 폴더 내부)와 폴더용 `Assets/B/Models/TrainingMirror.meta`(납품 폴더 바깥)를 자동 생성했다. 바깥의 폴더 메타는 기준 기록에 없었던 신규 파일임을 확인한 후 제거했다. 그 뒤 다시 실행한 보존 검사에서 지정 폴더 바깥의 추가/변경/삭제는 0개였다. Unity 프로세스를 실행·종료하거나 프로젝트 설정을 조작하지 않았다. 내부 FBX 메타는 이미 실행 중이던 Unity가 생성한 기본 임포트 메타데이터이며 직접 작성/편집하지 않았다. Unity가 향후 자동 새로고침하면 폴더 메타가 다시 생성될 수 있다.

## 검증 범위와 후속 확인

Unity를 실행하거나 씬/프리팹/코드/재질/설정/A·C 자산을 수정하지 않았다. **Unity 반사 동작, HMD 시점, RenderTexture 수명, 아바타 표시 제외, 실제 재질 연결, 충돌, 손 조작 간섭, VR 동선은 검증하지 않았다.** 기존 기능 검증 완료로 간주하지 않는다. Unity 임포터의 실제 결과 역시 이번에는 실행 확인하지 않았으며 위 축/크기 보고는 Blender 재반입과 FBX 데이터 검사 기준이다.

후방 150mm 안에 양쪽 발과 삼각 보강대를 구성했다. 실제 전도 안정성/하중/마찰은 메시 제작으로 검증할 수 없으므로 인증하지 않는다. Unity 배치 후 옆 작업대, K1_RearView 화면, 손 조작, 순간이동 통로와의 실제 간섭은 사용자가 확인할 항목이다.

## 재현

1. `workspace_audit.py before`는 첫 제작 전에 실행한 기준 기록이므로 재납품 때 기존 기준 파일을 덮어쓰지 않도록 주의한다.
2. Blender background에서 `build_training_mirror.py`를 실행하면 FBX 2개, 원본 blend, 기본 validation.json이 생성된다.
3. Blender background에서 `audit_and_preview.py`를 실행하면 확장 검사와 미리보기 8개가 생성된다.
4. 일반 Python + Pillow로 `label_previews.py`를 실행하면 미리보기에 임시 가이드 설명을 추가하고 종합 미리보기를 만든다. 라벨 적용은 렌더 직후 1회 실행한다.
5. `workspace_audit.py after`로 납품 폴더 밖 변경이 없는지 확인한다.
