## 3. 구성

새 asmdef는 없다. 기존 `MilTrainSimVR.B.TrainingField` 어셈블리가 PB·UI·XRI를 이미 참조하고 있어서, 스크립트 2개를 그 어셈블리에 추가했다.

| 객체 | 구성 |
|---|---|
| `SceneSystems/FieldSfx` (두 씬) | `TrainingFieldSfx`와 AudioSource 1개 |
| `Station_PressureBandage/BandageWrapSfx` (구급법) | `BandageWrapSfx`와 AudioSource 1개 (Content 밖) |

**`FieldSfx`의 AudioSource:** 2D(spatial blend 0), 루프 꺼짐, Play On Awake 꺼짐, 자체 clip 없음(PlayOneShot만 사용), Doppler 0, volume 1.

**`BandageWrapSfx`의 AudioSource:**

- 3D(spatial blend 1), 루프 켬, Play On Awake 꺼짐, Doppler 0
- Logarithmic, 최소 거리 1 m, 최대 거리 10 m, spread 0
- clip은 `BandageWrap_Loop_v1`

**공통 사항:**

- AudioListener를 추가하지 않았다. XR camera의 기존 1개를 쓰며, 기존 검사가 이를 확인한다.
- 전역 Singleton, DontDestroyOnLoad, `Time.timeScale`·`AudioListener.pause` 변경은 없다.

**Inspector 초기값:**

- `TrainingFieldSfx`: clickVolume 1, completeVolume 1
- `BandageWrapSfx`: volume 1, fadeIn 0.04 s, fadeOut 0.08 s, progressGap 0.1 s
- 원본 피크 차이(클릭 −12, 완료 −10, 붕대 −26 dBFS)를 그대로 쓰므로, 붕대가 작게 들리는 의도는 유지된다.
- 붕대는 손 거리(1 m 이내)에서는 감쇠되지 않는다.
- AudioSource volume 상한이 1이라, 더 크게 하려면 새 음원 버전이나 믹서가 필요하다.

## 4. 버튼 클릭음

**재생 방식:**

- `TrainingFieldSfx.clickButtons`의 각 버튼 `onClick`에 OnEnable 때 리스너를 1번 추가하고, OnDisable 때 같은 목록에서 제거한다.
- 목록의 같은 버튼은 한 번만 등록한다. 기존 리스너와 이벤트는 그대로 두었다(지우거나 교체하지 않음).
- 소리는 SceneSystems 객체에서 재생된다. 그래서 클릭 처리에서 버튼이 숨겨져도 끊기지 않고, activeInHierarchy도 검사하지 않는다.

**재생되지 않는 경우:** uGUI는 활성·상호작용 가능한 버튼이 실제로 눌렸을 때만 `onClick`을 낸다. 따라서 다음에는 소리가 나지 않는다.

- 호버
- 레이가 닿기만 한 경우
- 스크롤 드래그
- 비활성 버튼
- 차단판에 가려진 버튼

**연결한 버튼:**

## 5. 완료음

- `TrainingFieldCoordinator.LateUpdate`의 기존 완료 전환 조건 안에서 해당 station을 목록에 담는다. 이 조건은 `CourseLink.State == Completed`이고 `SeenState != Completed`일 때 `LastResult = Completed`로 기록하는 부분이다.
- 담은 station에 대해 LateUpdate 끝(상태·표시 처리 뒤)에 새 이벤트 `CourseCompleted`를 1번씩 발생시킨다. 기존 판정과 처리 순서는 바꾸지 않았다.
- 구독자 예외는 `Debug.LogException`만 남기며, 교육 흐름에는 영향이 없다. 오디오 쪽은 상태를 읽기만 하고 쓰지 않는다.
- 재생되지 않는 경우:
  - 교육 종료(Completed → Waiting)
  - 완료 화면을 유지하는 동안(전환이 없음)
  - 중단·Faulted
  - 개별 단계
  - 초기화·재구독(이전 상태와 비교하므로 새 전환이 생기지 않음)
- 다시하기 뒤 새 회차가 Completed에 도달하면 다시 1번 재생한다.

## 6. 붕대 감기 루프

`BandageWrapSfx`는 실행 순서 310의 LateUpdate에서 실행된다. 같은 프레임의 Application(102) 갱신이 끝난 값을 읽기만 한다.

- **재생:** 직전 표본보다 `WrapProgress`가 증가했을 때다. 다음 조건을 모두 만족해야 한다.
  - 과정 상태 Running
  - `Suspended`가 아님(중단 확인창 보류)
  - `IsResetting`이 아님
  - 이번·직전 Stage가 모두 Wrapping
  - `Block == None`. 즉 롤을 추적된 손이 잡고 영역 안에 있고, 드레싱이 배치돼 있고, 포커스가 있고, 시작이 허용된 상태다.
- **기준 재설정(소리 없음):** 다음 경우 직전 표본을 다시 잡는다. 그래서 감기 시작의 0, 마지막 프레임의 EndPlacement·1 보정, 초기화 값이 감기로 들리지 않는다.
  - 활성화 직후 첫 표본
  - `ResetCount`·`CancelCount`가 바뀌었을 때
  - 직전 Stage가 Wrapping이 아닐 때
- **정지:** 조건이 하나라도 깨지면 바로 0.08 s 페이드아웃한다. 조건은 유지되지만 증가가 0.1 s 넘게 없을 때도 같은 페이드로 멈춘다.
  - 대상: 손을 놓음, 영역 이탈, 추적·포커스 소실, 보류, 감기 완료, 취소, 초기화·다시하기, 과정 종료
  - 단순 정체는 Pause하므로, 다시 재생하면 이어서 들린다.
  - 그 밖의 경우는 Stop한다.
  - OnDisable(씬 이탈 포함)에서는 즉시 Stop한다.
- 계속하기 뒤에는 실제 증가가 다시 생길 때만 재생한다(Application이 첫 유효 프레임에는 진행률을 더하지 않는다).
- Play·UnPause는 시작할 때만 부른다. 프레임마다 Play를 호출하지 않는다.
- 객체 위치는 롤이 활성일 때 롤 위치를 따라간다. 장비의 부모·물리·잡기, wrapAmount·Stage·판정은 바꾸지 않는다.

## 8. 위험·미해결

1. 컴파일, 임포트, AudioClip 로드, 재생 모두 확인 전이다. 손으로 쓴 AudioImporter meta를 Unity가 다시 저장할 수 있다.
2. 압박붕대·지혈대의 마지막 확인 클릭으로 바로 완료되면, 클릭음과 완료음이 같은 프레임에 겹친다(청취 확인 대상).
3. KD-1 "처음부터"를 다시하기 계열로 포함했다. 빼려면 씬 목록과 검사 표(`ClickButtonFields`)를 함께 고쳐야 한다.
4. 붕대음은 원본 RMS가 약 −40 dBFS라 작게 들릴 수 있다. volume 상한은 1이다.
5. 루프 경계와 잦은 시작·정지에서 딱 소리가 나는지는 청취로만 판단할 수 있다(페이드 0.04/0.08 s).
6. 진행이 멈춘 뒤 소리는 최대 약 0.18 s 남는다(0.1 s 대기 + 0.08 s 페이드).

## 9. 사용자 확인 순서

1. Unity 임포트·재컴파일 → 구급법·화생방 읽기 전용 검사 → 오류·Missing·새 FAIL 없음.
2. 대상 버튼 클릭 → 클릭당 한 번. 호버·스크롤·차단된 버튼·AED 장비 버튼에는 클릭음 없음.
3. 클릭으로 화면이 즉시 바뀌어도(시작·중단하기·교육 종료) 클릭음이 끊기지 않음.
4. 각 과정 전체 완료 → 완료음 한 번. 교육 종료 버튼, 완료 화면 유지 중에는 추가 재생 없음.
5. 다시하기 후 재완료 → 새 회차에 완료음 한 번.
6. 붕대 진행률이 증가하는 동안만 마찰음. 롤을 잡고 가만히 있거나 영역 밖이거나 진행이 막히면 소리 없음.
7. 감기 중 중단 → 계속하기 → 중단 중에는 무음, 실제 감기가 다시 시작될 때만 재생.
8. 감기 완료·취소·다시하기·허브 복귀 → 루프가 남지 않음.
9. 붕대 루프의 반복 경계와 잦은 시작·정지에서 딱 소리가 없는지 청취.
10. Quest 2 + Link에서 소리 위치, 체감 음량, 클릭·완료음 구별, 다른 교육 UI와 함께 동작하는지 확인. 조정 항목은 `TrainingFieldSfx` clickVolume/completeVolume, `BandageWrapSfx` volume/fadeIn/fadeOut/progressGap, 루프 AudioSource의 최소·최대 거리.

### 반입 설정

v1 AudioImporter meta를 복제하고 GUID만 새로 지정했다. 나머지 필드는 바이트 대조에서 동일하다.

| 항목 | 저장한 meta 값 |
|---|---|
| Decompress On Load / PCM | `loadType: 0` / `compressionFormat: 0` |
| 샘플레이트 유지 | `sampleRateSetting: 0` |
| Preload | `preloadAudioData: 1` |
| Normalize / Force To Mono | `normalize: 0` / `forceToMono: 0` |
| Background / Ambisonic | `loadInBackground: 0` / `ambisonic: 0` |
| 플랫폼 override | `{}` |

`sampleRateOverride: 44100`은 v1의 비활성 필드값을 그대로 보존했다. Preserve 설정이므로 적용 대상이 아니며 원본 WAV는 48,000 Hz다. Unity를 실행하지 않았으므로 실제 AudioClip 임포트·설정 해석 완료를 뜻하지 않는다.

### 파일·참조 정적 대조

| 항목 | v1 | v2 |
|---|---:|---:|
| WAV 형식 | 비압축 PCM / 48,000 Hz / 16bit / Mono | 동일 |
| 표본 수 / 길이 | 124,800 / 2.600초 | 동일 |
| 샘플 피크 dBFS | −26.002 | −20.002 |
| 전체 RMS dBFS | −40.440 | −34.440 |
| 클리핑 표본 / 전역 DC 평균 FS | 0 / 0 | 0 / 0 |
| 마지막→첫 표본 차이 | 1 LSB | 2 LSB |

저장된 WAV를 다시 읽어 측정했다. v1 대비 최소제곱 진폭비의 증가량은 +6.000024 dB이며, 정확한 +6 dB 배율 적용값과의 최대 차이는 약 0.502 LSB다. PCM 양자화 수준의 차이이며, 새 음원의 +6 dB 변경과 일치한다. 체감상 두 배 음량이라는 뜻은 아니다. 루프 경계 수치는 청취 통과 판정이 아니다.

씬은 백업 대비 **두 클립 GUID만 변경**됐다. 그 외 전체 바이트가 같으므로 AudioSource volume 1, 스크립트 volume 1, fadeIn 0.04초, fadeOut 0.08초, progressGap 0.1초, 최소/최대 거리 1/10 m, 3D·루프·자동 재생 끔·Doppler 0 및 모든 나머지 씬 내용이 유지된다. 붕대 재생 조건 코드는 해시가 같으며 클릭·완료 연결도 유지된다.

**미실시:** Unity 실행·임포트·재컴파일·검사 메뉴·Play·Simulator·재생·직접 청취·빌드·커밋·Push. 위 내용은 파일·헤더·표본·참조·해시의 정적 대조 결과다.

### 사용자 확인 순서

1. Unity에서 임포트·재컴파일 후 v2 클립과 반입 설정 확인. Missing 또는 컴파일 오류가 없어야 한다.
2. 구급법 읽기 전용 검사 실행. v2 경로·해시·2.6초 길이·클립 연결 관련 새 FAIL이 없어야 한다.
3. 실제 감기 진행률이 증가하는 동안 음량 증가 확인. 클릭·완료음과 구별되고 주요 알림이 묻히지 않아야 한다.
4. 중단·감기 완료 시 기존 페이드로 정지하는지 확인. 붕대 루프를 5회 이상 들어 경계 딱 소리·끊김·주기적 무음이 없어야 한다.
