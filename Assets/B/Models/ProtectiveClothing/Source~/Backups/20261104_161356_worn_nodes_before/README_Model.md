# 보호장비 모델 — 참고 이미지 기반 외형 개선, 사용자 몸 착용 전환

## 확인된 내보내기 결함: Worn 스킨 메시 노드 변환 (2026-11-04, 모델 미수정)

Unity 검사 FAIL(Worn 메시 원점·Attach 최대 2011.62 mm)의 원인을 원시 FBX 판독으로 확인했다. 대상은 현재 h5, h4 백업, 11/03 18:20 FBX이며 세 파일이 같다. 세부는 `Docs/B/1104_보호의_착용교육과정_연결_구현기록.md` §12.3.
- 스킨 메시 6개 노드의 `Lcl Rotation`이 루트 대비 −90° X다. 반면 스킨 클러스터 바인드 좌표계(`TransformLink × Transform`)는 루트 전역과 정확히 같다. 파일 안에서 노드 변환과 스킨 바인드가 일치하지 않는다.
- 그래서 Unity의 메시 GameObject와 그 자식 `Attach_*_Worn`가 90° 돌아간 위치에 놓인다. 스킨 표시는 bindpose를 따른다.
- 필요한 작업(모델 범위, 아직 하지 않음): 노드 `Lcl`이 항등이 되도록 Worn FBX를 다시 내보낸다. h5 형상·가중치·65본·이름·GUID는 유지하고, 원시 노드 판독으로 확인한다.

## 최종 검토: h5 채택 및 전체 본 재수입 (2026-11-04)

**이 절과 `JacketDeformFixReport.json`의 h5 결과가 아래 h4/이전 작업 기록보다 우선한다.** 이번 후속 작업은 Blender 모델·FBX·검사·기록에 한정했다. 기존 Unity 변경은 보존했으며 C#·씬·Prefab·설정 수정, Unity 실행·테스트·빌드·커밋·Push를 하지 않았다.

최종 `.blend` 저장, Worn FBX 내보내기, 별도 `FBX_Roundtrip_Review.blend` 재수입 저장·대조 완료. h4 결과가 이미 생성된 상태를 확인한 뒤 보완했다. 현재 파일과 기존 백업을 보존했으며 시작 상태는 `Backups/20261104_145838_h4_review_before/`와 `BackupSHA256.json`에 추가 보관했다.

h4의 옆구리 축소·가중치 재전송·칼라 어깨 가중치·짧은 간선 평활은 유지했다. h5는 소매 아래·겨드랑이 주변 깊은 관통점과 반경 18mm 안의 인접 정점 위치만 부드럽게 조정했다. 기준 자세와 6개 자세의 인체 표면을 같은 조건으로 대조해 변위를 정했으며, h4 가중치는 그대로다. 인체·기준 골격은 변경하지 않았다.

h4→최종: 실제 좌표 변화 70개, 0.1mm 초과 52개, 최대 2.1251mm. 피부·의복 메시를 숨기는 변경이나 새 천 시뮬레이션·런타임 보정은 없다.

### 남은 제한과 원본 이력

소매 아래·겨드랑이·옆구리 관통은 현재 형상·가중치 보완 범위에서 잔존한다. 최종 전체 정점 최대 관통은 가벼운 굽힘 7.95mm, 팔 내림 5.82mm, 회전 5.67mm다. 팔꿈치 굽힘 최대 늘어남 2.395배, 손 가슴 2.476배는 h4와 같아 과도한 늘어남이 남는다. h4의 최대 18.5mm 옆구리 축소에 의한 실루엣 변화도 유지된다. 향후 해결 가능 범위나 필요한 기법을 이번 검토만으로 단정하지 않는다.

보존된 11/03 18:38 `.blend`는 두건·어깨 덮개가 있는 전환 이전 형상(19,282면), `PC_Armature`와 상의 가중치가 없고, 전환 이전 백업과 목록·메시가 일치함을 다시 확인했다. 이것은 파일 내용에 관한 사실이다. 이전 상태를 연 세션이 나중에 저장했을 가능성은 추정이며, 저장한 주체·프로세스·이유는 확인되지 않았다. 최종은 이를 작업 기준으로 쓰지 않았다.

**Unity 임포트·1인칭·거울·VR 품질·성능은 사용자 실행 미확인이다.** Blender 저장·내보내기·재수입 통과와 구분한다.

  | Glove_L / Glove_R | 해당 쪽 ForeArm·Hand·손가락 15개 | 그 밖→해당 ForeArm |
  | Overboot_L / Overboot_R | 해당 쪽 Leg·Foot·ToeBase | 그 밖→해당 Leg |

  정점당 최대 4개 영향, 정규화. 가중치 없는 정점 0개. 각 메시에 `PC_Armature` Armature 모디파이어(오브젝트 부모는 그대로 `ProtectiveClothing_Worn`).
- 천 시뮬레이션·착의 애니메이션·IK·추가 조작 대상은 없다. Pickup은 리그 없는 독립 소품 그대로다.

### FBX 구성(재내보내기)

```text
ProtectiveClothing_Worn.fbx (MESH, EMPTY, ARMATURE; deform 본만, leaf 본·애니메이션 없음)
  ProtectiveClothing_Worn
    PC_Armature
      mixamorig1:Hips ... (본 65개, 원본과 같은 계층; 가중치가 있는 본은 표의 사용 본뿐)
    <Component>_Worn           (스킨 메시, 6개)
      Attach_<Component>_Worn  (기준 자세 기준점; 몸을 따라가지 않음)
ProtectiveClothing_Pickup.fbx (MESH, EMPTY; 리그 없음, 계층 변경 없음)
```

내보내기 설정은 이전과 같다(Global Scale 1, apply_unit_scale, FBX_SCALE_UNITS, −Z 전방, Y 위, space transform 굽지 않음). Worn에만 `use_armature_deform_only`, `primary_bone_axis='Y'`, `secondary_bone_axis='X'`, `armature_nodetype='NULL'`을 더했다. Blender 내보내기는 아마추어의 자식이 아닌 스킨 메시를 원래 부모(`ProtectiveClothing_Worn`) 아래에 둔다(io_scene_fbx 연결 규칙). Blender로 다시 불러오면 importer가 메시를 아마추어 아래로 옮기지만 월드 행렬은 같다.

Unity 연결부는 이 구성을 명시적으로 반영한다. Worn FBX Import는 'Generic, 아바타 없음, 애니메이션 없음, 본 오브젝트 유지'로 바뀌었고 Pickup은 '리그 없음'을 유지한다. Unity에서는 Worn 인스턴스를 사용자 몸 마네킹 인스턴스의 원점에 두고, 각 Worn 본이 같은 이름의 마네킹 본을 기준 자세의 고정 차이로 따라간다.

## 형상 수정

상의는 기존 맞춤 외피를 유지해 어깨/소매 연결을 부드럽게 하고 팔꿈치·겨드랑이·허리에 절제된 주름을 만들었다. 앞여밈은 몸통 곡면을 따르는 얇은 직물 덮개로 바꿨다. 주머니는 네모난 상자 대신 휘어진 천 포켓, 약한 부풀음, 얇은 덮개와 가장자리 봉제 구분으로 제작했다. 올리브색 후드·얼굴 테두리·어깨 덮개는 전부 **Jacket_Worn 한 메시** 안에 포함했다(→ 사용자 몸 착용 전환에서 삭제, 목둘레는 위장 칼라로 마감). 후드의 목 통과 공간을 열어 목 내부의 불필요한 막힘을 제거했다.

하의는 골반·사타구니·다리 표면을 완만하게 정리하고 넉넉한 바지통, 무릎의 굴곡, 발목 모임, 허리띠와 허벅지 포켓을 보완했다. 허리·손목·발목의 피부 노출과 표면 교차를 렌더로 확인하며 보정했다.

장갑은 원본 마네킹 손의 해부학적 정점/손가락 사이 구조를 기반으로 얇은 고무 외피를 다시 만들었다. 이전의 손가락이 뭉친 Voxel 형태를 제거하고 다섯 손가락·엄지와 검지 사이·손등을 분리해 읽을 수 있게 했다. 길고 넓은 커프가 소매를 감싸며 입구·말린 테두리·고무 접힘을 표현했다. 본인 좌우 손을 각각 원본의 해당 손에 맞췄다.

덮개는 발목에서 발등·앞코로 이어지는 단면을 늘려 원통/신발의 딱딱한 접합을 줄였다. 고무 발목 주름, 입구 테두리, 밑창 립, 측면 겹침과 고정 띠를 추가했다. 본인 좌우 발을 각각 감싼다. 눈에 띄는 베이지색 L/R 패치는 Worn/Pickup에서 모두 제거했다. 좌우 식별은 기존 이름과 손·발의 실제 좌우 형상으로 유지한다.

Pickup 상·하의도 같은 위장 직물로 갱신했다. 둥근 접힌 층, 얕은 상단 굴곡, 소매·포켓·접힌 올리브 후드(→ 사용자 몸 착용 전환에서 삭제) 및 허리띠·다리 중앙 접힘으로 구별한다. 층 측면에는 별도 둘레 길이 UV를 사용해 두께 방향 무늬가 한 줄로 늘어나지 않게 했다. 장갑·덮개 Pickup에도 개선된 고무 형상을 동일하게 반영했다. 피벗·Grip·Attach는 외형 변경 후에도 이동하지 않았다.

## 텍스처와 공용 머티리얼

고유 장비 머티리얼 `PC_Shared` 1종, 메시마다 슬롯 1개를 유지했다. Blender 전용 Noise/시뮬레이션에 의존하지 않고 파일 이미지 기반 BaseColor/Roughness/Tangent Normal을 사용한다. Metallic은 0이다. 고무는 거칠기에 변화를 주어 검은색에서 형태가 읽히도록 했으며 금속 재질로 설정하지 않았다.

|---|---|---|
| PC_BaseColor_2K.png | 2048² → 2048² RGB | 단색 올리브/LR 패치 → 삼림 위장·올리브 후드/케이프·검은 고무 공용 아틀라스 |

아틀라스의 UV [0,.75]²는 위장 직물이고 오른쪽 영역은 올리브·고무·봉제용이다. 기본 직물 물리 밀도는 약 983px/m(2048 이미지, 1.5m당 UV .72)이며 몸통·소매·다리를 미터 단위 길이와 둘레로 배치했다. 소매와 바지의 실제 둘레 차이/모임에 따른 밀도 차이는 남지만 구성품마다 임의로 Smart UV를 꽉 채워 무늬 크기가 달라지는 방식은 피했다. 패널 경계는 봉제 방향에 놓고 방위각을 넘어가는 면의 UV 연결을 보정했다.

위장 원본은 **imagegen 스킬의 기본 내장 image_gen 도구**로 새로 생성했다. `ReferenceImages/Woodland_Generated_Master.png`가 생성 결과이고 사용 프롬프트 전체는 `ReferenceImages/ImageGen_Prompt.txt`에 보존했다. 원본 사진의 조명/그림자를 굽지 않았으며 생성 원본도 팔레트로 양자화해 명암을 제거했다. 이후 주기적인 미러 샘플링으로 경계를 연속화해 아틀라스에 배치하고 미세한 결·거칠기·탄젠트 노멀을 수치적으로 합성했다. 특정 제조사의 무늬를 정확하게 복제하거나 제품으로 인증한 것은 아니다.

## Unity에 전달할 확인/조정 사항

Unity를 시작하거나 Editor API/메뉴/Play/Simulator/테스트/빌드를 실행하지 않았다. 현재 씬·설정 코드와 `.mat`를 파일로 읽기만 했다. 코드·씬·Prefab·`.mat` 연결·Importer `.meta`는 수정하지 않았다. 기존 FBX 및 PNG의 `.meta`와 상위 폴더 GUID도 그대로이다.

기존 `PC_Shared.mat`는 BaseColor와 Normal을 같은 GUID로 참조하므로 연결을 바꿀 필요가 없도록 파일을 갱신했다. URP의 MetallicGloss Alpha용 기존 파생 이미지도 위처럼 갱신했으므로, Unity 작업자는 기존 FBX 2개/이미지 4개의 재임포트 및 머티리얼 표시 갱신을 확인하면 된다. FBX의 기존 materialImportMode는 0이므로 새 FBX에서 별도 머티리얼을 추출하는 절차를 요구하지 않는다. 실제 Unity 화면과 VR 반사는 아직 확인하지 않았다.
