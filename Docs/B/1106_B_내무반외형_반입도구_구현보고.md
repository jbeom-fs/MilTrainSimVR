## 반입 계층·제외 범위

처음 사용자 메뉴를 실행하면 A 씬을 Editor preview로 읽고, 새 GameObject에 허용한 외형 컴포넌트만 복사한다. Preview는 저장 없이 닫는다. B 씬에 A 씬을 추가 로드하거나 A 프리팹 연결을 유지하는 구조가 아니다.

```text
EnvironmentRoot
├─ B_BarracksShell                  # 두 운영 씬이 공유하는 B 프리팹 인스턴스
│  ├─ Shell                         # 원본 자식 Transform·활성 상태 보존
│  │  ├─ Floor / Ceiling / Ceiling_Joints
│  │  ├─ Wall_*                    # 비활성 North_Lintel도 비활성 상태 보존
│  │  └─ Window_L / Window_R        # 풀린 외형 계층, A Window.prefab 연결 제외
│  ├─ Door_Range
│  │  ├─ Model                     # 손잡이의 보이는 모델 포함
│  │  └─ Backing
│  └─ CeilingFixtures              # 원본 Barracks의 Transform 보존
│     └─ CeilingPanel ~ (5)        # 저장 원본에서 확인한 6개 외형
├─ B_BarracksInstallation           # 씬 소유 영수증
│  ├─ B_BarracksWalkable            # TeleportationArea 1개, 명시적인 셀 충돌체
│  └─ B_InteriorFill_*              # 필요한 경우에만 첫 반입에서 보조 점광원2개
└─ 기존 B 환경 객체                 # 무단 삭제 없음
```

복사 컴포넌트는 Transform, MeshFilter, MeshRenderer, 비트리거 BoxCollider/MeshCollider로 제한했다. Unity 객체 정체성·A prefab correspondence는 복사하지 않는다. Renderer 재질·그림자·정렬·렌더 설정과 메시 참조를 보존하되, A 씬의 베이크 인덱스는 가져오지 않는다. 선택 계층 밖의 장면용 probe 참조는 비운다. 창문에 기존 상위 충돌체가 있으면 재사용하고, 없을 때만 B 충돌체를 만든다.

제외: 침대8·관물대8, 중앙 Desk·총기·교육 패널, TV·기타·건조대·LightSwitch·포스터·소화기, A 교육 Controller·장비 코드, DoorTransition·ScreenFader, `Handle_Barracks` 기능 트리거, A XR/카메라/AudioListener/입력/EventSystem/Points, Lights_Temp의 A 광원, Outdoor·Room_Range 전체. Door_Range의 보이는 손잡이는 FBX 외형에 포함한다. 문 전환 코드는 없다. 창밖은 기존 B 배경을 사용하며 새 야외 공간을 만들지 않는다.

## A→B 자산 대응

실행 시 선택 외형의 Mesh/Material/Texture/FBX 의존성을 AssetDatabase로 확정한다. 원본 prefab correspondence는 의존성 수집에서도 제외한다. A Window.prefab은 외형을 읽기 위한 계층이며 사본의 연결 대상이 아니다. 실제 메시·재질·텍스처만 B 소유로 연결한다.

기본 경로 약어:

- `M = Assets/B/Models/TrainingEnvironment/Barracks`
- `T = Assets/B/Materials/TrainingEnvironment/Barracks`

| A 원본 | 사용자 메뉴 실행 후 B 대응 |
|---|---|
| `Models/Wall/Meshes/WallBox_*.asset` | `M/Wall/Meshes/` 동일 파일명 |
| `Models/Wall/Materials/Wall.mat` | `T/Wall/Wall.mat` |
| `Models/Wall/Textures/*` | `M/Wall/Textures/` 필요한 텍스처 |
| `Models/Floor/Materials/Floor.mat` | `T/Floor/Floor.mat` |
| `Models/Floor/Textures/*` | `M/Floor/Textures/` 필요한 텍스처 |
| `Models/Ceiling/Meshes/CeilingGrid.asset` | `M/Ceiling/Meshes/CeilingGrid.asset` |
| `Models/Ceiling/Materials/Ceiling.mat`, `CeilingJoint.mat` | `T/Ceiling/` 동일 파일명 |
| `Models/Ceiling/CeilingTile.png` | `M/Ceiling/CeilingTile.png` |
| `Models/CeilingPanel/CeilingPanel.fbx` | `M/CeilingPanel/CeilingPanel.fbx` |
| `Models/CeilingPanel/Materials/CeilingPanel_Emitter.mat` | `T/CeilingPanel/CeilingPanel_Emitter.mat` |
| `Models/Door/sage_glass_door.fbx` | `M/Door/sage_glass_door.fbx` |
| `Models/Window/Window.fbx` | `M/Window/Window.fbx` |
| `Models/Window/Materials/Window.mat`, `WindowGlass.mat` | `T/Window/` 동일 파일명 |
| `Models/Window/Textures/*` | `M/Window/Textures/` 필요한 텍스처 |

표의 A 경로 앞에는 `Assets/A/`가 붙는다. FBX 내부 재질은 복사된 B FBX의 subasset으로 대응한다. 실제 목록·GUID는 메뉴 실행 시 확정하므로 지금 생성·반입 완료로 보고하지 않는다.

정적 저장 자료에서 선택 외형에 확인한 벽 메시 7종:

```text
WallBox_0.2x2.644x9.84.asset
WallBox_1.2x0.8x0.2.asset
WallBox_1.69x0.344x0.2.asset
WallBox_1.69x1x0.2.asset
WallBox_1x2.644x0.2.asset
WallBox_3.02x2.644x0.2.asset
WallBox_4.692x2.644x0.2.asset
```

벽 메시는 정점 범위 ±0.5인 단위 상자이며 자식 scale이 실제 치수다. UV는 치수/4m 타일 기준으로 생성되어 있다. CeilingGrid는 실제 위치가 정점에 들어 있다. 메시 재생성·UV 재작성·scale 합치기·자식0/1 초기화를 하지 않는다. 원본 형상 수정이 필요하지 않아 Blender도 실행하지 않았다.

자산 복사 시 원본 데이터와 importer 설정을 B 경로에 복사하고, **각 사본 자체 GUID와 연결 GUID를 모두 새 대응값으로 치환한 뒤** Unity에 임포트한다. 씬 YAML은 수정하지 않는다. FBX/mesh의 local fileID를 보존하고 `(자산 경로, 타입, local fileID)`로 Renderer/mesh 참조를 B 사본에 연결한다. prefab에 A 자산 의존성이 하나라도 남으면 실패한다.

생성 기록:

- `M/ImportManifest.json`: 반입 revision/UTC, 원본 씬 SHA256, 선택 계층 목록, 모든 source/destination 경로·GUID·원본 데이터/meta SHA256.
- `Assets/B/Prefabs/TrainingEnvironment/B_BarracksShell.prefab`: 공유 B 환경 작업본.
- 씬별 `BarracksEnvironmentRecord`: 최초 배치 대상과 최초 좌표/yaw, 원본 스냅샷 해시, 성공 실행 횟수/UTC, 환경·이동 영역·보존한 임시 바닥 참조.

남겨도 되는 외부 참조는 Unity 기본 메시/내장 자산과 공용 URP 셰이더·패키지다. 저장 재질에서 확인한 공용 shader GUID는 `933532a4fcc9baf4fa0491de14d08ed7`이며 복사/수정하지 않는다. 읽기 전용 검사는 실제 package 의존성 경로도 출력한다. A/C 및 다른 공용 Assets 경로가 B 외형 의존성에 남으면 FAIL이다.

## 최초 배치·반복 보존

첫 반입에만 세 StationRoot의 위치·수평 회전을 계획한다. local/lossy scale1을 요구하며 자식 장비·판정·UI의 Transform 및 내부 참조는 변경하지 않는다. AED 누운 자세, 지혈대·압박붕대 앉은 자세, 보호의/거울·K1 관찰 구성을 기존 Content 그대로 이동한다.

- 좌측 구역: X=-3.85~-0.8, Z=-6.05~-1.8m.
- 우측 구역: X=0.8~3.85, Z=-6.05~-1.8m.
- 뒤쪽 한 구역: X=-3.85~3.85, Z=-9.22~-6.4m.
- 중앙 통로 검사: X=±0.65, Z=-6.15~-0.55m.

과정 순서와 yaw 0/90/180/270도 조합을 결정적인 순서로 검색한다. 실습자 측이 통로 쪽에 오도록 좌측270·우측90·뒤쪽180도를 우선한다. Content의 Renderer.localBounds, 충돌체, world-space Canvas와 FieldUI, 기존 실습범위, PracticeAnchor 주변 범위를 함께 측정한다. 바닥 FloorAnchor는 전체 StationRoot의 높이 이동으로 Y0에 맞춘다. 경계/높이 안에 후보가 없으면 축소하거나 자식을 분산하지 않고 실패·복구한다. 검사에서는 고정 실내 경계뿐 아니라 현재 환경 충돌체와 실습대 전체 경계의 겹침도 확인한다. 이 검색을 실제 Unity에서 실행한 결과는 아직 없다.

EntryAnchor는 첫 반입에서 `(0,0,-0.9)`, yaw180으로 방 안을 향한다. 입구판은 `(-2,1.45,-0.35)`, 기존 ExitAnchor는 `(2,0,-1.2)`, 출구판은 `(2,1.35,-0.35)`에 둔다. 안내판 내용·버튼·Coordinator 연결은 그대로다. 분야 표지와 실습 배치는 공유 환경 prefab 안에 넣지 않고 각 씬이 소유한다.

재실행은 영수증이 있으면 최초 배치 함수를 호출하지 않는다. 사용자 StationRoot·안내판·Entry/ExitAnchor·환경 자식의 크기·회전을 재설정하지 않는다. 공유 B 자산이 이미 있으면 A 씬을 다시 열어 동기화하지 않는다. 영수증/사본이 불완전하면 자동 재생성하지 않고 거절한다. 사용자가 배치한 결과가 경계 밖이면 FAIL로 설명하고 그 저장된 수동 배치를 보존한다.

재실행 때 바꾸는 것은 성공 기록과 **현재 장비/보드 배치를 읽어 계산하는 이동 셀 활성 마스크**다. 셀의 이름·위치·크기·회전·소유 구조가 바뀌었으면 자동 원복하지 않고 FAIL한다. prefab/메시/재질/표식/광원/셀 개수는 늘리지 않는다.

## 바닥·충돌·조명·실패 처리

임시 바닥 정리는 EnvironmentRoot의 직접 자식 Floor 또는 TempFloor 중 하나이며, 자식 없음·기존 TeleportationArea/BoxCollider·허용 컴포넌트 구성·외부 참조 없음을 확인한 경우에만 비활성화한다. 삭제하지 않고 영수증에 보존한다. 이름만 보고 지우지 않는다. 기존 FirstAid EnvironmentRoot의 Cube는 잡기/물리 구성이라 보존하고 Desk도 사용자/기존 환경 객체로 보존한다. 그 외 참조가 있거나 구성이 다른 바닥은 자동 정리하지 않고 실패한다.

원본 외형의 실제 바닥 윗면과 FloorAnchor는 Y0이다. 새 순간이동 표면은 40cm 셀 18×21개를 하나의 TeleportationArea에 명시적으로 연결한다. **표면만 Y=0.002m**로 두어 실제 바닥 충돌체와 같은 높이의 ray hit가 경쟁하는 문제를 피한다. 별도 Renderer/임시 바닥 모델은 추가하지 않는다. 위쪽 법선10도 이내만 허용한다.

벽 안쪽 여유를 두고 현재 Content·FieldUI·집기/안내판 경계를 뺀 뒤, 입구 근처에서 격자로 연결된 셀만 활성화한다. 격리된 바닥 조각은 목적지가 아니다. 각 실습 목적지 근처에 연결된 셀이 있는지도 검사한다. 기존 PracticeAnchor의 참조·Teleport 레이어는 보존하고 모든 활성 고정 목적지가 방 안 Y0인지 확인한다. Default 벽 충돌체와 기존 원거리 ray의 Default 레이어 포함 여부를 검사한다. 실제 벽 차단·장비 접근·룸스케일 이동 결과는 Play/VR에서 사용자가 확인해야 한다. XR Rig·입력·입구 추적 대기·요청 차단·Time.timeScale은 변경하지 않는다.

기존 B Directional Light는 유지한다. A 광원은 복사하지 않는다. 첫 반입 당시 방 안에 켜진 비방향 광원이 없을 때에만 씬 소유의 그림자 없는 보조 점광원2개(Y2.35, Z=-3/-7, range6, intensity1.2)를 추가한다. 형광등 외형·발광 재질은 B 사본을 사용한다. 카메라/AudioListener/Directional Light를 새로 만들지 않는다.

반입 후 참조·공간 검사가 FAIL이면 저장하지 않는다. 예외/저장 실패 시 실행 전 씬 바이트와 열린 씬 구성을 복구하고, 이번 실행에서 새로 만든 B 파일만 제거한다. 기존 B 작업본은 수정하지 않으므로 되돌림 대상도 아니다. 전역 SaveAssets·A builder·Prefab Apply는 호출하지 않는다. 복구 자체 오류도 별도로 Console에 보고한다.

## 정적 확인·보존 근거

- A 소스와 B 기존 도구·런타임을 읽고 새 코드의 경로 제한, 복사 whitelist, GUID 대응, 최초/재실행 분기, 읽기 전용 검사, 실패 복구 흐름을 정적으로 대조했다.
- 새 C#의 구분자/문자열 구조·후행 공백을 정적으로 확인했다. **컴파일 검사가 아니다.** XRI collider 목록·표면 법선·CurveInteractionCaster raycastMask API는 현재 설치된 package 소스로 확인했다.
- 작업 전 A/C/Packages/ProjectSettings와 기존 수정 파일을 묶은 1,621개 파일의 SHA256 기준을 보관하고, 코드 작성 후 비교에서 변경0개를 확인했다. 기존 사용자 코드·문서는 그대로다.

## 사용자 확인 순서 — 환경 영향 중심

1. Unity 컴파일 확인. Console 오류가 없고 새 환경 메뉴2개와 기존 메뉴들이 유지되는지 확인.
2. `B_FirstAid`를 열고 미저장 변경을 직접 처리한 뒤 **환경 반입1 → 환경 검사2**. Console FAIL0, 공유 B prefab/대응표 생성, 최초2+1과 입구 방향 확인.
3. `B_CBRN`에서 **환경 반입1 → 환경 검사2**. 같은 B 작업본 재사용, A 기능·XR 중복 없음, 보호의/거울·K1 관찰 공간 확인.
