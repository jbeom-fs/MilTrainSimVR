# B 구현 범위·실행 계획

작성일: 2026-10-21 · 담당: B

`Docs/B`의 기획·조사·구조 문서 7개와 작업 규약을 검토해 정리한 실행 계획이다. 초기 파일 조사와 이후 사용자 검증 보고를 구분해 진행 상태를 갱신한다. 세부 콘텐츠와 일정 제안은 확정 사항과 구분한다.

2026-10-21 작업 마감 기준으로 갱신했다. 다음 세션의 상세 시작점은 [작업 마감·인수인계](1021_작업마감_진행상황.md)다. 아래 설계·후보 목록과 실제 구현 완료 범위를 구분한다.

구현 방향 정정: 목표는 구급법과 화생방 제독을 사용자가 실제 VR 공간에서 보고·판단하고·장비를 조작하며 체험하도록 만드는 것이다. 완료 단위는 교육 콘텐츠의 체험 흐름이다. 공통 코드와 XR 기본 테스트는 이를 지원하며, 일반 Object 제어나 테스트용 Cube 확장을 다음 독립 제작 목표로 두지 않는다. 필요한 안내·배치·복원 기능은 실제 콘텐츠를 만들면서 함께 연결한다.

## 2. 수정 가능한 범위

추가 작업 규칙(2026-10-21): 에이전트는 코드를 직접 작성·수정하지 않는다. 사용자가 명시적으로 요청한 경우에만 구현 지시를 자연어 프롬프트 형태로 전달한다. “다음 단계 진행”이나 “구현 내용 설명”은 직접 코드 변경 또는 프롬프트 자동 제공의 허가로 해석하지 않는다. 기존 작성 코드는 삭제·되돌림 없이 보존한다. 이 규칙은 아래 경로별 수정 가능 범위보다 우선한다.

| 경로 | 권한 및 처리 |
| --- | --- |
| `Docs/B/**` | 요청 범위 내 문서 읽기·작성·수정 가능 |
| 다른 담당자의 `Docs/**` | 읽기 전용 |
| `Assets/B/**` | 요청 범위 내 읽기·생성·쓰기·수정 가능. 하위 `.meta` 포함 |
| 그 외 `Assets/**` | 전체 읽기 전용. A·C·Samples·Scenes·Settings·XR·XRI·TextMesh Pro·루트 파일 및 `.meta` 포함 |
| `Assets/B.meta` | B 폴더의 내부 파일이 아니므로 읽기 전용 |
| `Packages`, `ProjectSettings` 등 | 이번 지침으로 수정 권한이 추가되지 않음. 기존 규약과 별도 작업 승인 범위 적용 |

B 외부 자산 수정이 필요하면 **정확한 대상 경로 → 수정 이유 → 구체적 수정 방법·영향 → 사용자 승인 요청** 순서로 제시하고, 승인 전에는 변경하지 않는다. 삭제·이동·이름 변경·덮어쓰기와 Unity 자동 변경도 같은 경계를 적용한다. 파일시스템 권한 자체는 변경하지 않는다.

공용 자산은 원본 참조 또는 B 내부 작업본으로 사용한다. B 코드로 공용 자산을 직접 수정하거나 자동 수정 도구로 경계를 우회하지 않는다. 씬 진입·Build Settings 등록·공용 XR 설정 변경도 B 내부만으로 해결되지 않으면 별도 변경안을 제시한다.

## 3. 콘텐츠 범위

P1은 우선 제작 후보이며 전부 납품이 확정된 목록이 아니다. 다음 표의 순서는 개발 순서이며 실제 처치·제독 순서가 아니다.

| 구분 | 항목 | 구현할 내용 | 결정 상태 |
| --- | --- | --- | --- |
| 1차 대표 | FA-01 + FA-03: 상황 확인·도움 요청·AED | 판단 선택, 전원·버튼, 패드 배치·현재 부착 상태, 안내, 결과·재시도 | 통합기획서의 첫 과정 제안 유지 |
| 핵심 후속 | CBRN-05: 개인제독 | 대상·도구 선택, 지정 처리 행동, 누락·재접촉, 도구 회수 | B 확정 분야. 대상·위협·도구·교안은 미정 |
| P1 추가 후보 | FA-05: 지혈대 | 배치, 조임막대 회전, 고정·기록의 가상 조작 | 대표 과정 안정화 후 최종 범위 확정 |
| P1 추가 후보 | FA-04: 직접 압박·압박붕대 | 도구·위치, 유효 접촉 유지, 지정 경로 배치·고정 | 교안에 따라 지혈대와 별도 시나리오 구성 |
| P1 범위 확인 | CBRN-06: 개인 휴대장비 제독 | 제한된 장비 표면 처리, 잡기·회전, 재접촉 | CBRN-05와 대상 경계 확정 필요 |
| 담당 협의 | CBRN-02·03: 방독면·보호의 등 | 가상 착용·점검, 장비 구성 상태 | B 제작 확정 아님. 타 담당 제작 시 결과 상태만 연계 |
| P2 | FA-02, CBRN-07·04 | CPR 절차·리듬, 탈의·확산 방지, MOPP 장비 선택 | P1 안정화와 담당 협의 후 검토 |

공통 제공 후보: 목표·현재 단계·오류 자막, 장비 강조, 안내 음성, 수행 요약, 시작·중단·재시도. 안내 실습 우선, 무안내 평가는 후속 제안이다. 결과는 우선 메모리 내 수행 기록으로 다루고 점수·합격선·영구 저장은 확정하지 않는다.

보류: 실제 CPR 압박력·깊이·호흡 측정, 실제 방독면 밀착·제독 효과 판정, 전신 추적, 자유로운 천·붕대 시뮬레이션, 실제 부상자 운반, 전문 장비·지역 제독·제독소 운영, 멀티플레이·외부 센서·서버/LMS. 상세 의학·제독 수치와 절차는 승인 교안 없이 임의 확정하지 않는다.

### 콘텐츠 체험 기준의 구현 챕터

사용자 정정에 따라 앞으로의 제작 단위를 아래 콘텐츠 챕터로 정리한다. 기존 C01·C02는 기술 준비·검증 이력으로 보존한다. 아래 순서는 개발 제안이며 실제 처치·제독 순서가 아니다. AED 우선 제안은 유지하되 최종 착수 순서와 각 콘텐츠의 세부 범위는 확정 사항으로 간주하지 않는다.

| 콘텐츠 챕터 | 사용자가 VR에서 체험할 것 | 구현할 기능 | 달성 목표 |
| --- | --- | --- | --- |
| 1. 교육 공간·대상·장비 구성 | 환자·교육용 신체·도구가 배치된 공간에서 교육 상황 파악 | 콘텐츠별 실제 사용할 대상과 장비 모델 배치, 접근·조작 가능한 위치·크기·잡기 지점 구성 | 사용자가 교육 대상과 도구를 식별하고 조작에 착수 가능. 모델 미확보 시 대상 부위·기능을 구분할 수 있는 임시 모형 사용 |

| 5. 방호 착용·장비제독 — 범위/담당 협의 | 맡기로 확정한 가상 착용·점검 또는 휴대장비 표면 처리 | 방독면·보호의 담당에 따른 제작/결과 수신, 개인제독과 구분된 장비 표면·회전·접촉 조작 | 맡은 콘텐츠의 체험 또는 타 담당 모듈 연계가 동작. 미확정 기능은 자동 포함하지 않음 |
| 6. 전체 교육 연결·실기 검증 | 교육 선택·체험·결과·재시도·복귀 | 완성한 과정의 앱 진입·종료 연결, 결과 전달, Quest 2 + Link 조작성·가독성·성능 확인 | 사용자가 헤드셋으로 구급법·제독의 확정 과정을 연속 이용 가능 |

각 콘텐츠는 장비 조작, 조건 판정, 필요한 자막·음성, 오류 수정, 결과·재시도를 함께 연결해 작은 완결 체험으로 만든다. 콘텐츠 전체를 가로막는 공통 프레임워크 선행 완성은 요구하지 않는다. 애니메이션은 실제 교육에서 시범·장비 동작 표현에 필요할 때 추가한다.

2026-10-21 현재 인체·AED·패드 2개·부착 지점과 전원·부착·표시 전환 체험까지 구성했다. 현재 부착 후 분리는 차단하며 씬 재로드로 초기화한다. 다음 후보는 재시도·종료·장비 상태 복원이다. 일반 Cube 잡기 시험 확장으로 되돌아가지 않으며, 코드 변경은 직접 수행하지 않고 명시 요청 시에만 구현 프롬프트를 제공한다.

실제 Unity 작업은 [AED VR 튜토리얼 세부 기능](1021_AED_VR튜토리얼_세부기능.md)을 따른다. A 시작·전원 → B 패드 1개 부착 → C 패드 2개·완료 흐름은 Simulator 검증 완료이며, D 재시도·운영 검증은 미구현 부분이 남는다. 안내·강조·실패 후 재집기는 현재 AED 코드에 연결됐지만 일반적인 장비 전체 초기화·앱 복귀와 구분한다. C02 공통 Runner가 이 콘텐츠로 통합됐다고 간주하지 않는다.

C01은 해당 자산의 배치·참조 연결·작동 확인으로 수행한다. 실제 교육 장비의 조작점·부착 조건·접촉 유지·진행 이벤트는 C06·C07 등 장비별 기능으로 구현하고, 강제 배치·재시작 시 잡기 해제는 C03·C05에서 처리한다.

구현 순서 정정: C01·C02의 검증 결과를 활용해 C06 AED 또는 합의한 첫 실제 콘텐츠에 착수한다. C03~C05·C08의 기능은 그 콘텐츠에 필요한 만큼 함께 적용한다. 이어 C07 개인제독의 실제 대상·장비·조작을 완성하며 재사용을 확인한다. C09~C11은 별도 범위 결정 후 진행한다.

개발 단계 대응: M0=범위·환경·콘텐츠 자산 확인, M1=C01·C02의 검증을 토대로 실제 교육 대상·장비 구성, M2=C06 AED 체험과 필요한 C03~C05·C08 기능, M3=C07 개인제독 체험, M4=앱 연동 및 확정된 추가 콘텐츠, M5=완료한 콘텐츠의 실기 검증.

CPR 절차·리듬, 탈의·오염 확산 방지, MOPP 장비 선택, 무안내 평가 모드는 P2 후보로 유지한다. 배점·합격선·파일 저장·서버 전송도 현재 챕터의 확정 기능에 추가하지 않는다.

## 4. 구현 구조와 배치안

교육 진행, 장비 조작, 안내 출력을 분리한다. 재사용 범위는 AED와 개인제독에서 실제 필요한 계약으로 제한한다.

| 구성 | 책임 |
| --- | --- |
| `TrainingDefinition` | ScriptableObject로 단계·Action·완료 조건·Cue 정의. 실행 상태 저장 금지 |
| `TrainingRunner` + `TrainingContext` | 한 과정 진행, 실행 회차·현재 단계·기록, 중단·재시작. 교육명별 분기 없이 데이터 실행 |
| `SceneBindings` | 안정적인 대상 ID와 씬 Object·컴포넌트·앵커 연결 |
| `StepActionExecutor` | SetActive, Animator 제어, 앵커 배치, Cue 실행. 장비 고유 조작·XR 해제는 장비 측 요청 |
| `StepConditionEvaluator` | 일회성 행동 / 현재 상태 / 유지 조건 / 복수 조건 구분 |
| 장비·Interaction | 감지와 부착·회전·접촉 판정, 장비 상태·복원 책임 |
| `PresentationController` | 자막·음성 재생·교체·중단. 진행 판정과 분리 |
| `TrainingSubtitles` | 모든 자막을 전용 static class의 `const string`으로 단일 관리. 데이터는 고정 `SubtitleId`만 저장 |

현재 경로 `Assets/B/Scripts`, `Assets/B/Scene`은 유지한다. 추가 배치 제안은 `Scripts/Training`, `Scripts/Interactions`, `Scripts/Presentation`, `Data`, `Prefabs`, `UI`, `Audio`, `Animations`, `Tests`이며 모두 `Assets/B` 하위다. 실제 필요한 폴더만 구현 시 생성한다.

Runner 상태는 Idle → Entering → Running → Exiting → 다음 단계/Completed, 중단은 Stopped로 둔다. 조건은 진입 Action 전에 준비하고, 진입 완료 후에만 전환한다. 실행 회차·단계 번호로 이전 콜백을 무효화하고 같은 단계 완료는 한 번만 처리한다.

중단·재시작은 전환 차단 → 이전 실행 무효화 → 구독·대기 취소 → 안내 중단 → XR 선택 해제 → 등록 대상 상태 복원 → 실행 데이터 초기화 순서다. 장비별 부착·물리·Animation 상태를 복원하고 복원 이벤트는 평가에서 제외한다. 같은 Transform에 XR·물리·Animation·교육 이동이 동시에 쓰지 않도록 한다.

실기 일정은 사용자 결정으로 **전체 기능 구현 후** 진행한다. 이전의 조기 실기 반복 제안보다 이 결정을 우선한다. 교안 미확보 상태의 기술 조작 구현과 의료·제독 교육 기준 확정을 구분한다. 현재 패드 앵커·ID 짝은 사용자가 이번 구현 기준으로 승인했으며 의료 기준 전체의 승인으로 확대하지 않는다.

기존 일정: 기획·컨셉 발표 10/21, 개발 10/22~11/26, 완료 발표 11/20. 단계별 날짜는 미확정이다. 발표용 범위는 AED·개인제독의 완결된 체험을 우선 제안하며, 추가 P1과 발표 이후 작업량은 팀 합의로 정한다.

## 6. 검증 기준

통합기획서 V01~V11을 유지한다. 우선 검증할 실패 조건:

1. 누락·중복 대상 ID와 잘못된 자막 ID: 단계·대상을 명시하고 시작 차단.
2. 같은 프레임 중복 이벤트: 단계는 한 번만 전환.
3. 두 패드 부착 후 하나 분리: 현재 상태를 반영해 잘못된 완료 방지.
4. 잘못된 도구, 복수 Collider, 이미 겹친 채 활성화, 비활성화로 Exit 누락: 거짓 접촉·완료 방지.
5. 잡기·안내·Animation 중 중단/재시작: 선택 잔류 없이 초기 상태 복원, 이전 콜백 무효.
6. 안내 A에서 B로 교체: A 완료가 B 자막을 숨기지 않음. 상수 수정만으로 기존 에셋의 표시 문구 갱신.
7. 개인제독 추가: 공통 Runner에 교육명별 분기 추가 불필요.
8. Simulator와 Quest 2 + Link: 동일 핵심 과정 완료. Windows 빌드에서 자막 가독성·프레임 시간 실측.

코어 상태 전환·콜백 무효화·조건 판정은 자동화 검증 대상으로 계획한다. 실제 XR 잡기·충돌·가독성·성능은 Play Mode와 실기로 확인한다. 목표 프레임레이트·최소 PC·합격선은 별도 합의 전까지 수치를 만들지 않는다.
