## 2. 적용 범위와 구성

1차 적용 대상은 저장된 운영 씬 `Assets/B/Scene/B_CBRN.unity`의 `K1_Mirror`, `PC_Mirror`다. 개별 Tutorial/Equipment 씬에도 거울이 있으나 이번 운영 씬 적용과 구분하며 일괄 변경하지 않는다.

기존 거울 루트 아래 `Surface`, `Camera`를 유지하고, 이들과 형제인 `Visual` 자식 하나에 해당 외형 프리팹을 배치한다.

| 기존 루트 | Surface 유지 크기 | 추가할 외형 | Visual 로컬 변환 |
|---|---|---|---|
| K1_Mirror | 0.80×1.80m | K1_MirrorFrame | 위치 (0,0,0), 회전 (0,0,0), 배율 (1,1,1) |
| PC_Mirror | 0.90×1.90m | PC_MirrorFrame | 위치 (0,0,0), 회전 (0,0,0), 배율 (1,1,1) |

- `Visual`의 원점은 반사면 중심이다. FBX 내부 노드의 임포터 축 변환을 임의로 초기화하거나, 기존 거울 루트·Surface를 모델에 맞춰 변경하지 않는다.
- 기존 `screen`, `viewCamera`, `head` 참조·카메라 설정·RT 수명·다른 과정 아바타 제외 목록·교육 참조는 보존한다. 외형 Renderer를 거울의 `screen` 참조로 지정하지 않는다.
- 보존할 운영 씬 참조: K1 screen `1330465042`, camera `521825088`; PC screen `634190510`, camera `690376641`; 공통 head `1666508945`.
- 새 카메라·반사면·RenderTexture·조명·교육 컴포넌트를 만들지 않는다. 기존 런타임 코드를 수정할 필요가 없는 외형 부착 방식이다.
- 외형 1차 적용에는 Collider·Rigidbody·XR 잡기/선택 컴포넌트를 추가하지 않는다. 현재 거울에도 Collider가 없으며, 충돌 동작 추가는 이번 외형 부착 범위와 구분한다.

## 3. 자산·재질 적용안

후속 적용 시 만들 자산의 제안 경로다. 이번 설계에서 생성하지 않았다.

- 외형 프리팹: `Assets/B/Prefabs/TrainingMirror/K1_MirrorVisual.prefab`, `PC_MirrorVisual.prefab`.
- 공유 재질: `Assets/B/Materials/TrainingMirror/TrainingMirror_Metal.mat` 1개.
- 두 프리팹은 원본 FBX 메시를 참조하고, 모든 외형 Renderer를 같은 B 소유 URP/Lit 금속 재질에 연결한다. 기존 `MAT_K1_ObserverScreen`·`PC_MirrorScreen`은 외형에 재사용하거나 수정하지 않는다.
- Blender Metallic 0.8·Roughness 0.68을 참고해 Unity Metallic 0.8·Smoothness 약 0.32를 시작값으로 삼고 미리보기와 비교한다. Blender linear 기본색 수치를 Unity sRGB 색상 입력에 그대로 복사하지 않는다. 실제 Unity 색·광택 일치는 사용자 확인 전이다.
- 현재 두 FBX meta에는 globalScale 1, 파일 단위 사용, Collider 자동 생성 꺼짐, 자동 Mesh LOD 생성 꺼짐이 저장돼 있다. 실제 Unity 임포트 크기·축은 별도로 확인해야 한다. 불필요한 재임포트 설정 변경·추가 Read/Write 활성화는 하지 않는다.
- `Assets/B` 안의 정상적인 신규 자산/폴더 meta는 함께 관리한다. 제작 당시 좁은 납품 경계 때문에 제거했던 `TrainingMirror.meta`를 후속 적용에서도 반복 삭제하는 규칙으로 해석하지 않는다.

## 4. 현재 배치에 대입한 정적 여유

FBX 전체 로컬 AABB를 기존 운영 씬 거울 루트의 월드 변환에 대입한 예상 경계다. Unity Renderer/Collider 실행 측정이 아니다.

| 모델 | 예상 월드 X 범위 | 예상 월드 Y 범위 | 예상 월드 Z 범위 |
|---|---|---|---|
| K1 | −3.0701~−2.3191m | 약 0~1.871m | −5.1338~−4.4742m |
| PC | 3.2900~3.4500m | 약 0~1.951m | −4.0710~−3.1290m |

- 두 외형의 예상 경계는 저장된 작업대 기준 상자와 겹치지 않는다. 이 상자는 저장 Transform의 받침대 폭·깊이·높이 기준이며, 실제 테이블 메시 전체나 손 움직임을 측정한 결과는 아니다.
- 두 외형의 예상 XZ 경계는 저장된 순간이동 목적지 7곳과 겹치지 않는다. 실제 걸어서 이동하는 전체 경로·사용자 몸 여유의 통과로 확대하지 않는다.
- 바닥 접점은 계산상 Y≈0이다. float 오차 수준의 미세 음수는 별도 매몰 결함으로 분류하지 않는다. 하단 프레임 여유는 K1 약 29mm, PC 약 9mm이므로 실제 임포트 확인 전 배율을 임의 보정하지 않는다.
- K1_RearView 표시 영역, 옆 작업대, 몸·손·장비 조작 시 시야와 간섭은 적용 후 사용자 확인 항목이다.

## 5. 후속 적용 순서와 사용자 확인 기준

1. **임포트 확인:** 사용자가 FBX 두 개의 실제 Unity 치수·방향·원점·8개 부품을 확인한다. 임포터 변환으로 원시 좌표와 다를 수 있으므로, 다르면 기존 거울을 움직이지 말고 FBX 임포트 변환부터 확인한다.
2. **외형 프리팹·재질 구성:** 공유 URP/Lit 재질을 연결하고, 위치/회전 0·배율 1인 외형 프리팹 2종을 구성한다. 카메라·Surface·충돌·잡기 컴포넌트는 포함하지 않는다.
3. **운영 씬 부착:** 기존 거울의 별도 `Visual` 자식으로 각 외형을 한 번씩 배치한다. 저장 씬의 수동 위치·방향과 반사면은 유지한다. 기존 교육장/과정 생성 메뉴 재실행을 적용 절차로 사용하지 않는다.
4. **저장본 정적 비교:** 변경은 두 Visual 추가와 새 B 프리팹/재질/필요 meta 및 명시적으로 필요한 FBX 재질 연결 범위다. 기존 Surface·Camera·head·Station·교육·아바타 제외 참조와 이동 목적지를 대조해 보존을 확인한다. 새 Visual 중복은 없어야 한다.
5. **사용자 화면 확인:** 정면·측면에서 프레임 개구부와 반사면 정렬, 분홍 재질·검은 가림·겹침 깜빡임·바닥 부유/매몰이 없는지 확인한다. 프레임/뒤판이 반사 화면을 가리면 미완료다.
6. **사용자 기능 확인:** K1 착용과 후면 보기, 보호의 착용·완료/중단·재진입에서 기존 반사와 다른 과정 아바타 제외가 유지되는지 확인한다. 옆 테이블·몸/손/장비·순간이동 동선을 확인한다. 기존 단일 중앙 시점 반사 방식은 유지하며 새로운 양안 입체 반사 구현으로 확대하지 않는다.
7. **확인 기록:** 에이전트 정적 검토, 사용자 Unity 확인, 미확인 성능/장치 항목을 구분해 남긴다. 이번 설계로 Unity 적용·실행을 완료 처리하지 않는다.

허브 복귀 포털 구현은 [사용자 보류 결정](1110_허브복귀_포털방식_보류.md)을 유지한다. 이 설계는 구현 프롬프트가 아니며, 프롬프트는 사용자의 명시 요청 시 채팅의 단일 복사 가능한 코드 블록으로 제공한다.
