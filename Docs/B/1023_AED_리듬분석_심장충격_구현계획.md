## 1. 목표와 이번 범위

기존 전원·패드 부착 체험에 **리듬 분석 → 충격 필요 안내 → 충전·사용자 충격 버튼 조작 → CPR 재개 안내 → AED 1사이클 체험 완료**를 연결한다.

2026-10-23 사용자 결정:

- CPR 자체는 별도 구현한다. 이번에는 AED 리듬 분석·심장충격을 우선 추가한다.
- 패드 2개 부착은 분석 진입 조건이다. 이 시점에 교육을 완료하지 않는다.
- 충격이 필요한 고정 교육 시나리오 1개만 체험한다. 충격 불필요 분기와 시나리오 선택 설정은 구현하지 않는다.
- 충격 시행 후 CPR 재개 안내로 끝낸다. 이 문구는 CPR 수행 완료나 환자 회복 판정이 아니다.

이번 계획에 포함하지 않는 기능: CPR 동작·깊이·힘·리듬 평가, 2분 CPR/재분석 반복, 환자 상태 판단·도움 요청 추가, 상의 제거·커넥터 연결 조작 추가, NPC 추가, 패드 수동 분리·전원 끄기, 재시도·종료 버튼, 점수·저장·앱 통합.

현재 환자는 흉부가 노출되고 패드가 기기에 연결된 교육용 준비 상태로 취급한다. 환자 확인·신고·초기 CPR 등 선행 대응은 수행된 상황이라는 시작 설명을 둔다. 이를 사용자가 실제 수행했다고 채점하지 않는다.

## 3. 제안 체험 흐름

버튼을 직접 눌러 충격을 시행하는 교육용 AED를 기본 모델로 한다. 현재 모델의 실제 충격 버튼 표면 위치·그림과 선택 영역 정렬은 Unity에서 확인할 항목이다.

| 단계 | 사용자 경험 | 진행·입력 조건 |
| --- | --- | --- |
| 1. 기존 조작 | 시작 → 전원 → 두 패드 부착 | 기존 동작 유지. 전원·패드·앵커 점유가 모두 유효할 때만 다음 단계 |
| 2. 분석 전 접촉 중단 | 환자에게서 손을 떼라는 안내 | 양손 접촉 판정이 유효하고 모두 비접촉일 때 분석 시작. 충격 버튼 비활성 |
| 3. 리듬 분석 | 분석 중 표시·안내 | 비접촉 상태에서 정해진 분석 시간이 경과하면 시나리오 결과 출력 |
| 4. 충격 필요·충전 | 충격 필요 및 충전 중 안내 | 자동 충전. 충전 중 버튼 비활성. 완료 전 입력은 예약하지 않음 |
| 5. 충격 전 재확인 | 환자에게서 떨어져 있는지 확인하라는 안내 | 충전 완료 후 현재 비접촉 상태를 재확인. 버튼 강조·입력 가능 상태 표시 |
| 6. 충격 시행 | 사용자가 AED 표면의 충격 버튼 선택 | 입력 순간 전원·패드·충전·비접촉·현재 단계를 다시 검사. 모두 유효할 때만 1회 시행 |
| 7. CPR 재개 안내·완료 | CPR을 다시 시작하라는 안내와 AED 체험 완료 표시 | CPR 조작을 기다리지 않음. 환자 회복·전체 소생술 완료 문구는 사용하지 않음 |

### 분석 결과와 시간

- 실제 심전도 입력·생리 모델·환자 진단은 이번 범위에 없다. 분석 결과는 교육 시나리오에 따라 충격 필요로 고정한다.
- 현재 고정 충격 필요 흐름을 유지해 핵심 버튼 조작을 체험한다. 충격 불필요 분기·결과 선택 Inspector 설정은 필요하지 않다.
- 무작위 결과, 학습 도중 결과 선택 UI, 추가 씬은 만들지 않는다.
- 분석·충전·결과 표시 시간은 조절 가능한 교육용 값으로 둔다. 실제 기기의 고정 시간이나 의료 기준이라고 설명하지 않는다.
- 시간값의 구체 수치는 채택 기기 안내·음원 길이와 함께 구현 착수 시 정한다. 0 이하·비정상 값은 시작 전 검증한다.
- 분석 중 접촉하면 분석 시간을 초기화하고 접촉 중단 안내로 복귀한다. 재이탈 후 처음부터 분석한다. 이는 교육용 오류 복구 정책이며 실제 모든 AED의 동작을 뜻하지 않는다.

## 4. 접촉 확인 방식 — 기본 제안

접촉 중단을 안내 문구만으로 완료 처리하지 않고, **좌우 컨트롤러 위치 기준의 교육용 근접 영역과 환자 몸체 Collider의 겹침**으로 확인한다.

| 항목 | 설계 기준 |
| --- | --- |
| 확인 대상 | B 씬의 좌우 컨트롤러 pose와 등록된 환자 몸체 Collider |
| 판정 영역 | 컨트롤러별 오프셋·반경을 조정 가능한 작은 구형 영역. 구체 값은 Simulator에서 조정 후 실기에서 확인 |
| 제외 대상 | UI 레이·패드 앵커 안내·바닥·책상·AED 본체. 레이가 환자를 가리키는 것만으로 접촉 판정하지 않음 |
| 상태 | 접촉 / 비접촉 / 확인 불가를 구분. 양손 모두 유효한 비접촉일 때만 통과 |
| 누락 처리 | 손 참조·몸체 Collider 누락, pose 추적 소실, 대상 비활성은 확인 불가. 자동으로 비접촉 처리하지 않음 |
| 분석 중 접촉 | 분석 중단·시간 초기화·재안내. 손을 떼면 다시 분석 가능 |
| 충전 중 접촉 | 충전 자체는 계속 가능. 충전 중과 충격 직전의 접촉 규칙을 구분하며 충격 입력은 계속 잠금 |
| 충전 후 접촉 | 충격 버튼 입력 차단·접촉 중단 재안내. 교육용 기본안은 충전 상태 유지, 이탈 후 새 클릭 요구 |
| 충격 입력 | 화면의 버튼 활성 상태와 별도로 입력 순간 최신 접촉 상태를 재검사 |

현재 인체의 정적 비볼록 MeshCollider를 판정 대상으로 참조한다. 물리 겹침 질의 기반으로 구성해 기존 환자 Collider·Rigidbody 구성을 바꾸지 않는 방향을 우선한다. 초기부터 겹친 상태와 Collider 비활성도 매 판정에 반영한다. 입력 콜백과 물리 갱신 순서 때문에 오래된 비접촉 상태를 사용하지 않도록 확인한다.

이 방식은 컨트롤러를 기준으로 한 교육용 근사다. 실제 손·팔·전신·보조자의 모든 접촉을 측정하지 않는다. 현재 씬에 NPC를 새로 만들지 않으며, 이후 NPC 추가 시 해당 접촉 상태를 함께 받을 수 있는 작은 연결 지점만 둔다. 손 추적이나 공통 XR 설정 변경은 필요하지 않다.

충격 직전에는 주변 사람의 이탈도 확인해야 한다는 안내를 표시한다. 현재의 자동 판정 범위는 사용자 양손이며, 이를 주변 전체 인원의 접촉 검증 완료라고 표시하지 않는다.

## 5. 충격 버튼과 결과 피드백

- `AED_Trainer_Interactive`의 모델 표면에 충격 버튼 선택 영역·표시를 추가하는 방향이다. 전원 버튼의 World Space UI/XR 선택 방식을 재사용한다.
- 전원 버튼과 별도 입력 대상으로 분리한다. 충격 버튼을 누르는 동작이 전원 입력으로 중복 전달되지 않아야 한다.
- 모델 원본 FBX를 다시 제작하지 않고 B 래퍼 안에서 선택 영역을 연결하는 방향을 우선한다.
- 초기·패드 단계·분석·충전·완료·오류 상태에서는 충격 입력을 받지 않는다.
- 충전 완료 및 비접촉일 때 깜박임·문구로 조작 가능 상태를 알린다. 단순 색상 변경에만 의존하지 않는다.
- 유효 클릭 접수 시 즉시 입력을 잠그고 방전 상태를 먼저 확정한다. 연타·같은 프레임 중복 콜백·길게 누르기는 추가 충격을 만들지 않는다.
- 환자 접촉 상태에서 누른 입력은 저장하지 않는다. 손을 뗀 뒤 별도의 유효 클릭이 있어야 시행한다.
- 충격 시행 피드백은 짧은 장비 상태 표시와 확보된 효과음으로 구성한다. 환자 경련·회복 애니메이션이나 물리 충격은 이번 범위에 추가하지 않는다.
- 충격 시행을 환자 회복으로 표시하지 않는다. CPR 재개 안내로 연결한다.

| 기존 `AedPowerDevice` | 전원 상태·표시 유지. 분석·충격 진행을 이 컴포넌트에 몰아넣지 않음 |
| 신규 충격 장비 컴포넌트 | 충전·준비·방전 상태, 충격 버튼·깜박임, 유효 입력 검사와 1회 시행 결과 보고 |
| 신규 환자 접촉 확인 컴포넌트 | 양손 pose와 환자 Collider를 바탕으로 접촉·비접촉·확인 불가 보고. 단계 전환은 진행 측 책임 |
| 기존 `TrainingSubtitles` | 시작 목표 수정, 분석·충전·접촉 오류·충격 필요·CPR 재개·완료 문구의 단일 원본. 새 문자열은 `All`에도 반영 |
| 안내 음성 연결 | 새 단계의 자막과 대응 음원·선택적 효과음 재생, 교체·중단 처리. 출력은 진행 판정과 분리 |
| 기존 `AedPad`·`PadAttachAnchor` | 부착·점유 상태 제공. 이번에 수동 분리나 새 부착 알고리즘을 추가하지 않음 |

새 진행 상태는 기존 enum 값 뒤에 추가하는 방향이다. 필요한 의미는 분석 전 이탈 대기, 분석 중, 충전 중, 충격 대기, 충격 시행 피드백, CPR 재개 안내다. 최종 `ModuleCompleted`는 1사이클 체험 종료에만 사용한다.

공통 Runner 전환, 별도 범용 시나리오 프레임워크, 교육명별 전역 Manager는 이번 구현의 선행 작업으로 두지 않는다.

## 7. 안내·음성·종료 정책

- 주 안내와 오류 안내를 구분하고 한 번에 현재 행동이 명확히 보이게 한다. 같은 접촉 오류를 매 프레임 반복 출력하지 않는다.
- 문구 예시의 의미: 분석 전 손 떼기, 분석 중 접촉 금지, 충격 필요, 충전 중 대기, 충격 전 주변 확인, 충격 버튼 선택, 즉시 CPR 재개.
- 자막 원문은 코드·Inspector에 복제하지 않고 `TrainingSubtitles` 상수로 관리한다. 현 AED 구조의 직접 상수 참조 방식을 유지하며 이번에 자막 ID 데이터화까지 확대하지 않는다.
- 새 단계의 음성 대본과 음원을 준비해 연결하는 것을 계획에 포함한다. 확보 전에는 자막으로 기능 검증 가능하며 음성 검증은 별도 미완료로 기록한다.
- 음원 누락이나 무음 출력으로 진행이 영구 정지하지 않아야 한다. 음원 종료 대기가 필요한 단계와 화면 안내 시간을 기준으로 진행할 단계를 구분한다.
- 안내가 교체되거나 대상이 비활성화되면 이전 음성·대기·깜박임을 정리한다. 이전 재생의 완료 콜백이 새 안내나 완료 상태를 덮어쓰지 않아야 한다.
- CPR 재개 안내를 완료 표시가 바로 덮어쓰지 않게 한다. 최종 화면에 CPR 재개 안내를 유지하면서 AED 조작 교육 종료를 구분해 표시하는 기본안이다.
- 완료 후 전원·패드는 유지하고 충격 입력은 잠근다. 다시 체험은 기존처럼 Play 재시작/씬 재로드로 수행한다.
- 분석·충전 도중 비활성화/씬 종료 시 대기·이벤트·음성·깜박임을 취소한다. 씬 재로드는 완전 초기화다. 재로드 없는 비활성화 후 재활성화는 자동 진행·충격 재개를 차단하고 씬 재로드가 필요함을 알리는 방향이다. 일반 재시도 기능까지 구현한 것으로 보지 않는다.

## 8. 오류·중단 기준

| 상황 | 처리 목표 |
| --- | --- |
| 패드 1개만 부착 | 기존 남은 패드 안내 유지. 분석·충전 없음 |
| 분석 중 접촉 | 분석 결과 폐기·타이머 초기화, 손 떼기 후 재분석 |
| 충전 전·중 버튼 입력 | 충격 없음. 이후 단계에 입력 예약 없음 |
| 충전 완료 후 접촉 | 충격 차단, 손 떼기 안내. 비접촉 확인 후 새 클릭 필요 |
| 입력 직전 다시 접촉 | 최신 상태 검사로 충격 차단 |
| 전원·패드·앵커 점유 불일치 | 분석/충격 차단, 오류 표시. 상태가 깨진 채 완료하지 않음 |
| 손 추적·환자 참조 확인 불가 | 분석/충격 차단, 원인 구분. pose 복구 후에는 단계 조건 재확인 |
| 컴포넌트 비활성화·씬 종료 | 모든 새 입력·대기 작업 취소, 지연 완료 보고 무효화 |

## 9. 작업 순서와 완료 기준

| 순서 | 작업 묶음 | 완료 기준 |
| --- | --- | --- |
| 1 | 모델·UI·접촉 판정 연결 점검 | 충격 버튼 표면 위치, 양손 pose 참조, 환자 Collider 확인. B 내부 변경만으로 연결 가능 |
| 2 | 패드 완료 지점·분석 단계 연결 | 두 패드 부착 후 완료하지 않고 이탈 대기→분석 진행. 접촉 시 중단·재분석 가능 |
| 3 | 충전·충격 조작 | 충격 필요 시 충전 후 버튼 활성, 사용자 유효 클릭으로 한 번 시행 |
| 4 | CPR 재개·최종 안내 | 충격 시행 후 CPR 재개 안내·AED 1사이클 체험 완료. 불필요 분기는 제외 |
| 5 | 자막·음성·중단 정리 | 신규 문구·시작 목표 일치, 안내 교체·비활성화 시 잔류 작업 없음. 음원 확보 여부와 별도 검증 상태 기록 |
| 6 | 사용자 직접 회귀·Simulator 검증 | 사용자가 전원부터 충격·최종 안내까지 1사이클, 접촉 오류·중복 입력·재실행을 확인하고 결과 공유 |

일정은 소요 시간을 추정하지 않고 위 기능 묶음 단위로 진행한다. Quest 2 + Link 실기는 기존 사용자 결정대로 전체 기능 구현 후 수행한다.

## 10. 사용자 직접 실행 검증 체크리스트

| ID | 검증 상황 | 통과 기준 |
| --- | --- | --- |
| A01 | 기존 전원·패드 흐름 | 양손·패드 순서·정상 놓기·표시 전환 유지. 패드 1개로 분석 진입하지 않음 |
| A02 | 두 패드 정상 부착 | 전원·두 부착·대응 앵커 점유 확인 후 분석 단계 1회 진입. 기존 완료 문구 미출력 |
| A03 | 분석 시작 시 이미 접촉 | 분석 진행 없음. 손을 떼면 분석 시작 |
| A04 | 분석 중 재접촉 | 결과·타이머 초기화. 재이탈 후 전체 분석 시간이 새로 진행 |
| A05 | 충격 필요 | 충전→준비→유효 버튼 입력→충격 1회→CPR 재개 안내 순서 |
| A06 | 충전 전·중 반복 입력 | 충격 0회, 충전 완료 후 자동 충격 없음 |
| A07 | 충격 대기 중 접촉·이탈 | 접촉 중 차단, 이탈만으로 시행하지 않음. 새 클릭으로만 충격 |
| A08 | 버튼 입력 순간 재접촉 | 과거 준비 표시와 무관하게 충격 차단 |
| A09 | 연타·양쪽 레이·중복 콜백 | 유효 충격과 최종 완료는 각각 1회 |
| A10 | 범위 제외 기록 | 최신 사용자 결정으로 충격 불필요 분기 구현·검증은 제외. 기존 ID는 이력용으로 유지 |
| A11 | 누락·비활성·추적 소실 | 확인 불가를 비접촉으로 취급하지 않음. 참조 오류·전제 불일치에서 분석/충격 차단 |
| A12 | 분석·충전·충격 대기 중 종료 | 음성·깜박임·대기·입력 구독 정리. 이전 실행의 충격/완료 콜백 없음 |
| A13 | 재실행 | 전원 OFF, 패드 초기 상태, 충전/방전 초기화. 같은 충격 필요 1사이클 재수행 가능 |
| A14 | 안내 교체·음원 미확보 | 이전 안내가 새 자막을 지우지 않음. 자막만으로 완주 가능하며 음성 미검증은 별도 기록 |

에이전트는 상태 전환·입력 잠금·지연 콜백과 씬 연결을 파일 기준으로 정적 검토한다. 위 항목의 실행 확인, 실제 XR 버튼 선택·양손 접촉 판정·표시·음성 확인은 사용자가 직접 수행한다. 자동 테스트나 빌드가 필요한 경우에도 사용자가 직접 실행한다.

검증용 복제·임시 프로젝트는 생성하지 않고 기존 복제본도 재사용하지 않는다. 후속 구현 프롬프트에는 에이전트 실행 지시 대신 사용자의 확인 순서·기대 결과·실패 기준을 포함한다. 정적 검토, 사용자 Simulator·음성·실기 결과, 미검증 항목을 구분한다. 사용자 결과가 없는 항목은 미검증으로 남긴다.

## 11. 경로·변경 원칙

- 문서: `Docs/B/**`.
- 향후 구현 후보: `Assets/B/Scripts/AedTutorial/**`, 현재 AED 씬, AED 래퍼 Prefab, 필요 시 인체 래퍼의 B 소유 연결 정보, B 내부 음성·UI·테스트 자산.
- 공유 Rig는 B 씬 인스턴스의 참조·추가 연결을 사용한다. `Assets/Samples`, `Assets/XR`, `Assets/XRI`, `Assets/TextMesh Pro` 원본이나 다른 담당자 자산은 변경하지 않는다.

- 기존 인체·AED FBX 및 사용자 씬 보정값은 보존한다. 이번 범위의 버튼·안내·접촉 판정 연결에 필요한 최소 변경만 계획한다.
- 현재 사용자 요청은 구현 계획 작성이다. 코드는 직접 작성·수정하지 않는다. 구현 프롬프트도 명시 요청 시에만 제공한다.
