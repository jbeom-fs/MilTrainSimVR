- 상태 enum 정수값 변경 없음. 13을 `ModuleCompleted`로 바꾸지 않았다.

## 3. 초기값 보관 시점

- `AedPad.Awake()`에서 한 번만 보관한다. 첫 잡기·부착 전이며 이후 다시 쓰지 않는다. 진행 측 `Awake`가 바꾸는 값(잡기 활성·강조)은 보관 대상이 아니라서, 두 `Awake`의 실행 순서와 무관하다.
- 보관 항목: 부모, 로컬 위치·회전·스케일, Rigidbody `isKinematic`·`interpolation`, XR `throwOnDetach`·`interactionLayers`, 케이블 Renderer `enabled`.
- 전원·충격 장비·앵커·진행 컨트롤러의 초기값은 코드상 고정 시작 상태(전원 OFF, Idle, 미점유, 시작 대기)다. 별도 보관이 필요 없다.

## 4. 초기화 순서 (`OnRetryClicked`)

1. 상태가 13이 아니면 무시한다(연타 방지). 즉시 상태를 `NotInitialized`로 바꾼다. 이 값은 어떤 진행 핸들러·`Update` 단계에도 해당하지 않아, 이전 회차 평가와 초기화 중 장비 이벤트(예: 취소된 패드 해제)가 새 교육 행동으로 처리되지 않는다.
2. 다시하기 버튼 숨김·비활성.
3. 충격 장비 `ResetForNewRun()`.
4. 각 패드 `ResetForNewRun()` → 대응 앵커 `ResetForNewRun()`.
5. 전원 `ResetForNewRun()`(PowerChanged 이벤트를 내지 않음).
6. 컨트롤러 회차 값 초기화: 현재 패드, 부착 미리보기, 재접촉 기록, 중단 잠금 플래그, 접촉 표시 캐시, 분석 시간.
7. `ShowStartScreen()`: 안내 문구를 첫 문구로 되돌리고, 안내 패널·다시하기·전원 강조를 숨긴다. 전원 입력·패드 잡기를 잠그고 앵커 표시를 정리한 뒤, 시작 화면과 시작 버튼을 켜고 `WaitingForStart`로 둔다.

다시하기 버튼 이벤트 구독은 추가되었다. 다시하기 실행 시 구독을 다시 추가하지 않으며, 시작·다시하기 버튼, 전원·패드·충격 이벤트는 `OnEnable`/`OnDisable`에서 한 번씩 짝을 이룬다. 회차 반복으로 콜백이 누적되는 경로는 정적 검토에서 확인하지 못했다.

## 5. 장비별 복원 항목

| 장비 | 복원 |
| --- | --- |
| 패드 | 남은 XR 선택이 있으면 취소. 잡기·손 정보 해제, `IsAttached=false`, `AttachedAnchor=null`, 최초 부모·로컬 위치·회전·스케일, 잔여 속도 제거, 최초 kinematic·interpolation, Rigidbody 위치 동기화, `throwOnDetach`·`interactionLayers`(부착 시 0으로 바꾼 값), 케이블 표시, 강조 OFF, 잡는 패드 시각 모델·Collider ON |
| 앵커 | `AttachedPad=null`, 위치 안내·부착 가능 표시 OFF, 환자 부착 패드 OFF |
| 전원 | `IsOn=false`, 입력 잠금, 표시등 OFF 색·"꺼짐" 라벨, 버튼 비활성 |
| 충격 장비 | `Idle`, 충전 시간 0, 방전 이력 없음, 입력 잠금, 기억한 포인터 삭제, 버튼 비활성, 깜박임 OFF, 상태 라벨 빈칸 |
| 진행·UI | 위 4절 6·7단계. 잡기 활성(`grab.enabled`)은 기존처럼 전원 ON 이후 진행 측이 다시 켠다 |

`TryAttach()`가 바꾸는 값(부모, kinematic, interpolation, 위치·회전, `throwOnDetach`, `interactionLayers`, 시각 모델·Collider, 부착 상태·앵커 점유)을 모두 복원한다. 이 중 `interactionLayers`를 되돌리지 않으면 두 번째 회차에 패드를 잡을 수 없다.

## 6. UI 배치

- `RetryButton`: Canvas 직계 자식, 위치 (300, -85), 260×80, 36pt. 안내 패널(위에서 320, 아래 끝 y=-20) 아래 오른쪽에 둬 마무리 문구를 가리지 않는다.
- 시작 버튼(0, -140, 280×90)과 겹치지 않는다. 다시하기를 빠르게 두 번 눌러도 두 번째 입력이 시작 버튼에 닿지 않는다. 시작 검사에서 시작 패널 포함·시작 버튼 겹침을 막는다.
- 기존 Canvas의 레이캐스터와 씬 EventSystem·XRUIInputModule을 그대로 쓴다. 새 입력 체계는 없다.

## 7. 기존 동작 보존

전원·패드 조작, 비접촉 확인·분석, 충전 시간, 충격 허용 조건, 누름 시작 추적, 회차당 1회 충격, 마무리 문구 처리 코드는 수정하지 않았다. 추가 코드는 13 이후 다시하기 경로와 각 장비의 새 초기화 함수뿐이다. `Awake`의 시작 화면 구성은 같은 순서·값으로 `ShowStartScreen()`에 옮겼다. 다시하기 버튼 숨김만 추가했다.

## 8. 정적 검토

- 씬 YAML: fileID 중복 0, 끊긴 참조 0, 계층·컴포넌트 목록 불일치 0(스크립트 검사).
- 새 버튼은 기존 시작 버튼 블록을 복제했다. 부모·위치·크기·이름·초기 비활성·대상 Graphic만 바꿨다. `OnClick` 목록은 비어 있고 코드에서만 구독한다.
- 다른 컴포넌트 private 필드 강제 변경·`Awake`/`OnEnable` 직접 호출 없음. 범용 스냅샷·Reset 프레임워크 없음. `Reset()` 이름은 Unity 편집기 콜백과 겹치므로 쓰지 않았다.
- 구현 당시 컴파일·화면·조작: 미검증이었다. 이후 사용자가 검증 완료를 보고했다. 에이전트 직접 실행 결과는 아니다.
- 후속 정적 검토: 씬 로컬 fileID 중복·끊긴 참조 각각 0건 확인. 마지막 패드 부착 직후 XRGrabInteractable을 끄면 XRI의 Late detach가 남고, 다시하기에서 throwOnDetach를 복원한 뒤 다음 회차 전원 ON 시 kinematic Rigidbody 던지기 경고가 날 가능성을 지적했다(P3). 재현·수정·경고별 검증 결과는 제공되지 않았다. 재체험 불가나 패드 튐이 확인된 결함으로 기록하지 않는다.

## 10. 미검증·알려진 제약

- 사용자는 다시하기 검증 완료를 보고했다. 위 R00~R10 각각의 결과, 정확한 반복 횟수, 경고 로그 유무와 사용 장치는 따로 제공되지 않아 개별 통과로 채우지 않는다. Quest 2 + Link 실기는 별도 완료 확인 전이다.
- 중간 재시작·종료·메뉴 복귀·결과 저장·음성은 범위 밖이다. 다시하기는 상태 13에서만 가능하다. 중간 비활성화 후 상태 10은 기존처럼 씬 재로드가 필요하다.
- 패드 초기값은 `Awake` 시점의 씬 배치를 기준으로 한다. Play 중 Inspector로 패드 배치를 바꾸면 다시하기는 처음 값으로 되돌린다.
- 기존 하향 레이 접촉 보완의 제약(몸 아래 빈 공간을 접촉으로 볼 수 있음)은 그대로다.

## 11. B 외부 변경

없음. `Assets/B.meta`·다른 담당 자산·Packages·ProjectSettings를 바꾸지 않았다. 복제 프로젝트를 만들거나 재사용·삭제하지 않았고, Unity·Simulator·batchmode·테스트·빌드를 실행하지 않았다.
