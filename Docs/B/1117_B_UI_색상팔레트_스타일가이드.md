# B UI 색상 팔레트·스타일 가이드 — A·C 통일 작업 참고

작성: B · 2026-11-17  
기준 HEAD: `61d66f9`  
대상: 구급법 `B_FirstAid`, 화생방 `B_CBRN`의 현재 운영 UI

다른 담당자가 자기 씬의 UI를 B와 같은 시각적 기준으로 맞출 수 있도록, 실제 코드와 저장 씬에서 읽은 색·글꼴·배치·입력 표시 규칙을 정리했다. 새 디자인 제안이 아니라 현재 B UI의 전달 문서다. **색상·글꼴·버튼 상태는 공통 기준으로 사용하고, 과정별 단계 수·내용·성공 조건은 각 콘텐츠에 맞게 유지한다.**

기준 화면은 `B_CBRN`의 **KD-1 교육 보드**다. B의 다른 교육도 이 스타일을 따르지만 본문 길이·단계 수에 따른 배치 차이가 있다. 아래 좌표는 KD-1 운영 보드의 실제 예시이며 모든 씬에 강제할 좌표가 아니다. 이번 작성에서는 파일만 읽었으며 Unity·Play·헤드셋 확인은 하지 않았다.

## 2. 화면 UI 팔레트

**정확한 값은 Unity RGB 0~1 열을 우선한다.** HEX는 채널에 255를 곱해 반올림한 8비트 근삿값이다. HEX를 넣은 뒤 0.001 수준의 차이가 있으면 RGB 열로 맞춘다. 표의 값은 코드·씬에 지정된 색이며 별도 감마 변환을 적용한 값이 아니다. 별도 표기가 없으면 Alpha는 1이다.

| 역할 | HEX 근삿값 | Unity RGB 0~1 | Alpha | 사용 위치·의미 |
|---|---|---|---|---|
| 기본 배경 `Background` | `#12171C` | `(0.07, 0.09, 0.11)` | 1 | 교육 보드 전체 배경 |
| 기본 글자 `Text` | `#F0F2F5` | `(0.94, 0.95, 0.96)` | 1 | 제목·설명·행동·버튼 라벨 |
| 보조 안내 `Notice` | `#FFC759` | `(1.00, 0.78, 0.35)` | 1 | 시작 준비 상태·힌트·최근 결과 |
| 기본 버튼 `Button` | `#296BB3` | `(0.16, 0.42, 0.70)` | 1 | 교육 시작·확인·다시하기·계속하기·교육 종료 |
| 내부 카드 `Card` | `#1F262E` | `(0.12, 0.15, 0.18)` | 1 | 확인 항목 카드·중단 확인창 배경 |
| 완료 단계 `StepDone` | `#409E5C` | `(0.25, 0.62, 0.36)` | 1 | 현재 단계보다 앞의 완료 박스 |
| 현재 단계 `StepCurrent` | `#296BB3` | `(0.16, 0.42, 0.70)` | 1 | 현재 수행 단계 박스 |
| 미수행 단계 `StepAhead` | `#384047` | `(0.22, 0.25, 0.28)` | 1 | 다음 단계 박스·스크롤바 트랙 |
| 중단 요청 | `#9E452E` | `(0.62, 0.27, 0.18)` | 1 | 진행 화면의 ‘교육 중단’ 버튼 |
| 중단 확정 | `#9E3333` | `(0.62, 0.20, 0.20)` | 1 | 확인창의 ‘중단하기’ 버튼 |
| 차단판 `Shade` | `#0D0F12` | `(0.05, 0.06, 0.07)` | 0.88 | 조작할 수 없는 화면을 덮는 반투명 배경 |

앞의 8개 기본 역할은 [TrainingBoardStyle.cs](../../Assets/B/Scripts/TrainingUI/TrainingBoardStyle.cs)의 값이다. 중단 요청·중단 확정·차단판은 `B_CBRN` KD-1 보드와 `FieldUI/Blocker_1_KD1_CourseBoard`의 저장값이다. 이 3개가 현재 `TrainingBoardStyle` 상수로 정의되어 있다는 뜻은 아니다.

색 적용 원칙:

- **정상적인 ‘교육 종료’는 파랑**이다. ‘교육 중단’과 확인창의 ‘중단하기’를 구분한다.
- 준비·힌트에 쓰는 노랑을 현재 단계 박스나 일반 버튼의 기본색으로 사용하지 않는다.
- 단계 완료와 현재 행동을 색만으로 전달하지 않는다. 단계 번호·현재 단계명·상태 문구를 함께 둔다.
- 미수행 회색은 버튼 비활성과 다른 개념이다. 단계 박스는 원래 클릭 대상이 아니다.
- 순백·순검으로 임의 치환하거나 배경에 새 그라데이션·강한 발광을 추가하지 않는다.

### 버튼의 상태색 — Color Tint

두 운영 씬에서 읽은 Button·Scrollbar 계열 상태값은 다음과 같다. 아래 값은 **Image 기본색에 곱하는 틴트**이며, 버튼 배경색 자체를 회색으로 바꾸라는 뜻이 아니다.

| 상태 | Unity RGBA | HEX 근삿값 |
|---|---|---|
| Normal | `(1, 1, 1, 1)` | `#FFFFFFFF` |
| Highlighted | `(0.9607843, 0.9607843, 0.9607843, 1)` | `#F5F5F5FF` |
| Pressed | `(0.78431374, 0.78431374, 0.78431374, 1)` | `#C8C8C8FF` |
| Selected | `(0.9607843, 0.9607843, 0.9607843, 1)` | `#F5F5F5FF` |
| Disabled | `(0.78431374, 0.78431374, 0.78431374, 0.5019608)` | `#C8C8C880` |

- Transition: **Color Tint**.
- Color Multiplier: **1**.
- Fade Duration: **0.1초**.
- Target Graphic: 해당 버튼의 배경 Image. 라벨은 별도 TMP로 둔다.
- 파랑·갈색·빨강 버튼 모두 같은 상태 틴트를 사용한다. 눌림·비활성을 새 색 체계로 만들지 않는다.

## 3. 글꼴·문자 계층

기준 글꼴: `Assets/B/Fonts/NotoSansKR-Regular SDF.asset`. 현재 운영 보드의 해당 font GUID는 `47f3dda554fd6de42acf8effa834bd7b`이다. 다른 담당자는 자신의 글꼴 사본을 쓰거나 기존 참조를 유지하되, 같은 Noto Sans KR 외형·한글 표시 품질을 맞춘다. B의 동적 글꼴 자산을 직접 편집하지 않는다.

| 역할 | TMP Font Size | 색 | KD-1 예시 |
|---|---|---|---|
| 시작·완료 화면 제목 | 34 | Text | `StartPanel/Title`, `CompletionPanel/Title` |
| 중단 확인 질문 | 34 | Text | `Confirm/Question` |
| 결과 수행 수·큰 상태 안내 | 30 | Text 또는 Notice | 완료 `Count`, 차단 `Message` |
| 현재 행동 | 28 | Text | 실습 `Action` |
| 현재 단계 줄 | 26 | Text | `PracticePanel/StepLine` |
| 버튼 라벨 | 26 | Text | 시작·다시하기·중단·종료·계속하기 |
| 목적·방법·일반 설명·요약·진행 수 | 24 | Text | `Purpose`, `Description`, `Summary`, `Progress` |
| 준비 상태·힌트·최근 결과·확인창 설명 | 22 | Notice 또는 Text | `Ready`, `Hint`, `Result`, `Confirm/Detail` |
| 출처·과정의 제한 등 작은 부연 | 20 | Text | `Note` |
| 단계 박스의 번호 | 18 | Text | `Step_1/Label` 등 |

기본 설정:

- 현재 KD-1 보드의 위 텍스트는 **Normal 스타일**이며 Auto Size는 꺼져 있다. 전체를 Bold로 바꾸지 않는다.
- 제목·단계·행동·버튼은 중앙 정렬을 기준으로 한다. KD-1 기준 텍스트는 가로·세로 중앙 정렬이다.
- 긴 설명·목록의 정렬은 콘텐츠에 맞출 수 있지만, 같은 역할의 글자 크기·색·여백은 유지한다. 이는 다른 씬 적용 시의 조정 범위이며 B 전체가 왼쪽 정렬이라는 뜻은 아니다.
- 기본 Word Spacing·Line Spacing 추가값은 0이다. 실제 줄바꿈에 필요한 높이를 확보한다.
- 버튼 라벨·단계 번호·일반 안내 텍스트는 Raycast Target을 끈다.
- 문장이 길다고 본문을 단계 번호 크기인 18로 줄이지 않는다. 문장을 정리하고 필요한 본문은 스크롤한다.
- 동적 한글·숫자·괄호·단위·줄바꿈이 빠지거나 네모 글자로 나오지 않는지 확인한다.

## 4. 교육 화면의 배치 기준

### 공통 디스플레이

| 항목 | 현재 값 |
|---|---|
| Canvas | World Space |
| RectTransform | 720×440, pivot 중앙 |
| Canvas Local Scale | `(0.001, 0.001, 0.001)` |
| 실제 화면 크기 | 부모 배율이 1이면 약 0.72×0.44m |
| 화면 부모 | 위치·방향을 관리하는 미터 단위 Transform, scale 1 |
| 화면 외형 | Canvas와 형제인 `TrainingDisplay_Visual` |
| 배경 | 전체 720×440, Background 색 |

720×440은 교육 디스플레이 기준이다. C 전투 HUD·소형 손목 화면 등 다른 화면에도 이 물리 크기를 강제하지 않는다. 그런 화면은 색 역할·글자 계층·버튼 상태를 우선 맞추고 표시 거리와 시야에 맞게 크기를 조정한다.

### KD-1 기준 좌표 예시

단위는 Canvas 단위이며 중심 `(0, 0)` 기준이다. 시작·실습·완료 패널은 서로 다른 상태에 표시되므로 같은 상단 공간을 사용한다.

| 요소 | 중심 위치 x, y | 크기 w×h | 비고 |
|---|---|---|---|
| 시작·완료 제목 | `(0, 185)` | 660×50 | 상단 고정 |
| 실습 단계 박스 4개 | x `−255, −85, 85, 255`, y `190` | 각 160×40 | 박스 사이 간격 10 |
| 현재 단계 줄 | `(0, 148)` | 680×40 | 단계 박스 아래, 고정 |
| 시작·완료 스크롤 본문 | `(0, 8)` | 692×296 | 버튼 행과 분리 |
| 실습 스크롤 본문 | `(0, −8)` | 692×264 | 단계 줄·하단 행과 분리 |
| 시작 버튼 | `(0, −180)` | 260×64 | 하단 중앙 |
| 교육 중단 | `(−240, −180)` | 200×60 | 실습 중 하단 왼쪽 |
| 실습 다시하기 | `(240, −180)` | 200×60 | KD-1에 있는 기존 기능 |
| 완료 다시하기 | `(−240, −180)` | 200×60 | 완료 후 하단 왼쪽 |
| 교육 종료 | `(240, −180)` | 200×60 | 완료 후 하단 오른쪽 |
| 최근 결과 | `(240, −180)` | 200×60 | 시작 화면, 22·Notice |

```text
시작 화면                  실습 화면                    완료 화면
과정 제목                  [1][2][3][4]                 완료 제목
                           현재 단계명
설명·준비 상태              목적·방법                    수행 요약·수
      ↕ 본문 스크롤        현재 행동·보조 안내 ↕        부연 안내 ↕

        교육 시작           교육 중단  진행  [기존 기능]  다시하기     교육 종료
             최근 결과
```

- 단계 수는 실제 교육에 맞춘다. 4개로 강제하지 않고, 박스에는 번호만 넣고 긴 단계명은 별도 줄에 표시한다.
- 단계 박스는 완료=초록, 현재=파랑, 다음=회색이다. 시작·초기화에서 전체 미수행으로 두는 기존 표시 규칙을 유지한다.
- B의 TQ·PB·K1·PC는 내용·단계 수 때문에 본문 높이 등이 다르다. KD-1 좌표를 그대로 복사해 글자가 겹치게 만들지 않는다.
- 버튼의 높이·하단 위치를 우선 확보하고 남은 공간을 본문으로 사용한다.
- Content는 레이아웃 컴포넌트가 정렬한다. 저장된 본문 자식의 임시 anchoredPosition이나 SizeDelta를 최종 수동 배치값으로 복사하지 않는다.
- KD-1의 ‘실습 다시하기’를 다른 과정에 새로 추가하라는 뜻이 아니다. 각 과정의 기존 기능과 상태 전환을 유지한다.

## 5. 중단 확인·차단 화면

중단 요청과 실제 중단 확정을 분리한다. 확인창의 설명은 무엇이 멈추고, 확정하면 무엇이 초기화되는지 교육생이 이해할 수 있게 쓴다.

| 요소 | 위치 x, y | 크기 | 글자·색 |
|---|---|---|---|
| 확인창 카드 | `(0, 0)` | 720×440 | Card, Alpha 1 |
| 질문 | `(0, 140)` | 660×60 | 34, Text |
| 설명 | `(0, 55)` | 640×110 | 22, Text |
| 계속하기 | `(−150, −60)` | 240×64 | 파랑 버튼, 라벨 26 |
| 중단하기 | `(150, −60)` | 240×64 | 빨강 버튼, 라벨 26 |
| 일반 차단 메시지 | `(0, 0)` | 619.2×378.4 | 30, Notice |

- 확인창은 스크롤하지 않는다. 하단 버튼과 질문·설명이 모두 한 화면에 들어간다.
- B의 차단 Canvas는 대상 화면과 같은 방향으로 **화면 앞 4mm**에 있고, 전체 720×440을 덮는다.
- Shade와 확인창 배경은 레이를 차단한다. 뒤쪽 버튼·스크롤바가 눌리면 안 된다.
- 일반 글자·장식의 Raycast Target은 꺼 두고 실제 버튼·스크롤·차단 배경만 필요한 입력을 받는다.
- 중단·계속·초기화 동작은 각 콘텐츠의 기존 로직에 연결한다. 시각 통일을 위해 새 종료 경로나 전역 시간 정지를 만들지 않는다.

## 6. 스크롤 스타일·동작

현재 기준은 [TrainingScrollBody.cs](../../Assets/B/Scripts/TrainingUI/TrainingScrollBody.cs)와 운영 씬의 ScrollRect다.

| 항목 | 값·구성 |
|---|---|
| 스크롤 방향 | 세로만, Horizontal OFF / Vertical ON |
| Movement Type | Clamped |
| Inertia | OFF |
| Scroll Sensitivity | 8 |
| Viewport | RectMask2D, 투명 Image의 Raycast Target ON |
| 본문 | 위쪽 anchor·pivot, VerticalLayoutGroup + ContentSizeFitter |
| 본문 간격 | VerticalLayoutGroup Spacing 8 |
| 본문 글 영역 | KD-1 기준 폭 약 640 |
| 스크롤바 | 오른쪽, 폭 28, Auto Hide |
| 스크롤바 자리 | 본문 오른쪽 36 단위 확보 |
| 트랙 / 손잡이 | StepAhead / Button 색 |

표시 규칙:

1. 시작·실습·완료 화면이 새로 보이면 본문 맨 위에서 시작한다.
2. 현재 단계명이 바뀌면 맨 위로 이동한다.
3. 같은 단계의 진행률·상태 문구만 바뀔 때는 스크롤 위치를 유지한다.
4. 새 확인 카드가 나타나면 해당 카드가 보이도록 이동한다.
5. 내용이 화면에 들어가면 불필요한 스크롤바를 숨긴다.
6. 시작·다시하기·중단·종료 등 주요 버튼은 스크롤 본문 밖의 고정 영역에 둔다. B 운영 PB의 확인 버튼도 고정 영역으로 옮겨진 현재 형태를 따른다.

입력 외형을 맞추는 작업과 입력 바인딩 변경은 구분한다. 현재 B의 UI 클릭은 트리거이고, B 전용 입력 관리자가 스크롤 UI를 가리킨 손의 스틱을 스크롤에 사용한다. 다른 담당자는 자기 씬의 정상 입력 경로를 유지하며, B 리그나 입력 관리자를 단순히 가져와 덮어쓰지 않는다.

## 7. 문구·정보 구성

기본 정보 순서:

1. 지금 진행하는 과정·단계.
2. 이 단계의 목적과 방법.
3. 지금 해야 하는 행동.
4. 막힌 이유·준비 상태 등 보조 안내.
5. 진행 수·완료 결과와 다음 행동 버튼.

- 행동은 ‘잡으세요’, ‘표시된 위치로 옮기세요’, ‘버튼을 누르세요’처럼 구체적으로 쓴다.
- 한 화면에서 서로 다른 행동을 동시에 최우선으로 강조하지 않는다.
- 교육생 화면에 Runner 상태명·내부 필드명·디버그 오류 코드를 그대로 노출하지 않는다.
- 과정 제목을 행동 안내 자리에 반복하지 않는다. 설명과 현재 행동을 분리한다.
- 색만으로 결과를 설명하지 말고 완료·진행 수·다시하기 등 문구를 함께 둔다.
- 자막·안내 문구는 각 담당의 전용 `TrainingSubtitles` 등 문구 관리 클래스에서 관리한다. UI 통일을 이유로 B 교육 문구·의학 절차·성공 조건을 다른 콘텐츠에 복사하지 않는다.

## 8. 공간 안내 표식 — 화면 UI와 별도 역할

다음은 화면 밖에서 물건·착용 위치·접촉 대상을 가리키는 표식 기준이다. **파랑은 화면 조작·현재 단계, 하늘색은 공간의 현재 행동 대상**으로 구분한다.

| 역할 | HEX 근삿값 | Unity RGB | Alpha |
|---|---|---|---|
| 집기·조작·이동·착용·접촉 대상 | `#4DC7FF` | `(0.30, 0.78, 1.00)` | 선 1 / 면 0.28 |
| KD-1 공간 표식 완료 | `#40E659` | `(0.25, 0.90, 0.35)` | 1 |
| AED 부착 준비 | `#33F266` | `(0.20, 0.95, 0.40)` | 1 |
| AED 충격 강조 | `#FF381F` | `(1.00, 0.22, 0.12)` | 1 |

화면의 완료 단계 초록 `(0.25, 0.62, 0.36)`과 공간 완료 초록은 밝기가 다르므로 서로 바꿔 쓰지 않는다. AED의 초록·주황빨강은 장비 상태 의미가 있으므로 일반 버튼색으로 통일하지 않는다.

| 표식 종류 | 선 굵기 |
|---|---|
| 작은 조작 고리 | 4mm |
| 몸 착용 고리 | 6mm |
| 방향 화살표·꺾쇠 | 6mm |
| KD-1 영역 윤곽 / 번호 / 체크 | 9 / 7 / 9mm |

PB 영역·끝 부착 고리 등은 크기·판정 영역에 따른 기존 예외가 있다. 자세한 대상별 예외는 [공간 안내 표식 통일 기록](1112_B_공간안내표식_통일_구현기록.md)을 따른다. 선 굵기를 맞추기 위해 판정 반경·접촉 영역까지 변경하지 않는다.

- B 운영 씬의 표식은 깊이 가림을 피하는 전용 Overlay 재질을 사용한다. LineRenderer 정점 색은 흰색으로 두어 재질 색에 추가 틴트가 곱해지지 않게 한다.
- AED UI 강조용은 `B/Common/UIStatusMarkerOverlay`, 일반 공간 표식은 `B/Common/StatusMarkerOverlay`, 보호의 공간 장비명은 TMP Overlay 재질을 쓴다.
- 이 셰이더를 일반 교육 본문·모든 버튼에 일괄 적용하지 않는다. 스크롤 마스킹·차단판·그리기 순서·양안 표시를 따로 확인한다.
- 표식 장식에 새 Collider·Interactable·Raycaster를 붙이지 않는다. 기존 안내 표식은 실제 조작 대상을 가리지 않아야 한다.

## 10. 다른 담당자의 적용 순서

1. **참고 화면 확인:** `B_CBRN`의 KD-1 시작·실습·완료·중단 확인과, `B_FirstAid`의 다른 단계 수·확인 카드 사례를 읽기 전용으로 확인한다.
2. **역할 대응:** 자기 UI를 제목·목적·행동·힌트·결과·주 버튼·중단으로 나누고 §2·3의 색과 글자 크기를 대응시킨다.
3. **자기 자산에서 적용:** A는 `Assets/A`, C는 `Assets/C` 등 자기 소유 경로에서 작업한다. B 씬·프리팹·폰트·재질 원본은 수정하지 않는다.
4. **필요한 것만 재사용:** 숫자 팔레트·배치 원칙을 우선 적용한다. 프리팹·스크립트를 사본으로 사용할 때는 새 GUID와 필요한 참조·어셈블리를 확인한다. 스타일만 맞추려고 B 교육 시스템·리그·입력·소유권 관리 전체를 가져오지 않는다.
5. **저장값과 코드 일치:** Inspector 색을 맞춰도 런타임 코드가 다시 칠하면 달라진다. 단계 박스·버튼·안내의 코드 지정색도 같은 역할 값으로 맞추고, 한 요소를 여러 코드가 서로 칠하지 않게 한다.
6. **참조·동작 보존:** 기존 Button 이벤트, 교육 단계, 결과 계산, 씬 이동, XR 입력을 유지한다. 외형 변경에 섞어 기능을 바꾸지 않는다.
7. **사용자 실행 확인:** 각 담당자가 자기 씬에서 컴파일·화면·실기 입력을 확인하고 아래 항목으로 비교한다.

### 적용 후 확인 항목

- 시작·실습·완료·중단 확인에서 색 역할과 글자 계층이 같은가.
- 제목·현재 단계·주 버튼이 스크롤에 따라 사라지지 않는가.
- 가장 긴 실제 문구, 숫자·단위, 완료 요약이 잘리지 않는가.
- 레이 Hover·Pressed·Selected·Disabled 상태가 표시되는가.
- 비활성 버튼과 단순 안내 박스를 구분할 수 있는가.
- 중단 확인 중 뒤쪽 버튼·장비 버튼·스크롤바 입력이 차단되는가.
- 다시하기·화면 재진입·단계 전환 후 스크롤 위치가 규칙대로 복원되는가.
- 실제 사용 거리·사선·좌우 눈에서 글자와 공간 표식이 읽히는가.
- 스타일 적용 전후 교육 판정·입력·씬 이동이 유지되는가.
