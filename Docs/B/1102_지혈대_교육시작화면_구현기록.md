# 지혈대 교육 시작화면 구현 기록 — 2026-11-02

상태: **코드·구성/검사 메뉴 작성과 정적 검토 후, 사용자가 교육 시작화면 검증 완료를 보고했다(2026-11-02).** 미커밋. 개별 절차·장치·반복 횟수·실기 결과는 별도 미보고이며 에이전트 실행 검증은 하지 않았다.

갱신: 이후 커밋 `c11f8a2`로 커밋됐다(위 "미커밋"은 당시 기록). 6단계 진행·Runner 연결은 [6단계 구현 기록](1102_지혈대_교육6단계_Runner연결_구현기록.md)에서 확장했다.

## 1. 구현 범위

씬 진입 → 시작화면·장비 선택 잠금 → `교육 시작` 선택 → 시작 수락(1회) → 시작 패널 숨김·기존 조작 안내 표시 → 기존 잡기·배치·2챕터 조작.

포함하지 않음: 단계별 Runner 연결, 임시 TrainingDefinition, 교육 완료 화면, 최종 재확인, 다시하기, 과정 선택·복귀, 교육 시계 연결. 시간 기록은 기존대로 **부착 시점 기준 경과 시간**이다.

## 3. 입력 잠금

- `TourniquetTrainingStart`(씬 `TQ_Training/TQ_TrainingStart`)가 장비의 **모든 XRBaseInteractable**(본체 XRGrab 1 + 부품 조작점 4)의 `selectFilters`에 자신을 추가한다. K1TrainingLink의 방식을 참고해 새로 작성했다(K1 코드 복사·수정 없음).
- 필터 조건: 이미 잡고 있는 선택은 유지, 새 선택은 `Started` 상태이며 해당 interactor가 해제 대기 중이 아닐 때만 허용.
- XRI가 장비 자체 조건과 이 필터를 함께 적용한다. `enabled`·`interactionLayers`·Collider는 쓰지 않으므로 `TourniquetOperation.UpdateGates()`(단계별 조작점 켜기)·부착 후 본체 `interactionLayers=0` 잠금과 경쟁하지 않는다.
- 필터는 `OnEnable`에서 등록되어 첫 프레임부터 잠금. 장비·XR Rig·상태 스크립트를 끄지 않는다.
- 시작 버튼의 XR UI 입력은 장비 필터와 무관하므로 계속 동작한다.

## 4. 시작 수락

1. 버튼 클릭 → `TourniquetStartScreen`: 상태가 대기이고 버튼이 켜져 있을 때만 진행, 즉시 `interactable=false`.
2. 조작 안내(`TourniquetStatusBoard`)가 실행 중·참조 유효한지 확인.
3. `TourniquetTrainingStart.TryStart`: 참조(장비·Operation·잠금 목록이 장비 interactable 전체와 일치) + 준비 상태(`operation.IsReady`, 장비 미부착·미잡힘, 활성 interactable의 Interaction Manager, 선택 중 없음) 확인.
4. 성공: `Started`, 시작 패널 숨김, 조작 패널 표시, Console에 시작 로그.
5. 실패: `Faulted`, 잠금 유지, 시작 패널의 준비 안내 자리에 `StartUnavailable` 표시, 원인은 Console 오류로 기록. 버튼은 꺼진 채 유지.

- **중복 시작:** 상태 검사 + 버튼 비활성화. 같은 프레임 양손 클릭도 두 번째는 상태가 대기가 아니어서 무시.
- **자동 잡기 방지:** 시작 수락 순간 select 입력이 눌려 있는 interactor(`isSelectActive` 또는 `selectInput.ReadIsPerformed()`)는 그 입력을 놓을 때까지 장비 선택이 거부된다. 놓은 뒤 새로 누르면 잡힌다.
  - 정적 확인: Starter XR Rig NearFar는 `selectActionTrigger = StateChange`(눌린 순간만 선택 시작), UI press 입력(트리거)과 select 입력(그립)이 분리돼 있다. 위 해제 대기는 그 외 입력 구성까지 덮는 보조 조건이다.

## 5. 안내판

- 기존 `TQ_StatusBoard`의 월드 위치·회전·크기는 변경하지 않는다.
- 구조:

```text
TQ_StatusBoard (Canvas, TrackedDeviceGraphicRaycaster, TourniquetStatusBoard, TourniquetStartScreen)
├─ Background            raycast 끔
├─ Notice                PrototypeNotice — 두 화면 공용, StatusBoard가 씀
├─ OperationPanel        기존 Title/Instruction/Status/Detail — StatusBoard가 씀, 저장 시 비활성
└─ StartPanel            Title/Description/Ready/StartButton(Label) — StartScreen이 씀, 저장 시 활성
```

- **역할 분리:** StatusBoard는 Notice와 OperationPanel 텍스트만, StartScreen은 StartPanel 텍스트만 쓴다. 같은 텍스트를 두 컴포넌트가 쓰지 않는다. 시작 전 StatusBoard가 숨은 조작 패널을 갱신해도 화면에 겹쳐 보이지 않는다.
- **기존 텍스트 이동:** 메뉴 1이 board 직속 Title/Instruction/Status/Detail을 OperationPanel(부모 전체 채움·오프셋·회전·축척 없음)로 월드 자세를 유지한 채 옮긴다. 사용자 조정값은 그대로다. 레이아웃 revision(2)은 올리지 않았다.
- **시작 패널 초기 배치(안내판 단위, 최초 생성 시만):** 제목 215..265, 공용 Notice 113..205, 소개 −15..105(26pt), 준비 안내 −103..−27(24pt), 버튼 −225..−145(280×80, 30pt). 이후 실행은 사용자 조정 보존.
- **raycast:** 안내판 안에서 시작 버튼 Image만 `raycastTarget`. 배경·텍스트·버튼 글자는 끈다.
- 문구는 모두 `TrainingSubtitles` 상수(StartTitle, StartDescription, StartReady, StartButton, StartUnavailable). Inspector·UI에 원문을 저장하지 않는다. 교육생 화면에 키보드 단축키·내부 용어 없음.

## 7. 정적 검토 결과

- XRI 3.4.1 소스 확인: `XRBaseInteractable.selectFilters`는 필드 초기화 목록이라 비활성 조작점에도 등록 가능, 필터는 `CanSelect`에서 처리됨. `GetRegisteredInteractors`는 결과 목록을 비움. StateChange의 `isSelectActive`는 눌린 프레임 또는 선택 유지 중에만 참.
- 비활성 조작점은 Interaction Manager가 비어 있을 수 있어, 준비 확인의 Manager 검사는 활성 interactable에만 적용.
- 어셈블리: 새 Tutorial 어셈블리 → 장비 어셈블리 단방향 참조. 에디터 코드는 asmdef 없는 Editor 어셈블리라 자동 참조.
- 시작 대기 중에도 레이 hover 강조는 허용된다(선택만 차단).
- 구성 메뉴가 게이트 컴포넌트를 끄는 등의 개발자 강제 조작은 사용자 결함으로 분류하지 않는다(필터는 `isActiveAndEnabled`일 때만 작동).
- IDE 진단·컴파일은 실행하지 않았다.

## 9. 후속 범위

단계별 교육 진행·Runner 연결(게이트 상태를 Runner 상태로 대체 가능) → 최종 확인·완료 UI → 다시하기(`ResetToInitial()` + 게이트 재잠금) → 직접 압박·압박붕대 → B 과정 선택·복귀. 교육 시계 연결 시 시간 기록 기준을 별도로 결정한다.
