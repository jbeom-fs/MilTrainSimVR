## 3. 실습 6단계와 최종 확인 단계

- 교육 데이터: `tq-place → tq-band → tq-turn → tq-secure → tq-record → tq-fasten → tq-final-check`.
- 실습 단계 ID·순서·누적 조건(단계 i = 장비 상태 1..i 현재값)은 그대로다.
- 최종 확인 조건: 장비 6개 상태(State, `tq-device`, true) + `final-confirmed`(State, `tq-trainee`, true). Action 조건은 쓰지 않는다.
- `TourniquetTrainingIds.Steps`·연결부 `current/reached` 배열·단계 표시 분모는 6개 그대로라 분모 7, 없는 장비 신호 읽기, 인덱스 어긋남이 없다. 최종 확인은 `StepIndex == -1`이며 별도 상수로만 다룬다.
- 교육생 입력 상태는 별도 대상 `Target_Trainee`(`tq-trainee`)에 둬 프로그램이 검사한 장비 상태와 구분한다.

### Action 대신 State를 쓴 이유 (공통 Context 확인 결과)

`TrainingContext.ReportAction`은 진입 프레임(`frame <= enteredFrame`)과 다른 토큰의 입력을 거절하고, 수락한 Action은 `actions[]`에 단계가 끝날 때까지 남는다. 지우는 API가 없다. 따라서 Action으로 연결하면 (a) 장비가 무효일 때 받은 클릭이 나중에 장비가 회복되는 순간 자동 완료되고, (b) 수락 후 무효화가 불가능하다. State는 연결부가 매번 덮어쓸 수 있어 수락·철회를 연결부가 관리한다. 공통 코드는 바꾸지 않았다.

## 4. Runner가 Completed가 되는 정확한 조건

Runner LateUpdate(순서 0)의 `Tick`에서 최종 확인 단계 조건 7개가 모두 참일 때. `final-confirmed`는 아래 경우에만 참이다.

1. 이 과정이 시작한 회차(`IsCurrentRun`), Runner `Running`, 현재 단계 `tq-final-check`.
2. 대기 중인 수락 입력이 없음.
3. 버튼 클릭 순간 `TryConfirm`이 `Observe()`로 장비 실제 값(`IsAttached && AttachedTarget == Target`, `IsBandPrepared`, `WindlassTurnDegrees >= RequiredTurnDegrees`, `IsWindlassSecured`, `IsTimeRecorded`, `IsStrapFastened`, `operation.IsReady`)을 다시 읽고 6개가 모두 참.

클릭은 Update 단계(EventSystem)에서 처리되므로 같은 프레임 Runner Tick이 이를 판정한다. 완료 로그 `[Training] Completed`는 이때만 나온다.

## 5. 확인 입력의 귀속과 무효화

- 수락 시 `confirmToken = runner.CurrentToken`(RunId·StepEntry), `confirmFrame` 기록.
- 철회(새 입력 요구) 조건:
  - 토큰이 바뀜(다른 단계·회차).
  - Completed 전 `Observe`(매 LateUpdate·장비 이벤트)에서 장비 상태 하나라도 무효.
  - Runner가 판정했는데 완료되지 않음(`frameCount > confirmFrame`이고 아직 Running). 수락 입력은 최대 다음 프레임 Tick까지만 유효하다.
- 거절된 클릭(`Unmet`)은 아무것도 저장하지 않는다. 장비가 회복돼도 자동 완료되지 않고 새 클릭이 필요하다.
- 새 회차 시작·RunId 변경 시 `ClearFacts`가 입력 상태·요약을 지운다.
- 중복 방지: 버튼은 클릭 처리 즉시 비활성, 대기 중이면 연결부도 무시. 양손·연속 클릭에도 수락 1회, Completed는 Runner가 1회만 낸다.
- 시작 전·실습 중·완료 후: 최종 확인 패널이 숨어 버튼이 레이를 받지 않고, `TryConfirm`도 `IsFinalCheckStep`이 아니면 무시한다.

## 6. 화면 전환과 텍스트 소유권

`TourniquetStartScreen`만 패널을 켜고 끈다(LateUpdate, 실행 순서 112 = Runner 0·연결부 106·표시부 110 뒤).

| 화면 | 조건 |
|---|---|
| 시작 | 시작 게이트가 Started가 아님 |
| 최종 확인 | `link.IsFinalCheckStep` |
| 완료 | `link.Summary != null`(이 회차 Runner Completed 뒤 연결부가 보관한 요약) |
| 실습 | 그 외(중단 포함) |

버튼 클릭이 화면을 직접 바꾸지 않는다. 완료 화면은 Runner Completed 확인 뒤에만 나온다.

| 텍스트 | 작성 주체 |
|---|---|
| StartPanel 전체 | TourniquetStartScreen |
| OperationPanel/Title·Instruction | TourniquetTrainingGuide |
| Notice, OperationPanel/Status·Detail | TourniquetStatusBoard |
| FinalCheckPanel/Title·Description·ItemsLeft·ItemsRight·Result·ConfirmButton/Label | TourniquetFinalCheck |
| CompletionPanel/Title·SummaryLeft·SummaryRight·Time·Note | TourniquetCompletionPanel |

- 최종 확인 항목 줄은 연결부 현재값(`충족/미충족 · 항목`). 결과 줄은 "장비 상태 검사 결과"임을 명시하고, 교육생 확인은 버튼 입력만이다. 시선·육안 확인을 측정한다고 표현하지 않는다.
- 미충족 시 결과 줄: 부족 안내 + 첫 미충족 항목의 복구 행동(`TourniquetTrainingGuide.RecoveryAction`). 거절 뒤 회복되면 "다시 선택" 안내.
- 시작 버튼 처리 전 표시부 확인 대상에 최종 확인·완료 컴포넌트를 추가했다(하나라도 동작하지 않으면 시작 거부, 장비 잠금 유지).

## 7. 완료 요약과 시간 기록

- Runner Completed가 된 프레임에 연결부 LateUpdate가 1회 보관: 장비 6개 상태(다시 읽음), 이 회차의 최종 확인 입력 여부, `operation.IsTimeRecorded`, `operation.RecordedElapsedSeconds`.
- 시간은 기존 부착 시점 기준 기록값이다. 기록 순간 고정되므로 완료 화면에서 증가하지 않는다. 현실 시각·완료 시각으로 바꾸지 않았고 `ElapsedSecondsSource`도 연결하지 않았다.
- 메모리에만 보관한다(다음 회차 시작 시 삭제). 파일·서버 저장 없음.
- 완료 뒤: 장비 자세·고정·시간 기록 유지. 자동 초기화·재시작·시작화면 복귀 없음. 장비 입력은 기존처럼 완료 후에도 허용(마지막 조작·놓기가 끊기지 않게).

## 9. 정적 검토

- 공통 Runner/Context 소스 대조: Runner Tick은 LateUpdate, 한 프레임 한 단계, 진입 다음 프레임부터 판정. State 조건은 TrainingTarget 현재값을 읽는다. Completed 시 `completed` 이벤트·로그 1회.
- 장비 코드 대조: 부착 후 이동 불가, 밴드 준비·막대 고정·시간 기록·마감은 한 번 참이 되면 유지된다. 회전량은 고정 전 회전 중에만 줄어든다. 따라서 최종 확인 단계에서 **일반 사용자 조작으로 장비 상태를 무효로 만드는 경로는 확인되지 않았다.** 미충족 안내·철회 경로는 `ResetToInitial()`·컴포넌트 비활성 같은 개발자 강제 조작에서만 재현될 것으로 본다.
- 컴파일·IDE 진단은 실행하지 않았다(VS Code 진단은 열린 파일만 대상이라 새 파일 결과 없음). 이름·참조·람다 오버로드는 직접 읽어 확인했다.
- 남은 점:
  - 새 스크립트 2개의 `.meta`는 Unity 임포트 때 생성된다.
  - 기존 씬은 메뉴 1 실행 전에는 시작화면·연결부 참조 부족으로 시작이 거부된다(장비 잠금 유지).
  - 새 패널 배치는 글꼴 지표 추정만 확인했다. 헤드셋 가독성은 미확인.
  - Runner 중단 시 화면은 실습 패널(중단 문구)로 돌아간다. 복구 UI는 없다.

| ⑤ | 확인 완료 선택 | `Final check input accepted` → `[Training] Completed` → `Completion summary kept` 로그 순서. 완료 화면 7개 항목 `수행`, 시간 = 시간 기록면·이전 Detail 값과 같은 MM:SS | 클릭만으로 화면 전환(Completed 로그 없음), 시간 불일치 |
| ⑥ | 연속 클릭·양손 동시 클릭, 완료 후 추가 입력 | accepted·Completed 각 1회, 완료 화면 유지 | 2회 이상, 화면 깜빡임 |
| ⑦ | 무효 상태: 일반 조작으로 무효화 가능한지 먼저 시도 | 일반 조작으로는 무효화 경로 없음이 예상(§9). 개발자 강제 조작(예: 장비 초기화)은 별도 구성 점검으로 기록: 완료 차단, `미충족` 표시·복구 안내, 회복 후 새 클릭 필요 | 무효 상태 완료, 이전 클릭으로 자동 완료 |
| ⑧ | 완료 화면에서 1분 이상 대기 | 시간 값 고정, 장비 상태 유지, 자동 초기화·시작화면 복귀 없음 | 시간 증가, 초기화 |
| ⑨ | Play 종료 후 재실행 | 시작 대기·장비 잠금, 최종 확인·완료 흔적 없음, 새 회차 run 1 | 이전 결과 잔존 |
| ⑩ | 메뉴 1 재실행 → 메뉴 2 | 패널·버튼·대상 중복 없음, 안내판 위치·사용자 조정 유지, 레이 대상 2개·저장 활성 1개 | 중복, 위치 변경, 숨은 패널 버튼이 입력 가로챔 |

Play 중 새 문구로 동적 TMP 폰트 자산이 git 변경으로 보일 수 있다(코드가 폰트를 수정하지 않음).

## 11. 후속 범위

다시하기: Runner 정지 → 잡기 종료 → `ResetToInitial()` → 연결부 회차 기록·입력·요약 초기화 → 장비 재잠금 → 시작 게이트 상태 복귀 → 시작화면. 그다음 과정 선택·복귀, 교육 시계 연결 여부 결정.
