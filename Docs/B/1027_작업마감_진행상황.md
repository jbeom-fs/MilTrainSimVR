## 3. 최종 조작 흐름 — 다음 작업 기준

1. 고정장치 조작점 가까이에서 선택 버튼을 새로 누른다. 해제 후 선택을 놓고 덮개 조작점을 다시 잡아 끝까지 연다.
2. 한 손으로 방독면 본체를 잡고 위로 꺼낸다. 완전 이탈 뒤에는 같은 손으로 자유롭게 옮기고 돌릴 수 있다. 놓으면 그 위치에 정지한다.
3. **본체를 한 손으로 잡고 있는 상태에서 다른 손으로 끈 조작점 하나만 잡는다.** 두 손이 각각 좌우 끈을 잡는 방식이 아니다. 시작할 때는 본체 손과 끈 손 모두 자기 대상의 그립을 유지한다.
4. 본체를 안정적으로 든 채 끈 손을 선택한 조작점의 펼침 경로에 맞춰 당긴다. 끈 전체가 점진적으로 펼쳐져 `Unfolding → Ready`가 되어야 한다. 시간 경과나 T 입력으로 자동 펼침을 하지 않는다.
5. 펼침 완료 후 본체를 얼굴 근처로 가져가면 얼굴 기준으로 부드럽게 스냅된다. 얼굴 임시 고정은 본체를 손으로 받치는 동작을 편의상 대신한다.
6. 얼굴에 붙은 뒤에는 본체 손을 놓아도 된다. 끈 하나를 잡은 **한 손**으로 위쪽·정수리·후두부 경로를 따라 넘긴다. 후두부 안착 시 `Worn`으로 고정되고 양손을 놓아도 머리를 따라간다.
7. 해제는 본체를 잡은 상태에서 Activate를 새로 누른다(Simulator의 T). 끈은 준비 자세로 돌아간다. 해제 직후 얼굴 앞에 남아 있어도 다시 붙지 않고, 얼굴에서 충분히 떼거나 돌린 뒤 재접근해야 스냅된다.

끈 조작 대상은 아무 끈 부분이 아니라 `StrapSelectPoint_L/R`(반지름 0.03m)이다. 어느 쪽 하나를 잡아도 된다. 최종 제어 손은 가장 최근 끈을 선택한 손 하나이며, 손 전환 시 기준을 다시 잡는다.

최초 펼침은 주머니와 충분히 떨어진 곳에서 확인한다. 주머니 경계와 펼친 끈 외곽이 겹치면 진행을 멈추며 `Unfolding paused …` 로그를 남긴다. 경로 허용 범위를 벗어나도 진행하지 않는다. **현재 미작동 원인이 입력·선택·공간 조건·경로 중 무엇인지는 확정되지 않았다.**

## 4. 유지할 구현과 설정

- 런타임: `Assets/B/Scripts/K1GasMask/`. Editor 구성 도구: `Assets/B/Editor/K1GasMask/`의 `K1GasMaskTrainingSetup` partial 파일들.
- 메뉴 1은 방독면 구성, 메뉴 2는 방독면·씬 검사, 메뉴 3은 주머니·수납·상호작용 구성, 메뉴 4는 주머니·수납·착용 연결 검사다. 재구성 시 기존 참조·조정값 보존 정책을 유지한다.
- 재질 저장은 해당 재질별 `SaveAssetIfDirty`만 수행한다. 검사 메뉴는 씬을 열거나 저장·수정하지 않는다. 대상 씬 검사를 못 하면 `NOT RUN / INCOMPLETE`이며 성공으로 기록하지 않는다.
- 씬의 방독면 검색은 비활성 포함 전체 계층의 Prefab 연결 인스턴스를 기준으로 한다. 수납 방독면은 1개다.
- 덮개 본 3개는 `K1CarrierFlapPose`, 머리끈 본 19개는 `K1MaskHarnessPose`만 쓴다. 본체는 자유 잡기 동안 XRI·`K1MaskExtraction`, 얼굴 고정 동안 `K1MaskWear`가 제어한다.
- 수납·추출은 접힌 머리끈 자세다. 방독면은 주머니 +Y 방향으로만 추출되고 9개 렌더 부품의 수납 외곽이 입구 평면 위 5mm를 넘어야 이탈한다. 예상 추출량은 약 0.247m다.
- 추출 시작 직전에 현재 해제·완전 열림을 재확인하고 덮개 닫힘 제한을 먼저 건다. 부분 추출 중 놓아도 제한은 유지하며 수납 복귀·완전 이탈 시 푼다.
- 좌우 끈 자기 경로는 각각 착용 101점·펼침 21점이다. 이전 양손 중점 경로나 T 펼치기·0.8초 자동 재생을 다시 적용하지 않는다.
- 얼굴 기준은 XR 카메라 아래 `K1_FaceReference`다. 기본 오프셋 `(0, -0.038, +0.018)m`, 스냅 0.08m/35°, 정렬 0.3초다. 재스냅 허용은 유효한 추적 상태에서 0.15m 밖 또는 55° 밖으로 벗어난 것을 관측한 뒤다. 실측·교육 합격 기준이 아닌 체험 설정이다.
- 머리끈 bounds는 지원 자세 322개를 BakeMesh한 범위에 각 면 0.02m 여유를 더해 계산한다. `harnessRenderer`·`boundsSpace`·`renderBounds`를 컴포넌트에 직렬화하고 `OnEnable`에서 Renderer에 적용한다. 기준은 현재 임포트의 `HarnessRoot` 공간이다. Editor에서 `localBounds`를 대입하고 Prefab 저장만으로 보존된다고 설명하지 않는다.
- 런타임 JSON 읽기·BakeMesh, 매 프레임 bounds 재계산, `updateWhenOffscreen` 강제 사용은 없다. 실제 화면에서 끈이 사라지지 않는지는 별도 사용자 확인 대상이다.

## 6. 남은 문제·제약과 우선순위

1. **최우선 — “줄이 당겨지지 않음” 확인.** 본체 선택·완전 이탈·끈 선택·공간 조건·손 경로를 순서대로 구분한다. 최종 방식의 정상 작동이 보고되기 전 완료 처리하지 않는다.
2. **착용 끝까지 확인.** 한 손 펼침 → 얼굴 스냅 → 같은 한 손으로 정수리 통과 → 후두부 안착 → 양손 놓기 → 고개 이동 → 명시적 해제·재접근을 확인한다. 최신 [착용 기록 11.3절](1027_K1_착용_얼굴스냅_머리끈_구현기록.md#113-한-손-끈-조작-정정-확인-2026-10-27)을 사용한다.
3. **정적 검토 참고 — 추출 재시작 시 손 이동 여유.** 현재 `K1MaskExtraction`은 후보 추출량이 1mm를 넘을 때만 닫힌 덮개를 확인하고 손 기준을 버린다. 수납 위치에서 잡은 채 덮개를 닫고 손을 아래로 내리면 후보량이 0으로 제한되어 이전 기준이 남을 수 있다. 다시 열어도 손을 이전 높이까지 올려야 추출되는 경로다. 덮개 관통과 별개이며 실행 재현·수정 완료는 확인되지 않았다. 이번 문서 작업에서 수정하지 않았다.
4. **화면·추적·도달 거리.** 끈 펼침·정수리·후두부·복귀에서 컬링, 관통, 가림, 손 전환·추적 복귀 시 튐, 얼굴 오프셋·렌즈 근거리 클리핑을 확인한다. bounds는 표본과 여유 기반이며 모든 연속 변형을 포함한다는 증명이 아니다.
5. **체험 구성의 제약.** kinematic 방독면·주머니는 상호 물리 반응이 없고 놓은 방독면에 중력·던지기가 없다. 재수납·재잠금은 구현 범위가 아니다. 정화통을 단 채 수납하는 구성이나 스냅이 실제 군 절차·밀착성·보호 성능 검증을 뜻하지 않는다.

끈 조임, 교육 단계 Runner·안내 UI·평가·점수·다시하기, 음성은 오늘 완료 범위가 아니다. 다음 기능은 별도 선택하며 자동 착수하지 않는다. 기존 AED 기능·문서도 오늘 범위에서 변경하지 않았다.

## 7. 다음 세션 시작 순서

1. `git status --short`로 현재 변경을 확인하고 보존한다. 이 문서의 커밋은 마감 시점 기준이다.
2. 사용자가 Unity Console의 최신 컴파일 오류 유무를 확인한다. 데이터 재구성이 필요할 때 메뉴 3을 `Keep existing`으로 실행한다. 오늘 최신 한 손 데이터 생성 기록은 이미 있으므로 무조건 미구성으로 단정하지 않는다.
3. `B_K1_Tutorial`에서 Simulator를 끄고 메뉴 2·4를 실행한다. FAIL·INCOMPLETE는 해당 항목을 구분한다.
4. 사용자가 PC Simulator에서 본체와 끈 **하나**의 그립을 유지해 펼치기를 확인한다. 안 되면 `Extracted` 여부, 실제 선택 대상·선택 유지, `Unfolding paused` 로그, `UnfoldProgress` 변화를 먼저 확인한다. 버튼 입력과 경로 제한을 구분하기 전 원인을 단정하지 않는다.
5. 펼침이 되면 착용·고정·해제까지 이어 확인하고 결과를 기록한다. 필요 수정은 사용자 요청 시 한국어 자연어 구현 프롬프트로 작성한다. 에이전트는 코드를 직접 수정하지 않는다.
6. Quest 2 + Link는 사용자 방침에 따라 전체 기능 구현 후 별도 수행한다. PC Simulator 통과를 실기 통과로 기록하지 않는다.
