# ABC 공통 VR 메뉴 — 구현 기록·설치 안내

작성: 2026-11-17. 기준 HEAD `c7346bb`. 이번 세션에 한한 사용자의 직접 코드 수정 허가로 중단된 작업을 이어 구현했다. **후속 사용자 보고로 메뉴 UI 작동은 확인됐다. 최신 레이·원형 포인터 표시 수정의 컴파일·VR 가시성 및 A/C 연계 결과는 아직 확인 전이다.** 상세 피드백 이력은 §8에 구분했다.

## 1. 결과와 적용 범위

재사용 프리팹: [`Assets/B/Prefabs/CommonMenu/CommonPauseMenu.prefab`](../../Assets/B/Prefabs/CommonMenu/CommonPauseMenu.prefab).

- Quest 2 왼손 메뉴 버튼으로 열기. 오른손 시스템 버튼은 사용하지 않는다.
- 기능 버튼은 **계속 / 메인으로 / 게임종료** 3개다. 메뉴 버튼을 다시 눌러도 계속과 같은 경로로 닫는다.
- 열 때 게임 시간·일반 오디오·XRI 이동을 보류한다. 머리와 컨트롤러 추적, 메뉴 레이, UI 입력은 계속 동작한다.
- 계속을 선택하면 버튼을 비활성화하고 해제 안내를 표시한다. 양손 트리거·그립, 왼손 메뉴 버튼을 놓고 양손 스틱을 중앙으로 돌려야 재개된다. HMD·양손 추적과 앱 포커스도 필요하다. 입력 해제가 한 프레임 동안 처리된 뒤 메뉴를 숨기고 재개한다.
- 메인으로는 기존 A `CourseRoute.ReturnToHub()`를 읽기 전용으로 재사용하여 `A_Hub`으로 복귀한다. 이미 허브면 해당 버튼만 비활성화한다. 허브를 로드할 수 없으면 메뉴를 유지하고 안내한다.
- 게임종료는 빌드에서 `Application.Quit()`, 에디터에서 Play 종료다. 재시작·설정·확인 팝업은 추가하지 않았다.

실제 배치는 B 운영 씬 **`B_FirstAid`, `B_CBRN`** 각 1개다. B 개별 장비·교육 씬과 A/C 씬에는 자동 배치하지 않았다. **공통 사용 가능한 프리팹 완성과 A/C 콘텐츠의 일시정지 연계 완료는 별개다.** A/C의 직접 입력·AI·발사·비동기 처리는 해당 담당자가 아래 인터페이스에 연결해야 한다. C의 기존 왼손 메뉴 다시하기 삭제도 C 담당 범위로 유지했다.

## 2. 다른 씬에 설치

1. 프리팹을 대상 씬 루트에 1개 배치한다. 루트와 상위 객체 배율은 1로 유지한다. `DontDestroyOnLoad`는 사용하지 않는다. 씬을 나가면 제거되고 다음 씬에서 그 씬의 프리팹을 사용한다.
2. 활성 `XROrigin`이 하나면 자동 탐색한다. 여러 개라면 `CommonPauseMenu.xrOrigin`에 해당 씬의 리그를 Inspector로 지정한다. 리그 자체를 B 리그로 교체할 필요는 없다.
3. HMD 카메라와 양손 컨트롤러에 Input System `TrackedPoseDriver`가 필요하다. 위치·회전·Tracking State 액션이 활성·바인딩되어 있어야 한다. 양손 interactor의 `handedness`가 Left/Right로 지정되어야 한다.
4. 활성 EventSystem은 하나, `XRUIInputModule`의 XR Input은 켜져 있어야 한다. 없으면 메뉴가 하나를 생성한다. 기존 EventSystem이 호환되지 않거나 중복이면 로그를 남기고 메뉴 열기를 거부한다. 기존 것을 임의 삭제하지 않는다.
5. 프리팹의 글꼴·패널·글꼴 Overlay·레이 재질 참조를 유지한다. 화면은 `Awake`에서 한 번 생성되므로 편집 모드 프리팹에는 루트 컨트롤러와 허브 경로 컴포넌트만 보인다. 시작할 때 `PausePanel`과 3개 버튼이 생성된다.
6. A/C의 별도 메뉴키 바인딩을 중복 사용하지 않는다. 시스템이 먼저 소비하는 입력은 이 메뉴에서 강제로 회수할 수 없다.
7. 실제 빌드의 Scene List에 `Assets/A/Scenes/A_Hub.unity`가 있어야 한다. 에디터에서는 A 경로 클래스의 기존 대체 로드가 가능하므로, 에디터 복귀 성공만으로 빌드 설정 완료로 판단하지 않는다.

메뉴를 코드로 생성해야 한다면 이 프리팹을 직렬화 참조하여 `Instantiate`하고 씬에 한 개만 유지한다. 활성 메뉴가 이미 있으면 추가 인스턴스의 컨트롤러는 비활성화된다. 파일을 A/C 아래에 복사하여 메뉴 코어를 중복 정의하지 않는다.

## 3. A/C 콘텐츠 일시정지 연결

코어 네임스페이스·어셈블리: `MilTrainSimVR.B.CommonMenu`.

콘텐츠의 활성 MonoBehaviour에 `ICommonMenuListener`를 구현하고 해당 asmdef에 코어 참조를 추가한다. 메뉴를 열 때 활성 리스너를 수집한다. 메뉴가 열린 뒤 새로 생성되는 콘텐츠는 생성 측에서도 `CommonPauseMenu.IsPaused`를 확인해야 한다.

| 연결점 | 콘텐츠 담당 동작 |
|---|---|
| `OnCommonMenuPaused()` | 기존 상태를 보관하고 AI·발사·직접 입력·unscaled 진행·포털 전환을 보류한다. 잡은 물건 선택을 강제로 취소하지 않는다. |
| `OnCommonMenuResumed()` | 보류 이전 상태를 복원한다. 손 입력 기준점을 다시 잡고, 메뉴 중 입력으로 발사·단계 완료·자동 부착이 실행되지 않게 한다. |
| `OnCommonMenuLeaving()` | 씬 이동/앱 종료 전 처리. 계속용 초기화나 교육 재시작을 하지 않고 보류를 유지한다. |
| `CommonPauseMenu.IsPaused` | 메뉴 표시·입력 해제 대기·종료 전 상태에서 true. 매 프레임 직접 입력을 읽는 코드에서 보조 차단에 사용한다. |

MonoBehaviour 외부에서는 `Paused`, `Resumed`, `Leaving` 정적 이벤트도 사용할 수 있다. 구독한 쪽에서 반드시 해제한다. 일반적으로 인터페이스 하나로 연결하면 충분하다. 이 프리팹은 OVRInput을 직접 읽는 발사/다시하기 코드, unscaled Update, 네트워크·외부 비동기 작업까지 자동으로 멈추지는 않는다.

Paused는 시간·오디오 보류 후, 메뉴 표시 전 호출한다. Resumed는 입력 차단 복원 후, 원래 시간·오디오 복원 전 호출한다. Leaving 뒤 정상 씬 이동/종료에는 Resumed를 보내지 않는다. 동기 허브 이동 중 예외가 나면 콘텐츠를 보류한 채 메뉴를 다시 표시하며, 이후 계속에서는 Resumed가 온다. 연결 컴포넌트는 Leaving에서 되돌릴 수 없는 데이터 삭제를 실행하지 않는다.

메인 경로는 프리팹의 `CommonMenuHubRoute`다. 코어는 A/C 교육 어셈블리를 참조하지 않는다. 허브 어댑터만 기존 `MilTrainSimVR.A.Common`을 참조한다. 경로를 교체한다면 `CommonMenuMainRoute`의 **동기 로드 계약**을 지킨다. 비동기 전환을 지원한다고 간주하지 않는다.

### 3.1. A/C 담당자가 연결할 파일·역할

| 목적 | 참조할 B 파일 또는 타입 | 대상 씬 담당자의 작업 |
|---|---|---|
| 메뉴 프리팹 설치 | `Prefabs/CommonMenu/CommonPauseMenu.prefab` | 씬 루트에 배치하고 리그 지정 |
| 일시정지 인터페이스 | `Scripts/CommonMenu/ICommonMenuListener.cs` | 기존 교육/전투 관리 컴포넌트 또는 해당 씬 전용 어댑터에서 구현 |
| 직접 입력 차단 | `CommonPauseMenu.IsPaused` | OVRInput·InputAction 콜백·Update에서 발사, 다시하기, 장비 조작, 포털 진입 전에 확인 |
| 허브 복귀 | `Scripts/CommonMenu/Hub/CommonMenuHubRoute.cs` | 기존 참조 유지, A_Hub 빌드 등록 확인 |
| B 연결 예시 | `Scripts/TrainingField/TrainingFieldCoordinator.cs` | 기존 로컬 보류와 공통 메뉴 보류를 별도로 보관하는 방식 참고 |
| 입력 복원 예시 | `Scripts/Interaction/BControllerInputActionManager.cs` | UI 복원 후 새 hover 상태가 덮이지 않도록 콜백 시점 참고 |

리스너를 구현하는 담당자 코드는 각자의 A/C 폴더에서 관리한다. 해당 코드가 asmdef 아래라면 그 어셈블리의 References에 **`MilTrainSimVR.B.CommonMenu`**를 추가한다. 메뉴 코어에 A/C 전투·교육 어셈블리 참조를 추가하지 않는다. 기본 허브 어댑터를 그대로 쓰면 콘텐츠 쪽에서 `MilTrainSimVR.B.CommonMenu.Hub` 타입을 직접 참조할 필요는 없다.

- **일시정지 진입:** 리스너 자신과 리그·EventSystem을 비활성화하지 않고 콘텐츠 진행 플래그를 보류한다. 메뉴는 열린 시점의 활성 리스너를 저장하므로 이 컴포넌트가 재개 콜백을 받을 수 있어야 한다.
- **기존 보류와 겹침:** 메뉴 진입 전부터 열려 있던 교육 중단창·별도 보류 상태를 기억한다. 메뉴를 닫는다고 모든 콘텐츠를 무조건 실행 상태로 만들지 않는다.
- **계속:** 기존 보류 상태로 복원하고, 손의 현재 자세로 장비 조작 기준점을 다시 잡는다. 메뉴 중 놓은 물건의 놓기 동작이나 누른 발사 입력을 뒤늦게 실행하지 않는다.
- **메인/종료:** Leaving 이후 교육을 다시 시작하지 않는다. 허브 전환이 실패하면 메뉴가 다시 표시될 수 있으므로 여기서 장비·저장 데이터를 되돌릴 수 없게 삭제하지 않는다.
- **추가 생성물:** 메뉴 중 생성되는 AI/장비/타이머는 생성 시 `IsPaused`를 확인하고 같은 보류 상태를 적용한다. 이미 예약된 발사·이동·비동기 완료 처리도 담당 코드에서 중지/보류한다.

## 4. 입력·시간·오디오 처리

- 메뉴가 소유하는 런타임 InputAction에 `<XRController>{LeftHand}/{MenuButton}`을 바인딩한다. 양손 트리거·그립·스틱도 전용 액션으로 읽는다. 공용 입력 원본과 B 입력 사본은 수정하지 않는다.
- 양손 컨트롤러 아래에 메뉴 전용 `XRRayInteractor`를 임시 생성한다. Interaction Layer Mask를 0으로 두어 물건 선택/활성화를 막고, Raycast Mask는 UI 레이어(5)만 포함한다. 메뉴 배경·버튼·라벨도 UI 레이어로 생성한다. 기존 손의 잡기 선택 때문에 메뉴 클릭이 막히지 않도록 리그의 기존 Interaction Group 밖에 둔다. 메뉴를 닫으면 제거한다.
- 처음 열 때 눌려 있던 트리거, 추적/포커스 복구 시 계속 눌린 트리거는 먼저 놓아야 메뉴 클릭에 사용된다.
- 기존 XRI 선택에는 필터를 추가한다. 기존 장비 잡기는 유지하고 새 선택은 막는다. 선택 중이던 텔레포트 지점은 일반 놓기 대신 취소로 해제한다.
- 켜져 있던 LocomotionProvider만 끈 뒤 원상 복구한다. 기존 interactor의 활성화 입력 리더를 잠시 Unused로 바꾸고 원래 객체 참조를 복원한다. 기존 Near-Far/Ray/Poke의 UI 처리와 다른 Canvas 입력도 보류 후 복원한다.
- `Time.timeScale`, `AudioListener.pause`는 열기 직전 값을 저장한다. 계속·컨트롤러 비활성화·정상 메인 이동·종료 경로에서 복원한다. timeScale을 무조건 1로 만들지 않는다. `ignoreListenerPause`를 사용하는 오디오·외부 시스템은 콘텐츠 리스너 담당이다.
- 지연된 텔레포트 요청이나 자체 이동 큐를 쓰는 씬은 콘텐츠 연계에서 해당 요청도 취소해야 한다. XRI의 이미 큐에 들어간 요청을 삭제하는 공개 API가 없으므로 이 코어가 모든 사용자 정의 이동 큐를 지운다고 보장하지 않는다. B 기본 리그는 지연값 0인 기존 구성을 유지한다.

## 5. B 연결

`TrainingFieldCoordinator`가 공통 리스너를 구현한다. 공통 메뉴 보류와 기존 교육 중단 확인 보류는 별도 상태다. 공통 메뉴를 열면 모든 station의 기존 `SetHeld`·`HoldPhysics` 경로를 사용하고, 닫을 때 기존 중단 확인이 열렸던 station은 보류를 유지한다. 보류 중에는 시작·중단·종료·입구 처리와 완료 판정 갱신을 진행하지 않는다.

`RunnerFieldCourse`는 완료된 장비도 Suspended에 포함한다. Runner의 Held는 기존처럼 Running일 때만 설정한다. `TrackedGrabHold`는 메뉴 중 손 입력을 추적 소실과 같은 자세 유지·복구 기준점 경로로 처리한다. `BControllerInputActionManager`는 메뉴 중 텔레포트 조준과 기존 UI hover 입력 처리를 막고 재개 시 스틱 역할을 복원한다.

B 개별 교육 씬은 Coordinator가 없으므로 프리팹만 추가해서 운영 씬과 같은 교육 보류가 완성된다고 보지 않는다. 해당 씬의 장비·과정 SetHeld를 연결하는 리스너가 추가로 필요하다.

## 7. 파일·백업·정적 확인

새 코드: `Assets/B/Scripts/CommonMenu/`의 코어·UI·입력 차단·포인터·문구·인터페이스·경로와 `Hub/` 어댑터, asmdef 2개 및 meta. 새 프리팹: `Assets/B/Prefabs/CommonMenu/`.

원본 백업: `Assets/B/Models/TrainingDisplay/Source~/Backups/20261117_before_common_menu/`. 중단 시점의 3개 스켈레톤 파일을 재사용했다. 추가 기존 코드 원본은 HEAD에서 백업했다. 스테이징·커밋·Push는 하지 않았다.

정적 확인은 새 자산 meta·GUID 중복, prefab 내부 fileID, 씬의 추가 instance/root와 원본 diff, 어셈블리 JSON·순환 참조, 로컬 설치 XRI/Input System API를 대상으로 한다. 씬의 기존 패키지 GUID는 패키지 meta 또는 작업 전 씬과 구분해서 판독한다. 정적 확인은 컴파일/임포트/실행 통과 근거가 아니다.

구현 직후 정적 확인 결과: 새 코드/asmdef/프리팹 11개 모두 meta가 있고 GUID 중복이 없다. 프리팹·두 씬의 중복 fileID는 0개다. 당시 두 씬은 메뉴 instance·stripped Transform·SceneRoots 항목을 제거하면 HEAD 원본과 일치했다. 새 외부 참조는 모두 meta로 확인했으며 Unity 내장 리소스 GUID 2종은 별도로 구분했다. 프로젝트 asmdef JSON 파싱·어셈블리 순환 참조 0개, 추적 diff의 B 외 경로 변경 0개를 확인했다. 이후 사용자 확인 과정에서 관찰한 글꼴·B_CBRN 추가 저장 diff는 보존했으며, 위 원본 일치 결과를 현재 작업 트리 전체에 확대하지 않는다.

## 8. 사용자 실행 확인

후속 컴파일 오류 보고: `CommonMenuInputGate.cs:39`에서 `CancelInteractableSelection(XRBaseInteractable)`의 CS0619가 발생했다. 인수를 `IXRSelectInteractable`로 명시 변환해 현행 오버로드를 선택하도록 수정했다. 설치된 XRI 소스의 인터페이스 시그니처를 대조했으며 수정 후 Unity 재컴파일 결과는 아직 확인 전이다.

후속 실행 피드백: 메뉴는 표시되지만 상호작용되지 않는다고 사용자가 보고했다. `CommonMenuPointer`의 `raycastMask=0`이 원인인 코드 경로를 확인했다. XRI `XRRayInteractor.UpdateUIModel`은 같은 마스크를 `model.raycastLayerMask`에 전달하고 `TrackedDeviceGraphicRaycaster.ShouldTestGraphic`이 UI의 레이어와 비교하므로, 0이면 모든 UI Graphic이 제외된다. 메뉴 배경·버튼·라벨을 Unity 기본 UI 레이어(5)로 생성하고 메뉴 레이의 마스크도 해당 레이어로 맞췄다. Interaction Layer Mask 0과 기존 콘텐츠 입력 차단은 유지했다. 코드 경로 정적 대조 완료, 수정 후 양손 hover·트리거 클릭의 실제 결과는 사용자 확인 전이다. Play를 종료한 뒤 재실행해야 새로 생성된 메뉴/레이에 반영된다.

후속 사용자 확인: **메뉴 UI 작동은 확인됐으나 레이·포인터가 보이지 않는다고 보고했다.** 기존 레이 Renderer는 기본 표시 순서 0이고 메뉴 Canvas는 31000이어서 Overlay 셰이더여도 메뉴에 덮일 수 있는 구성이었다. 레이를 메뉴 앞인 31001로 올리고, 31002의 원형 포인터를 UI hit 위치에 추가했다. 두 표시 모두 UI 레이어에 두고, 기존 Overlay 재질의 런타임 사본만 Queue 4010·흰색 기반으로 사용한다. 버튼을 가리키면 하늘색, 트리거를 누르는 동안 노랑, 버튼 외에는 밝은 회색이다. 포인터에는 collider/Graphic이 없어 UI 판정을 가로채지 않는다. 추적/포커스 상실·메뉴 숨김 때 표시도 끄며, 닫을 때 생성 객체와 재질 사본을 제거한다. 기존 공유 재질·글꼴·다른 씬은 수정하지 않았다. 변경 전 두 소스는 백업 아래 `followup_pointer_visibility/`에 보관했다. **표시 수정 후 컴파일·VR 가시성은 아직 사용자 확인 전**이다. Play 재실행 후 양손 선·원형 포인터·버튼 hover/누름 색과 기존 클릭을 확인한다.

1. Unity 임포트·컴파일 오류와 Missing Script/참조가 없는지. 운영 씬마다 메뉴 1개, EventSystem 1개인지.
2. Quest 2 왼손 메뉴 버튼 단일 누름으로 한 번 열리고, 오른손 시스템 버튼은 Meta 동작을 유지하는지. 메뉴 버튼 재누름으로 계속이 되는지.
3. 양손 각각 레이·트리거로 3개 버튼을 누르는지. 양손 장비 잡기, 메뉴 진입 시 트리거 누른 상태에서도 자동 클릭이 없는지.
4. 메뉴 중 이동·회전·텔레포트·새 장비 선택·기존 보드 클릭·활성화가 막히는지. 조준 중 열기→스틱 놓기→계속에서 텔레포트가 뒤늦게 실행되지 않는지.
5. 계속 클릭 후 입력 해제 안내가 보이고, 버튼·스틱 해제 후 재개되는지. 메뉴 클릭이 AED 부착·교육 완료·장비 조작으로 전달되지 않는지.
6. B 6개 교육에서 진행·판정·물리·소리가 보류되는지. 지혈대/덮개/감기 도중과 완료 후 장비, 양손 물건 놓기·재잡기도 확인한다.
7. 기존 ‘교육 중단’ 확인창→공통 메뉴→계속에서 기존 확인창과 보류가 유지되고, 그 확인창의 계속/중단은 정상 동작하는지.
8. 메뉴 중 추적 소실·앱 포커스 상실·복구에서 자동 클릭/재개가 없고 복구 후 입력 해제로 계속할 수 있는지. 메뉴 컨트롤러 비활성화 시 시간·오디오·입력 설정이 복원되는지.
9. 열기 전 timeScale 0.5 또는 AudioListener.pause=true였던 상태가 계속 뒤 그대로 복원되는지. 일반 게임 소리와 별도 ignoreListenerPause 소리는 분리 확인한다.
10. 메인 복귀 시 A_Hub이 정상 로드되고 시간·오디오가 남지 않는지. 허브 미등록 빌드에서는 안내와 메뉴 보류가 유지되는지. 게임종료는 실제 Quest 빌드에서 종료되는지.
11. A/C 담당자 연계 후 허브→A/B/C→허브 왕복, 발사/AI/타이머·포털·자체 큐를 포함해 확인한다. 프리팹 재사용 가능만으로 A/C 실행 검증 완료를 보고하지 않는다.
