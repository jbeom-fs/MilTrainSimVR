### 2.2 감기 전 확인의 입력 순간 상태 판정 — 정적 코드상 가능 경로

- `Tutorial/PressureBandageTrainingLink.cs`의 `CanConfirmCheck`(220행 이후)·`TryConfirmCheck`는 `IsHoldValid`, `IsPlacementValid`, `InputFocused`를 읽는다.
- 이 값은 `PressureDressing.LateUpdate` → `Refresh`(191행 이후)에서 갱신된다. 버튼 입력은 Update에서 처리되므로 직전 LateUpdate의 값으로 수락될 수 있다.

- 사용자 확인: 정상 유지 입력은 수락, 놓기·추적 소실·배치 이탈과 겹친 입력은 거부되고 나중에 자동 적용되지 않아야 한다. 실행 재현은 아직 없다.

## 3. 확인 범위와 남은 확인

- 검토자는 보고서·소스·기존 로그를 읽었다. Unity 실행, 메뉴 실행, Play, Simulator, 헤드셋, 테스트·빌드를 수행하지 않았다.
- 기존 로그에는 메뉴 실행 및 FAIL 결과가 있다. 이를 최신 모든 파일의 컴파일 성공이나 교육 완주 성공으로 확대하지 않는다.
- 시작 잠금, 적용 취소 시 전후 확인 철회, 완료 후 다시하기 연결에서 추가 필수 수정 사항은 찾지 못했다. 이는 실행 통과 판정이 아니다.
- 3챕터 전체 수행, 감기 전후 확인, 적용 취소 후 복구, 완료 요약, 완료 후 다시하기, 반복 회차, 표식 가독성은 사용자 확인이 필요하다. 상세 절차는 구현 기록 §14 ①~⑩.
- 제품·감기 방향·회전 수·겹침·고정법·시간·허용오차는 개발 기준이다. 실제 압박력·혈류·지혈 성공 판정 기능은 없다. 제품·교안 확정은 별도 후속이다.
