# Windows PC VR 빌드 크래시 분석 — 2026-11-19

상태: **기존 크래시 덤프 7개에서 DirectX 12 네이티브 충돌 위치를 확인했고, 사용자가 DX11 실행 시 크래시 없이 실행됨을 보고했다. DX11 우회 효과는 사용자 확인 완료다.** Unity 공식 이슈 UUM-140564와 호출 스택이 일치한다. 에이전트는 게임·Unity·테스트·빌드를 실행하지 않았으며 프로젝트 코드·씬·설정은 변경하지 않았다. 공용 Windows Graphics API 고정과 재빌드는 아직 수행하지 않았다.

## 3. 원인 판단

**직접 충돌 위치는 Unity DX12 임시 버퍼 해제/회수 경로로 확인됐다. 알려진 Unity 엔진 결함과 일치할 가능성이 높다.**

Unity 공식 [UUM-140564: Crash in Release builds in ScratchAllocator::ReleaseExcessScratch](https://issuetracker.unity.com/issues/10698)는 6000.3.11로 변경한 팀들의 보고와 함께 DestroyScratch → ReleaseExcessScratch → ReclaimMemory → QueueExecute → FlushInternal → EndCurrentRenderSubPass → EndRenderPassImpl → 그래픽 작업 스레드의 같은 경로를 제시한다. 해당 이슈는 중복으로 닫힌 상태다. 이 사실을 현재 프로젝트의 해결 완료나 특정 패치 버전의 해결 보장으로 확대하지 않는다.

손 모델 추가가 그래픽 리소스 사용량·타이밍에 영향을 줬을 가능성은 남아 있지만, 덤프에 ControllerHandPose나 장갑 표시 코드의 직접 오류를 지목하는 근거는 없다. 어떤 자산 업로드가 촉발했는지는 현재 덤프만으로 확정하지 않는다. 손 적용용 Editor 도구 삭제를 원인으로 판단할 근거도 없다.

화생방 로드 때 출력되는 Camera.stereoTargetEye / SRP 메시지는 별도 경고다. 그 메시지가 없는 허브 시작 기록에서도 같은 DX12 함수가 충돌하므로 현재 주원인으로 확정하지 않는다.

## 4. 사용자 비교 실행

재빌드·프로젝트 변경 없이 기존 실행 파일을 DX11로 실행해 비교한다. PowerShell에서 사용자가 직접 실행한다.

```powershell
& "D:\TeamProject\Build\2026_11_19\MilTrainSimVR.exe" -force-d3d11 -logFile "D:\TeamProject\Build\2026_11_19\Player_DX11.log"
```

`-force-d3d11`은 Direct3D 11 렌더링을 강제하는 Unity 공식 실행 인자다. 근거: [Unity 6000.3 플레이어 실행 인자](https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/command-line-arguments/player).

확인 순서와 기준:

1. Quest Link를 연결한 같은 환경에서 실행하고 새 Player_DX11.log가 Direct3D 11 사용을 기록하는지 확인한다. DX11을 사용할 수 없다고 나오면 비교 실행은 성립하지 않는다.
2. 허브 → 화생방 진입, 화생방 내 이동·장비 조작·거울 보기, 허브 복귀, 구급법 진입을 확인한다.
3. DX12에서 종료됐던 경로를 반복해 종료가 사라지는지 확인한다. DX11 정상 시 DX12 경로의 문제라는 판단이 더욱 강해진다. 한 번 성공을 장시간 안정성 검증으로 확대하지 않는다.
4. DX11도 종료되면 Player_DX11.log와 새 덤프를 별도 분석해 같은 충돌인지 다른 문제인지 구분한다.

DX11에서 정상 동작하면 Windows 빌드 Graphics API를 Direct3D11로 고정하는 방안을 우선 검토한다. 이는 ProjectSettings의 공용 변경이므로 현재 분석 요청에서 적용하지 않았다. 장기적으로 엔진 패치 검토도 가능하지만, 공식 해결 내용 확인과 팀 버전 합의를 거쳐야 한다.

이번 작업은 로그·덤프·소스·설정 읽기와 B 문서 기록뿐이다. DX11 실행·재빌드·설정 변경·수정 코드 작성·스테이징·커밋·Push는 하지 않았다.

## 5. 사용자 DX11 실행 결과

2026-11-19 사용자는 안내한 DX11 실행 후 “크래시 없이 실행됨”을 보고했다. 기존 DX12 충돌 덤프와 함께 보면 이번 문제를 DX12 렌더링 경로로 좁힐 수 있으며, DX11 실행을 우회 방법으로 사용할 근거가 확보됐다.

새 DX11 로그를 별도로 읽어 확인한 것은 아니며, 사용자 보고를 각 교육과정 완주·반복 씬 전환·장시간 안정성 검증 완료로 확대하지 않는다. 특정 자산이 엔진 결함을 촉발했는지와 UUM-140564와의 동일 결함 여부는 여전히 추정이다.

후속 권장 사항은 다음 Windows 배포 빌드에서 Graphics API를 Direct3D11로 고정하는 것이다. 현재 공용 ProjectSettings는 변경하지 않았다. 이 설정을 적용하기 전에는 기존 실행 파일에 `-force-d3d11` 인자를 사용한다. 손 모델·장갑 표시 코드를 되돌릴 추가 근거는 확인되지 않았다.
