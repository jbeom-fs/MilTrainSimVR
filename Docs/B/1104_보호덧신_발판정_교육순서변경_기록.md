# 보호덧신 발·발목 판정 이전과 보호의 교육 순서 변경 (2026-11-04)

> **마감 검토:** 구현 후 실제 코드 정적 검토에서 미해결 3건을 남겼다. §10이 점 삭제 후 새 기본값 복구 안내와 검사 PASS의 해석보다 우선한다. 새 변경은 여전히 미컴파일·미실행·미커밋이다. 재개는 [1104 마감](1104_작업마감_진행상황.md)을 따른다.

상태: **코드 수정 완료. 컴파일·메뉴 1~4·Play·Simulator·헤드셋은 모두 미실행(사용자 확인 대상). 미커밋.** 이전 구현은 사용자가 검증한 뒤 `255d254`로 커밋했고, 이번 작업은 그 위의 변경이다. 이전 기록의 '미확인' 표시는 당시 상태이며 현재 상태가 아니다.

범위: 보호덧신(코드·UI 이름 `Overboot`, 화면 표기 '덮개') 착용 영역을 허벅지 앞에서 발등·발목으로 옮기고, 교육 순서를 바꿨다. 다른 장비, 공통 Training, Packages, ProjectSettings, Blender 원본·FBX·임포트 설정·GUID·본·bindpose·형상·가중치는 바꾸지 않았다.

## 2. 발 판정 정의

- **형태**: 기존 구 판정을 그대로 쓴다. 새 형태는 도입하지 않았다.
- **부모 본**: 같은 쪽 `mixamorig1:LeftFoot` / `RightFoot`(발목 관절). UserBody가 이 본을 추정 발 위치와 몸 방향으로 매 프레임 놓으므로 영역도 함께 움직인다.
- **위치(본에서 계산, 월드 좌표·고정 바닥 높이 미사용)**
  - 수평: 발목(Foot)과 발볼(ToeBase)의 중점, 즉 발등 위.
  - 수직: 발목 높이 + 0.075 × (무릎 높이 − 발목 높이).
  - 메뉴가 이 위치를 발 본의 로컬 오프셋으로 저장한다(실제 로컬값은 메뉴 로그와 메뉴 2·4 검사 줄에 표시).
- **크기**: 반지름 0.14 m(월드, 미터).
- **선정 근거**: 마네킹 바인드 자세, Blender `ReferenceInspection.json`, 1.77 m 기준.

| 대상 | 값 | 영역 중심과의 관계 |
|---|---|---|
| 발목(LeftFoot head) | (0.152, 0.031, 0.099) | 0.07 m: 안 |
| 발볼(LeftToeBase head) | (0.163, −0.102, 0.008) | 0.14 m: 경계 |
| 영역 중심 | 약 (0.158, −0.036, 0.130) | 바닥 위 0.13 m |
| 영역 위끝 | 약 0.27 m | 정강이 하단 |
| 무릎(LeftLeg head) | 높이 0.518 | 0.39 m: 밖 |
| 반대쪽 발 영역·발 | 좌우 발목 간격 0.30 m | 0.31 m: 밖, 두 영역 겹치지 않음 |
| 착용 Worn 덧신 | 높이 0.006~0.293, Attach 0.105 | 영역과 대체로 같은 높이대 |
| 덧신 Pickup Attach | Grip보다 0.034 m 아래 | 잡은 손과 거의 같은 위치로 판정 |

- **판단**: 덮개를 잡은 손을 발등·발목 주변(바닥 위 약 0~27 cm 높이, 발 앞뒤 ±14 cm)으로 가져가면 착용된다. 바닥 아래로 내릴 필요가 없다. 허벅지·무릎·허리와 반대쪽 발은 밖이다.
- **반지름**: 0.14보다 크게 하면 좌우 영역이 가까워지고(간격 0.31 m) 위끝이 정강이 중간으로 올라가므로 넓히지 않았다.
- **실행 시 축척**: 눈높이 1.6 m면 몸 축척이 약 0.96~0.97이라 본 거리는 줄지만 반지름은 그대로다. 메뉴 2·4가 저장 자세와 실행 축척 양쪽에서 검사한다.

## 3. 추정 발 위치 — 정적 확인

`ProtectiveClothingUserBody.Solve`:
- 몸 루트 = (HMD 수평 위치 − 휴식 눈 수평 오프셋, 바닥). 방향은 머리 방향을 0.3 s로 따라간다. 발은 몸 루트 기준 휴식 위치에 놓인다(`SolveLeg`). 발 회전은 몸 방향만 따른다.
- **몸을 앞으로 숙이기**: 머리가 수평으로 이동한 만큼 몸 루트와 추정 발, 덮개 영역이 함께 앞으로 간다. 실제 발은 그대로이므로 영역이 실제 발보다 앞에 생긴다. 고리가 영역을 표시하므로 고리를 보고 가져가면 된다.
- **고개만 내리기**: 수평 이동이 작으면 발 위치 변화도 작다. 거의 수직으로 내려다보면 마지막 방향을 유지한다.
- **웅크리기**: 골반만 내려가고(최대 0.6 m) 발은 제자리다.
- **방향 전환**: 몸 방향이 머리를 따라 돌므로, 고개만 돌려도 0.3 s에 걸쳐 발과 영역이 눈 아래 축을 중심으로 회전한다.
- **영향 범위**: 기존 추정 방식에서 오던 문제로, 덮개 영역뿐 아니라 착용된 하의·덧신 표시와 거울 속 다리 모습에도 같은 영향이 있다. 이번 범위에서는 고치지 않았고, 허벅지 판정을 남기거나 영역을 다리 전체로 넓혀 감추지도 않았다. 실제 발 추적이 아니며, 화면과 문서에도 추정으로 표기한다.

## 4. 기존 씬 이전 (메뉴 1·3 공통, `EnsureUserBody` 안)

메뉴 1과 메뉴 3은 같은 몸 구성 함수를 쓴다. 영역 점 `PC_Zone_Overboot_L/R`마다 다음 순서로 처리한다.
1. 점이 없으면 발 본 아래 새 기본값으로 만든다(반지름 0.14).
2. **이전 생성값과 정확히 같으면 1회 이전**한다. 조건은 아래를 모두 만족하는 것이다.
   - 부모가 같은 쪽 `UpLeg`
   - 월드 위치가 이전 공식(엉덩이~무릎 중간 + 앞 0.12 + 바깥 0.07 m)과 0.1 mm 안
   - 로컬 회전 0, 축척 1, 자식 없음, Transform 외 구성 요소 없음
   - 반지름 0.12
   
   이전하면 발 본 아래로 옮기고, 위치는 발 기준으로 다시 계산하며, 반지름은 0.14로 바꾼다.
3. 이미 발 기본값이면 유지한다. 재실행해도 다시 움직이지 않는다.
4. 그 밖은 사용자 조정값으로 보고 **유지**한다. 로그에 현재 부모·위치·반지름과 손으로 옮길 목표(발 본, 새 기본 위치, 반지름)를 적는다. 메뉴 2·4의 발 기준 검사가 FAIL로 알린다. 점을 지우고 메뉴를 다시 실행해도 새 기본값이 된다.

이름으로 찾아 재사용하므로 중복 생성되지 않는다. 다른 부위 영역의 생성·유지 규칙은 바뀌지 않았다. 메뉴 2·4는 읽기 전용이다. 실제 씬 갱신은 사용자가 메뉴 1·3을 실행해야 일어난다.

## 5. 검사 (`ValidateZones`, 메뉴 2·4 공통)

- 부모: 같은 쪽 `Foot` 본 하위인지, 좌우 쪽이 맞는지(기존 배치 검사를 새 부모로 판정).
- 덮개별로 저장 자세와 실행 축척 양쪽에서 검사한다(몸의 다리 본 참조 사용).
  - 발(발목~발볼 선분)이 영역 안에 들어와야 한다.
  - 무릎, 엉덩이 관절, 골반, 반대쪽 발은 영역 밖이어야 한다.
  - 영역 위끝이 무릎 높이보다 낮아야 한다.
  - 중심이 바닥보다 위여야 한다.
  - 줄에 부모, 로컬 오프셋, 반지름, 중심·발목·무릎·위끝 높이를 보고한다.
- 특정 절대 높이나 반지름을 통과시키는 예외는 두지 않았다. 판정 기준은 몸의 본뿐이다.
- 기존 영역 쌍 거리 검사, 장갑 손 검사, 본·가중치·좌표계·Attach 검사는 그대로다.

## 6. 교육 순서와 근거

순서: **하의 → 상의 → 왼쪽 덮개 → 오른쪽 덮개 → 왼쪽 장갑 → 오른쪽 장갑**
- `ProtectiveClothingTrainingIds.Order`만 바꿨다. `ProtectiveClothingPart` 열거값과 구성품별 단계·상태 ID는 그대로다.
- 누적 State 조건과 마지막 단계의 6종 조건은 `Order`에서 만들어지므로 유지된다. 단계 박스, 단계 줄, 허용 구성품, 완료 요약도 `Order`를 따른다.
- 메뉴 3을 다시 실행하면 교육 데이터 `PC_ProtectiveClothingTraining.asset`의 단계가 새 순서로 다시 쓰이고, 메뉴 4가 일치를 검사한다.

근거와 확정 수준:

| 내용 | 근거 | 수준 |
|---|---|---|
| 보호의 → 보호덧신 → 방독면 → 보호장갑 | 공식 군 공개자료(국방일보 2021-04-26, https://kookbang.dema.mil.kr/newsWeb/20210426/1/BBSMSTR_000000010025/view.do) | 공식 공개자료 확인 |
| 하의 → 상의 | 공개 비공식 교육 정리와 사용자 기억이 일치 | 현행 승인 교안 원문 미확보 |
| 왼쪽 → 오른쪽 | 개발상 선택 | 근거 없음 |

방독면은 이번 과정에 포함하지 않는다(보호의 6종 과정). 전체 MOPP 절차로 표시하지 않으며, 승인 교안이 확정됐다는 문구도 넣지 않았다.

## 7. 정적 검토 (실행 아님)

- 호출 관계
  - `EnsureUserBody` → 영역 생성 → `MigrateOverbootZone`(덮개만)
  - `DefaultZonePoint`의 덮개 분기는 `model`을 쓰지 않는다(이전 함수는 `null`로 호출)
  - `ValidateZones`는 `ZoneDefaults`의 새 부모와 몸의 `leftLeg/rightLeg` 참조를 쓴다
- 직렬화 호환
  - `ProtectiveClothingUserBody.zones`(점·반지름) 구조는 그대로다. 저장된 씬은 메뉴를 실행하기 전까지 기존 허벅지 점을 그대로 쓴다.
  - 교육 데이터 자산은 단계 배열만 메뉴 3이 다시 쓴다.
- 판정·표시·검사의 일치: 모두 같은 영역 점과 반지름을 읽는다(1절).
- 문구
  - 새 덮개 문구는 가운뎃점 없이 한글·공백·마침표만 쓴다(글꼴 검사 대상).
  - 장비 씬 안내 두 줄과 교육 씬 세 줄 맞춤 계산상 범위 안이다.
- **컴파일 결과는 미확인이다.**

## 9. 남은 제한

- 발은 HMD 기반 추정이다. 몸을 숙이거나 머리를 돌리면 추정 발과 영역이 머리를 따라 움직인다(3절). 실제 발 추적이 아니다.
- 반지름 0.14 m와 위치 비율(발등 중점, 발목 + 정강이 7.5 %)은 개발값이다. 착용 동작의 편의성은 사용자 확인 ③·⑥·⑨로 판단해야 한다.
- 화면 표기는 기존대로 '덮개'다. '보호덧신'으로 바꿀지는 별도로 결정해야 한다(문구 상수만 바꾸면 된다).
- 하의 → 상의 순서는 승인 교안 원문으로 확인하지 못했다.

## 10. 마감 정적 검토 — 미해결 (2026-11-04)

사용자 요청으로 보고서와 실제 diff·관련 호출을 정적으로 대조했다. 이 절은 실행 결과가 아니며, 아래 3건의 코드 수정이나 추가 프롬프트 작성 없이 문서 마감한다.

### 10.1 실제 발로 숙일 때 목표도 이동하는 기존 제한

`ProtectiveClothingUserBody.Solve`의 몸 루트는 HMD 수평 위치·방향을 따르고 `SolveLeg`의 발 목표는 몸 루트 기준 휴식 위치다. 실제 발을 향해 숙이면 추정 발·판정도 함께 이동한다. 가상 발·고리가 맞는다는 것과 실제 발에 자연스럽게 접근할 수 있다는 것은 별개다. 이번 변경에서 새로 발생한 것으로 실행 재현하지 않았고, 기존 추정 방식의 조작 위험으로 분류한다.

§8의 ⑥·⑨ 확인에서 목표 이동 자체만 정상으로 끝내지 말고, 실제 발 주변에서 손이 닿는지·고리를 쫓아 과도하게 앞으로 뻗어야 하는지 사용자 확인이 필요하다. 불편하면 발 위치 유지·몸 방향 추정 정책의 별도 설계를 검토한다. 실제 발 추적을 추가했다고 표현하지 않는다.

### 10.2 점 삭제·재생성 때 이전 반지름 유지

`EnsureUserBody`는 영역 점을 새로 만들더라도 `zones` 배열의 반지름이 유효하면 기존 값을 유지한다. `MigrateOverbootZone`도 점의 부모·위치가 발 기본값이면 반지름을 재설정하지 않고 반환한다.

따라서 이전 씬에서 점만 삭제하면 새 발 위치에 점이 만들어져도 반지름 0.12m가 남을 수 있다. §4의 "점을 지우면 새 기본값" 및 같은 메뉴 로그는 현재 코드에서 0.14m 복구를 보장하지 않는다. 이 안내는 보완 전까지 그대로 믿고 사용하지 않는다. 새 점 생성 시 기본값 적용과 기존 사용자 조정값 보존을 구분할 필요가 있다. 일반 교육생의 런타임 결함이 아닌 Editor 복구 경로의 정적 결함이다.

보완 후 사용자 확인 기준: 이전 씬에서 안전하게 점을 삭제하고 메뉴 1 또는 3 실행 → 발 위치와 반지름 0.14m 생성 → 재실행 시 유지. 기존 점의 사용자가 정한 유효 반지름은 자동 덮어쓰지 않아야 한다. 이 문서 작성자는 씬을 삭제·복제하거나 메뉴를 실행하지 않았다.

### 10.3 검사 통과가 보장하는 범위

`ValidateZones`는 위끝이 무릎 높이보다 낮은지를 확인한다. 따라서 정강이 중간까지 올라오는 다른 설정도 나머지 조건에 따라 통과할 수 있다. 영역 쌍 검사도 중심 간 거리가 각 반지름보다 크면 통과하며 구끼리 중첩은 NOTE가 될 수 있다.

현재 기본값 오류로 단정하지 않지만 PASS만으로 "정강이 하단까지만"과 "좌우 비중첩"이 보장된다고 설명하면 안 된다. 조정 허용 범위·중첩 정책을 정한 뒤 검사·문구를 일치시킬 필요가 있다. 허용치를 넓혀 통과시키는 방식은 사용하지 않는다.
