# AED 단계별 음성 안내 작업 계획

작성: B · 2026-10-23 (Asia/Seoul)

상태: **보류**. 2026-10-23 사용자가 음성 안내·음원 제작은 나중에 진행하고 다음 기능을 우선하라고 정했다. 아래 대본·설계는 참고 기록으로 유지한다. 음원 제작·코드·씬 변경·실행 검증은 아직 수행하지 않았다. 음성 제작 방식과 최종 대본은 제안 상태다.

마감 보충(2026-10-23): 이후 우선 작업인 완료 후 다시하기가 `1c1d57b`로 커밋되었고 사용자가 검증 완료를 보고했다. 음성 보류 방침은 유지한다. 아래 HEAD·작업 트리·흐름은 음성 계획 최초 조사 시점의 기준이며, 최신 상태는 [1023 작업마감](1023_작업마감_진행상황.md)을 따른다.

목표는 기존 조작과 자막에 단계별 음성을 더해, 사용자가 장비를 보며 안내를 듣고 체험하도록 하는 것이다. 충격 불필요 분기·CPR 조작·반복 사이클은 추가하지 않는다.

## 2. 첫 적용 범위와 대본 초안

전원 켜기 전 시작·버튼 안내는 기존 자막을 유지하고, 첫 음성 적용은 전원 켜짐 이후 핵심 안내부터 진행하는 안이다. 패드 이동 중 매 프레임 바뀌는 미리보기 문구나 상태 라벨은 모두 음성화하지 않는다.

아래 이름은 향후 음원 식별용 제안이며 아직 파일을 만들지 않았다. 화면 문구의 원본은 계속 `TrainingSubtitles`다. 음성용 문구를 별도 원본으로 중복 관리하지 않고, 대응 자막 상수 및 의미와 함께 관리할 방식이 필요하다.

| --- | --- | --- | --- |

마지막 화면의 상세 설명은 유지한다. 첫 적용에서 화면 전체 설명을 길게 낭독할지는 별도 선택이다. 기본 제안은 즉시 할 행동을 짧게 들려주고, 약 2분 후 재분석·반복·119 인계의 자세한 설명은 기존 자막으로 남기는 방식이다. 새 의료 절차·수치·에너지 설명은 만들지 않는다.

## 3. 재생·교체 규칙

- 안내 음성은 한 번에 하나만 재생한다. 단계 진입 시 재생하고 같은 상태의 매 프레임 호출로 재생을 반복하지 않는다.
- 단계가 바뀌면 이전 안내는 정리한다. 지나간 패드 안내가 충전·충격 단계까지 이어지거나 대기열에서 뒤늦게 재생되지 않아야 한다.
- 분석·충격 전 손 떼기 안내는 이전 일반 안내보다 우선한다. 접촉 오류가 지속되는 동안 매 프레임 음성을 반복하지 않는다.
- 충격 대기에서 접촉·비접촉이 잠깐 반복될 때 같은 안내가 과도하게 재시작되지 않도록, 새 안내가 필요한 상태 변화와 짧은 중복을 구분한다. 구체 제한 시간은 음원 길이와 사용자 확인 결과로 정한다.
- 음성이 재생되는 동안에도 기존 장비 조작은 허용한다. 음성 때문에 버튼·패드 입력을 새로 잠그지 않는다.
- 음원 누락·재생 실패가 교육 진행을 막지 않게 한다. 자막과 기존 판정 흐름으로 완주 가능해야 한다.
- 음성 종료를 교육 완료 조건으로 삼지 않는다. 이전 재생의 종료 처리가 새 자막·상태·충격 잠금을 변경하지 않게 한다.
- 체험 재실행이나 실제 씬 종료 시 이전 음성이 남지 않아야 한다. 개발자 전용 강제 조작을 별도 필수 기능으로 확대하지 않는다.

## 4. 기존 시간·상태와 연결할 주의점

분석 5초·충전 3초는 기존 교육용 값이다. 음성 추가를 이유로 검증된 시간을 임의로 늘리지 않는다.

| 상황 | 연결 기준 |
| --- | --- |
| 두 패드 부착 당시 이미 비접촉 | 이탈 대기가 짧을 수 있음. 분석 음성만 들려도 손대지 말라는 의미가 전달되도록 구성 |
| 분석 중 다시 접촉 | 현재 분석 음성을 정리하고 손 떼기 안내. 재분석 시작 시 현재 분석 안내로 교체 |
| 충전 안내 길이가 3초보다 김 | 짧은 대본·음원 길이부터 조정. 충전 완료 상태를 오래된 음성에 맞춰 지연시키지 않음 |
| 충전 완료 후 곧바로 버튼 선택 | 준비 안내를 기다리게 하지 않고 유효 충격을 처리한 뒤 후속 처치 음성으로 교체 |
| 충격 대기 중 재접촉 | 접촉 중단 안내로 교체. 비접촉 복구 후 준비 안내의 과도한 반복 방지 |
| 충격 이후 | 마지막 음성은 한 번 재생. 완료 자막은 음성 종료와 무관하게 유지 |

연결 지점은 현재 진행 컨트롤러의 전원·패드·분석·충전·충격 상태 전환이다. `instructionText.text`가 같은지 비교하는 것만으로 재생 수명을 결정하지 않는다. 새 범용 진행 시스템이나 공통 Runner 전환은 필요하지 않다.

## 5. 자산·구성 제안

- 음원 후보 위치: `Assets/B/Audio/AedTutorial/`. 아직 폴더·파일 생성 없음.
- 연결 후보: `Assets/B/Scripts/AedTutorial/**`, 현재 AED 씬 또는 B 소유 장비 래퍼.
- 한 개의 안내 재생 채널을 먼저 사용한다. 기존 진행 로직·패드·전원·충격 장비와 출력 책임을 분리한다.
- 음성은 일정한 한국어 발음·화자·음량으로 준비한다. 녹음/TTS 방식과 음성 선택은 음원 제작 시 결정한다.
- 장비 방향에서 들리게 할지, 위치와 무관하게 들리게 할지는 음원 연결 시 제안값을 명시한다. 공간 음향·볼륨·청취 거리는 사용자 확인 항목이다.
- 새 패키지·공용 오디오 설정·대규모 Mixer 구성은 선행하지 않는다. B 외부 자산을 수정하지 않는다.
- 현재 자막 원문·핵심 의미와 대응하는 음원을 연결한다. 문구가 바뀌면 해당 음원도 함께 검토할 수 있게 대응표를 남긴다.

## 6. 진행 순서

1. 단계별 대본과 음원 제작 방식 결정.
2. 음원 준비 및 파일·대본 대응표 작성.
3. 현재 상태 전환에 재생·교체·중단 기능 연결.
4. 정적 검토로 잘못된 참조·중복 재생 경로·기존 판정 변경 여부 확인.
5. 사용자가 실제 소리와 조작을 함께 확인.

이 문서는 구현 프롬프트가 아니다. 기존 코드 제공 정책에 따라 코드는 직접 작성하지 않으며, 구현 프롬프트는 사용자 명시 요청 시에만 작성한다.

## 7. 사용자 직접 확인 항목

| 확인할 상황 | 기대 결과 |
| --- | --- |
| 전원 → 패드 2개 → 분석 → 충전 → 충격 → 마무리 | 현재 단계의 안내가 순서대로 들리고 기존 조작 결과 유지 |
| 안내가 끝나기 전에 다음 조작 | 이전 안내가 정리되고 현재 안내 재생. 조작을 불필요하게 기다리게 하지 않음 |
| 분석 중 재접촉·손 떼기 | 음성과 화면이 같은 행동을 안내. 중첩·연속 끊김이 과도하지 않음 |
| 충전 완료 직후 충격 버튼 선택 | 오래된 충전·준비 안내가 후속 처치 설명을 덮지 않음 |
| 충격 대기 중 접촉·비접촉 반복 | 같은 문구가 매 프레임·지나치게 자주 반복되지 않음 |
| 체험 종료 후 대기 | 음성 1회, 마무리 자막 유지, 추가 충격·반복 없음 |
| 체험 재실행 | 이전 음성이 남지 않고 새 회차 안내 시작 |
| 실제 청취 | 음량·발음·속도·기기/헤드셋 출력이 적절하고 자막과 의미 일치 |

모든 실행 검증은 사용자가 직접 수행한다. 에이전트는 복제 프로젝트 생성·재사용, Unity·Simulator·자동 테스트·빌드 실행을 하지 않는다. 음원과 연결이 아직 없으므로 위 항목은 모두 미검증이다.
