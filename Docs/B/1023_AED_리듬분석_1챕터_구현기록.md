## 1. 흐름

두 패드 부착 → 전원·두 패드·대응 앵커 점유 재확인 → 환자에게서 손 떼기 안내 → 양손 유효한 비접촉 확인 → 리듬 분석 → 분석 완료·다음 단계 대기.

- 패드 1개 부착 시 기존 남은 패드 안내를 유지한다. 분석에 들어가지 않는다.
- 기존 `CompleteModule()` 종료는 없앴다. 두 패드가 부착되면 `AwaitingHandsOff`로 1회 진입한다.
- 분석 중 접촉·확인 불가 → 경과 시간 0, 원인별 안내, 다시 `AwaitingHandsOff`. 양손이 다시 유효한 비접촉이 되면 처음부터 분석한다.
- 분석은 `Update`에서만 시간을 누적한다. 코루틴·Invoke 같은 지연 콜백이 없어 중단된 분석이 나중에 완료로 처리되지 않는다.
- 완료는 상태 전환으로 1회만 처리한다. `ModuleCompleted`·전체 완료 문구·충전·충격·회복은 실행하지 않는다.
- 완료 후에도 매 프레임 장비 상태와 접촉 상태를 다시 읽는다. 후속 챕터는 `PatientContact` 캐시가 아니라 판단 시점의 `contactMonitor.Evaluate()`를 사용한다.
- 분석 단계(7·8·9) 중 전원·패드·앵커 상태가 깨지면 `Faulted`로 막는다.
- 분석 단계 중 컨트롤러 비활성화 → 경과 0. 재활성화 시 `InterruptedReloadRequired`로 바꾸고 패드·전원 입력을 잠근 뒤 씬 재로드를 안내한다. 자동 재개·일반 재시도는 없다.

| 값 | 상태 | 진입 조건 | 나가는 조건 |
| --- | --- | --- | --- |
| 7 | `AwaitingHandsOff` | 두 패드 부착 + `AllPadsAttached()` 성공. 분석 중 접촉·확인 불가 | 양손 `Clear` → 8 |
| 8 | `AnalyzingRhythm` | 7에서 양손 `Clear` | 접촉·확인 불가 → 7(경과 0). 경과 ≥ 분석 시간 → 9 |

## 3. 환자 접촉 판정 — `PatientContactMonitor`

진행 제어와 분리된 상태 보고 전용 컴포넌트. 상태 전환은 컨트롤러가 정한다.

| 항목 | 내용 |
| --- | --- |
| 입력 | 좌우 `TrackedPoseDriver`(B 씬 Rig 인스턴스의 Left/Right Controller), 환자 몸체 Collider 목록 |
| 추적 유효 | 컨트롤러 활성 + Tracking State 액션 활성·바인딩 존재 + 값에 Position 비트 + Position 액션 활성·바인딩 존재. Transform 존재만으로 인정하지 않음 |
| 접촉 | 컨트롤러 local 오프셋 위치의 구가 등록 Collider와 겹침(`Physics.OverlapSphereNonAlloc`, 환자 레이어만, Trigger 무시). 또는 프로브 바로 위에 환자 표면이 있음(하향 `Collider.Raycast`) |
| 확인 불가 | 손 참조 누락, 컨트롤러 비활성, 추적 소실, Collider 누락·비활성, 모니터 비활성, 겹침 버퍼 포화 |
| 결과 합산 | 한 손이라도 접촉 → 접촉. 양손 모두 유효한 비접촉 → 비접촉. 그 외 → 확인 불가 |
| 제외 | 등록 Collider만 비교하므로 책상·바닥·AED·패드·안내 표시는 대상 아님. UI 레이는 사용하지 않음 |

교육용 설정값: 양손 반경 `0.08m`, 오프셋 `(0,0,0)`(컨트롤러 pose 원점). 실기 측정값이 아니며 Simulator·Quest에서 조정할 값이다.

제약:

- 컨트롤러 위치 기반 교육용 근사다. 실제 손·팔·전신·주변 인원의 접촉을 측정하지 않는다.
- 정적 비볼록 MeshCollider는 표면 삼각형에서만 겹침이 잡힌다. 컨트롤러를 몸 안쪽으로 반경보다 깊이 넣는 경우를 위해 하향 레이 보완을 넣었다. 환자가 위를 보고 누운 자세라는 가정이다. 몸 아래 틈(예: 팔과 바닥 사이)도 접촉으로 볼 수 있다.
- 손 추적 모드로 전환되면 XRI 모달리티 관리자가 컨트롤러 객체를 끄므로 확인 불가가 된다. 손 추적 접촉 판정은 범위 밖이다.
- 환자 Collider 구성(정적 비볼록 MeshCollider 1개)과 Rigidbody 구성은 바꾸지 않았다.

## 7. 검증

후속 정책 갱신(2026-10-23): 아래 복제본 실행 결과는 정책 변경 전의 검증 이력이다. 앞으로 실행 검증은 사용자가 직접 수행하며, 에이전트는 복제 프로젝트 생성·기존 복제본 재사용·검증 실행을 하지 않는다. 아래 기록을 후속 변경의 실행 검증 완료로 확대하지 않는다.

열린 Editor와 충돌하지 않도록 프로젝트를 scratchpad에 복제해 batchmode PlayMode로 실행했다. 임시 테스트 소스는 복제본에만 있고 원본에 넣지 않았다. 결과 7/7 통과.

| 테스트 | 확인 내용 |

자동 검증 방식:

- 손은 테스트용 XRController 장치의 위치·추적 상태를 바꿔 실제 Rig의 TPD·XRI 액션·모달리티 관리자를 거쳐 움직였다. 패드는 테스트용 interactor로 XRI 선택·해제를 실행해 기존 놓기 판정·Snap을 그대로 거쳤다.
- 분석 시간은 테스트에서 1초로 줄여 실행했다. 씬 저장값 5초는 A에서 확인했다.
- batchmode에는 Game 뷰 포커스가 없어 Simulator 테스트(A)만 복제본에서 Input System 입력 라우팅을 "항상 Game 뷰"로 바꿔 실행했다. 원본 설정은 바꾸지 않았다.

미검증:

- 사용자 Editor에서의 Simulator 수동 조작(실제 손 떼기 체감, 반경 0.08m 적정성, 안내 가독성).
- 새 문구의 실제 화면 표시. 글리프 누락 오류가 없어진 것만 확인했다.
- Quest 2 + Link 실기: 사용자 결정대로 전체 기능 구현 후.

## 9. 다음 충전·충격 챕터 연결 지점

- `IsAnalysisPhase()`와 비활성화 잠금 처리 대상에 충전·충격 상태를 포함한다.
- 최종 완료에 `ModuleCompleted = 6`을 사용한다.
