# 압박붕대 붕대 끝 거리 기반 자동 부착 (2026-11-03)

상태: **코드·Prefab 수정 완료. 컴파일·메뉴 1/2·Play·Simulator·헤드셋 모두 미확인. 미커밋.** 착수 시 이전 작업(영역 유지식 감기 등)과 폰트·씬·Prefab의 사용자 메뉴 1 결과는 미커밋 상태였고, 모두 보존했다. 테이프 판정은 바꾸지 않았다. ③~⑦ Dressing 조건 누락은 별도 후속이다.

## 1. 최종 동작

감기가 완료되면 다음 순서로 진행한다.

1. 붕대 끝을 잡는다.
2. 표시된 목표 반경 0.08 m 안으로 가져간다.
3. 그 프레임에 바로 부착된다. 손을 놓을 필요는 없다.
4. 선택이 해제되고, 기존 놓인 자세(`SeatEnd`)로 자동 정렬된 뒤 잠긴다.
5. Taping 단계로 넘어간다.

앞뒷면·기울기·회전 방향은 부착 판정에 전혀 쓰지 않는다. 부착 후 자세는 항상 올바른 배치 자세다.

## 2. 거리 판정

- 기준: `Anchor_EndFix` 월드 위치와 `EndMark` 목표점(감김 끝에서 `endFixDistance` 진행한 표면점) 사이 거리. 컨트롤러·잡기점·메시 중심은 쓰지 않는다.
- 설정: `PressureBandageApplication.endSnapRadius`. C# 기본값 0.08 m.
  - Prefab: `endPositionTolerance 0.03`, `endTiltTolerance 40`, `endDirectionTolerance 50` 세 줄을 `endSnapRadius: 0.08` 한 줄로 바꿨다.
  - 씬: Application override 없음(검색 0건). 따라서 실효 값은 0.08 m이고, 별도 사용자 조정값은 발견되지 않았다.
  - 새 필드에 이전 이름을 연결하지 않았다. 그래서 예전 0.03 m가 새 반경으로 넘어오지 않는다.
- 규칙: `WithinEndSnap(fixPoint, mark)`는 거리만 비교한다. 각도 비교 함수 `JudgeEnd`와 `EndCheck`는 삭제했다.

## 3. 각도 조건을 제거한 경로

- `Application`:
  - 필드 `endPositionTolerance`·`endTiltTolerance`·`endDirectionTolerance`를 삭제했다.
  - `JudgeEnd`(면·기울기·방향)를 삭제했다.
  - `EndCheck`를 `EndDistance`·`IsEndInSnapRange`로 바꿨다.
  - `TryPlaceEnd`(정상 놓기)도 같은 거리 판정을 쓴다.
- `TrainingGuide`: `EndAction`을 삭제했다. 끝을 잡은 동안에는 "붕대 끝을 표시 가까이 가져가세요."만 표시한다.
- `TrainingSubtitles`: `ActEndFlip`·`ActEndFlat`·`ActEndTurn`·`ActReleaseEnd`를 삭제했다. `ActEndToMark`, `PlaceEnd`, `EndRejected` 문구를 거리 기준으로 바꿨다.
- `StatusBoard`: 끝 줄은 거리 안이면 "표시 위치에 맞음", 밖이면 "맞지 않음 · 표시 위치가 아님"으로 표시한다.
- `PressureBandageGuide`:
  - 끝 표식을 부착 반경 고리 + 중심 고리(`FlatMeshWriter.Target`)로 바꿨다. 반경은 `EndSnapRadius`를 그대로 쓴다.
  - 방향 화살표를 삭제했다.
  - 사용하지 않게 된 `Ring`·`Arrow` 메시 도구를 삭제했다.

## 4. 처리 순서(`Application.LateUpdate`, 실행 순서 102)

1. `WatchPlacement`·`FollowDressing`로 적용 취소가 났으면 이번 프레임에 부착하지 않는다. `resetting` 중에는 LateUpdate 전체를 건너뛴다.
2. `HandleReleases`: 추적된 손의 정상 놓기만 처리한다. 거리 안이면 `AttachEnd`, 밖이면 `EndRejected`.
3. `UpdateWrap`: 감기가 완료되면 끝이 생긴다. 아직 아무도 잡지 않았으므로 부착되지 않는다.
4. `UpdateEndSnap`: 아래 조건을 모두 만족하면 `AttachEnd`를 호출한다.
   - Stage가 EndPlacement
   - 끝이 선택 중
   - 포커스 유효
   - 드레싱 배치 유효
   - 실제 선택 손의 추적(`EndHandTracking`, 지금 다시 읽음)
   - 거리 판정 통과
5. `AttachEnd`의 내부 순서:
   1. Stage가 EndPlacement가 아니면 아무것도 하지 않는다.
   2. `CancelSelection(endGrab)`: XRI `CancelInteractableSelection` 경로로 선택을 해제한다.
   3. `pendingEndRelease = false`
   4. `SeatEnd`: 놓인 자세로 정렬하고 Rigidbody 위치도 함께 맞춘다.
   5. 끝 충돌체를 끈다(다시 잡기 잠금).
   6. Stage를 Taping으로 바꾼다.
   7. `Version`을 1 올린다. 이 값으로 Ribbons가 놓인 끝 띠를, Guide가 테이프 틀을 다시 그린다.

선택 해제 후 Transform을 정렬하므로 XRI가 손 위치로 되돌리지 않는다. 선택이 끝나 XRI가 더는 끝을 구동하지 않기 때문이다.

## 5. 중복 확정·추적 소실·초기화

- 취소 경로로 생긴 `OnEndExited`는 `isCanceled`이므로 `pendingEndRelease`가 false가 되고, `AttachEnd`에서 한 번 더 false로 둔다.
- 정상 놓기와 잡은 상태 부착이 같은 프레임에 겹쳐도, `AttachEnd` 맨 앞의 Stage 확인 때문에 한 번만 실행된다.
- 추적이 끊긴 손으로 놓거나 취소로 놓인 경우는 `IsTrackedRelease`가 거짓이라 부착 입력이 되지 않는다. 추적이 복구돼도 과거 놓기는 적용되지 않는다. 대기 값은 같은 프레임에 소비되고 저장되지 않는다.
- 생성 직후이거나 아무도 잡지 않은 끝은, 거리가 가까워도 `endGrab.isSelected`가 거짓이라 부착되지 않는다.
- 적용 취소(`CancelApplication`)와 다시하기(`ResetEquipment`): `ClearApplicationState`가 `pendingEndRelease`·`EndDistance`를 초기화하고, 끝 충돌체를 다시 켜며, 끝을 초기 배치로 되돌린다.

## 6. 테이프 판정 보존 근거

- `tapePositionTolerance 0.03`, `tapeTiltTolerance 35`, `tapeDirectionTolerance 45`, `JudgeTape`, `TryFixTape`, `TapeCheck`는 diff가 없다.
- 안내의 `TapeAction`, `ActTape*`, `ActReleaseTape`도 그대로다.
- 끝과 테이프는 판정 함수(`WithinEndSnap` / `JudgeTape`)도 안내 함수도 공유하지 않는다.
- 메뉴 2에는 원래 테이프 각도 정적 검사가 없었다. 이번에도 추가·변경하지 않았다.

## 7. 메뉴 1/2

메뉴 1:
- `Guide_Arrow`를 한 번 삭제한다(직접 만든 표시 전용 마커).
- Guide 참조를 다시 연결한다: ring, tapeFrame, zoneOutline.
- 안내판·버튼·감기 영역 값은 쓰지 않는다. 이름으로 찾으므로 다시 실행해도 중복이 생기지 않는다.
- 부착 반경은 메뉴가 쓰지 않는다. Prefab 값을 그대로 쓰며 사용자 조정을 보존한다.

메뉴 2(`ValidateEndSnap`, Prefab·씬 각각):
- 반경이 예전 0.03 m이면 FAIL.
- 실효 값을 INFO로 보고한다. 사용자 값이나 인스턴스 override이면 그렇게 표시한다.
- 끝 각도 허용오차 필드가 남아 있지 않은지 확인한다.
- 정적 판정: 기준점을 반경의 0.9배 거리에 두면 그대로·뒤집힘·70° 기울임·135° 회전 모두 부착, 1.1배 거리에서는 모두 미부착.
- Guide에 화살표 마커가 없고 끝 표식이 Ring인지 확인한다. 표식 수 기대값은 3이다.

## 8. 사용자 적용 순서

1. 재컴파일한다.
2. 메뉴 1을 실행한다. 로그에서 `Guide_Arrow removed`를 확인한다.
3. 메뉴 2를 실행한다.
4. Play/Simulator로 확인한다.

메뉴 1 실행 전 메뉴 2에서는 표식 수 4로 FAIL이 날 수 있다.
