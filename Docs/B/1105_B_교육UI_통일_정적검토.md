# B 교육 UI 통일 구현 보고·실제 코드 정적 검토 — 2026-11-05

> **11/06 후속 완료:** 아래 초기 지적과 중단본의 미완 항목은 후속 수정·씬 적용 및 사용자 검증 완료 보고로 갱신됐다. 커밋은 `2e8a105`이며 [1106 검토 §10](1106_B_교육UI_통일_수정본_정적검토.md#10-사용자-검증-완료와-커밋-반영)과 [최신 진행상황](1106_진행상황_남은작업.md)을 우선한다. 이 문서 본문은 당시 검토·중단 이력으로 보존한다.

> **마감 상태:** 수정 프롬프트 전달 이후 부분 수정 중 한도에 도달했다. 최신 파일 상태는 §7과 [1105 마감](1105_작업마감_진행상황.md)을 우선한다. 아래 §1~6의 지적은 초기 검토 이력이며, 수정 전체 완료나 사용자 실행 통과를 뜻하지 않는다.

기준: 사용자 첨부 보고서 `ee81d041-97a4-4316-a5a9-fd3291ff0471/붙여넣은 텍스트.txt`, 현재 작업 폴더의 diff와 신규 코드. 검토자는 코드·씬·자산을 수정하거나 컴파일·메뉴·Play·Simulator·헤드셋·테스트·빌드를 실행하지 않았다.

## 1. 결론

공통 스타일/레이아웃, 5과정 정의와 적용·검사 메뉴, AED/TQ 표시 연결, 기존 구성 메뉴4곳 연결이 있다. 장비 판정과 과정 진행 본체 변경은 제한적이며 KD-1·씬·글꼴 변경은 현재 git diff에 없다. 다만 UI 적용 전 보완할 사항은 다음 세 종류다.

1. 지혈대의 실제 런타임 출력과 새 글자 검사 후보가 불일치한다. 완료 요약은 실제4/3줄인데 후보3/3줄, 높이100으로 계획됐다. 최종 확인 결과도 실제 조합문 후보가 빠져 있다.
2. K1 기존 메뉴6은 비활성으로 보존한 Mark도 겹침 검사에 포함하여 새 UI를 오판한다. 새 UI 검사와 기존 검사 기준의 불일치가 코드상 확인됐다.
3. 진행 화면의 단계별 목적·방법 설명은 아직 공통 구현되지 않았다. K1은 과정 제목을 Purpose로 재배치하며 나머지 일반 진행 화면은 기존 행동/상태를 배치한다. ‘설명+행동’ 구조까지 완료했다고 볼 수 없다.

실행 재현/화면 관찰이 아닌 코드 대조 결과다. 사용자 KD-1 한 회차 성공은 보존하고 이번 5과정 UI 실행 통과로 확대하지 않는다.

## 2. 지혈대 출력 후보 누락과 완료 요약 공간 부족 — 중간 우선순위

- `Assets/B/Editor/TrainingUI/TourniquetBoardUi.cs:123`은 완료 요약 두 열을 각각 높이100으로 잡는다. :124~126의 후보는 실습6단계만 사용하고 Take(3)/Skip(3)으로 나눈다.
- 실제 `TourniquetCompletionPanel.cs:109`~115는 실습6개에 FinalCheckTitle을 추가하여 총7개를 쓰고 왼쪽4/오른쪽3줄로 나눈다. 새 후보에서 최종 확인 항목과 왼쪽4줄 상태가 빠져 있다.
- 사용 중인 글꼴 faceInfo는 pointSize90·lineHeight130.32다. 새 검사와 같은 계산에서 Detail22pt의 4줄은 약127.4인데 영역은100이다. 새 검사는 후보3줄 약95.6만 확인해 통과시킬 수 있다. 실제 완료 화면에서 제목/시간 줄과 겹칠 위험이 있고 기존 TQ 검사도 실제4줄 후보로 FAIL을 낼 수 있다. 실제 TMP 렌더는 미확인이다.
- 같은 파일 :115는 FinalCheckUnmet/Blocked를 단독 후보로 넣지만 실제 `TourniquetFinalCheck.cs:147`~148은 해당 문구+줄바꿈+RecoveryAction을 조합한다. 긴 복구 문구가 붙는 분기의 높이 검사가 누락되어 있다. 해당 분기의 실제 사용자 실행 재현은 하지 않았다.
- 보완은 기존 실제 문구 생성과 후보를 일치시키고 그 결과에 맞춰 UI 공간을 배분하는 범위다. 기존 요약의 최종 확인 항목이나 복구 안내를 삭제해 공간에 맞추지 않는다. 모든 상태의 후보가 확인되지 않았으므로 보고서 ‘33개 영역 통과’는 구현자가 계산한 후보에 한정한다.

## 3. K1 기존 메뉴6의 숨긴 장식선 겹침 오판 — 중간 우선순위

- `K1BoardUi.cs:86`~88은 CompletePanel/Mark를 삭제하지 않고 비활성으로 보존한다.
- 기존 `K1GasMaskTrainingSetup.TrainingGuide.cs:715`의 ValidateCompletePanel은 Title/Mark/Body/Source/RetryButton을 모두 집계하며 :739~747의 위치·겹침 검사에서 활성 여부를 고려하지 않는다.
- 저장된 Mark는 y137·높이6이다. 새 공통 흐름에서 완료 Body 영역은 y−58..162가 되어 Mark의134..140과 겹친다. 화면에서는 숨겨지지만 기존 메뉴6은 Mark/Body 겹침 FAIL을 낼 코드 경로다. 보고서의 ‘기존 기준으로 실패할 수 있음’을 더 구체적으로 확인한 것이다.
- 보완은 구조/참조 검사와 실제 표시 대상의 겹침 검사를 구분하거나 공통 UI의 레이아웃 검사와 연결하는 범위다. 기존 전체 검사를 끄거나 유효한 장식선·버튼 검사를 무조건 통과시키지 않는다.

## 4. 설명+행동 구성의 남은 범위 — 요구사항 미완

- 사용자는 KD-1의 상단 챕터/단계 제목, 목적·방법 설명과 현재 행동이 연결된 UI를 B 전체 기준으로 지정했다.
- AED 정의는 단계 줄 뒤 Action을 배치한다(`AedBoardUi.cs:97`). PC/PB 일반 진행도 Action과 상태/진행/확인 카드를 배치한다. TQ 일반 조작도 Action/상태/Detail이며 Purpose는 최종 확인 설명에만 쓴다.
- K1은 Purpose 역할에 `K1Text.CourseTitle`만 배치한다(`K1BoardUi.cs:72`). 단계별 사용 목적·방법 설명으로 바뀌는 구현은 아니다.
- 상단 제목·색·번호와 배치 통일은 구현됐지만 단계별 설명+행동 문구/연결은 별도로 완료 여부를 구분해야 한다. 기존 승인 문구·근거를 우선 사용하며 새 의료/화생방 절차·횟수/효능 기준을 발명하지 않는다.

## 5. 확인한 보존과 적용 구조

- TrainingBoardStyle은 색 역할, TrainingStepRow는 번호/색 표시만 담당한다. 기존 PC/PB/K1 Guide의 변경은 단계 색·K1 준비 줄 중심이다.
- AED adapter는 기존 컨트롤러 State를 읽으며 충격 조작·진행을 변경하지 않는다. TQ adapter도 Runner/Link/화면 상태를 읽어 새 행을 표시한다.
- 공통 메뉴는 미저장 씬을 차단하고 과정별 적용→새 검사→저장한다. 실패 과정은 저장본을 다시 열고 최종 요약에서 성공·실패를 구분한다. 읽기 전용 검사는 미로드 씬을 additive로 열고 닫는다.
- PC3/PB1/TQ1/K1 5 구성 메뉴가 같은 ApplyInScene을 호출한다. 기존 장비 생성 코드를 이 검토에서 다시 실행하지 않았다.
- 현재 작업 diff에는 대상 씬 변경이 없으므로 메뉴 적용 완료가 아니다. 직접 YAML 수정이나 글꼴·KD-1·공용 Overlay 변경은 확인되지 않았다.

## 6. 다음 순서

위 코드/검사 불일치와 설명 구성의 남은 범위를 보완한 뒤 사용자 컴파일→공통 적용 메뉴→공통 검사 및 기존 과정별 검사→과정별 화면/완주·다시하기를 확인한다. 먼저 확인할 화면은 TQ 완료 요약(7개·4/3줄)과 K1 기존 메뉴6의 Mark 오판 해소다. 사용자 실행 전에는 저장5개·FAIL0·헤드셋 가독성 통과로 보고하지 않는다.

프로젝트 코드는 수정하지 않았으며 수정 프롬프트는 사용자 명시 요청 시 채팅으로 제공한다. 이번 정적 검토에서는 Docs/B만 갱신했다.

## 7. 한도 도달 중단본 스냅샷 — 2026-11-05

사용자가 한도 도달로 중단·문서 마감을 요청했다. 실제 파일의 부분 반영만 읽어 확인했으며 새 수정본 전체 리뷰·컴파일·실행은 하지 않았다.

- K1 기존 검사에 Drawn과 필수 표시 요소 검사가 추가돼 비활성 Mark를 제외하는 보완이 반영됐다. 실행 확인은 없다.
- TQ 런타임은 SummaryColumns(실습6+최종확인7항목, 4/3줄), ItemColumns, ResultLine을 추가했고 기존 TQ 검사도 사용한다.
- 그러나 새 `TourniquetBoardUi`는 아직 기존6항목3/3줄·높이100·단독 결과 후보를 사용한다. 새 후보와 공유 함수 연결, 실제 문구에 맞는 높이·배치가 남았다.
- 5과정 런타임의 목적 설명 상수·필드·표시가 일부 추가됐다. 새5개 BoardUi에는 설명 자식 생성·참조·후보·배치 연결이 아직 없다. K1은 기존 CourseTitle을 Purpose로 배치한다.
- AED의 새 purposeText는 TryValidate 필수인데 현재 AedBoardUi.SetRefs가 연결하지 않는다. 연결이 끝나기 전 공통 적용 메뉴의 자체 검사가 실패할 수 있다. 단순히 메뉴 재실행만 하면 해결된다고 안내하지 않는다.
- 현재 5개 씬은 적용 변경이 없고 마지막 부분 수정의 사용자 실행 결과는 미보고다. 이전 보고의 ‘코드와 메뉴 완료’와 이후 중단본을 구분한다.

다음은 해당 부분 구현을 끝내고 전체 정적 검토한 뒤 사용자 적용·실행 확인이다. 이번 마감은 코드를 이어 작성하지 않는다.
