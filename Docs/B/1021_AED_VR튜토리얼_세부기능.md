# AED VR 튜토리얼 세부 기능

작성일·최종 진행 갱신: 2026-10-21. 기능 명세와 실제 구현 상태를 구분한다. 다음 세션은 [작업 마감·인수인계](1021_작업마감_진행상황.md)를 먼저 읽는다. 이번 마감 기록에서 구현 파일을 변경하지 않는다.

첫 제작 단위는 사용자가 안내를 따라 AED 전원을 켜고 패드 2개를 부착하는 장비 조작 체험이다. 게임 튜토리얼처럼 매 단계가 **안내 표시 → 대상 강조 → 직접 조작 → 판정 → 성공 피드백 → 다음 단계**로 연결돼야 한다. 의료적 세부 순서·부착 위치는 승인 교안과 채택 장비를 따른다. 이 모듈 완료를 전체 AED 교육·소생술 완료로 표시하지 않는다.

초기 인체는 사용자가 지정한 `Assets/B/Models/Mannequin/Mannequin.fbx`였다. 이후 사용자의 곡면 패드 표시 교체 요청에 따라 제작한 `Assets/B/Models/Pad_Mannequin/Mannequin_AED_Attached.fbx`를 현재 사용한다. 기존 FBX는 보존한다. `Mannequin_Patient` 래퍼에 부착 지점·안내·몸체 Collider를 구성하고, 성공 후 원래 AED 패드를 숨기고 인체의 해당 곡면 패드를 켠다.

## 0. 작업 마감 시 실제 상태

| 범위 | 2026-10-21 상태 |
| --- | --- |
| S00~S06 | 시작·전원·실제 잡기·위치/방향 미리보기·놓을 때 Snap·남은 패드·두 패드 상태 기준 완료 안내까지 구현. 사용자 Simulator 검증 결과 문제 없음 |
| 부착 표시 | 처음 인체 패드 OFF. 성공 시 AED 패드 시각 자식·Collider OFF / 인체의 해당 곡면 패드 ON. 논리 루트와 장비 상태 유지 |
| 기준 | Pad01→오른쪽 위 가슴, Pad02→왼쪽 옆가슴. 현재 위치·짝은 사용자 승인. 거리 6cm·부착면 방향 45°·면 위 회전 검사 해제 |
| 모델 보정 | 새 인체 루트 X scale -1과 패드 그림 MirrorFix 재질 보정 유지. 이미 누운 정적 FBX에 기존 본 회전·눕힘 회전을 중복 적용하지 않음 |
| 실제 진행 구조 | `AedTutorialStartController`, `AedPowerDevice`, `AedPad`, `PadAttachAnchor`로 연결. C02 Runner 통합이나 자막 ID 기반 데이터 진행을 이미 구현했다고 간주하지 않음 |
| S07 | 완료 문구는 구현. 씬 내 재시도·종료 버튼과 전체 상태 초기화는 미구현. 현재 초기화는 씬 재로드/Play 재시작 |
| 현재 제외 | 부착 후 다시 잡기·분리, 전원 끄기·토글, 자동 도구 회수, 음성·점수·결과 저장·앱 복귀 |
| 실기 | 사용자 결정으로 전체 기능 구현 후 진행 |

아래 표의 미구현 복구·재시도·교육 확장 항목은 설계 후보로 유지한다. 현 모듈 완료를 전체 교육 완료로 확대하지 않는다.

## 1. 단계별 체험

아래 문구는 튜토리얼 UI 예시다. 현재 원문은 TrainingSubtitles 상수를 직접 참조한다. 단계 데이터의 SubtitleId 연결은 향후 데이터화 설계이며 이번 실제 진행 구조는 아니다. 단계 ID와 순서는 게임 진행 설계용이다.

| 단계 | 화면 안내 예시 | 사용자가 할 행동 | 완료 조건·다음 처리 |
| --- | --- | --- | --- |
| S00 목표·시작 | “AED 전원과 패드 부착을 연습합니다. 시작을 선택하세요.” | VR UI의 시작 버튼 선택 | 준비된 장비 상태 확인·초기화 후 시작을 1회 접수. 학습 중 시작 버튼 비활성화 |
| S01 전원 켜기 | “표시된 AED 전원 버튼을 누르세요.” | 강조된 전원 버튼 조작 | 실제 AED 전원 상태가 켜지면 표시등 변경·성공 피드백 후 S02. 다른 버튼이나 몸체 접촉으로 진행하지 않음 |
| S02 패드 집기 | “패드 한 개를 집으세요.” | 아직 부착되지 않은 패드 중 하나 잡기 | 실제 XR 선택 상태에서 해당 패드 ID 확인. 현재 조작 패드로 지정하고 그 패드에 맞는 위치를 안내 |
| S03 패드 가져가기 | “패드의 표시를 확인하고 안내된 부위로 가져가세요.” | 잡은 패드를 해당 부착 영역으로 이동 | 올바른 패드·위치·설정된 방향 허용 범위가 충족되면 배치 가능 표시. 이때는 아직 부착 완료가 아님 |
| S04 손 놓아 부착 | “표시된 위치에서 잡기를 놓으세요.” | 유효 영역에서 잡기 입력 해제 | 정상 XR 선택 해제 후 재검사·Snap·물리 고정·Attached/점유 갱신. AED 패드 시각·Collider를 숨기고 인체 곡면 패드 표시 후 진행 |
| S05 남은 패드 | “남은 패드를 부착하세요.” | 남은 패드를 집어 같은 방식으로 부착 | 미부착 패드에 대해 S02~S04 반복. 두 패드 중 먼저 집는 순서는 강제하지 않는 기본안. 장비·교안이 요구할 때만 제한 |
| S06 완료 조건 확인 | “패드 부착 상태를 확인합니다.” | 안내 확인 | AED 전원 켜짐과 패드 2개의 현재 부착 상태를 함께 재검사. 충족 시 결과 화면, 미충족 시 필요한 행동으로 안내 복구 |
| S07 결과·재시도 — 일부 후속 | “장비 조작 연습을 완료했습니다.” | 현재 완료 안내 확인. 다시 하기·종료 선택은 후속 설계 | 현재는 완료 문구와 씬 재로드 초기화까지 구현. 씬 내 재시도·종료는 잡기·장비·표시·UI 정리 및 복귀 대상 확정 후 구현 |

S03에서 잡은 채 영역에 닿기만 해서는 S04 완료로 처리하지 않는다. 영역 밖으로 이동하면 배치 가능 표시를 해제하고 S03 안내로 돌아간다. 떨어뜨린 패드는 다시 집도록 현재 목표를 유지한다. 장비는 보이는 곳에서 직접 다루게 하며, 사용자가 할 동작을 자동 배치로 건너뛰지 않는다.

S00 화면 확인은 교육 시작 의사 확인이다. 환자 상태를 실제로 관찰·판단했다는 판정으로 사용하지 않는다. 환자 상태 확인·도움 요청·기기별 후속 행동은 이 모듈 이후 승인 교안에 맞춰 별도 체험 단계로 연결한다.

## 2. Unity에서 만들 기능 단위

아래는 구성 요소와 책임의 설계안이다. 기존 컴포넌트로 가능한 부분을 재사용하고, 장비 판정·튜토리얼 연결에 필요한 동작만 추가한다.

| 기능 | Unity 구성 | 맡을 동작 |
| --- | --- | --- |
| 교육 공간·환자 | B 씬, `Assets/B/Models/Pad_Mannequin/Mannequin_AED_Attached.fbx`, AED 거치 위치 | 새 정적 인체와 장비 배치, 몸체 MeshCollider. 기존 앵커와 새 모델의 축·스케일 정렬 및 사용자 씬 보정값 유지 |
| 안내 패널 | World Space Canvas, TextMeshPro 텍스트, 버튼 | 제목·현재 목표·단계 진행·패드 부착 개수·짧은 오류 표시 |
| VR UI 선택 | EventSystem, XR UI Input Module, Tracked Device Graphic Raycaster와 기존 Rig의 UI 상호작용 | 시작·재시도·종료를 실제 컨트롤러로 선택. EventSystem/Input Module 중복 방지 |
| 전원 버튼 | 모델 표면의 World Space UI Button, TrackedDeviceGraphicRaycaster, AedPowerDevice | 실제 XR UI 입력을 전원 켜짐·표시등과 연결. 한 입력의 중복 처리 방지 |
| 패드 개별 잡기 | 패드별 Collider·Rigidbody·XR Grab Interactable | 좌·우 어느 손으로도 패드 잡기·이동·놓기. 동일 패드 중복 선택 방지 |
| 부착 지점 | 환자 래퍼의 앵커·AttachTarget, 패드 AttachPoint, ID·거리/방향 허용 조건 | 현재는 Transform 거리·방향으로 유효 여부와 Snap 위치·회전을 판정. 별도 Trigger 감지 Collider는 사용하지 않음 |
| 부착 확정·표시 전환 | 패드 장비 상태, XR 해제·물리 전환, attachedDisplay | 정상 놓기 때 Snap·고정하고 평면 패드 대신 인체 곡면 패드 표시. 현재 부착 후 다시 잡기·분리는 차단 |
| 목표 시각 표시 | 전원 버튼 표시, 패드 강조용 표시물, 반투명 배치 안내, 성공/오류 표시 | 현재 행동에 필요한 표시만 켜고 단계 변경 시 정리. 색 외에도 모양·문구로 상태 구분 |
| 단계 진행 연결 | 현재 AedTutorialStartController와 장비별 이벤트. 공통 Runner 재사용은 별도 설계 | 시작·입력·상태·부착 결과를 현재 목표와 연결. 기존 C02와 실제 AED 구현의 완료 범위를 구분 |
| 안내 수명 | 자막 상수/ID, 선택적 AudioSource·AudioClip | 한 번에 주 목표 하나. 이전 음성·표시 종료가 새 안내를 지우지 않게 관리. 초기에는 자막만으로 완주 가능 |
| 결과·재시도 | 완료 화면과 장비별 초기화 | 현재 모듈 완료 표시, 잘못된 조작 피드백, 위치·전원·부착·안내·진행 복원 |

XR Socket Interactor는 부착점 구현 후보지만 기본 동작은 Hover 중인 대상을 자동 선택하려는 방식이다. Prefab 배치만으로 “손을 놓았을 때 부착”과 “올바른 패드만 허용”이 완성됐다고 가정하지 않는다. 이번 명세의 감지·선택 해제·검증·부착 순서를 만족하도록 설정과 장비 판정이 필요하다.

## 3. 각 단계에 필요한 설정

| 설정 | 내용 |
| --- | --- |
| 단계 ID | 현재 목표를 식별하는 고정 ID |
| 안내 ID | TrainingSubtitles에서 조회할 문구 ID. 원문 중복 저장 금지 |
| 안내 음성 | 선택 사항. 자막과 의미 일치 |
| 강조 대상 | 버튼·패드·부착 위치 등 지금 볼 대상 |
| 허용 행동 | 이번 단계에서 어떤 행동이 진행으로 인정되는지 |
| 완료 조건 | 버튼 사건·현재 전원 상태·패드 ID·현재 부착 상태 등 |
| 성공 처리 | 성공 표시, 이전 안내 정리, 다음 목표 활성화 |
| 오류 처리 | 짧은 오류, 현재 목표 유지, 올바른 대상 재안내 |
| 복구 처리 | 이전 전제 상태가 깨지거나 도구가 떨어졌을 때 필요한 행동 안내 |

공통 TrainingDefinition을 사용하는 C02와 현재 AED 전용 진행 구조를 구분한다. AED에는 이미 화면 안내·목표 강조·실패 후 재집기·남은 패드·완료가 연결돼 있다. 이 기능이 공통 Runner에 데이터화됐다는 의미는 아니다. 후속 재시도·복원도 현재 콘텐츠에 필요한 작은 범위부터 연결한다.

## 4. 오류·복구 규칙

| 상황 | 화면·장비 반응 | 진행 처리 |
| --- | --- | --- |
| 전원 대신 다른 부분 조작 | 전원 버튼을 다시 강조 | S01 유지 |
| 부착 위치 오류 | 배치 불가 표시와 짧은 위치 안내 | 부착·완료 없음. 잡기/놓기는 계속 가능 |
| 다른 패드의 위치에 접근 | 현재 패드에 맞는 지점 안내 | 잘못된 조합으로 부착하지 않음 |
| 유효 위치에 닿았지만 계속 잡고 있음 | “잡기를 놓으세요” 안내 | 부착 확정 전까지 다음 패드 안내로 넘어가지 않음 |
| 패드를 바닥에 떨어뜨림 | 해당 패드를 다시 강조 | 현재 목표 유지·재집기는 구현. 접근 불가능한 도구의 자동 회수는 후속 설계 |
| 이미 부착한 패드가 다시 분리됨 — 후속 | 부착 개수 갱신, 미부착 패드 안내 | 현재는 분리 차단. 분리를 허용하는 교육 범위가 확정되면 복구 설계 적용 |
| 전원이 다시 꺼짐 — 후속 | 전원 복구 안내 | 현재는 한 번 켜기만 구현. 끄기·토글을 허용하는 범위 확정 시 적용 |
| 시작/완료 입력 중복 | 기존 처리 유지 | 과정 시작·단계 전환·완료는 각각 필요한 횟수만 실행 |
| 다시 하기 선택 | XR 선택과 진행 작업을 먼저 정리하고 초기화 | 이전 회차 이벤트·음성·안내가 새 회차에 반영되지 않음 |

두 패드 중 먼저 집는 순서는 강제하지 않는다. 현재 모듈에서는 사용자가 승인한 Pad01·Pad02의 지정 앵커 짝을 적용한다. 이는 이번 구현 기준이며, 채택 장비나 교안이 바뀌면 대응 관계를 재검토한다.

## 5. 실제 제작 순서와 각 완료 목표

| 작업 묶음 | 만들 것 | 체험으로 확인할 완료 목표 |
| --- | --- | --- |
| A 시작·전원 | 실제 교육 대상·AED 모델, 시작 UI, 목표 문구, 전원 버튼 강조·상태 표시, 입력 판정 | 시작을 선택하면 전원 버튼 안내가 나오고 직접 눌렀을 때 패드 안내로 변경 |
| B 패드 1개 부착 | 실제 패드 잡기, 환자 부착점, 배치 안내, 놓기·부착 판정, 오류 피드백 | 패드를 집으면 위치 안내, 맞는 곳에서 놓으면 부착 성공. 오답 위치·잡은 채 접촉은 미완료 |
| C 패드 2개·전체 진행 | 두 패드 상태, 남은 목표 선택, 완료 전 현재 상태 재검사 | 먼저 집는 패드가 달라도 남은 패드를 안내하고 둘 다 부착됐을 때 결과 표시 |
| D 재시도·운영 검증 | 장비·물리·UI·진행 초기화, 중단 정리, Simulator·Link 검증 | 완료/중간 상태에서 재시도해도 첫 안내부터 정상 체험 가능 |

A~C와 인체 곡면 패드 표시 교체까지 구현·사용자 Simulator 검증 완료다. 다음 후보는 D의 재시도·종료·상태 복원이며 실제 착수 범위는 미확정이다. 실기 측정은 사용자 결정대로 전체 기능 구현 후 진행한다.

## 6. 검증 목록

1. 시작 전에는 과정이 자동 완료되지 않으며 시작 입력을 반복해도 한 번만 시작한다.
2. 모든 단계에서 현재 할 행동과 대상이 화면으로 명확히 보인다. Console을 보지 않고 진행 가능하다.
3. 전원 버튼을 직접 조작해야 다음 목표로 진행한다. 다른 부위 접촉은 진행을 만들지 않는다.
4. 패드 잡기→위치 안내→유효 표시→손 놓기→부착→다음 안내가 실제 조작과 일치한다.
5. 위치 오류·잘못된 조합·잡은 채 접촉·패드 누락은 성공으로 처리하지 않는다.
6. 먼저 집는 패드와 사용하는 손이 달라도 설계한 동등한 흐름으로 수행 가능하다.
7. 부착 상태 해제나 전원 꺼짐을 허용하는 후속 범위에서는 조건·안내에 반영한다. 현재 모듈은 분리·끄기를 지원하지 않는다.
8. 결과는 두 패드의 현재 부착 상태와 전원 상태가 충족될 때 한 번만 표시된다.
9. 현재 씬 재로드로 초기 상태가 복원된다. 씬 내 재시도 구현 후에는 잡기 중·부분 부착·완료 상태별 초기화를 추가 검증한다.
10. Quest 2 + Link의 UI 선택·가독성·버튼·패드 조작은 사용자 결정에 따라 전체 기능 구현 후 별도 검증한다.

## 7. 이후 구급법·화생방 체험 연결

환자 상태 확인·도움 요청 등은 승인 교안에 맞춰 시작 단계에 추가하고, 기기별 후속 지시도 별도 단계로 연결한다. 개인제독에서는 동일한 안내 구조로 대상 확인→도구 선택→지정 처리→누락/재접촉 확인→회수·결과를 구성하되, 부착 판정을 그대로 제독 성공 조건으로 재사용하지 않는다.

모든 프로젝트 구현 자산은 Assets/B 내부에 두고 공용 원본은 참조한다. 프로젝트 코드는 직접 작성·수정하지 않으며 구현 프롬프트도 명시 요청 시에만 제공한다. 모델·문서 작업 등 별도 요청은 해당 허용 범위에서 수행한다.
