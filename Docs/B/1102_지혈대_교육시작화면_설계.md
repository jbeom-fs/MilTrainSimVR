- 사용자 보고: 지혈대 기존 조작 검증 완료. 개별 체크리스트·손 조합·실기까지 통과한 것으로 확대하지 않는다.
- 복구 커밋 `e8eda1f` 확인. 조사 시작 시 작업 트리는 깨끗했다.
- C 폴더는 팀 수신 기준 `f534400`과 Git tree가 동일하며 이번 복구 커밋에는 C 변경이 없다.
- 현재 `TourniquetStatusBoard`는 기존 배치·부품 조작 안내를 표시한다. 버튼·교육 시작 대기 상태는 없다.
- 현재 지혈대 씬은 표시 전용 안내판이며 UI raycaster·EventSystem이 없는 구성이다. 화면만 꾸미는 것으로 XR 버튼 입력이 완성되지 않는다.
- `TourniquetOperation`은 부착 여부와 밴드·막대·기록·마감 상태로 부품 선택을 제어한다. 교육 시작 여부를 판단하는 공통 Runner 연결은 아직 없다.

## 2. 이번 사용자 흐름

씬 진입 → 시작화면·장비 선택 잠금 → 교육 시작 선택 → 시작화면 숨김·기존 안내 표시 → 본체 잡기·배치와 기존 2챕터 조작.

첫 범위는 교육 시작 진입 제어다. 단계별 Runner 연결·최종 재확인·교육 완료 화면·다시하기는 다음 작업이다. 시작 버튼을 누른 것만으로 전체 3챕터 완료로 기록하지 않는다.

## 3. 화면 구성

기존 안내판의 월드 위치·회전·크기를 유지한다. 월드 고정 화면 하나에서 시작 패널과 기존 조작 안내 패널을 전환한다. XR Rig나 사용자 시야는 이동하지 않는다.

| 영역 | 제안 문구·행동 |
|---|---|
| 제목 | 지혈대 가상 조작 교육 |
| 소개 | 지혈대를 표시된 부위에 배치하고, 밴드·조임막대·시간 기록·마감 스트랩 조작을 체험합니다. |
| 준비 안내 | 교육 시작을 선택한 뒤 안내에 따라 지혈대를 조작하세요. |
| 시제품 안내 | 기존 `PrototypeNotice`의 가상 조작·개발용 영역 안내 유지 |
| 버튼 | 교육 시작 |

문구는 과정의 `TrainingSubtitles` 상수에서 관리한다. 원문을 Inspector·UI·교육 데이터에 중복 저장하지 않는다. 키보드 단축키·개발 내부 용어는 교육생 화면에 넣지 않는다.

시작 화면에서는 기존 조작 안내·진행 수치·시간 기록 텍스트가 시작 버튼과 겹치지 않는다. 버튼 이외의 설명·배경은 UI 선택을 가로막지 않는다. 버튼은 한 개로 시작하며 과정 복귀·종료·다시하기는 이번 화면에 추가하지 않는다.

## 4. 시작 동작과 장비 입력

| 상태 | 화면 | 장비 선택 |
|---|---|---|
| 시작 대기 | 제목·소개·준비 안내·시제품 안내·시작 버튼 | 본체와 네 부품 조작점 모두 차단 |
| 시작 수락 중 | 중복 시작을 차단 | 시작 준비 확인 전까지 차단 |
| 조작 시작 | 기존 배치·부품 조작 안내 | 본체·부품의 기존 조건과 현재 단계에 따라 허용 |
| 시작 준비 실패 | 원인·시작 불가 상태 표시 | 잠금 유지 |

- 시작 버튼은 한 번만 수락한다. 양손 동시 선택·연속 클릭이 회차나 전환을 중복 생성하지 않는다.
- 입력 잠금은 장비 자체 상태와 별도의 교육 시작 조건이다. 장비·상태 스크립트·XR Rig를 통째로 비활성화하지 않는다.
- K1의 추가 선택 필터 방식은 참고할 수 있다. 지혈대 본체 1개·부품 4개에 대해 기존 선택 조건과 함께 동작하는 시작 잠금이 필요하다.
- 기존 `TourniquetOperation.UpdateGates()`가 매 프레임 부품을 활성화하므로, 교육 시작 쪽에서 `enabled`나 interactionLayers를 반복 덮어쓰는 경쟁 구조는 피한다.
- 시작 이후에도 부착 전 부품 잠금, 밴드→막대→기록→마감 순서, 부착 후 본체 잠금은 그대로 유효하다.
- 시작 버튼 입력이 같은 손의 장비 선택으로 함께 처리되지 않는지 확인한다. 시작 입력을 놓고 새로 잡을 수 있어야 한다.
- 기존 시간 기록은 장비 부착 시점부터의 경과 시간이다. 이번 시작화면만으로 기록 기준을 교육 시작 시점으로 바꾸지 않는다. 이후 교육 시계 연결에서 따로 결정한다.

## 5. UI 연결과 기존 검사와의 관계

- 기존 XR Origin·카메라·Interaction Manager를 유지한다. UI 입력 연결은 지혈대 B 씬 범위에서 구성한다.
- K1 시작화면의 월드 Canvas·`TrackedDeviceGraphicRaycaster`·단일 `EventSystem`/`XRUIInputModule` 구성을 참고한다. K1 자산 자체는 수정하지 않는다.
- 실제 지혈대 씬의 근거리·원거리 컨트롤러 UI 선택 설정을 확인해야 한다. 손잡기 입력과 버튼 선택 입력을 동일한 것으로 단정하지 않는다.
- 기존 설정 메뉴의 `No UI raycaster`·`No EventSystem` 검사는 표시 전용 2챕터 기준이다. 시작화면 적용 시 단일 XR UI 입력 구성과 버튼 참조를 검사하는 기준으로 함께 갱신해야 한다.
- 설정 메뉴 재실행은 화면·버튼·리스너·EventSystem을 중복 생성하지 않고 기존 안내판 월드 배치와 사용자 조정을 유지해야 한다.
- 안내판 전체 회전과 무관하게 버튼·글자 겹침을 판단한다. K1의 월드 AABB 겹침 오판 경로를 새 화면에 가져오지 않는다.
- Simulator는 데스크톱 조작 확인 때 활성화하고, 저장 상태 검사 때는 기존 비활성 기준을 따른다.

## 6. 사용자 확인 기준 — 새 시작화면은 모두 미확인

| 순서 | 행동 | 기대 결과 |
|---|---|---|
| S1 | 컴파일·설정/검사 메뉴 실행 | 오류·참조 누락·중복 UI 없음. 시작화면을 포함한 새 검사 기준 적용 |
| S2 | Play 시작, 버튼은 누르지 않음 | 시작화면만 표시. 본체·네 부품을 근거리/원거리로 선택해도 조작되지 않음 |
| S3 | 컨트롤러 레이로 교육 시작 선택 | 시작 버튼 동작, 시작 패널 숨김, 기존 배치 안내 표시 |
| S4 | 시작 입력을 놓고 본체를 새로 잡음 | 정상 잡기·미리보기·배치 가능. XR Rig·사용자 위치·시야 유지 |
| S5 | 빠른 클릭·양손 선택 | 시작 전환 1회, 장비가 시작 입력만으로 붙잡히거나 이동하지 않음 |
| S6 | 기존 조작을 끝까지 수행 | 배치→밴드→막대 회전·고정→시간 기록→마감 동작 유지. 교육 완료 UI가 구현됐다고 해석하지 않음 |
| S7 | Play 종료 후 재실행 | 다시 시작 대기. 이전 실행의 조작 허용 상태로 시작하지 않음 |
| S8 | 설정 메뉴 재실행 후 확인 | 화면·버튼·EventSystem 중복 없음, 안내판 월드 Transform 유지 |

에이전트는 실행하지 않았다. 새 구현 이후 사용자가 확인한 결과만 반영한다. 기존 지혈대 검증 완료 보고를 새 화면 통과 근거로 재사용하지 않는다.

## 7. 작업 경계
