## 2. 사용자 흐름과 입력 방식

| 단계 | 입력 | 결과 |
|---|---|---|
| 초기 | — | 잠김, 덮개 닫힘(열림 0). 고정장치 표시등 주황. 덮개 조작점 비활성 |
| 해제 | 고정장치 조작점(`Anchor_ClosureGrab`)에 손을 가까이 대고 선택(그립) 버튼을 **새로 누름** | 해제, 표시등 초록, `Unlocked` 이벤트 1회 |
| 전환 | 해제한 선택을 놓음 | 고정장치 조작점 비활성, 덮개 조작점(`Anchor_FlapGrab`) 활성. 덮개 열기에는 새 누름이 필요 |
| 열기 | 덮개 조작점에서 선택을 누른 채 손 이동 | 손 이동량을 덮개 손잡이 경로에 투영해 열림 값 갱신 |
| 놓기 | 선택 해제 | 현재 열림 유지 |
| 다시 잡기 | 다시 선택 | 그 순간의 손 위치·열림 값이 새 기준. 덮개가 손으로 튀지 않음 |

- XRI 구성: 조작점마다 `XRSimpleInteractable` + 비트리거 `SphereCollider`(반지름 0.018m). 스타터 리그의 Near-Far 근거리 캐스터는 트리거를 무시하므로 비트리거다. 상호작용 대상 Collider는 각 조작점의 구 1개로 고정해 주머니 물리 Collider가 선택되지 않는다.
- `XRGrabInteractable`을 쓰지 않는다. 주머니 본체·덮개 Transform을 XRI가 움직이지 않으며, 손은 열림 값만 만든다.
- 선택 허용 필터(`IXRSelectFilter`, `K1CarrierLid`): 새 선택은 해당 컨트롤러가 추적 중이고 조작점에서 `maxHandDistance`(기본 0.25m) 이내일 때만 허용한다. 먼 거리 레이 선택과 추적 소실 상태의 선택을 막는다. 이미 잡고 있는 손은 계속 통과시킨다(XRI가 선택 유지 중에도 필터를 재평가하기 때문).
- 잠긴 상태: 덮개 조작점이 비활성이고 필터도 거부하므로 덮개를 잡을 수 없다.
- 한 손 제어: 덮개 조작점은 `InteractableSelectMode.Single`. 다른 손이 선택하면 이전 손은 해제되고, 새 손이 현재 열림에서 이어서 제어한다.
- 추적 유효성: 선택한 인터랙터의 부모 `TrackedPoseDriver`에서 추적 상태(Position 비트)와 위치 입력을 확인한다(AED 접촉 검사와 같은 기준). 추적이 없으면 덮개를 움직이지 않고 기준을 버린다. 추적이 돌아오면 그 순간을 새 기준으로 삼아 튀지 않는다.
- 손 위치는 인터랙터 attach가 아닌 컨트롤러 포즈(`TrackedPoseDriver` Transform)를 쓴다. 레이 attach의 썸스틱 당김 등이 섞이지 않는다.
- 재잠금 없음. 실제 잠금 방식(벨크로·똑딱이·버클)과 군 절차는 확인되지 않아 모델링하지 않았다. 해제는 "지정 조작점 선택 + 색 변화"의 체험용 표현이다.

## 3. 덮개 자세 변환·보간

데이터: `K1_Carrier_Metadata.json`의 `rig.opening_poses`(0, 0.25, 0.5, 0.75, 1). 메뉴 3 실행 시 Editor가 변환해 `K1CarrierFlapPose`에 직렬화한다. 런타임은 `Source~`·JSON·UnityEditor API를 쓰지 않는다.

1. 표본마다 본 4개(BagRoot·FlapBase·FlapMid·FlapTip)에 대해 `D = C × (pose × rest⁻¹) × C⁻¹`(C: (x,y,z)→(-x,z,-y)), `importedPose = D × importedRest`. importedRest는 FBX 에셋의 실제 rest Transform이다. 방독면 수납 변환과 같은 방식이지만 별도 함수로 두어 수납 계산을 바꾸지 않았다.
2. 임포트 rest 위치와 메타데이터 rest 위치가 1mm를 넘게 다르면 중단한다. BagRoot가 어떤 표본에서든 움직이면 중단한다.
3. FlapBase/FlapMid/FlapTip만 부모 기준 local 위치·회전으로 바꿔 저장한다. 스케일이 1이 아니면 중단한다. Blender Euler·basis 값은 복사하지 않는다.
4. 런타임 보간: 인접 표본 사이 위치 Lerp, 회전 Slerp. 정적 확인 결과 각 본은 표본 간격마다 한 축으로 같은 각도(FlapBase 31.25°, FlapMid 3.75°, FlapTip 15°)만 돌고 local 위치는 일정하다. 0과 0.5 표본의 Slerp 중간값이 0.25 표본과 0.03° 이내로 일치해, 구간 보간이 원본의 선형 굽힘과 맞는다.
5. 열림 값은 `Mathf.Clamp01`로 0~1 밖으로 나가지 않는다.

손 → 열림 값:

- `K1CarrierLid`가 시작 시 같은 보간으로 `Anchor_FlapGrab`의 경로를 41점(주머니 로컬)으로 샘플링한 뒤 닫힘으로 되돌린다.
- 제어 중 목표점 = 기준 열림의 경로점 + (현재 손 − 기준 손). 현재 열림 ±`maxStepPerFrame`(기본 0.1) 구간에서 목표점과 가장 가까운 경로점을 찾아 열림 값으로 쓴다. 경로의 먼 부분으로 한 프레임에 건너뛰지 않는다.
- 손잡이 경로(정적 계산, Blender 주머니 좌표 y=뒤, z=위): 0 (−0.131, 0.121) → 0.25 (−0.190, 0.302) → 0.5 (−0.113, 0.496) → 0.75 (0.084, 0.601) → 1 (0.311, 0.553). 앞·위로 들어 올린 뒤 주머니 위를 넘어 뒤로 넘기는 약 0.86m 호다. 완전 열림 손잡이는 주머니 루트 뒤 약 0.31m, 상판 위 약 0.55m에 있다.

## 4. 상태 제공

`K1CarrierLid`(주머니 루트):

| 멤버 | 의미 |
|---|---|
| `IsUnlocked` | 고정장치 해제 여부 |
| `Openness` | 현재 열림 0~1 (`K1CarrierFlapPose.Openness`) |
| `IsFullyOpen` | 완전 열림. 열림 ≥ `fullyOpenEnter`(기본 0.97)에서 켜지고 < `fullyOpenExit`(기본 0.93)에서만 꺼짐 |
| `Unlocked` | 해제될 때 1회 |
| `FullyOpenChanged` | `IsFullyOpen`이 실제로 바뀔 때만. 같은 시점에 Console 로그 1줄 |

- 임계값·거리·프레임당 최대 변화량은 공학적 조작 설정이다. 교육 합격 기준이 아니다.
- 경계 부근 반복 알림은 히스테리시스로 막는다.
- 상태는 런타임 값이며 직렬화하지 않는다. Play에서 연 상태가 씬에 저장되지 않는다(Play 종료 시 Unity가 되돌림, 검사로도 확인).
- 방독면 잡기·꺼내기·교육 Runner 연계·점수는 없다.

## 5. Prefab 구성 (메뉴 3)

```text
K1_Carrier_Training            Rigidbody(kinematic), K1CarrierFlapPose, K1CarrierLid
  ModelSpace/K1_Carrier/…
    FlapBase/FlapMid/FlapTip   (기존 COL_Flap* 물리 Collider 그대로 본을 따라감)
      … Anchor_ClosureGrab
            ClosureSelectPoint   SphereCollider r=0.018 + XRSimpleInteractable (저장 시 활성)
            ClosureIndicator     지름 0.02m 구, MAT_K1_Carrier_ClosureIndicator, Collider 없음, 그림자 없음
        Anchor_FlapGrab
            FlapSelectPoint      SphereCollider r=0.018 + XRSimpleInteractable (저장 시 비활성)
  ColliderSpace/…              (기존 몸체 Collider 5개 그대로)
```

- 반복 실행: 기존 컴포넌트·조작점·표시등을 이름으로 찾아 재사용한다. 중복 생성 없음. 기존 `K1CarrierLid`의 색·거리·임계값과 조작점 반지름은 유지하고, 참조·자세 데이터·필수 설정(비트리거, 자기 Collider만, Single 선택, 저장 시 활성 상태)만 다시 쓴다.
- `Keep existing`: 기존 Prefab에 위 구성만 추가·갱신한다. 씬 인스턴스 override(위치 등)는 건드리지 않는다.
- `Replace`: 새 Prefab을 만든 뒤 같은 구성 단계를 거치므로 상호작용과 자세 데이터가 포함된다.
- 방독면 수납 복원(메뉴 1·3)은 이전과 같다. 메뉴 1은 주머니 상호작용을 건드리지 않는다.
- 조작점 구는 주머니 내부(안쪽 벽 기준)에서 2mm 이상 떨어져 입구를 막지 않고 수납된 방독면에 닿지 않는다. 조작점 오브젝트는 Prefab 내부에서 kinematic 주머니의 일부다.
- Animator(컨트롤러 없음)는 이전과 같이 본을 쓰지 않는다. 덮개 본은 `K1CarrierFlapPose.Apply`만 쓴다.

## 6. 검사 변경 (메뉴 4)

- 재질: "재질 1개" → 폴더 안 재질이 아틀라스와 표시등 **정확히 2개**. 표시등은 URP Unlit.
- Collider: "총 8개" → 물리 MeshCollider 8개 + 조작점 SphereCollider 2개, 그 밖의 Collider 없음. 입구·내부 비침범 검사에 조작점 구도 포함(비활성 포함).
- 스크립트: "MonoBehaviour 없음" → 루트의 `K1CarrierLid`·`K1CarrierFlapPose`와 두 조작점의 `XRSimpleInteractable`만 허용(정확히 4개, 다른 스크립트·누락 스크립트는 FAIL).
- 추가: `K1CarrierLid.TryValidate`, 참조 연결(자기 Prefab의 자세·조작점·`Anchor_FlapGrab`·표시등), 조작점 설정(비트리거, 자기 Collider만, Single, 위치 0·Scale 1, 렌더러 없음, 저장 시 활성/비활성), 표시등(재질, Collider 없음), 자세 데이터(구동 본 = 렌더 FlapBase/Mid/Tip, 표본 열림 값 = 메타데이터, 닫힘 표본 = 저장된 Prefab 자세, 표본 FK가 메타데이터 자세를 1mm 이내로 재현 — 본 원점과 본 X/Y 5cm 지점).
- 씬: 주머니 인스턴스의 `K1CarrierLid`·`K1CarrierFlapPose` 유효, 덮개가 닫힘으로 저장, 고정장치 조작점 활성·덮개 조작점 비활성으로 저장.
- 유지: 대상 재질만 `SaveAssetIfDirty`, 대상 씬 미검사 시 INCOMPLETE, 방독면 검색은 `SceneInstances`, 검사 메뉴는 씬·자산을 저장·수정하지 않음(Prefab은 `LoadPrefabContents`로 읽고 저장 없이 해제).

## 7. 정적 검토 결과 (에이전트, 실행 아님)

- XRI 3.4.1 패키지 소스 확인: `IXRSelectFilter`(`canProcess`, `Process`), `XRBaseInteractable.colliders`(비어 있으면 자식 Collider 자동 수집·트리거 제외), 선택 유지 중 `CanSelect` 재평가, 스타터 Near-Far 근거리 캐스터 `physicsTriggerInteraction = Ignore`, `selectActionTrigger = StateChange`(새 누름 필요), `keepSelectedTargetValid = 1`.
- 메타데이터: 열림 표본 5개, BagRoot 고정, 본별 등각 단일 축 회전, local 위치 일정, Slerp 보간 오차 ≤0.03°.
- 본 쓰기 경로: 덮개 본 Transform을 쓰는 코드는 `K1CarrierFlapPose.Apply` 하나. XRGrabInteractable·Animator Controller·Cloth 없음.
- 검사 함수에 자산·씬 저장/수정 호출 없음.
- 열려 있던 Unity Editor가 새 스크립트를 자동 임포트했다(`.meta` 생성). 에이전트는 Unity를 조작하지 않았고 `Editor.log`만 읽었다. 로그에는 `MilTrainSimVR.B.K1GasMask.dll`·`Assembly-CSharp-Editor.dll` 컴파일 성공(`Tundra build success`)과 `error CS` 없음이 기록돼 있으나, 그 컴파일이 마지막 수정(`K1CarrierLid.cs` 완전 열림 로그 줄 등)까지 포함했는지는 확인할 수 없다. 컴파일 확인은 사용자 항목으로 남긴다.
- 미확인: `LoadPrefabContents` 프리뷰 씬에 새 GameObject를 부모 지정으로 넣는 동작, 메뉴 실행 결과, 실제 선택·조작 감각.
