# 압박붕대 감김 경로 캐시 수정 — 2026-11-03

사용자 요청: "감김경로부터 수정". 감김 경로 FAIL 3건에 한해 직접 코드 수정을 진행했다. 나머지 확인 입력·단계 조건 문제는 이번 범위에 넣지 않았다.

## 1. 근거와 원인 판단

- 기존 로그는 오늘 Unity 시작으로 `C:/Users/MBC/AppData/Local/Unity/Editor/Editor-prev.log`로 이동돼 있다.
- 해당 로그 11137~11145행: 피부 여유 3.0 mm, 팔 축 거리 0.033 m, 안쪽 출구 거부 모두 PASS.
- 11354행 이후 스크립트 재컴파일·어셈블리 재로드가 있고, 11770~11778행에서 동일 항목이 피부 여유 -42.3 mm, 팔 축 거리 0.000 m, 안쪽 출구 거부 FAIL로 바뀐다.
- `PressureBandageWrapPath`의 `readonly wrapProfile` 배열은 재로드 시 새 배열로 생성되지만, 일반 private bool `prepared`는 핫 리로드 때 복원될 수 있다. `prepared == true`인데 반지름 배열은 0인 상태가 되면 `WrapProfileAt`이 재계산을 건너뛴다. 이 경로는 세 FAIL과 일치한다. 실제 사용자 재현 실행으로 확정한 결과는 아니다.
- Unity 공식 근거: [핫 리로드의 private 필드 복원과 NonSerialized](https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/code-reload-serialization/script-serialization/how-unity-uses), [readonly 필드의 직렬화 제외](https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/code-reload-serialization/script-serialization/rules).

## 2. 변경

파일: `Assets/B/Scripts/BleedingControl/PressureBandage/PressureBandageWrapPath.cs`.

- `prepared`, `widened`를 `[System.NonSerialized]`로 지정. 배열과 캐시 상태가 재로드 때 함께 초기화되게 한다.
- `OnValidate`에서 두 플래그를 무효화. 직렬화된 피부 프로파일·경로 값을 변경한 뒤에도 다음 조회에서 재계산하게 한다. 콜백 안에서는 기하 계산·Unity 객체 접근을 하지 않는다.
- 다음 `WrapProfileAt` 호출은 기존 `PrepareProfile(null)`로 피부 기반 외곽을 재생성한다. 드레싱 적용은 기존 `PrepareProfile(corners)`·`UpdateProfile(corners, tolerance)` 경로를 유지한다.
- 경로 수학식·검사 기준·허용오차·씬·Prefab·모델은 변경하지 않았다. 기존 폰트 변경도 보존한다.

## 3. 사용자 확인 순서

1. Unity 재컴파일 오류 여부 확인. Play가 아닌 상태에서 `B/Pressure Bandage/2. Validate Prefab and Practice Scene (report only)` 실행. 먼저 메뉴 1을 누르지 않아도 저장된 씬의 경로가 정상 계산되어야 한다.
2. 피부 여유가 `Clearance` 이상(기본 3 mm, 기존 검사 허용오차 유지), 팔 축 거리가 검사 기준보다 큼, 안쪽 출구 거부 PASS인지 확인. 최종 FAIL 개수도 기록.
3. 메뉴 2를 연속 두 번 실행. 다음으로 사용자 IDE의 Recompile Scripts 등으로 실제 스크립트 재컴파일·도메인 재로드를 발생시킨 뒤, 씬 재열기나 메뉴 1 없이 메뉴 2 재실행. 세 항목이 다시 FAIL로 바뀌면 실패.
4. 메뉴 1 → 메뉴 2 실행·재실행. 저장된 프레임·측정 프로파일·사용자 경로 값 보존, 중복 생성 없음 확인.
5. Simulator에서 교육 해당 단계까지 진행. 피부와 드레싱 밖 감김·고리 표시, 정상 경로 진행, 팔을 가로지르는 이동과 안쪽 롤 출구 거부 확인. 완료 후 다시하기에도 동일 동작 확인.
