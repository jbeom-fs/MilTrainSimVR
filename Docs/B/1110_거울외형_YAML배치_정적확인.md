## 2. FBX 참조 fileID와 근거

FBX meta의 `internalIDToNameTable`이 비어 있어, Unity가 이미 저장해 둔 임포트 결과(`Library/Artifacts`)를 읽어 fileID를 확인했다. 읽기만 했고 Unity나 Editor 스크립트는 실행하지 않았다.

- K1 결과 파일: `Library/Artifacts/df/dfd0af92c16f5910e99c7481476cb9ba`. PC 결과 파일: `Library/Artifacts/21/212b600c2a1e9700a35c76c9c41912c2`. 둘 다 Unity SerializedFile v22 형식이며, 객체 45개가 모두 크기 검사를 통과했다.
- 파일 생성 시각은 14:25:59로, FBX 최종 수정 시각 14:23:03보다 뒤다. 각 FBX의 부품 이름을 가진 직렬화 결과는 하나씩만 있다.
- 결과 파일 안의 객체 ID가 YAML fileID와 같다는 점은 사용자 확인을 마친 `B_FirstAidTable.prefab`으로 교차 확인했다. 이 프리팹의 메시 참조 `5060444177187149915`와 루트 ID `919132149155446097`·`-8679921383154817045`가 Table_2 결과 파일의 Mesh `Box001`과 루트 객체 ID에 그대로 있다.
- FBX 내부 Geometry ID는 쓰지 않았다. 모든 메시에 `4300000`을 가정하지도 않았다.

임포트 결과에서 확인한 구조는 두 모델 모두 같다. 루트 `K1_MirrorFrame` 또는 `PC_MirrorFrame` 아래에 부품 8개가 있고, 루트를 포함한 9개 노드의 Transform이 모두 위치 0·회전 0·배율 1이다. 메시 경계도 설계 좌표와 같다(K1 X ±0.421, Y −0.950~0.921, Z −0.010~0.150 / PC X ±0.471, Y −0.980~0.971, Z −0.010~0.150). 삼각형 합계는 K1 1,148, PC 1,212다. ## 3. 외형 프리팹 구성

이미 사용자 확인을 마친 `B_FirstAidTable.prefab`과 같은 방식이다. 새 프리팹 안에 FBX 모델 프리팹을 넣고, 재질만 덮어쓴다.

```
Visual                      (GameObject + Transform, 위치 0 / 회전 0 / 배율 1)
└─ K1_MirrorFrame           (FBX 모델 프리팹 인스턴스, 임포트 루트 Transform)
   ├─ K1_Frame / K1_Backplate / K1_RearSupport_L·R / K1_RearBrace_L·R / K1_Foot_L·R
   │   (FBX의 Transform + MeshFilter + MeshRenderer)
```

PC_MirrorVisual도 같은 구조이며, 중간 노드 이름은 `PC_MirrorFrame`이다.

- 덮어쓴 값:
  - MeshRenderer 8개의 `m_Materials.Array.data[0]`을 공유 금속 재질로 연결했다. 각 Renderer의 재질 칸은 1개다.
  - FBX 루트의 위치·회전 값은 Unity 기본 형식에 맞춰 적었다. 값은 임포트 결과와 같은 0/항등 회전이므로, 내부 노드를 초기화한 것이 아니다.
- 추가하지 않은 것: Collider, Rigidbody, Animator, Camera, Light, RenderTexture, 반사면, XR 잡기·선택 컴포넌트, 교육 컴포넌트.
- 각 프리팹 파일에는 Visual GameObject, Visual Transform, PrefabInstance 1개, 그 루트를 가리키는 stripped Transform만 있다. 루트는 하나이고 외형도 하나다.

## 4. 공유 금속 재질

`TrainingMirror_Metal.mat`은 B 소유 `KD1_Furniture.mat`의 YAML 구조를 템플릿으로 썼다. 템플릿 파일은 바꾸지 않았다.

- 셰이더: URP/Lit `{fileID: 4800000, guid: 933532a4fcc9baf4fa0491de14d08ed7, type: 3}`. B의 다른 Lit 재질 42개와 같은 참조다.
- 설정: `_Surface` 0(불투명), `_Metallic` 0.8, `_Smoothness` 0.32. 텍스처와 키워드는 없다.
- 색 공간: 프로젝트가 Linear(`m_ActiveColorSpace: 1`)이고, Unity 재질 색은 sRGB 값으로 저장된다. 그래서 Blender의 linear (0.065, 0.075, 0.082)를 sRGB로 바꿔 `_BaseColor`·`_Color` = (0.2828, 0.3035, 0.3171)로 저장했다. 이 값을 다시 linear로 바꾸면 0.065 / 0.075 / 0.082로 돌아온다.
- 기존 `MAT_K1_ObserverScreen`과 `PC_MirrorScreen`은 사용하지도 수정하지도 않았다.

## 6. 미확인 사항

- Unity가 이 YAML을 다시 불러온 결과는 확인하지 않았다. 누락 메시, 분홍 재질, 프리팹 연결, 저장 시 Unity가 YAML을 다시 정리하는지 여부가 여기에 해당한다.
- 실제 색과 광택은 미리보기와 비교하지 않았다.
- 정렬·접지·가림·깜빡임, 머리 이동 시 반사, K1 후면 보기, 보호의 착용 반사, 테이블·손·순간이동 간섭, 교육 종료·중단·재진입 후 동작도 확인하지 않았다.
- Unity Editor가 작업 중 실행 상태였다. B_CBRN이 Editor에 열려 있고 저장하지 않은 변경이 있다면, 저장하지 말고 디스크 버전을 다시 불러와야 이번 배치가 적용된다.
- 배치 판단은 이번 임포트 결과의 부품 이름·fileID에 근거한다. 나중에 FBX를 다시 내보내면서 부품 이름이나 노드 구조가 바뀌면 재질 덮어쓰기가 끊길 수 있으므로 다시 대조해야 한다.

## 7. 사용자 확인 순서

1. Unity에서 변경된 자산과 B_CBRN 씬을 다시 불러온다.
2. 누락 메시, 분홍 재질, 외형 중복이 없는지 확인한다. Hierarchy에서 `K1_Mirror`·`PC_Mirror` 아래가 각각 Surface, Camera, Visual 순서이고, Visual 아래 `*_MirrorFrame`과 부품 8개가 있는지 본다.
3. 프레임 개구부와 반사면이 정렬되는지, 바닥에 정상 접지하는지 확인한다.
4. 머리를 움직이며 반사 영상, 프레임 가림, 겹침 깜빡임을 확인한다.
5. K1 착용·후면 보기와 보호의 착용에서 몸·장비 반사가 유지되는지 확인한다.
6. 옆 테이블, 손 조작, 순간이동 경로와의 간섭을 확인한다.
7. 교육 종료·중단·재진입 후에도 기존 동작이 유지되는지 확인한다.

새 외형이 반사면을 가리거나 기존 교육·반사 참조가 바뀌어 있으면 미완료로 판단한다. 문제가 생기면 백업 씬으로 되돌릴 수 있다. 신규 프리팹·재질은 별도 파일이므로 지우기만 하면 된다.
