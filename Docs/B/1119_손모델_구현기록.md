# B 공통 리그 손 모델 적용 — 구현 기록 (2026-11-19)

상태: **사용자가 메뉴 1·2의 정상 실행 완료를 보고했으며, 공통 리그와 보호의 3개 씬에 저장된 적용 결과를 정적으로 대조했다.** Play·Quest 2 동작은 미확인이다. 아래 최초 구현 당시의 메뉴 실행 전 설명은 이력이며, 최신 상태는 §9를 우선한다. 정적 검토 결과를 VR 동작 통과로 기록하지 않는다.

후속: 사용자 삭제 지시에 따라 적용용 Editor 도구를 제거했다. 메뉴는 더 이상 제공되지 않으며 저장된 적용 결과와 런타임 코드는 유지한다. 삭제 내역은 §10을 우선한다.

## 5. 정적 검토 결과

- `HandTracking.DriverOf`·`K1CarrierLid`·`TourniquetDevice/Operation`·`PressureBandageApplication/PressureDressing`·`ProtectiveClothingEquipment`·`KD1Equipment`·`CommonPauseMenu` 는 모두 `interactor.GetComponentInParent<TrackedPoseDriver>()` 로 찾는다. 손은 컨트롤러의 형제(Camera Offset 아래)라 부모 사슬에 들어가지 않으므로 계속 컨트롤러 TrackedPoseDriver 를 찾는다.
- `RelativeHand`(제자리 조작)·`TrackedGrabHold`·`FreeHold`·`GrabBring` 은 Interactor·attach transform·컨트롤러 driver 를 쓰고 근접 캐스터 원점은 쓰지 않는다 → 조작량·자세 유지·추적 소실 처리 무변경.
- `BControllerInputActionManager`(스틱 역할·텔레포트·UI 스크롤), 공통 메뉴 레이·입력 복구는 컨트롤러 쪽 컴포넌트만 쓴다. ControllerHandPose 는 자체 InputAction(`<XRController>{LeftHand}/{Grip}` 등)만 읽어 B 입력 에셋을 켜고 끄지 않는다.
- 보호장갑: 숨김 조건(`HmdDrawsWorn && 해당 장갑 worn 메시 activeInHierarchy`)·forceRenderingOff·HMD/거울 분리를 그대로 두고 대상 Renderer 만 기본 손으로 바꿨다. 왼/오른 장갑이 각자 자기 손만 숨기고, 해제·초기화(worn 메시 숨김) 시 다음 LateUpdate/onBeforeRender 에 손이 돌아온다. 몸이 꺼지거나 시작 실패면 `HideAll` 이 손을 보이게 둔다. 추적·입력·Interactor 는 끄지 않는다.
- 보호의 구성 도구 `ProtectiveClothingSetup` 은 c312d6c 에서 삭제되어 현재 다시 실행할 경로가 없다. 장갑 Renderer 연결은 이번 메뉴 1 만 설정한다. 과거 도구를 git 에서 되살리면 옛 필드 이름 `leftControllerModel` 을 찾으므로 그대로는 동작하지 않는다 — 되살릴 때 이 메뉴 기준으로 고쳐야 한다.
- KD-1: `KD1HandMount` 는 컨트롤러 TrackedPoseDriver(현재 바인딩상 Quest 에서는 aim/pointer 자세가 우선) + fitPosition `(±0.01, -0.03, -0.12)`·fitRotation 으로 패드를 둔다. 기본 손은 그립 자세를 따르므로 둘 사이 상대 위치는 런타임 aim↔grip 차이에 달려 정적으로 확정할 수 없다. **근거 없이 fit 값을 바꾸지 않았다.** 패드 착용으로 손을 숨기지 않으며 착용·해제·접촉 판정·모델 무변경.
- 외부 Roslyn(`Unity 6000.3.13f1/Editor/Data/DotNetSdkRoslyn/csc.dll`)으로 수정 스크립트 2묶음의 타입 검사만 scratchpad 출력으로 해 오류 0. Unity 임포트·컴파일을 대신하지 않는다.

## 8. 미검증·남은 판단

- **손 위치 vs 근접 잡기**: 근접 캐스터 원점을 그립 자세(손 원점)로 옮겼다. 반지름 0.1 m 는 그대로라 체감 범위는 실기 확인 필요. 되돌리려면 공통 리그 Prefab 에서 해당 Near-Far Interactor 의 Sphere Interaction Caster `Cast Origin` override 를 Revert 한다.
- **잡은 물체와 손의 간격**: 잡은 물체는 기존처럼 Interactor attach(컨트롤러 aim 자세 기준)에 붙는다. 손은 그립 자세라 물체가 손 앞에 약간 떠 보일 수 있다. 장비별 attach 를 일괄 초기화하지 않았다. 실기에서 어긋남이 큰 장비만 개별 조정한다.
- **보호장갑과 손 위치 차이**: 장갑은 컨트롤러 자세 + `wristOffset` 으로, 기본 손은 그립 자세로 놓인다. 바뀌는 순간 위치 차이가 보이면 `wristOffset/handRotationOffset` 조정 대상이다 (이번 무변경).
- **KD-1 정렬**: 3개 씬(`B_CBRN`, `B_KD1_Equipment`, `B_KD1_Tutorial`)의 KD1HandMount fitPosition/fitRotation 무변경. 실기에서 패드가 기본 손 손목에서 벗어나면 좌우 마운트 값을 세 씬에 같게 조정한다.
- 손 Renderer 그림자·URP 재질 표시, 거울 카메라 컬링에 손 포함 여부, 성능은 미확인.

## 9. 사용자 메뉴 실행 후 저장본 정적 검토

2026-11-19 사용자 요청: 구현 보고서·실제 코드·씬 구성을 대조하고 문제를 보고한다. 사용자는 메뉴 1·2를 정상 실행했다고 보고했다. 에이전트는 Unity·Simulator·테스트·빌드를 실행하지 않았으며 코드·프리팹·씬은 변경하지 않았다. 이번 후속 변경은 이 기록과 Docs/B/AGENTS.md뿐이다.

### 9.1 저장 결과와 소스 대조

- `B_XR_Origin.prefab`: Camera Offset 아래 C 손 프리팹 좌우 각 1개를 중첩 참조한다. 손마다 로컬 위치 0·회전 identity의 `B_PalmPoint`가 1개씩 있고 좌우 근접 캐스터가 해당 점을 참조한다. 컨트롤러 외형 2개만 비활성화됐다.
- 변경 전 HEAD와 프리팹 override를 속성별로 대조했다. 기존 입력 액션 참조와 Interactor 설정 값은 유지됐고, 손 추가·근접 캐스터 원점 변경·외형 비활성화 외의 기존 동작 설정 변경은 발견하지 못했다. 루트 이름 저장과 YAML 인용·순서 변경은 별도 직렬화 차이다.
- B 씬 11개 모두 공통 리그 인스턴스가 1개씩 있다. 리그 개별 속성 override는 이름·위치·회전 계열이며, 손·캐스터·컨트롤러 외형 설정을 덮어쓰는 override는 발견하지 못했다.
- `B_CBRN`, `B_ProtectiveClothing_Equipment`, `B_ProtectiveClothing_Tutorial`의 `leftHandModel`은 공통 리그의 왼손 SkinnedMeshRenderer(fileID 7035100983345267098), `rightHandModel`은 오른손 Renderer(fileID 5303875590615372752)를 참조한다. 세 씬 모두 같은 좌우 대응이며 예전 컨트롤러 Renderer 배열은 교체됐다.
- `ProtectiveClothingUserBody` 변경은 필드 이름·직렬화 이전 속성·메서드 이름·설명 정리다. 장갑 표시 조건, `forceRenderingOff`, 카메라별 표시 처리의 계산식은 이전과 같다. 새 손은 컨트롤러의 형제 계층이라 Interactor 부모의 TrackedPoseDriver 조회를 가로채지 않는다.
- 보호의 씬 재저장 시 추가된 `floorReference: 0`, 튜토리얼의 `pickupMarker/pickupLabel/startGate: 0`은 기존 미직렬화 필드의 null 기본값 기록이다. 이번 손 적용에 의한 새로운 값 손실 근거는 발견하지 못했다.

### 9.2 문제 판단과 남은 확인

**현재 저장 구성과 변경 코드에서 추가로 수정해야 할 확정 오류는 발견하지 못했다.** 메뉴 검사 성공을 손과 장비의 실제 정렬·교육 조작·렌더링 통과로 확대하지 않는다.

1. **물체와 기본 손의 간격 — 실기 미확인:** 손은 device/grip 자세를 따르고 기존 장비 attach는 컨트롤러 쪽에 유지된다. 근접 감지 원점만 손바닥으로 이동했으므로 손바닥에서 잡기 시작해도 물체가 붙는 위치까지 손바닥으로 바뀐 것은 아니다. 기본 잡기·원거리 가져오기를 실제로 해 보고 눈에 띄는 간격·튐이 있는 장비만 개별 판단한다. 현재 새 결함으로 확정하지 않는다.
2. **보호장갑·KD-1 정렬 — 실기 미확인:** 보호장갑의 wristOffset/handRotationOffset, KD1HandMount의 fit 값은 이전 기준을 유지한다. 좌우 장갑 전환과 패드 착용 시 위치·회전 차이가 있는지 확인해야 한다. 파일만으로 보정값을 정하거나 일괄 변경하지 않는다.
3. **문서 상태 — 이번에 정정:** 최초 기록과 재개 포인터의 ‘프리팹·씬 적용 전’ 표현을 사용자 실행 보고 및 저장본 반영 확인 상태로 갱신했다. 메뉴 1 반복 실행의 ‘변경 없음’까지 사용자가 확인했다고 추정하지 않는다.
4. **기존 실기 조건:** B_CBRN의 XR Interaction Simulator는 현재 저장본에서 활성 상태다. 이 m_IsActive 0→1은 손 작업 전부터 있던 미커밋 변경이며 손 메뉴가 새로 켰다고 분류하지 않는다. Quest 2 실기 결과는 Simulator를 끈 조건과 구분해 기록한다. 이번 검토에서 해당 설정을 바꾸지 않았다.

다음 사용자 확인의 우선순위는 ① 손 추적·손가락 동작과 근거리/원거리 잡기 ② 좌우 장갑 전환·초기화 및 HMD/거울 표시 ③ KD-1 좌우 정렬 ④ 기존 장비 조작·공통 메뉴·이동·씬 전환이다. 구체적 입력·기대 결과·실패 기준은 §7을 사용한다. 사용자가 이미 완료한 메뉴 1·2를 미실행 상태로 재배정하지 않는다.

## 10. 적용용 Editor 도구 삭제

사용자 명시 지시로 `Assets/B/Editor/XR/BRigHandsSetup.cs`, `MilTrainSimVR.B.XR.Editor.asmdef`와 각각의 `.meta` 등 4개 파일을 삭제했다. 따라서 손 적용·갱신 및 구성 검사 메뉴는 더 이상 제공되지 않는다. 빈 폴더와 폴더 `.meta`는 삭제 대상에 포함하지 않았다.

삭제 후 4개 파일의 부재와 공통 리그의 좌우 손 프리팹 참조, 보호의 3개 씬의 좌우 손 Renderer 필드 유지를 파일로 확인했다. 손 프리팹·모델·재질, `ControllerHandPose`, `ProtectiveClothingUserBody` 등 런타임 코드와 적용된 씬·프리팹은 변경하지 않았다. Unity 실행·컴파일·Play 검증, 스테이징·커밋·Push는 하지 않았다.
