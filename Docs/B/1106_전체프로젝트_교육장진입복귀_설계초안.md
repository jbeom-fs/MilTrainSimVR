# 전체 프로젝트와 B 교육장 진입·복귀 설계 초안 — 2026-11-06

> **11/10 최종 마감:** [1110 작업 마감](1110_작업마감_진행상황.md)과 [포털 보류 문서의 A 후속 정보](1110_허브복귀_포털방식_보류.md)를 우선한다. A가 HubPortal_ToHub 프리팹과 적용 안내를 준비했으나 B 설치와 사용자 보류 해제는 아니다. 현재 B 출구는 분야 간 직접 이동 코드이며, 허브 경유·포털 방식은 후속 채택안이다. 이번에는 문서만 갱신한다.

## 11/10 최신 결정 — 허브 경유·포털 재사용·구현 보류

- [1110 허브 복귀 포털 방식·보류](1110_허브복귀_포털방식_보류.md)를 우선한다. 최종 이동은 **허브→구급법→허브→화생방→허브**이며 구급법↔화생방 직접 이동을 제외한다.
- B 출구는 버튼 대신 A 허브와 동일한 포털 형태로 구성하고 A 기존 기능을 재사용한다. A가 포털 기능을 추가 변경할 수 있어 사용자 지시로 구현은 보류하며 지금은 문서만 기록한다.
- 아래 분야 이동·복귀 UI·별도 연결 씬 안내는 이력이다. 현 코드·씬의 직접 이동은 아직 변경하지 않았으며, A 변경 확인 후 최신 구조를 점검한다.

## 11/09 현황 — 수동 배치 완료·A_Hub 기준 후속 연결

- 구급법·화생방에 B 소유 내무반/테이블 자산을 YAML로 적용했고 사용자가 씬 수정 확인 완료를 보고했다. 사용 종료된 운영 씬 생성·자동 반입 도구는 삭제하고 읽기 전용 검사만 유지한다.
- 현재 A_Hub에는 B_FirstAid·B_CBRN 진입 포털이 존재하고 A의 HubPortal·CourseRoute가 씬 이동을 제공한다. B의 기존 출구는 두 분야 간 이동 전용이므로 B→허브 복귀 UI·종료 정리·재진입 정책이 다음 연결 범위다.
- 공용 EditorBuildSettings에는 B 두 씬이 이미 등록돼 있다. A_Hub는 없고 첫 씬은 SampleScene이므로 실제 배포용 Build Profile의 시작 씬과 목록을 확인한다.
- 사용자 추가 과제인 화생방 거울 외형 모델링과 후속 작업 순서는 [1109 작업 마감](1109_작업마감_진행상황.md)을 따른다. 현재 문서 갱신으로 허브 연결이나 모델 제작을 시작하지 않는다.
- 아래 A_Sandbox 추가 로드/별도 연결 씬 초안은 과거 후보이며 현재 채택안으로 재사용하지 않는다. A/C 작업물과 B 밖 설정의 소유권 경계는 유지한다.

## 11/06 방향 이력 — A 환경 외형 반입과 메뉴 정리

사용자는 A의 모델링만 B 씬에 가져오는 방식이 좋아 보인다고 했으며, 그 전에 씬 작업용 메뉴를 정리하는 순서에 대한 의견을 요청했다. 아래의 A_Sandbox 추가 로드/별도 연결 씬 안은 이전 후보이며 현재 채택 방향으로 구현하지 않는다.

- A 원본 씬·코드·프리팹·모델은 보존한다. 공간 외형을 B 소유 작업본으로 가져와 EnvironmentRoot 아래 구성하고 기존 B의 XR·교육·UI·StationRoot를 사용한다.
- A의 교육 진행·총기 조작·문 전환 코드와 XR/입력 시스템을 환경 외형과 함께 가져오지 않는다. 실제 반입할 방/건물/집기 범위는 후속 배치 설계에서 정한다.
- 독립적으로 유지할 환경은 필요한 모델/재질 의존성을 B 작업본으로 복사한다. A 원본을 편집하거나 원본 참조에 변경을 적용하지 않는다.
- 선행 작업은 B Editor 메뉴 정리 제안이다. 아직 코드/메뉴 정리를 실행하지 않았다.

메뉴 정리 의견:
1. 현재 Training Field의 구급법/화생방 구성·갱신 및 읽기 전용 검사 4개는 주 작업 메뉴로 유지한다.
2. 개별 과정 최초 생성·프리팹 재생성·세부 장비 구성·Tutorial UI 적용은 개발 도구 하위로 모아 현재 운영 씬 작업과 구분한다. 사용 종료 또는 삭제가 승인됐다고 가정하지 않는다.
3. 메뉴 노출 정리와 내부 함수 삭제를 구분한다. 기존 과정 빌더가 TrainingUiSetup.ApplyInScene을 호출하고 보드 검사도 기존 Setup의 문구 후보를 재사용하므로 파일 통째 삭제를 하지 않는다.
4. 최초 생성과 기존 씬 갱신, 검사 기능의 역할을 명확히 한다. 향후 환경 반입 후에도 갱신/검사가 수동 환경 배치·StationRoot를 덮어쓰지 않는 기준을 정한다.
5. 참조 없는 일회성 도구만 삭제 후보로 정리한다. A/C 메뉴는 변경하지 않는다.

현재 문서는 방향·의견 기록이며 구현 프롬프트나 코드 수정이 아니다.

## 사용자 결정

- PB 마지막 확인은 넘어가도 된다고 했다. 다음 작업으로 다시 요구하지 않는다. 이를 개별 장치/체크리스트 항목의 통과 결과로 확대하지 않는다.
- 다음 범위는 전체 프로젝트에서 B 교육장으로 진입하고 복귀하는 흐름의 설계다. 구현 지시가 아니다.
- 교육 선택/복귀 공간은 기존 A 공간을 활용할 수 있으면 활용한다. 단 **A 작업물에 변동을 가하면 안 된다**는 사용자 조건이 우선이다.

## A 보존 경계

A의 원본 씬·프리팹·모델·재질·스크립트·메타, 기존 배치와 교육 동작은 유지한다. A 원본 씬에 B 버튼/연결 컴포넌트를 붙여 저장하는 작업도 하지 않는다. 기존 출입문의 잠금을 해제하거나 DoorTransition을 씬 전환 코드로 수정하는 방식도 제외한다.

새 연결 기능은 Assets/B 아래 별도 씬/오브젝트/코드가 소유한다. A/C 문서는 읽기 전용이며 타 담당에게 도구로 메시지를 보내지 않는다. 공용 BuildSettings 등 B 밖 설정 변경은 이 설계로 승인된 것이 아니다.

## 읽기 확인한 현재 구조

- A 공간: Assets/A/Scenes/A_Sandbox.unity. 내무반/사격장과 기존 XR Interaction Manager·EventSystem이 있다.
- A DoorTransition은 같은 씬 안 목적 Transform으로 이동한다. 사격장 B/C용 Door_Exit는 잠긴 상태로 구성돼 있다. 기존 문에 씬 전환 기능이 이미 있다고 가정하지 않는다.
- B는 B_FirstAid/B_CBRN 사이 Single 씬 전환이 있고, 각 씬이 XR Origin과 입구 추적/배치를 소유한다.
- B 출구는 실습 소유자가 없고 대상 씬을 사용할 수 있을 때 이동한다. 완료/중단 정리는 기존 과정 동작을 유지한다.
- B 결과는 현재 방문 중 메모리 상태다. 점수·영구 저장·전체 이수 추적을 이번 연결에 자동 추가하지 않는다.

## A를 보존하며 활용하는 연결안

별도 B 소유 연결 씬에서 A_Sandbox를 원본 그대로 추가 로드하고, 교육 선택 안내와 복귀 기준점을 B 연결 씬 소속 오브젝트로 둔다. A 공간·기존 방 이동은 그대로 사용한다. 이 방식의 실제 로딩/입력 호환성은 구현 전에 정적 설계를 더 구체화해야 하며, 아직 완성되거나 실행 확인된 구조가 아니다.

흐름 초안:

1. 연결 씬이 A 공간을 읽어온다. A의 XR/입력 구성을 사용하며 연결 씬에 중복 XR Origin·EventSystem을 두지 않는다.
2. B 소유 안내에서 구급법 또는 화생방을 선택한다. 원본 A 오브젝트의 배치/설정을 바꾸지 않고 연결 안내를 별도로 둔다.
3. B 교육장으로 이동할 때 외부 복귀 정보만 전달하고, 목적 교육장은 기존 EntryAnchor/실제 HMD 추적 대기 흐름을 사용한다.
4. 구급법↔화생방 이동에서는 최초 외부 복귀 정보를 유지한다. 이를 직전 B 씬으로 덮어써 복귀가 B 안에서 맴돌게 하지 않는다.
5. 교육장 밖으로 나가면 A 공간을 불러오는 연결 씬으로 돌아가 B가 소유한 복귀 기준점에 사용자를 배치한다.

새 복귀 기능과 기존 B 분야 이동은 구분한다. 실습 진행/보류/완료 요약 등 현재 소유권이 남아 있을 때의 정리는 기존 중단·교육 종료 경로를 따른다. 이동만으로 장비/과정을 임의 완료하거나 중단시키지 않는다.

## 다음 설계에서 정할 사항

- A 공간 안 B 안내의 실제 위치와 진입/복귀 기준점. 기존 A 공간을 가리거나 사격 동선을 침범하지 않아야 한다.
- A 교육이 진행 중일 때 B 진입을 허용할지와, 복귀할 때 A 교육 상태를 어떻게 취급할지. A 기존 동작을 변경하지 않는 범위에서 합의해야 한다.
- 외부 진입 요청과 복귀 정보를 누가 보관할지, 직접 B 씬 실행 시 외부 복귀 기능을 어떻게 표시할지.
- 씬 전환 중 입력·화면 처리와 XR/입력 시스템 단일 소유권. A 기존 시스템을 임의로 비활성화해 중복을 해소하는 방식은 쓰지 않는다.
- C 연결은 담당 범위와 진입점이 확정된 뒤 같은 공용 흐름에 연결한다. 이번 B 설계로 C 파일을 변경하지 않는다.

이 초안은 사용자 조건을 기록하고 연결 방향을 제시한 것이다. 코드·씬·프리팹·ProjectSettings 수정, Unity 실행, 스테이징·커밋은 하지 않았다.
