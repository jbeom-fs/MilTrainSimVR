## 9. AED Raycaster 적용 수정본 검토

사용자 보고와 실제 AedBoardUi/TrainingUiSetup 및 적용→검사→저장/복구 경로를 읽었다. 코드·씬·글꼴 수정이나 실행 검증은 하지 않았다.

- AedBoardUi.Build의 create 블록에서만 KeepXrRaycasterOnly를 호출한다. 검사 경로 Build(false)는 정리 함수를 호출하지 않는다.
- 정리 함수는 Canvas를 확인하고 TrackedDeviceGraphicRaycaster가0개일 때만 추가한다. 기존 XR 컴포넌트에는 설정을 쓰지 않는다.
- GetType()==typeof(GraphicRaycaster)인 컴포넌트만 제거하고 남은 정확타입을 다시 확인한다. BaseRaycaster 전체나 모르는 하위 타입을 지우지 않는다.
- CheckScene은 XR용 정확히1개·enabled1과 일반 GraphicRaycaster0을 각각 검사한다. 이전 항상false가 되는 서로 다른 클래스 간 is 비교를 제거했고 실제 개수·상태·타입을 로그에 포함한다.
- 실패가 남으면 Apply의 검사에서 예외가 나 저장 전 취소되고 저장본으로 복구되는 구조는 유지된다. 반복 적용이 XR 컴포넌트를 새로 중복 생성하지 않는다. 기존에 중복이 있다면 임의 삭제하지 않고 검사 FAIL로 남긴다.
- 이번 수정 범위에서 추가 필수 코드 오류는 발견하지 못했다. ‘반복 적용이 중복을 생성하지 않음’과 ‘모든 사전 중복을 자동 정리함’은 구분한다.
