# B 내무반 외형 반입 도구 검토 — 2026-11-06

## 결론과 확인 범위

구현보고서, 새 C#5개(총1,037행), 기존 B 입구/이동 코드, 설치된 XRI 소스 및 현재 Editor.log를 읽었다. **보완3건**이다. 첫째는 기존 로그에서 확인한 실제 메뉴 실패, 나머지 둘은 정적 코드에서 확인한 배치/검사 문제다. 에이전트는 Unity 컴파일·메뉴·Play·Simulator·HMD·테스트·빌드를 실행하지 않았다.

보고서는 실제 반입 미실행 시점 설명이지만 현재 Editor.log에는 B_FirstAid 반입 실패가 있다. 따라서 ‘메뉴 실행 대기’만으로 현재 상태를 설명하지 않는다. 현재 공유 B 프리팹/ImportManifest는 존재하지 않고 B 운영 씬의 새 변경도 없다. 로그에는 저장본 복구·이번 생성 자산 제거가 명시돼 있다.

## P1 — 실제 경계가 고정 구역보다 커서 구급법 반입 실패

근거: BarracksEnvironmentSetup.Layout.cs:19의 Slots, :103의 PlaceStations, :138의 실패 조건. 실제 Editor.log의 오류는 ‘실제 경계로 2+1 배치 후보를 찾지 못했습니다’다.

| 구분 | 측정/허용 크기 |
|---|---|
| 왼쪽·오른쪽 구역 각각 | 폭3.05×깊이4.25m |
| 뒤쪽 구역 | 폭7.70×깊이2.82m |
| AED 실제 측정 | 4.02×4.48m |
| 지혈대 실제 측정 | 2.65×4.72m |
| PB 실제 측정 | 4.91×3.58m |

배치 코드는 이 실제 경계에 각 방향으로0.08m씩, 전체 치수로0.16m씩 여유를 더한다. 회전 후보는0/90/180/270도다.

- AED는 여유 포함 최소 변이4.18m라 양옆 구역의 폭3.05m와 뒤쪽 깊이2.82m 모두 초과한다.
- PB도 최소 변이3.74m라 어느 구역에도 들어가지 않는다.
- 지혈대는 양옆 구역에는 맞지 않고, 회전하면 뒤쪽 구역에는 수평 치수상 들어갈 수 있지만 다른 두 실습대가 배치되지 않아 전체 검색은 실패한다.

즉 현재 고정 구역에서는 검색 순서나 단순 재실행으로 해결되지 않는다. 앞선 공간 조사는 저장된 areaSize 기준이었고, 이번 코드는 Content+FieldUI+비활성 오브젝트까지 포함한 실제 종합 경계를 측정하므로 더 큰 값이 나온다.

보완 방향: 어떤 Renderer/Collider/Canvas/실습범위가 각 경계의 최솟값·최댓값에 기여하는지 먼저 출력하여 실제 필요한 범위와 표시용 경계를 확인해야 한다. 그 결과로 구역·통로·배치 탐색을 조정하거나 더 넓은 공간 안을 재검토한다. 장비 축소·판정 삭제·경계 검사 무력화로 통과시키지 않는다. 이 로그는 현재 고정2+1 알고리즘의 실패를 입증하며, 내무반 안의 모든 가능한 배치가 물리적으로 불가능하다는 증명은 아니다.

## P2 — 입구 안내판이 초기 시선 뒤쪽에 배치됨

근거: BarracksEnvironmentSetup.Layout.cs:155~158.

- EntryAnchor 위치(0,0,-0.9), yaw180 → 사용자 정면은-Z.
- EntranceBoard 위치(-2,1.45,-0.35).
- ExitBoard 위치(2,1.35,-0.35).

두 보드는 입구보다Z가0.55m 크므로 사용자 뒤쪽이다. 입구 정면 벡터와 보드 중심까지 수평 벡터의 내적은-0.55이며, 정면에서 수평 약105.4도다. 기존 Coordinator는 실제 HMD가 추적되면 EntryAnchor 방향으로 정렬한다. 따라서 입장 직후 정면에서 입구 준비/교육장 안내를 찾기 어려운 배치다. 아직 이 코드는 구급법 배치 실패 뒤에 있어 실제 화면 재현 결과는 아니다.

보완 방향: 입구 안내판을 입구 시선의 앞/읽기 가능한 방향에 두고 입구 사용자를 향하게 한다. 방/통로/실습대 간섭 검사와 함께 시선 앞쪽 여부도 확인한다. 기존 입구 추적 대기 및 정렬 로직을 바꿀 필요는 없다.

## P2 — B 외형 수동 편집 후 벽·문·창이 이동 셀 계산에서 빠짐

근거: BarracksEnvironmentSetup.Layout.cs:190~203의 Obstacles, :263의 WalkableMask, Inspect.cs:209 이후의 InspectWalkable.

Obstacles는 실습대, 입구/출구 보드, 기존 환경 소품을 넣지만 `child.name == "B_BarracksShell"`이면 외형 전체를 건너뛴다. 따라서 그 안의 벽·문·창 충돌체는 목적지 제외 마스크에 들어가지 않는다. 고정 Interior 사각형만으로 외곽을 제한한다.

원래 요구하고 보고서도 보존한다고 한 **B 환경 자식의 수동 위치/크기/회전 변경 후 재실행**에서 문제가 된다. 예를 들어 B 작업본의 벽을 실내 통로 안쪽으로 옮기면 해당 벽 부근 셀을 제외하지 않는다. InspectWalkable도 같은 누락된 WalkableMask와 비교하므로 마스크 일치 검사만으로는 이를 검출하지 못한다. 별도 환경 충돌 검사는 실습대 전체 경계·입구·실습 목적지 중심을 보지만 모든 이동 셀의 사용자 공간이나 중앙 통로 전체를 검사하지 않는다.

이는 Inspector로 컴포넌트를 강제 파손한 사례가 아니라 도구가 지원한다고 한 환경 배치 편집 흐름의 검사 누락이다. 현재 원본 외형 그대로 반입했을 때의 VR 관통을 재현했다는 뜻은 아니다. 벽을 통한 레이 차단은 별도 경로이므로 ‘반드시 벽을 뚫고 이동한다’고 확대하지 않는다.

보완 방향: 새 외형의 실제 활성 벽/문/창 등 충돌체를 높이와 형상에 맞춰 목적지 제외에 반영하고, 바닥/천장은 별도로 분류하여 바닥 전체를 장애물로 처리하지 않는다. 사용자 점유 여유와 입구 연결성/통로, 셀 주변 충돌을 함께 확인한다. 수동 배치를 보존하되 유효하지 않은 목적지는 거절해야 한다.
