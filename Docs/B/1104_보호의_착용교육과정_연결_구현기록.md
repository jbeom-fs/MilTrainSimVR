## 2. 교육 흐름

시작 화면 → ① 상의 → ② 하의 → ③ 왼쪽 장갑 → ④ 오른쪽 장갑 → ⑤ 왼쪽 덮개 → ⑥ 오른쪽 덮개 → 자동 완료·요약 → 완료 후 다시하기 → 시작 화면.

- **순서 데이터**: `ProtectiveClothingTrainingIds.Order`(= `ProtectiveClothingPart` 열거 순서). 교안이 확정되면 이 배열과 `TrainingSubtitles`의 단계 문구만 바꾸고 메뉴 3을 다시 실행하면 된다.
  - 단계 ID(`pc-jacket`, `pc-trousers`, `pc-glove-left`, `pc-glove-right`, `pc-overboot-left`, `pc-overboot-right`)와 상태 ID(`jacket-worn` … `overboot-right-worn`)는 위치가 아니라 구성품에 속하므로, 순서를 바꿔도 그대로 유지된다.
  - 여섯 구성품의 누락·중복은 `TryValidateOrder`가 검사한다(Link 검증, 메뉴 3 시작, 메뉴 4).
- **완료 조건**: k번째 단계는 `Order[0..k]`의 현재 착용 상태를 모두 요구한다(누적 State 조건, Action 없음). 마지막 단계는 여섯 구성품의 현재 착용을 모두 요구한다.
- **같은 데이터 기준**: 단계 순서, 완료 조건(교육 데이터), 허용 구성품(Gate), 안내 대상(Guide), 단계 박스, 요약 순서가 모두 `Order`에서 나온다.
- **판정하지 않는 것**: '착용'은 장비의 가상 착용 상태(`ProtectiveClothingEquipment.IsWorn`)만 뜻한다. 밀착·여밈·오염 방지·보호성능은 판정하지 않으며, 그렇게 표시하지 않는다.

## 4. 상태와 책임 분리

- **장비 상태 소유자**: `ProtectiveClothingEquipment`(착용, 선택 해제, Pickup/Worn 표시, 장비 초기화).
- **교육 연결**: 장비 상태를 읽기만 해서 TrainingTarget과 Runner에 전달한다(Link).
- **교육 허용 조건**: 장비 쪽 작은 연결점(`wearGate`)으로 제공한다. 장비 어셈블리는 Tutorial을 모른다.
- **화면 전환**: StartScreen 하나. **다시하기**: TrainingReset 하나. **요약**: Link가 현재 RunId에 귀속해 한 번 확정.
- **안내 소유권**: 교육 씬에서는 교육 Guide만 안내 문구·고리를 쓴다. 장비 안내판 `PC_Board`(`ProtectiveClothingGuide`와 개발용 초기화 버튼)는 메뉴 3이 **삭제하지 않고 비활성으로 보존**한다. 실행 중에도 시작 관문이 활성 장비 안내를 발견하면 시작을 거부한다(우회 방지). 장비 씬의 안내는 그대로다.

## 5. 상태 전환

| 관문 상태 | 화면 | 잡기·착용 | 표식 |
|---|---|---|---|
| WaitingForStart | 시작 화면, 준비/불가 이유 줄, 시작 버튼(준비 시에만 활성) | 전부 잠금 | 숨김 |
| Started + 실행 중 | 실습 화면 + 단계 줄 | 현재 단계의 미착용 구성품만 | 고리 하나 |
| Started + Completed + 이번 회차 요약 | 완료 화면 | 전부 잠금(Runner가 실행 중이 아님) | 숨김 |
| Resetting | 시작 화면(버튼 꺼짐) | 전부 잠금 | 숨김 |
| Faulted | 시작 화면, 시작 불가 또는 다시하기 실패 줄 | 전부 잠금 | 숨김 |

**시작**: 버튼은 준비 상태(아래 조건 충족)일 때만 활성이고, 누르는 순간 꺼진다. `TryStart`는 WaitingForStart에서만 한 번 받는다.
- 준비 조건: 참조, 순서 데이터, 장비·몸 유효, 초기화 실패 아님, 장비의 관문이 이 관문, 활성 장비 안내 없음, 착용 0, 모든 Pickup 복귀, 선택 없음, 매니저 등록, 장비·몸 실행 중, 포커스.
- 일시적인 거부(장비를 잡고 있음, 몸 대기, 포커스)는 대기 상태를 유지한다. 설정 오류와 Runner 시작 실패는 Faulted로 바꾼다.
- Runner가 첫 단계로 정상 시작한 경우에만 Started가 된다. 그 순간 선택 입력을 누르고 있는 인터랙터는 손을 뗄 때까지 새 선택을 못 한다(압박붕대와 같은 방식).

**단계 제한**:
- 시작 전·완료 후·다시하기 중에는 장비 조작이 잠긴다.
- 실습 중에는 선택 필터와 착용 판정이 **같은** `link.AllowsPart`를 쓴다. 이미 잡은 장비라도 허용되지 않은 구성품은 착용되지 않는다(장비가 arming을 해제할 뿐, 선택을 강제로 끊지 않는다).
- 기존 규칙(한 손 한 장비, 장갑 반대 손, 추적, 포커스, 영역 밖 arming)은 그대로다.
- 다음 구성품은 Runner가 단계를 넘긴 뒤에만 열리므로, 한 프레임에 여러 단계를 건너뛰거나 다음 구성품을 미리 착용할 수 없다.

**자동 완료**: 마지막 구성품을 착용하면 다음 프레임에 Runner가 Completed가 된다. 같은 프레임 Link(55)가 여섯 착용을 다시 확인하고 이번 RunId의 요약을 한 번 만든다. 완료 패널(110)과 StartScreen(112)이 그 뒤에 완료 화면을 보인다.
- Completed인데 여섯이 모두 착용되지 않았다면 요약을 만들지 않고 "교육이 중지되었습니다"를 표시한다.
- 최종 확인 버튼이나 확인용 단계는 없다. 점수·영구 저장·무안내 평가도 없다.

**다시하기**(완료 화면의 버튼만, 연속 입력은 버튼 즉시 꺼짐 + `IsResetting`으로 차단):
① 관문 Resetting, 고리·단계 줄 정리 → ② Runner 정지, Link가 RunId·상태·요약을 잊음 → ③ `ResetEquipment()` → ④ 착용 0, Worn 숨김, Pickup 활성, 선택 없음, 초기화 실패 아님을 확인 → ⑤ 완료 캐시·버튼 정리. 컨트롤러는 UserBody가 장갑 표시에 따라 자동으로 복원 → ⑥ 관문 WaitingForStart, 시작 화면.
- 실패하면 Faulted로 바꾸고 "다시하기를 준비하지 못했습니다"를 표시하며, 시작 버튼은 꺼진다.
- 씬 재로드는 없다. XR Origin·시점·거울·안내판·착용 영역 값은 건드리지 않는다.

## 6. 실행 순서와 상태 전달

| 순서 | 구성 요소 | 동작 |
|---|---|---|
| Update(-105 부근) | XRI 매니저 | 선택 처리, 장비 필터 → 관문 `AllowsSelect` |
| LateUpdate 0 | TrainingRunner | 지난 프레임 Link가 쓴 상태로 Tick |
| 40 | UserBody | 몸 해석 |
| 50 | Equipment | 착용 판정(관문 `AllowsWear`) |
| 55 | Link | 이번 프레임 착용 상태 기록, Completed면 요약 확정 |
| 105 / 110 / 112 | Guide / Completion / StartScreen | 표시 |

**한 프레임 지연**: 프레임 N에 착용 → N의 Link 기록 → N+1의 Runner(0)가 단계 진행 → 다음 구성품 선택은 N+2의 XRI 갱신부터 가능하다. 진행 대기 중에는 "다음 단계로 넘어갑니다."가 보인다.
- 오래된 상태 방지: 시작 시 Link가 상태를 모두 false로 비운 뒤 Runner를 시작하고 즉시 현재 값을 쓴다. Runner는 진입 프레임에는 판정하지 않는다. 다시하기 때는 Runner 정지와 상태 비우기가 장비 초기화보다 먼저 일어난다. 요약은 RunId가 일치하고 Completed일 때만 유효하다.

## 11. 남은 제한

- **순서는 임시**: 교안이 확정되면 `Order`와 문구를 교체해야 한다. 실제 착용 품질(밀착·여밈·오염 방지·보호 성능)은 판정하지 않는다.
- **한 프레임 지연**: 단계 진행은 착용 다음 프레임에 일어나고, 다음 구성품 잡기는 그다음 프레임부터 가능하다. 사용 중에 체감할 정도는 아닐 것으로 보지만 미확인이다.
- **시작 화면 비용**: 대기 중 매 프레임 준비 검사를 한다. 성능 영향은 미측정이다.
- **교육 중 다시하기 없음**: 이번 범위다. 실습 중 문제가 생기면 Play를 다시 시작해야 한다.
- **h5 모델 제약**(1104 기록 §9): 소매 아래·겨드랑이·옆구리 관통이 가벼운 굽힘 최대 7.95 mm·팔 내림 5.82 mm·회전 5.67 mm 남는다. 팔꿈치 굽힘 최대 늘어남 2.395배, 손 가슴 2.476배, 옆구리 실루엣 최대 18.5 mm 축소가 남는다. 몸통·다리는 추정 자세이고 거울은 단안 영상이다. Unity 임포트·1인칭·거울·성능은 미확인이다.
- **임포트 설정**: Worn `.meta`의 `animationType`은 메뉴 1/3 실행 시 0→2로 바뀐다. 모델 작업의 바이트 보존 정책과 충돌할 수 있으므로, 커밋 시 Generic(2) 상태를 유지할지 사용자가 결정해야 한다.

- 메시 노드 전역(루트 × Lcl)은 바인드 좌표계와 **−90° X만큼 다르다**. 파일 내부에서 노드 변환과 스킨 바인드가 서로 맞지 않는 것이다. Blender importer의 재부모화·축척 100 보상(1104 미비작업 기록 §9의 원시 재수입 실패)도 같은 원인으로 보인다. 원인은 io_scene_fbx가 아마추어의 자식이 아닌 스킨 메시의 Lcl에 축 변환을 한 번 더 적용한 것으로 **추정**하며, 확인하지 않았다.
- 판단: importer의 정상 보상 변환이 아니라 **내보낸 파일의 노드 변환 결함**이다. 검사 장면 정규화 결과(§9)는 Unity 정상 근거로 쓰지 않는다.

검사 변경(`ValidateWornFrames`, 메뉴 2·4 공통):
- **스킨 좌표계 계약**(새 검사): 모든 본의 `bone × bindpose`가 Worn 루트 좌표계와 같아야 한다(1 mm, 0.1°). 각 메시를 그 좌표계로 그린 경계가 마네킹 바인드 자세 경계(+0.1 m) 안에 있어야 한다. HMD·거울에서 옷이 그려지는 위치의 계약이다. 원시 FBX 기준으로는 통과가 예상되지만 **Unity 결과는 미확인**이다.
- **노드 변환 계약**(기존 검사를 분리): 메시 GameObject가 루트 원점(항등)에 있어야 한다. 현재는 FAIL이 예상된다. 기대값(항등)·실제 위치/회전/축척·원인·영향을 보고하고, 보상하지 않는다.

### 13.3 부품별 가중치 읽기와 판정

- 부품마다 `sharedMesh.boneWeights`를 읽는다. 예외가 나거나 '가중치 수 ≠ 정점 수'이면 그 부품만 미읽기로 두고 이유를 남긴다.
- 읽은 부품의 판정:
  - 0.0001을 넘는 가중치만 유효로 본다.
  - 유효 가중치가 잘못된 인덱스(범위 밖이나 빈 본)를 가리키면 위반이다.
  - 허용 부위 밖 가중치, 필수 본이 스킨 목록에 없음, 필수 본에 가중치 없음도 위반이며 FAIL로 보고한다. 보고에는 판정한 부품 목록을 함께 적는다.
- 미읽기 부품은 별도의 NOT RUN으로 대상·이유를 보고한다. 부위 규칙·필수 본 가중치·동반 본 가중치를 판정하지 않았다는 뜻이며, PASS가 아니다.
- FAIL과 NOT RUN이 함께 나올 수 있다. 읽은 부품이 하나도 없으면 PASS 문장 없이 NOT RUN만 남는다. 읽기 위해 임포트 설정을 바꾸지 않는다.

### 13.4 원점·스킨 좌표계·Attach 보고

- 세 검사(스킨 좌표계 / 메시 노드 원점 / Attach)와 허용치는 그대로이며, 보상하지 않는다.

## 14. 남은 좌표계 FAIL 2건 — 검사 기준 보완 (2026-11-04)

상태: **Editor 검사 코드만 수정했다. 수정본의 컴파일·메뉴 1~4·Play는 미실행.** FBX·`.meta`·가중치·골격·텍스처·씬·런타임 코드는 바꾸지 않았다. 이 절은 §12.2 #1·§12.3·§12.8 ③·§13.4·§13.7의 '스킨 좌표계/노드 원점' 해석보다 우선한다.

### 14.1 근거: 최신 실행 결과와 원시 판독

- **최신 메뉴 결과**(사용자 실행, 이전 검사 코드): FAIL 2건이었다.
  - '스킨 좌표계 = 루트': 6종 모두 0.0 mm, 90.00°.
  - '메시 노드 = 루트 항등': 회전 (270,0,0)°.
  - 같은 결과에서 '노드 vs 스킨 좌표계'는 0.0°·0.0 mm였다.
  - 그 밖에 Attach 0.00 mm, 65본 계약, 65본 직접 추종·동반 0, 부위 가중치(6부품 판정), 좌우 컨트롤러 각 9개는 모두 PASS였다.
- **현재 Worn FBX**: SHA256 `037fdfed…` = `Source~/WornNodeFix/DeliveryManifest.json`의 전달 파일.
- **원시 판독**(임시 판독 스크립트, 읽기만 함): 메시 노드 `Lcl`이 루트 아래 항등이고, 6종 모두 '스킨 바인드 = 노드 = 루트 전역'이다. 원시 FBX 계약은 충족한다.

### 14.2 루트 항등 가정이 Unity 검사에 맞지 않았던 이유

- Unity FBX 임포트(`bakeAxisConversion` 꺼짐)는 FBX 축 변환을 모델 루트 GameObject에서 빼고, 그 회전을 루트의 자식에 둔다. 그래서 원시 FBX에서는 항등인 메시 노드가 Unity에서는 루트 대비 −90° X GameObject가 된다. 메시 정점은 그 GameObject 공간의 좌표다.
- 스킨 표시식은 `bone.localToWorld × bindpose × 정점`이다. Unity의 bindpose는 그 메시 GameObject 기준으로 만들어진다. 따라서 기준 자세에서 `bone × bindpose`는 루트가 아니라 **메시 GameObject의 행렬**과 같아야 한다.
- 이전 검사는 이를 루트 항등과 비교했기 때문에, 정상 임포트에서도 90°가 나왔다. Attach 0.00 mm와 경계 상자 정렬 통과는 이 해석과 일치한다.
- **정정 1**: "스킨 좌표계 FAIL이면 즉시 Blender 재내보내기"(§12.9·§12.8 ③)는 이 FAIL에는 해당하지 않는다. 앞으로도 판단 근거는 새 일관성 검사(14.3)의 잔차와 사용자 표시 확인이다.
- **정정 2**: §12.4·§13의 "Unity가 `optimizeBones`로 마네킹 말단 13본을 제거한다"는 추정은 최신 결과(마네킹 골격 65본, 직접 추종 65·동반 0)로 틀렸음이 확인됐다. 동반 규칙은 다른 임포트를 위한 제한된 예외로 남기며 현재는 쓰이지 않는다.

### 14.3 새 비교 공간과 판정식 (`ValidateWornFrames`, 메뉴 2·4 공통)

1. **스킨 좌표계 = 메시 GameObject 좌표계**(필수)
   - 판정식: 각 메시의 GameObject 공간에서 잔차 `mesh.worldToLocal × bone.localToWorld × bindpose`가 항등인지 본다.
   - 대상: 그 메시에서 가중치가 0.0001을 넘는 본(실제 가중치 본)만 판정한다.
   - 허용치(기존 그대로): 위치 1 mm, 각도 0.1°, 축척 1e-3.
   - 보고: 판정 부품, 가중치 본 슬롯 수, 판정하지 않은 등록 전용 본 수, 최대 잔차(위치·회전·축척).
   - 가중치가 잘못된 본 인덱스나 빈 본을 가리키거나 가중치 본이 하나도 없으면 FAIL이다. 가중치를 못 읽은 부품은 NOT RUN이다.
   - 실제 불일치는 계속 FAIL이다. 노드와 바인드가 1 mm·0.1°를 넘게 어긋나면 그 각도가 루트에 대해 몇 도인지와 관계없이 FAIL이다. 특정 회전(90° 등)을 예외로 두지 않았다.
   - 기준 자세: 비교에는 Worn 자산의 rest 본을 쓴다. rest = 마네킹 바인드 자세 검사(ValidateWornRig)를 그대로 유지한다.
2. **공통 모델 공간 정렬**(보조): 각 메시를 위 스킨 좌표계로 그린 경계가 공통 모델 공간에서 마네킹 바인드 자세 경계(+0.1 m) 안에 있어야 한다. 경계 상자 비교일 뿐이며, 표면·착용감·변형 품질의 통과가 아니다.
3. **메시 GameObject의 루트 대비 변환**: 회전·위치·축척을 INFO로만 보고하며 필수 판정이 아니다. 아무것도 덮어쓰지 않는다.
4. **원시 FBX 노드 계약**: Unity 임포트로는 볼 수 없다.
   - 현재 FBX의 SHA256을 계산해 전달 기록과 대조한다. 일치하면 기록의 `raw_fbx_fail_1_fixed`·`raw_fbx_fail_5_fixed`·`raw_blender_parent_local_direct_check_passed` 값을 '재측정하지 않은 기록' INFO로 보여 준다.
   - 해시가 다르거나 기록이 없으면 NOT RUN이며, 기록의 PASS를 현재 Unity PASS로 쓰지 않는다.
5. **Attach**: 이름·부모·공통 모델 공간 위치를 문서와 대조한다(1 mm, 그대로). 실패 시 진단은 '같은 로컬 오프셋을 그 메시의 스킨 좌표계로 놓은 위치'로 바꿨다. 이전 진단은 '메시가 루트 원점'을 가정했다.

### 14.4 유지한 것

- 65본 이름·부모 계약, 스킨 등록 본 검사, 런타임과 같은 본 대응(현재 직접 65·동반 0), 부위별 실제 가중치 FAIL/NOT RUN 구분(가중치 읽기를 `ReadBoneWeights`로 공용화, 기준 0.0001·유효 인덱스 동일), 동반 본 가중치 검사.
