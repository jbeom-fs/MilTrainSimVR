# C02 교육 진행·완료 판정 구현 안내

작성일: 2026-10-21 · 변경 범위: `Assets/B/**`, `Docs/B/**`

C01에서 검증한 XR 조작을 교육 진행과 연결한다. 검증용 과정은 **Cube 잡기 → 놓기 → 다시 잡고 3초 유지 → 완료**다. 실제 처치·제독 교육 절차가 아닌 공통 시스템 테스트다.

## 1. 추가한 기능

| 구성 | 구현 내용 |
| --- | --- |
| `TrainingDefinition` | 교육 ID·단계 ID·완료 조건을 ScriptableObject로 보관. 실행 결과는 에셋에 쓰지 않음 |
| `TrainingTarget` | XR/장비 UnityEvent에서 행동을 보고하고 bool 상태를 갱신. 직접 단계 전환하지 않음 |
| `SceneBindings` | 대상 ID와 실제 Target 연결. 중복 ID·누락 참조·중복 상태 ID 검사 |
| `TrainingContext` | 현재 단계의 행동·상태·유지 조건을 판정하는 일반 C# 실행 데이터 |
| `TrainingRunner` | 시작·중단, 이벤트 구독, 프레임 종료 시 조건 평가, 다음 단계·완료 이벤트와 Console 진단 로그 |

스크립트: `Assets/B/Scripts/Training`.
교육 데이터: `Assets/B/Data/C02_GrabReleaseHold.asset`.
테스트 씬: `Assets/B/Scene/B_C02_TrainingTest.unity`.
자동 테스트: `Assets/B/Tests/Editor/TrainingContextTests.cs`.

기존 `B_FirstAid.unity`의 저장된 구성을 복사한 테스트 씬에만 Runner·Bindings·Cube Target·이벤트 연결을 추가했다. 원본 씬과 공용 Prefab은 수정하지 않았다. 기존 `Test.cs`도 보존했다.

## 2. 실행 순서

1. Unity가 새 스크립트·asmdef·에셋을 가져오고 컴파일을 마칠 때까지 기다린다.
2. `Assets/B/Scene/B_C02_TrainingTest.unity`를 단독으로 연다. C01 씬과 Additive로 동시에 실행하지 않는다.
3. Console을 열고 Play 실행. `B_Training_C02`의 Runner가 자동 시작한다.
4. Game 창에 포커스를 두고 C01에서 사용한 Simulator 조작으로 Cube를 지정한다.
5. 오른손 `G`를 누른 상태로 Cube를 잡는다. Console이 `grab-cube`에서 `release-cube`로 변경되는지 확인한다.
6. 누르고 있던 `G`를 떼어 놓는다. Console이 `hold-cube-3-seconds`로 변경되는지 확인한다.
7. Cube를 다시 지정하고 `G`를 누른 상태로 3초 유지한다. 다음 완료 로그가 한 번 출력되는지 확인한다.

```text
[Training] Step: grab-cube
[Training] Step: release-cube
[Training] Step: hold-cube-3-seconds
[Training] Completed: c02-grab-release-hold
```

잡기 입력은 오른손 `G`, 왼손 `Shift + G`다. 사용자 검증 결과 현재 환경은 누르고 있는 동안 잡고 키를 떼면 놓는 방식이다. 기존 토글 안내를 이 동작으로 정정한다. 왼손으로 유지할 때는 해당 키 조합을 유지한다. 놓은 뒤 Cube를 다시 지정해야 잡을 수 있다. 3초 유지 중 놓으면 해당 유지시간은 0부터 다시 계산한다. 현재 단계는 Console에서 확인하며 자막 UI는 C04에서 구현한다.

검증용 전체 상태 초기화는 **Play 종료 → 다시 Play**로 수행한다. Runner의 `Stop Training`은 교육 진행·구독만 중단한다. `Start Training`은 진행 데이터를 새로 시작하며, 잡힌 물체·위치·장비 상태를 복원하지 않는다. XR 선택 해제와 씬 상태 복원은 C05 범위다.

## 3. 판정 방식

| 종류 | 의미 | 예 |
| --- | --- | --- |
| `Action` | 현재 단계 진입 이후 발생한 특정 대상의 일회성 행동 | `test-cube`가 `grab` 보고 |
| `State` | 평가 시점의 현재 bool 상태 | 두 패드의 `attached=true`가 모두 유지됨 |
| `HoldState` | 현재 상태를 설정 시간 동안 연속 유지. 불충족 시 시간 초기화 | `test-cube`의 `held=true`를 3초 유지 |

한 단계의 조건은 전부 충족해야 한다(AND). 잘못된 대상·행동은 무시한다. 대상/상태가 없거나 비활성 상태면 조건을 충족하지 않는다. `ExpectedValue=false`도 대상/상태의 존재를 먼저 요구하므로 누락된 상태를 성공으로 처리하지 않는다.

행동 콜백에서는 완료 사실만 기록하고 실제 전환은 Runner의 `LateUpdate`에서 수행한다. 같은 프레임에 반복 호출해도 한 단계만 전환한다. 새 단계에 진입한 프레임의 추가 행동은 받지 않아 이전 단계의 중복 입력이 다음 단계를 완료하지 않게 한다.

실행 ID·단계 진입 번호를 담은 `TrainingStepToken`으로 이전 실행·단계의 지연 보고를 거절한다. 비동기 장비 동작은 시작 시 `Runner.CurrentToken`을 보관하고 완료 시 `Runner.ReportAction(targetId, signalId, token)`을 호출해야 한다. UnityEvent의 `TrainingTarget.ReportAction`은 즉시 발생한 현재 행동용이다.

C02 상태는 `Idle / Running / Completed / Stopped`다. C03의 진입·종료 Action 및 비동기 대기 구현 시 `Entering / Exiting`과 해당 전환 규칙을 추가한다.

## 4. Inspector 연결

`B_Training_C02`에는 Runner와 SceneBindings가 있다. Runner의 Definition은 테스트 교육 데이터, Bindings는 같은 GameObject의 SceneBindings로 연결돼 있다. SceneBindings의 Targets에는 Cube의 TrainingTarget을 등록했다.

Cube의 Target ID는 `test-cube`, 상태 ID는 `held`, 초기값은 false다. `XR Grab Interactable`의 이벤트 연결은 다음과 같다.

| XR 이벤트 | Target 호출 | 용도 |
| --- | --- | --- |
| Select Entered | `SetStateTrue("held")` | 현재 잡기 상태 갱신 |
| Select Entered | `ReportAction("grab")` | 잡은 행동 보고 |
| Select Exited | `SetStateFalse("held")` | 놓기 상태 갱신 |
| Select Exited | `ReportAction("release")` | 놓은 행동 보고 |

위 `SignalId`는 판정용 ID이며 출력 자막이 아니다. 향후 자막 원문은 기존 지침대로 `TrainingSubtitles` 상수에만 선언한다.

## 5. 완료 기준과 검증 상태

- Unity 컴파일·EditMode 테스트: 원본 프로젝트 설정을 보존하기 위해 B 코드·테스트만 복사한 별도 임시 프로젝트에서 Unity `6000.3.13f1`로 실행. 12개 통과, 실패·건너뜀 0개.
- 자동 테스트 범위: 중복 전환, 잘못된 대상·행동, 현재 상태 해제, 누락 상태, 유지시간 초기화, 이전 토큰, 중단·새 실행, 데이터 검증. 동일 테스트의 독립 .NET 실행도 통과.
- 신규 씬 정적 검사: Object ID 중복 없음, 신규 Script·데이터 참조와 XR 콜백 4개·3단계 데이터 연결 확인. 실제 씬 Play 검증과 구분.
- 원본 `B_FirstAid.unity`: 작업 전후 SHA256 동일 확인.
- 신규 테스트 씬의 Simulator 기본 흐름: 사용자 검증 완료 보고. 잡기→놓기→3초 유지 동작에 문제없음. 현재 입력은 키를 누르는 동안 잡고 떼면 놓는 방식이다.
- Quest 2 + Link 실기: 확인 대기. Simulator 통과와 별도로 기록한다.

검증 기준: 위 3단계 완주, 유지 중 놓았을 때 시간 초기화, 완료 로그 1회 출력. Play 종료·재실행 후 같은 동작 반복 가능해야 한다. 사용자 보고는 기본 흐름 통과로 기록하며, 추가 수동 항목의 개별 수행 결과까지 추정하지 않는다.

## 6. 이번 단계 이후

사용자 정정에 따라 다음 작업은 실제 구급법·제독 체험 구성을 우선한다. 기존 AED 우선 제안을 기준으로 환자·AED·패드와 전원·부착 조작을 구체화하고, 필요한 Object 제어·안내·복원은 해당 체험에 함께 연결한다. C03~C05 전체를 별도 일반 테스트로 선행 완성하지 않는다. 코드는 직접 작성하지 않으며, 명시적 요청 시에만 구현 프롬프트를 제공한다.
