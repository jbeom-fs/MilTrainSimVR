# 교육 시스템 구조 검토

작성일: 2026-10-19
범위: 기존 설계 + static class 자막 요구사항 검토.
기준: Unity/C#, Quest 2, 컨트롤러 2개, 사용자 1명. 프로젝트 경로는 `D:\TeamProject\MilTrainSimVR`, Editor 버전은 `6000.3.13f1`. XR SDK는 이번 구조 검토에서 미확인.
판정: 구현 가능한 설계. 아래 보완 규칙 적용 필요. 본 문서는 설계 검토이며, 기존 Unity 코드 검토·컴파일·실기기 검증은 미수행.

## 구조

```text
TrainingDefinition (ScriptableObject, 변경하지 않는 교육 데이터)
 └─ Steps: EnterActions / CompletionConditions / ExitActions
                ↓
TrainingRunner (현재 교육 1개, 단계·전환·종료·재시작 소유)
 ├─ TrainingContext (이번 실행 상태, 대상 연결, 행동 전달 경로)
 ├─ StepActionExecutor → 활성 상태 / Animator / 배치 / 안내
 ├─ StepConditionEvaluator ← Interaction 행동 + 장비 현재 상태
 └─ 초기 상태 캡처·복원과 장비별 Reset 호출

SceneBindings: 교육 데이터의 대상 ID → 실제 씬 Object·컴포넌트
Interaction: 감지·장비 동작·상태 갱신 → 이번 실행에 행동 전달

Cue: SubtitleId + AudioClip
 → PresentationController
     ├─ TrainingSubtitles.Get(SubtitleId) → static class의 const string
     ├─ 자막 UI
     └─ 음성 재생
```

TrainingContext는 Runner가 소유하는 작은 런타임 데이터 객체로 시작한다. 별도 전역 Manager를 만들지 않는다. Action 실행기는 물리·잡기 세부 처리를 장비 컴포넌트에 요청하고, 각 장비 내부 상태를 직접 변경하지 않는다.

## 1. static class 자막과 교육 데이터 연결

- 모든 출력 문구는 TrainingSubtitles의 const string에 선언한다. 교육별 중첩 static class를 사용할 수 있다.
- Inspector의 Cue에는 자막 원문 대신 SubtitleId를 보관한다. TrainingSubtitles.Get에서 명시적 switch로 상수에 연결한다.
- static/const 필드는 Unity 직렬화 대상이 아니다. ScriptableObject 필드에 상수 값을 복사해 저장하면 이후 상수 수정이 기존 에셋 문구에 자동 반영되지 않으므로 문자열 복제는 금지한다.[1]
- SubtitleId enum은 명시적 정수값을 부여한다. 기존 값 재번호·재사용 금지. None과 잘못된 값은 구분한다.
- 리플렉션·필드명 문자열 검색은 사용하지 않는다. 없는 ID는 시작 전 검사에서 명확히 보고한다.
- Cue는 SubtitleId와 음성 클립의 연결 정보만 보관한다. 자막만 있는 Cue도 허용한다. 음성과 문구의 의미 일치는 콘텐츠 검수 대상이다.

## 2. 데이터 직렬화와 씬 연결

- 초기 Action/Condition 설정은 Serializable 데이터와 명시적 종류 값으로 구성한다. 일반 interface 목록이 Inspector에서 자동 편집될 것이라 가정하지 않는다.[1]
- 실제 필요한 Action만 지원: SetActive, Animator 제어, 배치, PlayCue. 종류별 세부 데이터와 필수값을 검사한다.
- ScriptableObject에는 씬 실행 상태나 씬 대상 참조를 저장하지 않는다. 대상 ID는 SceneBindings에서 연결한다.
- 씬 연결은 직렬화된 목록으로 편집하고 런타임 조회용 Dictionary를 만든다. Dictionary의 기본 Inspector 직렬화를 가정하지 않는다.[1]
- 시작 전: ID 중복·누락, 필요한 컴포넌트, 유효한 단계·조건·Cue 검사. 잘못된 설정이면 해당 교육 시작을 중단하고 대상과 단계를 명시한다.

## 3. 단계 진행과 중복 처리

- Runner 상태는 Idle / Entering / Running / Exiting / Completed / Stopped로 구분한다.
- 조건은 진입 Action 전에 준비하되, 다음 단계 전환은 진입 작업 완료 후 허용한다. 일반 안내 음성은 기본적으로 진행을 막지 않는다.
- 대기 작업 중 입력을 허용할지 단계 설정으로 명시한다. 허용한 입력은 현재 단계에만 반영하고, 잠근 입력은 상호작용 자체를 비활성화한다.
- 이벤트 콜백 안에서 재귀적으로 다음 단계를 실행하지 않는다. 전환 요청은 한 번만 접수해 순차 처리한다.
- 실행 회차 ID와 단계 진입 번호로 오래된 완료 콜백을 무시한다. 재시작 시 이전 실행 콜백은 모두 무효다.
- 정상 종료는 ExitActions를 실행한다. 중단·재시작은 완료 보상 등 정상 종료 동작을 실행하지 않고 취소·정리 후 초기화한다.

## 4. 행동 이벤트와 현재 상태 구분

- 버튼 누름은 단계 진입 후 발생한 사건으로 판정한다. 패드 부착·보호의 착용은 장비의 현재 상태로 확인한다.
- 두 패드가 모두 부착되어야 한다면 과거 부착 이벤트 2개를 세지 않고 현재 두 패드 상태를 확인한다. 하나를 떼면 조건도 다시 불충족이다.
- 잘못된 도구·대상 행동은 완료에 포함하지 않는다. 여러 Collider는 같은 논리 대상 ID로 묶고 중복 진입·이탈을 처리한다.
- InteractionZone은 감지만 담당한다. 부착 확정, 회전 누적, 접촉 유지의 실제 판정은 해당 행동 컴포넌트가 담당한다.
- 활성화 시 이미 겹친 대상, 비활성화·파괴로 Exit 이벤트가 오지 않는 경우도 상태를 재확인·정리한다. Trigger 설정, Rigidbody 구성, 레이어 충돌 설정을 함께 검사한다.[2]
- 유지 시간은 유효 도구·대상·실행 상태일 때만 증가한다. 접촉 해제 시 초기화 또는 누적 정책을 해당 교육 요구로 정한다.

## 5. Object·Animation·Transform 제어

- SetActive가 Runner·실행기·안내 시스템의 부모를 끄지 않도록 교육 대상과 시스템 루트를 분리한다.
- 끄거나 재배치할 잡기 대상은 먼저 XR 선택을 해제하고 관련 작업을 중단한다. 단순 Transform 변경만으로 처리하지 않는다.
- Transform 소유자는 한 시점에 하나: XR 잡기 / 물리 / 교육 이동 / Animation. XR Grab은 이동 방식에 따라 Rigidbody 또는 Transform을 제어하므로 동시 쓰기를 막는다.[3]
- 배치 작업은 대상 ID와 목적지 앵커 ID를 사용한다. 부모·로컬/월드 좌표 기준을 명시한다.
- Animator는 정해진 상태·파라미터로 제어한다. 단순 시간 지연을 실제 Animation 완료로 간주하지 않는다.
- 기다리는 동작은 완료·취소·실패를 구분한다. 중단·대상 소실 시 대기를 끝내고 오류를 보고한다. 무한 반복 Animation을 완료 대기 대상으로 지정하지 않는다.
- 기본 Action 목록은 순차 실행. 음성·시범 Animation 등 동시 재생할 작업만 비대기 시작으로 명시한다. 임의 병렬 그래프는 도입하지 않는다.

## 6. 음성·자막 수명

- 단계 안내는 한 번에 하나. 새 안내로 교체할 때 이전 음성과 자막을 함께 정리한다.
- 각 Cue 재생에 식별자를 부여한다. 이전 음성 완료 콜백이 새 자막을 숨기지 못하게 한다.
- 잘못된 접촉 피드백은 반복 충돌마다 출력하지 않는다. 같은 오류의 연속 재생을 제한한다.
- 오류 안내가 본 안내를 중단하는지, 자막만 표시하는지 명시한다. 초기 버전은 짧은 오류 자막으로 제한한다.
- 환경음·효과음은 단계 안내 음성과 채널을 분리한다. 안내 중단이 모든 AudioSource를 중단하는 구조는 피한다.

## 7. 재시작·중단

중단 순서: 전환 차단 → 실행 회차 무효화 → 이벤트 구독 해제·대기 작업 취소 → 안내 중단 → XR 선택 해제 → 장비·씬 상태 복원 → 실행 데이터 초기화.

복원 대상은 교육이 변경하는 대상만 명시적으로 등록한다. 씬 전체를 자동 스냅샷하지 않는다.

- 활성 상태, 부모, 로컬 위치·회전·크기.
- 변경한 물리 상태와 잔여 속도.
- 장비 부착·조임·오염 처리 상태, Collider/Interaction 활성 상태.
- 변경한 Animator 상태·파라미터.
- 진행 중 유지 시간, 완료 플래그, 자막·음성.

장비 고유 상태는 작은 Reset 계약으로 장비가 복원한다. 재시작 중 발생한 복원 이벤트는 평가에 반영하지 않는다. 씬 비활성화·종료 시에도 구독과 작업을 정리한다.

## 검증 계획

1. 자막 연결: static 상수만 수정 → 기존 교육 에셋 수정 없이 표시 문구 변경 확인.
2. 데이터: 대상·Cue 누락, 중복 ID → 교육 시작 전 정확한 오류 확인.
3. 단계: 같은 프레임 중복 행동 → 단계 1회 전환 확인.
4. 상태: 패드 부착 후 분리 → 완료 조건 무효 확인.
5. Trigger: 복수 Collider, 이미 겹친 채 활성화, 도구 비활성화 → 잘못된 유지·완료 없음 확인.
6. 작업: Animation 대기 중 중단·재시작 → 대기 종료, 이전 콜백 무시 확인.
7. XR: 잡고 있는 도구 재배치·비활성화 → 선택 잔류·위치 진동 없음 확인.
8. 안내: 음성 A 중 B 재생 → A 완료가 B 자막을 지우지 않음 확인.
9. 복원: 임의 단계에서 반복 재시작 → 최초 장비·씬 상태 일치 확인.
10. 재사용: AED 후 방독면 과정 추가 → Runner에 교육별 분기 없이 구성 확인.
11. Quest 2 빌드: 컨트롤러·부착·제독 접촉, 자막 가독성, 성능 실측. 성능 합격 기준은 목표 프레임레이트 확정 후 설정.

이는 실행할 검증 목록이며 통과 결과가 아니다. 첫 구현 전 XR SDK와 버전, 입력 방식, 대표 장비 모델 확정 필요.
