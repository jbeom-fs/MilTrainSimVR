# 압박붕대 직접 압박 판정 영역 완화와 진행률 표시 (2026-11-03)

상태: **코드·Prefab 수정 완료. 컴파일·메뉴 1/2·Play·Simulator·헤드셋 모두 미확인. 미커밋.** 착수 시 작업 트리에는 감기 전 확인 입력 판정 수정(미커밋)과 폰트 자산 변경이 있었다. 둘 다 보존했다. ③~⑦ Dressing 조건 누락은 이번 범위가 아니다.

## 1. 판정 영역

| 값 | 이전 | 변경 | 저장 위치 |
|---|---|---|---|
| `pressZoneRadius` | 0.08 m | **0.12 m** | C# 기본값 + `PressureBandage_Training.prefab` |
| `pressZoneHeight` | 0.16 m | **0.22 m** | C# 기본값 + Prefab |
| `pressZoneBelow` | 0.03 m | 0.03 m 유지 | — |
| `contactCheckSeconds` | 5 s | 5 s 유지 | — |

- 적용 방식: Prefab YAML의 `PressureDressing` 직렬화 값 두 줄을 직접 바꿨다(diff 2줄).
- 씬(`B_PressureBandage_Tutorial`)의 Prefab 인스턴스에는 이 네 필드의 override가 없다. 따라서 씬 실효 값은 Prefab 값 0.12 / 0.22 / 0.03 / 5 s다.
- 별도 사용자 조정값은 발견되지 않았다.
- 메뉴 1(`ConfigureDressing`)은 이 값을 쓰지 않는다. 기존 컴포넌트는 `GetOrAdd`로 유지되므로 메뉴를 다시 실행해도 예전 값이 복원되지 않는다. 메뉴 1 로그에는 실효 값이 표시된다.
- 메뉴 2 `ValidateContactZone`(Prefab·씬 각각):
  - 이전 좁은 값(반경 0.08 / 높이 0.16)이 남아 있으면 FAIL이다.
  - 실효 값은 INFO로 보고한다. 개발 기본값과 다른 값은 "user value", 인스턴스 override가 있으면 "[instance override]"로 표시한다. 이런 사용자 값은 덮어쓰지 않고 보고만 한다.
- 판정 구조는 그대로다(`Refresh`). 조건은 양손 컨트롤러 추적 + 영역 안 + 배치 유효 + 포커스이고, GRAB은 필요 없다. 연속 누적 방식(끊기면 0, 첫 프레임 0, `MaxCountedStep`)도 같다.
- 이탈 유예, 추적 판정, 완료 시간, Single Select, 한 손 유지 조건(`holdReach`)은 변경하지 않았다.

## 2. 진행률 표시

- 화면: 단계 줄 + 행동 한 문장 + `압박 유지 N%` 한 줄(`TrainingSubtitles.ContactProgressFormat`).
- 담당: `PressureBandageTrainingGuide`만 갱신한다(`contactProgressText`, `ShowProgress`).
- 값: `PressureDressing.ContactProgress`를 읽어 정수 %로 표시한다(내림, 0~100). 읽기 전용이다. 새 타이머·완료 판정·이력 변경은 없다. 접촉 시간 계산은 여전히 `PressureDressing.Refresh` 한 곳뿐이다.
- 표시 조건: 현재 안내 요구가 `Contact`(③ 직접 압박)일 때만 보인다. 추적 소실·포커스 이탈 안내 중에도 같은 단계이므로 0%가 보인다(끊기면 `contactSeconds`가 0).
- 다른 요구, 시작·최종 확인·완료 화면에서는 빈 줄이다.
- 이력(`HasCompletedContactPractice`)은 진행률에 쓰지 않는다. Link(104)가 연습 기록을 본 같은 프레임에 Guide(105)의 요구가 다음으로 넘어가므로 줄도 함께 사라진다. 100% 표시를 위한 지연은 없다.
- 다시하기: `ClearForReset`이 캐시를 초기화하고 빈 줄로 만든다. Awake도 빈 줄로 시작한다.
- `TryValidate`는 진행률 텍스트를 요구한다. 행동 문장과 같은 텍스트이거나 확인 영역 안에 있으면 오류다.

## 3. 안내판 레이아웃 개정 6

배치는 안내판 단위 기준이다.

| 요소 | 개정 5 | 개정 6 |
|---|---|---|
| `Practice/ContactProgress` (신규, 24pt, 왼쪽) | — | y 58, 높이 36 → 40..76 |
| `Practice/Check/Card` | (0,-4) 612×158 → -83..75 | (0,-40) 612×154 → -117..37 |
| `Practice/Check/CheckTitle` | y 50 | y 14 (-3..31) |
| `Practice/Check/CheckItems` | y -24 | y -60 (-115..-5) |
| 행동 문장 | 80..176 | 그대로 |
| 확인 버튼 | -180..-120 | 그대로 |

- 개정 4 이후 안내판에는 이후 개정의 경로만 한 번 다시 배치한다(`RevisionPaths`, `PathsAfter`). 개정 5 안내판은 위 네 요소만, 개정 4 안내판은 개정 5와 6 요소를 함께 받는다.
- 안내판 위치·회전, 다른 텍스트, 버튼 위치는 유지된다.
- 현재 씬은 개정 5다. 카드·제목·항목·행동 문장의 저장 위치는 개정 5 기본값과 같아서 덮어써지는 사용자 조정은 없다.
- 글자 크기는 줄이지 않았다. 24pt 한 줄은 약 34.8이고 높이는 36이다.
- 메뉴 재실행 시 `EnsureText`가 이름으로 찾으므로 텍스트가 중복되지 않는다. Guide는 `GetOrAdd`, 참조는 SerializedObject로 다시 기록하고, 리스너는 추가하지 않는다.
- 메뉴 2 추가 검사:
  - Guide 참조 일치, 저장 시 활성·빈 텍스트, 확인 영역 밖
  - 단계 줄·박스·행동 문장·카드·제목·항목·확인 버튼과 겹치지 않음
  - 텍스트 맞춤 후보 "압박 유지 100%"
  - 기존 버튼·그래픽 겹침 검사가 새 텍스트도 포함
