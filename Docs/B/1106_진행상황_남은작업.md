## 3. 이번 UI 통일에서 보완한 사항

### 단계 설명과 공통 구성

- 5개 과정 모두 설명 영역 생성·참조 연결·검사 후보·공간 배분을 연결했다. 단계 제목과 같은 안내 대상을 따라 설명을 표시하며 시작·완료·초기화 시 이전 설명을 지운다.
- K1의 중복 과정 제목은 비활성으로 보존했다. 숨긴 완료 Mark를 겹침으로 오판하던 기존 검사는 구조 확인과 실제 표시 요소의 배치 확인으로 분리했다.
- 보호의·압박붕대 완료 요약과 검사에서 실제 문구 생성 함수를 공유한다.
- 공통 적용·읽기 전용 검사 메뉴와 기존 과정 구성 메뉴의 연계를 추가했다. 반복 적용 시 중복 생성·배치 누적을 막는 구조다.

### 지혈대 표시와 검사

- 완료 요약 7항목을 실제 출력과 같은 왼쪽 4줄·오른쪽 3줄로 검사한다. 최종 확인의 미충족/거절 문구와 복구 행동 조합도 실제 출력 함수로 후보를 만든다.
- 설명·행동·결과·요약 영역에 맞춰 보드 공간을 조정했다. 지혈대 보드 높이 640, 요약 열 높이 130, 최종 확인 결과 104, 조작 행동 170이며 압박붕대 보드 높이는 600이다.
- 복구 중 제목·현재 단계 박스·설명·행동·표식이 Guide의 같은 대상을 사용한다. 예: 4단계 고정 중 회전량 부족 → `보완 3/6 · 막대 회전` → 회전량 회복 후 4단계 표시로 복귀. Runner의 진행 기록은 되돌리지 않는다.
- 검토 중 잠시 제기한 ‘지혈대 세로 공간 초과’는 합산 오류로 철회했다. 필수 미해결 문제로 재등록하지 않는다.

### AED 입력 구성

- 처음 공통 적용 때 K1·보호의·압박붕대·지혈대는 저장됐으나 AED는 Canvas Raycaster 검사 1건으로 저장 취소됐다. Console 오류 2개는 같은 원인의 상세 로그와 전체 요약이었다.
- AED 적용 경로에서 정확한 일반 `GraphicRaycaster`만 제거하고 기존 `TrackedDeviceGraphicRaycaster` 설정은 보존한다. XR용이 없을 때만 추가한다.
- 읽기 전용 검사는 정리를 수행하지 않고 XR용 1개·활성 1개와 일반 Raycaster 0개를 따로 검사한다. 기존 XR 중복을 임의 삭제하는 기능과는 구분한다.
- 후속 사용자 검증 완료 및 `2e8a105` 커밋이 있으므로 AED 적용 실패를 현재 미해결로 남기지 않는다.

## 4. 유지할 사용자 결정

- **B 교육 화면은 현재 KD-1 UI/UX를 기준으로 유지한다.** 상단 챕터·단계 제목, 설명과 현재 행동의 구분, 진행 박스, 완료 요약을 각 과정 내용에 맞춰 재사용한다. 전 과정을 KD-1의 4단계로 통일하지 않는다.
- 문구는 버튼 조작만 지시하지 않고 목적·방법을 함께 설명한다. 예: 제독 패드는 장비 표면에 두드려 사용한다는 설명 후 현재 체험할 부위를 안내한다.
- ‘그립’ 대신 ‘잡으세요’처럼 행동으로 안내한다. KD-1 화면의 포장 지칭은 사용자가 선택한 `KD-1` 표현을 기준으로 유지한다.
- KD-1은 한 손으로 가능한 간단한 체험이다. 양손 필수 흐름이나 엄격한 각도·접근·속도 판정을 다시 추가하지 않는다.
- 공용 `B/Common/StatusMarkerOverlay`의 다른 체험 민트 표식 적용은 **추후 씬 통합 시점**이다. 이번 교육 보드 UI 통일로 다른 씬 표식까지 적용됐다고 기록하지 않는다.

## 5. 다음 작업

현재 완료한 UI를 다시 만드는 대신 **분야별 운영 씬 통합 설계**를 다음 범위로 잡는다. 이 문서 갱신은 설계·구현 착수 지시가 아니다.

**11/06 후속 요청·공간 기준 정정:** 사용자는 실제 예비군 교육장처럼 하나의 공간에서 교육받고 구급법·화생방을 명확히 구분하도록 지시했다. [분리 운영 흐름 설계](1106_구급법_화생방_분리_운영흐름_설계.md)를 하나의 B 교육장 안에 두 구역·각 3개 실습 위치를 배치하는 흐름으로 수정했다. 최초안의 분야별 메뉴·상위 메뉴를 통한 분야 변경은 대체됐다. 현장 이동·실습 시작·완료/중단·다시하기를 같은 교육장 안에서 수행한다. 설계 수정이며 구현 완료는 아니다. 상세 배치·이동 수단·씬 구성·XR 소유권은 후속 설계 대상이다.

**추가 정정·구현 프롬프트 요청:** 하나의 공간 기준은 분야별 내부다. 구급법과 화생방은 별도 씬으로 구성 가능하며 각 씬 안 세 과정은 현장 이동으로 연결한다. 향후 교육장 모델 교체에 대비해 환경과 과정별 실습 루트를 분리하고, 루트의 위치·수평 회전 변경만으로 판정·UI·초기화가 새 배치를 따르도록 한다. 사용자는 이 범위의 한국어 구현 프롬프트를 요청했다. 본 에이전트는 코드·씬을 직접 변경하지 않는다.

**구현보고서 후속 정적 검토:** [분야 운영 씬 구현본 검토](1106_분야운영씬_구현본_정적검토.md). TrainingField 구성/검사·운영·6과정 연결 코드와 기존 12파일 변경을 읽었다. B_FirstAid 저장 씬 변경 없음·B_CBRN 미생성으로 구성 메뉴 미적용 단계다. 보완 4건: 중단 확인의 강제 잡기 취소로 KD1 수납/AED 낙하 등 장비 상태 변경, 시작 소유권 없이 LateUpdate 가림판에 의존, K1/보호의 월드 바닥 높이 0으로 수직 재배치 미대응, EntryAnchor 재배치와 실제 XR 시작 위치 미연결. 실행 재현·컴파일·메뉴 실행은 하지 않았다. 코드/씬 수정 없이 문서만 갱신했다.

**4건 수정본 재검토 — 현재 우선:** 같은 검토 문서 §7을 따른다. 강제 선택 취소 제거·6과정 동기 시작 승인·FloorAnchor 연결·런타임 입구 배치 반영을 읽기 확인했다. 기존 4건을 그대로 재배정하지 않는다. 잔여 P1: PB/KD1/K1의 보류 중 목표 접근이 재개 후 즉시 부착·수행·스냅 판정될 수 있음. P2: 추적 3초 타임아웃에 임시 자세로 entryPlaced 확정, 지연 HMD 추적 후 재배치 없음·진입 대기 중 시작 승인 가능. 씬 미생성/미갱신·실행 미확인 상태는 유지한다. 코드·씬을 수정하거나 실행하지 않았다.

**재무장·진입 대기 후속 수정본 — 위 §7보다 우선:** 검토 문서 §8. PB 끝·KD1 미완료 영역·K1 얼굴/끈의 현장 보류 복귀 재무장과 실제 HMD 추적까지 시작 차단·진입 준비 안내가 반영됐다. 위 P1/3초 타임아웃 문제는 현재 미해결로 재배정하지 않는다. 추가 P2 1건: Provider만 끄므로 입구 대기 중 TeleportationArea/Anchor 요청이 큐에 남아 진입 후 재활성화 때 과거 목적지로 이동할 수 있다. 로컬 XRI 요청·큐 소스까지 읽기 확인했으며 실행 재현은 하지 않았다. 씬 구성 메뉴·컴파일·사용자 실기 확인은 여전히 미보고다.

**순간이동 선택 필터 수정본 — 현재 최신:** 검토 문서 §9. Coordinator의 씬 내 TeleportationArea/Anchor 선택 필터·준비 중 거절·진입 직후 눌린 select 입력 해제 대기·종료 정리를 확인했다. 설치 XRI 실행 순서·요청 이벤트·입력 처리와 현재 Teleport Interactor의 hover 활성 옵션 0도 대조했다. 현재 B 구성 기준 추가 필수 코드 문제 미발견이며 위 §8의 요청 잔류를 그대로 미해결로 재배정하지 않는다. 컴파일·메뉴·Play·HMD 통과는 아니다. 다음은 사용자 컴파일→메뉴1/2→3/4→대기 중 요청/누른 채 연결/새 입력 확인이다. 씬 미생성·미갱신 상태와 사용자 실행 확인 미보고는 유지한다.

1. 구급법(AED·지혈대·압박붕대)과 화생방(K1·보호의·KD-1)의 과정 선택·진입·완료·중단·복귀·재진입 흐름을 정한다.
2. 통합 방식과 XR Origin·카메라·입력·EventSystem의 소유 주체를 정한다. 개별 씬에 적용한 교육 보드 구성과 과정별 상태 초기화 경로를 유지한다.
3. 선택한 통합 구조에 맞춰 참조·UI·상태 정리 기준을 정하고, 다른 체험의 민트 상태 표식에 공용 Overlay 셰이더를 적용할 범위를 목록화한다.
4. B 운영 흐름이 정해지면 A/C 진입·복귀 지점, 과정 ID·결과 전달, 빌드 진입점을 협의한다. 타 담당 파일·공용 설정을 임의 수정하지 않는다.
5. 실제 통합 변경 후 사용자가 과정 전환·중단·재진입·반복 회차와 최종 시연 환경의 가독성·입력·성능을 확인한다. 기존 사용자 검증을 통합본 검증으로 대체하지 않는다.

## 11. B Editor 메뉴 재배치 — 현재 메뉴 위치 (2026-11-06)

A 환경 모델 반입 전 메뉴 경로·표시 이름만 바꿨다. 메뉴 함수·검사 내용·Play/컴파일/미저장 씬 차단 조건·실패 복구·Content/배치 보존 동작·파일/클래스/asmdef/GUID는 그대로다. 교육 기능 변경 없음. 같은 그룹 안 번호는 기존 번호(작업 순서, 각 생성 뒤 그 검사)를 유지해 코드·로그·과거 기록의 "메뉴 N" 참조가 계속 맞는다. 컴파일·메뉴 실행은 사용자 확인 전이다.

## 12. A 공간 외형의 B 반입 조사

- 사용자 요청으로 A_Sandbox 저장 씬·공간 코드·메시/재질 참조와 B 저장 실습범위를 읽었다. [공간 조사 문서](1106_A공간_모델반입_정적조사.md), [정적 조사도](1106_A공간_정적조사도.png)를 작성했다.
- 내무반 바닥8×9.44m/천장2.644m, 사격장15.5×35.4m/천장4.67m. 사격장 후방 대기 영역은15.5×6m다. 두 방 바닥 윗면은Y=0이다.
- 기존 B 일렬 실습범위 총폭은 구급법9.763m/화생방9.254m로 내무반 폭8m를 넘는다. 추천 후보는 침대8·관물대8 등을 제외한 내무반 빈 외형+2+1/ㄷ자 배치다. 일렬 유지가 우선이면 사격장 후방이 후보지만 B 작업본에서 전방 마감이 필요하다. 최종 공간/좌표는 아직 미확정이다.
- 공간은 단일 FBX가 아니라 씬 배치·생성 WallBox/CeilingGrid 메시·재질·집기 조합이다. 필요한 의존성을 B의 새 GUID 작업본으로 구성하고 A 원본·빌더는 수정/실행하지 않는다.
- 이번 조사에서는 Unity/Blender 실행·코드/씬/에셋 수정 없이 Docs/B에 문서·조사도만 작성했다. 기존 메뉴 정리 등 사용자 변경은 보존했다.

## 13. 내무반 외형 반입 도구 구현본 검토 — 최신

- [구현보고서](1106_B_내무반외형_반입도구_구현보고.md)와 새 C#5개, 기존 입구·이동 코드 및 로컬 Editor.log를 대조했다. [후속 검토](1106_B_내무반외형_반입도구_정적검토.md)에 보완3건 기록.
- 보고서의 ‘메뉴 실행 대기’ 시점과 달리 현재 로그에는 구급법 환경 반입→실제 경계 배치 실패→씬 복구/신규 자산 제거가 있다. 현재 B 프리팹/대응 JSON과 씬 반입 결과는 없다. 에이전트가 실행한 것이 아니다.
- P1: 실제 AED4.02×4.48, TQ2.65×4.72, PB4.91×3.58m에 추가 여유까지 있어 고정 좌우3.05×4.25/후방7.70×2.82 구역으로 배치할 수 없다. 앞선 areaSize 조사보다 종합 경계가 크다. 기여 오브젝트 분석과 배치 설계 보완이 먼저다.
- P2: EntryAnchor는-Z를 보지만 입구 안내판은 뒤쪽Z=-0.35(입구Z=-0.9)에 배치된다. P2: 이동 마스크가 B_BarracksShell을 통째 제외하여 지원 대상인 B 외형 자식 수동 편집 후 벽/문/창 위치를 반영하지 못한다. 후자의 현재 VR 관통 재현을 주장하지 않는다.
- A 원본 해시는 기존과 같고 A/C·B 씬/모델/재질·설정 변경은 없다. 기존 교육 검증 완료 상태는 유지한다. 에이전트는 Unity 실행/코드·씬·에셋 수정 없이 Docs/B만 갱신했다.
