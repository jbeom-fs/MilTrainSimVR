## 3. 메뉴와 실행 순서

| 메뉴 | 동작 |
|---|---|

메뉴 4의 결과 판정:

| 상태 | 마지막 줄 | Console 수준 |
|---|---|---|
| `B_K1_Tutorial`이 열려 있고 모든 필수 검사 PASS | `Result: no FAIL items.` | Log |

대상 씬이 열려 있지 않으면 `NOT RUN  Scene and stored-mask checks: open … and run '4. …' again.` 줄을 남기고 씬·수납 검사를 하지 않는다. 메뉴 4는 씬을 열거나 저장·수정하지 않는다. 씬 파일 자체가 없으면 FAIL이다.
메뉴 2(`Validate Prefab and Scene`)의 판정 의미는 바꾸지 않았다. 씬이 열려 있지 않으면 기존처럼 INFO로 씬 검사를 생략한다.

방독면 인스턴스는 구성(메뉴 3)과 두 검사 메뉴 모두 같은 기준으로 센다: 씬 전체 계층(비활성 포함)에서 `K1_GasMask_Training` Prefab에 연결된 인스턴스 루트. 정리용 부모 아래에 있어도 1개로 세고, 이름만 같은 일반 GameObject는 세지 않는다. 2개 이상이면 FAIL.

재질 저장은 해당 함수가 만들거나 갱신한 재질만 대상으로 한다(`AssetDatabase.SaveAssetIfDirty`). 프로젝트 전체 저장(`SaveAssets`)이나 `Refresh`를 쓰지 않으므로 다른 자산의 저장 대기 변경은 그대로 남는다.

메뉴 3은 1단계(방독면 Prefab·씬)가 있어야 실행된다.
반복 실행 시 재질은 같은 파일을 갱신하고, Prefab은 확인 후에만 교체하며, 씬 인스턴스는 기존 것을 재사용한다.
씬에 주머니나 방독면 인스턴스가 2개 이상이면 아무것도 바꾸지 않고 오류로 중단한다.
주머니 위치는 새로 만들 때와 Prefab을 교체할 때만 작업대에 다시 놓는다. 그 외에는 사용자가 옮긴 위치를 유지하고 방독면만 다시 맞춘다.

기존 `1. Build ...`에서 방독면 Prefab 또는 씬을 교체하면 수납 상태가 사라지므로, 주머니 Prefab이 있으면 같은 실행 끝에 수납을 자동 복원한다. 둘 다 유지하면 임포트·재질만 갱신되고 씬 override는 그대로다.

## 4. 임포트·재질

- FBX 헤더: Y-up, 단위 계수 100(1단위=1m), 루트 노드 Rx(-90). 방독면과 같은 Blender 내보내기 설정이다.
- 축 대응 (x,y,z)Blender → (-x,z,-y)Unity를 별도 회전으로 다시 적용하지 않는다. Prefab 생성 시 앵커·본 5곳의 실제 임포트 위치가 이 대응과 5mm 이내인지 확인하고, 다르면 보정 없이 중단한다. 음수 Scale·100배 보정 없음.
- 렌더 FBX: Scale 1 + 파일 단위, Generic, Optimize Game Objects/Strip Bones 끔(비변형 BagRoot 유지), 압축 끔, 탄젠트 가져오기, 카메라·조명·자동 Collider 끔. FBX 재질 `MAT_K1_Carrier_Atlas` → 프로젝트 재질 1개로 리맵.
- 충돌 FBX: Scale 1, 리그 없음. 참조 본은 일반 Transform으로만 들어온다.
- `MAT_K1_Carrier_Atlas`: URP Lit Opaque, Metallic 워크플로. BaseColor(sRGB ON) → Base Map, Normal(Normal map, OpenGL +Y) → Normal, MetallicSmoothness(sRGB OFF) → R=Metallic/A=Smoothness, AO(sRGB OFF) → Occlusion(G). 8개 부품이 모두 이 재질 하나를 공유한다.

```text
K1_Carrier_Training            Rigidbody(kinematic, gravity off)
  ModelSpace (identity)
    K1_Carrier (FBX)
      … FlapBase / FlapMid / FlapTip
            └ COL_FlapBase / COL_FlapMid / COL_FlapTip   convex MeshCollider, 렌더러 없음
```

- 몸체는 바닥 1 + 벽 4의 개별 convex 상자다. 전체를 감싸는 단일 Convex Collider가 없으므로 입구가 열려 있다.

- 충돌 FBX의 참조 본 계층은 보존하되 비활성화했다. 별도로 구동하지 않는다.
- 스크립트·XR 상호작용 컴포넌트 없음. 방독면 Prefab과 같이 kinematic이므로 Play 시작 시 떨어지거나 흩어지지 않는다.

## 6. 씬 배치

- 기존 XR Origin·Simulator(비활성)·조명·바닥·작업대·1m 기준물은 그대로 둔다. 씬을 재생성하지 않는다.
- 주머니: 작업대 위, 앞(+Z)이 사용자 시작 위치(-Z)를 향하도록 Y 180°. 바닥 중심 = 주머니 루트이므로 상판 + 2mm에 둔다.
- 어깨끈은 FBX상 가방 바닥 아래 최대 0.19m까지 늘어진다. 늘어진 부분은 루트 뒤 약 0.163m부터 바닥 아래로 내려가므로, 작업대 뒤 모서리를 루트 뒤 0.158m에 맞춰 끈이 상판을 뚫지 않고 모서리 밖으로 늘어지게 했다.
  - 현재 작업대(중심 z=1.0, 깊이 0.6) 기준 예상 루트 (0, 0.852, 1.142), 앞면 z≈1.03. 1단계 방독면 위치(z≈0.95)보다 약 0.2m 멀다. 다음 단계에서 손 도달이 문제면 주머니를 옮긴 뒤 메뉴 3을 다시 실행하면 방독면이 따라 맞춰진다(끈 관통은 그 경우 다시 확인).
- 방독면: 작업대 위에 있던 기존 인스턴스를 주머니 안으로 옮겼다. 새 인스턴스를 추가하지 않는다. 예상 루트 (-0.027, 0.981, 1.172), Y 180°.

## 7. 수납 자세 적용 방식

규약: JSON 행렬은 row-major 4×4·열벡터, 단위 m, Quaternion WXYZ, Blender 축. 아래 C는 (x,y,z)→(-x,z,-y) 점 대응 행렬이다.

1. **루트**: 주머니 `Anchor_MaskStored`와 방독면 `Anchor_FaceFit`을 일치시킨다. `방독면 루트 = MaskStored(월드) × FaceFit(루트 기준 로컬)⁻¹`. FaceFit 로컬 변환은 실제 임포트 값을 쓴다.
2. **교차 확인**: 위 결과를 `stored.K1_root`로 독립 계산한 `주머니 모델 × C × K1_root × C⁻¹`와 비교한다. 1mm/0.5°를 넘으면 쓰지 않고 중단한다. 루트 좌표와 앵커 정렬을 이중 적용하지 않는다.
3. **머리끈 본 24개**: Blender Euler·basis delta를 localRotation에 복사하지 않는다.
   `D = C × (pose × rest⁻¹) × C⁻¹`(모델 공간 변형), `importedPose = D × importedRest`, 부모 기준으로 바꿔 localPosition/localRotation에 쓴다. importedRest는 FBX 에셋의 실제 rest Transform이다. 임포트 rest 위치와 JSON rest 위치가 1mm를 넘게 다르면 중단한다. 이 방식은 FBX가 본 축을 바꿔도 같은 변형을 낸다.
4. **BlendShape**: `stored.shape_key_values`(모두 0) × 100. Tighten 4개가 0이어도 본 19개가 rest와 달라 수납 자세는 기본 자세가 아니다.
5. 값은 씬 인스턴스의 Prefab override로 저장된다. 방독면 Prefab 원본은 기본 자세로 유지된다.

정화통 부착 수납은 이번 체험 구성이다. 실제 군 수납 절차를 검증한 상태가 아니다.

## 8. 정적 검토 결과 (에이전트, 실행 아님)

- FBX 바이너리를 직접 읽어 확인: 노드 계층·이름, 재질명 `MAT_K1_Carrier_Atlas`, 루트 Rx(-90), 단위 계수 100, 메타데이터와 같은 앵커·본 위치, 충돌 FBX 덮개 프록시의 본 부모, 끈 정점 분포.
- K1 FBX `K1_HarnessRig`는 루트 원점·무회전 → JSON의 armature 공간 = K1 장면 공간.
- JSON 수치: 저장 자세 본 원점 24개가 모두 주머니 내부(벽 안쪽 면 기준)에 있음(최소 여유 약 18mm). rest와 다른 본 19개. NaN/Infinity 없음.
- `Anchor_MaskStored`(위치 = stored.K1_root, 회전 = X 90°)와 `facefit_in_K1_root`(X 90°)가 서로 맞음.
- 몸체 프록시 5개는 내부를 침범하지 않고 덮개 프록시는 닫힌 상태에서 입구(z 0.254) 위·전면 벽 바깥에 있음.
- C# 코드는 컴파일하지 않았다. Unity에서 첫 컴파일 오류 여부를 사용자가 확인해야 한다.

메뉴 4의 검사는 Prefab·씬의 실제 Transform으로 아래를 PASS/FAIL로 보고한다: 임포트·재질 설정, 재질 1개 공유, 축 대응, 몸체 크기, 본·앵커 계층, Collider 8개 구성과 덮개 바인딩, 충돌 프록시 비렌더, 내부·입구 비침범, 인스턴스 각 1개, 기존 씬 객체 유지, 작업대 위 배치·방향, FaceFit/MaskStored 일치, stored.K1_root 일치, 본 24개 자세 일치(본 원점과 본 X/Y 방향 5cm 지점), BlendShape 값, 강체 부품·본 원점의 내부 포함.
씬·수납 검사는 메뉴 4의 필수 항목이다. 대상 씬이 열려 있지 않으면 결과는 INCOMPLETE이며 통과가 아니다.

### 8.1 정적 검토 지적 수정 (2026-10-27)

| 지적 | 수정 | 위치 |
|---|---|---|
| P2 재질 저장 범위 | 전역 `AssetDatabase.SaveAssets()`를 대상 재질별 `SaveAssetIfDirty`로 교체. 방독면 재질 3개, 주머니 재질 1개만 저장 | `K1GasMaskTrainingSetup.cs` `CreateOrUpdateMaterials`, `K1GasMaskTrainingSetup.Carrier.cs` `CreateOrUpdateCarrierMaterial` |

FAIL이 있으면 FAIL 판정 우선. 메뉴 4는 대상 씬이 활성 씬일 때만 씬·수납 검사 실행, 아니면 NOT RUN + 재실행 안내 | `K1GasMaskTrainingSetup.cs` `Report`, `K1GasMaskTrainingSetup.Carrier.cs` `ValidateCarrier`, `ValidateStoredScene` |

이 수정은 수납 좌표 계산·본 자세 변환·Collider 구성·모델·텍스처·Prefab·씬을 바꾸지 않는다.

수정 후 정적 검토(에이전트, 실행 아님):
- 두 Editor 스크립트에 `AssetDatabase.SaveAssets(`·`Refresh(` 호출 없음.
- 메뉴 4에서 씬 검사를 건너뛰는 경로는 `NotRun`을 기록하고, `Flush`는 `notRun > 0`이면 성공 문구를 출력하지 않는다. `ValidateStoredScene` 내부 생략 경로도 `NotRun`이다.
- 메뉴 2는 `NotRun`을 쓰지 않으므로 판정이 이전과 같다.
- 방독면 검색: `StoreMaskInScene`, `ValidateStoredScene`, `ValidateScene` 모두 `SceneInstances` 사용. 시뮬레이터 검색은 이번 범위가 아니어서 루트 기준 그대로다.
- 검사 함수(`Validate*`, `Report`)에는 씬 열기·저장·dirty 표시, Transform·활성 상태 변경, 자산 저장 호출이 없다. Prefab 검사는 기존처럼 `LoadPrefabContents`/`UnloadPrefabContents`로 읽기만 한다.
- 컴파일·메뉴 실행은 하지 않았다.

## 9. 사용자 확인 순서

준비: Unity에서 컴파일 완료 확인 → `B_K1_Tutorial` 저장 상태 확인.

1. `B/K1 GasMask/3. Build Carrier and Store Mask in Scene` 실행.
   기대: Console에 `[K1 Carrier] Build` 로그와 `Result: no FAIL items.` 실패: `FAILED` 또는 FAIL 항목. 그 로그를 그대로 전달.
2. Scene 뷰에서 1m 기준물 옆 주머니·방독면 크기 확인. 주머니 높이 약 0.27m, 폭 약 0.30m.
3. 주머니 덮개를 숨기거나(Part_BagFlap·Part_Closure_Flap 렌더러 잠시 끄기, 저장하지 않음) 위에서 보아 방독면이 안에 들어 있고, 사용자 쪽에서 볼 때 정화통이 화면 오른쪽(월드 +X)인지 확인. 방독면이 사용자를 향하므로 이것이 착용자 왼쪽이다.
4. 주머니 천 질감·Normal 요철·AO가 보이는지, 금속 고리만 약한 금속감인지 확인. 분홍·검정 재질이면 실패.
5. 머리끈이 앞으로 펼쳐지지 않고 방독면 뒤·위쪽으로 접혀 주머니 안에 있는지 확인. 끈이 주머니 벽 밖으로 크게 나오면 실패.
6. `K1_Carrier_Training > ColliderSpace`의 몸체 Collider 5개가 바닥·벽으로 나뉘어 입구가 비었는지, Scene 뷰에 충돌 프록시가 렌더링되지 않는지 확인.
7. `FlapBase/FlapMid/FlapTip` 아래 각각 `COL_Flap*` Collider가 있는지 확인. FlapBase를 잠시 회전해 Collider가 덮개와 함께 움직이는지 본 뒤 Undo(저장하지 않음).
8. Hierarchy에 XR Origin·작업대·1m 기준물·조명이 각 1개, 방독면은 주머니 안 1개뿐인지 확인. 어깨끈이 작업대 뒤 모서리 밖으로 늘어지고 상판을 뚫지 않는지 확인.
9. 선택: Play 진입 시 주머니·방독면이 떨어지거나 흩어지지 않는지 확인. 조작은 아직 없음.

### 9.1 지적 수정 확인 (2026-10-27)

1. 컴파일: Console에 `K1GasMaskTrainingSetup` 관련 컴파일 오류가 없어야 한다.
2. `B_K1_Tutorial`을 연 상태에서 메뉴 4 실행.
   기대: 씬·수납 항목(`Active XR Origin count`, `K1_GasMask_Training instance count = 1`, `Folded harness …` 등)이 PASS로 찍히고 마지막 줄 `Result: no FAIL items.` 실패: `NOT RUN` 줄이 있거나 FAIL 항목.
3. 다른 씬(예: 빈 새 씬, 저장 불필요)을 연 상태에서 메뉴 4 실행.
   기대: Warning 로그, `NOT RUN  Scene and stored-mask checks: …` 줄, 마지막 줄 `Result: INCOMPLETE …`, `no FAIL items` 문구 없음, 현재 씬이 그대로 열려 있음. 실패: 성공 문구 출력, 씬 전환·저장 발생.
4. `B_K1_Tutorial`에서 빈 GameObject(위치 0, 회전 0, Scale 1)를 만들고 방독면을 그 아래로 옮긴 뒤 메뉴 2와 메뉴 4 실행.
   기대: 두 메뉴 모두 `K1_GasMask_Training instance count = 1` PASS, 메뉴 4의 수납 자세 항목 PASS. 실패: count 0 또는 2. 확인 후 Undo로 되돌리고 씬을 저장하지 않는다.
5. 재질 저장: 메뉴 1(Prefab·씬 `Keep existing`)과 메뉴 3(Prefab `Keep existing`) 실행.
   기대: `MAT_K1_Body/Harness/Lens`, `MAT_K1_Carrier_Atlas` 재질 설정 유지·저장, 주머니 안 방독면 위치·접힌 머리끈 유지, 이후 메뉴 4 `Result: no FAIL items.` 실패: 수납 해제, 재질 누락. 다른 자산의 저장 대기 변경이 이 실행으로 저장되지 않아야 한다(저장 대기 자산이 있었다면 해당 파일의 git 변경 여부로 확인).

## 10. 미검증·제약

- Unity 실제 임포트 축·크기·재질 표시, 컴파일, 검사 메뉴 결과: 사용자 확인 전. 10/27 지적 수정(재질 저장 범위, INCOMPLETE 판정, 인스턴스 검색 기준)도 사용자 실행 결과 없음.
- 덮개 Collider는 스킨 천을 근사한 3개 강체 판이다. 혼합 구간을 정확히 덮지 않는다.
- 원본 K1의 Attach_P_LD 고정 꼬리와 정화통 겹침(삼각형 접촉 75쌍)은 수납 이전부터 있던 것이다. 이번에 수정하지 않았다.
- 버클과 앞 고정 본 구간 접촉은 원본 구조상 의도된 접촉으로 분류되어 있다.
- 주머니 치수는 실측이 아닌 프로젝트 추정이다. 실제 군 수납 절차·잠금 방식은 확인되지 않았다.
- 손 도달·자유 궤적·꺼내기 간섭·Quest 2 + Link 실기는 이번 정적 확인 범위가 아니다. 실기는 전체 기능 구현 후 사용자 확인 대상이다.
- 다음 단계 연결 앵커(`Anchor_FlapGrab`, `Anchor_ClosureGrab`, `Anchor_ExitPlane`, `Anchor_ExtractEnd`, `MaskInteractionFrame/Anchor_MaskPickup`)는 보존만 했다. 사용 코드는 없다.
