# 통합 씬 사용자 피드백 7건 반영본 정적 검토 — 2026-11-06

## 결론과 범위

사용자 첨부 구현보고서와 실제 변경 코드, 저장된 운영 씬, 프리팹, 설치된 XRI 소스, AED 앉은 모델 생성 스크립트·결과 JSON을 대조했다. 검토 범위에서 추가 필수 코드 오류는 발견하지 못했다. 컴파일·구성 메뉴·Play·Simulator·HMD 통과라는 뜻은 아니다.

현재 상태는 **코드와 모델 준비, 저장된 운영 씬 적용 대기**다. `B_FirstAid.unity`, `B_CBRN.unity`는 이번 변경에 포함되지 않았다. 보호의/상처 표식, 금지 영역 숨김, 앉은 자세, 가림판 정렬 변경은 사용자가 구성 메뉴를 실행해야 기존 Content에 적용된다. 반면 공유 런타임의 테이프 판정과 보류 처리는 코드 변경이다.

에이전트는 프로젝트 코드·에셋을 수정하거나 실행하지 않았다. 검토 문서와 진행상황 포인터만 갱신했다. 글꼴·BuildSettings·기존 문서 등 사용자 변경은 보존했다.

## 남은 문제와 확인 우선순위

### 1. 운영 씬 적용은 아직 완료되지 않음

`TrainingFieldSetup.LinkStation`은 기존 Content에도 `ApplyFieldPresentation`을 실행한다. 따라서 Content 삭제 없이 갱신하도록 구현돼 있다. 다만 이번에는 메뉴 미실행이므로 저장 씬을 이미 7건 개선 완료 상태라고 취급하면 안 된다.

사용자 확인 순서: 컴파일/임포트 확인 → 메뉴 1·2 Build or Update → 메뉴 3·4 Check(report only) → 두 씬 저장 및 변경 내역 확인. 검사 FAIL 0은 구조/참조 확인이며 아래 시각·상호작용 확인을 대신하지 않는다.

### 2. 패널 비침은 모든 시점에서 해결됐다고 확정할 수 없음

`TrainingFieldSetup.cs:1051`에서 가림판의 sortingOrder를 자기 보드와 맞춘다. 기존 +10에 따른 강제 앞그리기를 제거한 점은 타당하다. 다만 별도 Canvas의 거리 정렬에 의존한다. 원본 보드/글꼴까지 포함한 픽셀 단위 깊이 가림을 새로 구현한 것은 아니다. 보고서도 비스듬한 시점에서 순서 역전 가능성을 명시한다.

현재 보드와 뒤 실습대 안내가 실제로 겹치는 위치에서 정면·좌우 이동·비스듬한 시점·HMD 양안을 확인해야 한다. 남는다면 이 항목은 추가 보완 대상이다. 현재 검토만으로 실제 재발을 확정하거나 완전 해결로 승인하지 않는다.

### 3. 앉은 자세의 접근성은 확인되지 않음

`TrainingFieldSetup.cs:1143`의 TQ/PB 방식은 상체를 내리되 팔을 기존 T자세로 유지한다. AED 의자는 체형 비율 추정으로 배치한다. 구현보고서가 명시한 한계이며 코드와 일치한다. 앉았다는 사실만으로 사용자 키에 따른 불편이 해결됐다고 확정할 수 없다.

사용자가 낮은 시점에서도 상처·초록 영역·AED 패드 위치에 닿는지, 무릎/발이 PracticeAnchor·트레이·보드를 침범하는지, 앵커와 표시가 피부에 맞는지 확인해야 한다. 저장/재열기·메뉴 반복·StationRoot 이동/수평 회전·두 번째 회차 초기화까지 확인한다. 이 검토에서 Blender 생성 스크립트를 실행하거나 보고서의 렌더 결과를 직접 재현하지는 않았다.

### 4. Time.timeScale 제거와 실제 기기 검증은 구분

`TrainingFieldStation.cs:162`의 보류는 자유 Rigidbody를 임시 kinematic으로 바꾸며, 잡힌 장비는 XRI에 맡긴다. `TrainingFieldCoordinator.cs:448`은 물리 복구 후 과정 보류를 해제한다. AED 충전과 과정별 시간 보정 연결을 확인했다.

검토 중 일반 XRI가 임시 kinematic 상태를 잡기 시작 시 원래 상태로 저장할 가능성도 조사했다. 현재 AED는 보류 중 새 패드 잡기를 막고 놓을 때 직접 물리를 설정하며, KD-1도 놓은 뒤 상태별 물리를 다시 적용한다. 따라서 이 일반적인 가능성을 현재 장비의 확정 결함으로 보고하지 않는다.

중단 창에서 Simulator 시점/손/이동/UI는 계속 작동하고 해당 과정의 충전·진행·자유 물체 낙하만 멈춰야 한다. 계속하기·중단 확정·완료·다시하기·두 번째 회차에서 물리 상태와 재무장을 확인한다. 실제 VR에 영향이 없다는 보장은 아직 없다.

## 후속 — 사용자 구급법 구성 메뉴 실패, 위 미발견 결론보다 우선

사용자가 메뉴 1 실행 실패 로그를 제공했다. 로컬 Editor.log에도 같은 예외가 있다. `ApplySeatedAed` 1249행에서 중단됐으며 구급법 씬은 저장하지 않고 디스크 상태로 되돌렸다. 에이전트가 메뉴를 실행한 결과가 아니다. 이전 정적 검토에서 FBX 단위 및 몸의 축 차이를 놓쳤다.

### 발견 1: 메시만 교체하기에 두 FBX의 단위/루트 변환이 다름

FBX 바이너리를 읽기 전용으로 해석했다. 원본 `Mannequin_AED_Attached.fbx`의 UnitScaleFactor/OriginalUnitScaleFactor는 100이고, 새 `Mannequin_AED_Seated.fbx`는 1이다. 새 FBX 모델 루트에는 Lcl Scaling (100,100,100)이 있다. 두 .meta 모두 globalScale 1, useFileUnits/useFileScale 1이다.

Blender에서 전체 계층을 다시 불러왔을 때 월드 좌표가 일치하는 것은 메시 단독 호환성을 입증하지 않는다. 현재 코드는 기존 Transform을 유지한 채 `body.sharedMesh = seated`로 메시만 교체하므로 새 모델 계층의 단위 보정이 함께 적용되지 않는다. 생성 보고서의 node_frames_equal 및 roundtrip 0만으로 이 사용 방식을 승인할 수 없다.

### 발견 2: 월드 Y 경계의 꼭대기/바닥을 머리/발로 간주한 검사

원본 FBX 몸체 정점 범위는 Y 약 0.004000~0.269525, Z 약 -1.777216~0.002161이다. 원본의 긴 신체 축은 Z이며 원본 환자 프리팹은 루트 회전 identity, 모델 인스턴스도 회전 identity로 저장돼 있다. PadAnchors도 흉부 위치가 Z 약 -1.2~-1.38인 좌표다. 새 FBX의 몸체 Y 범위는 약 0.004000~0.721885다.

원본/새 단위 배율 차이를 적용하면 max Y 차이는 `0.269525 - 0.721885 * 0.01 = 0.262306m`, min Y 차이는 `0.004000 * 0.01 - 0.004000 = -0.003960m`다. 사용자 로그의 drop 0.262 / feet -0.004와 일치한다. 이 값은 의도한 상체 하강 0.3996m를 재는 값이 아니다.

같은 원본 Y 크기로 scale을 계산하면 `0.265525 / 1.77 ≈ 0.150`이며 drop 허용 범위는 약 0.030~0.090m다. 따라서 0.262m가 상한을 넘어 예외가 난 것으로 설명된다. 발 -4mm만 보고 허용 오차를 늘릴 사안이 아니다. 동일한 잘못된 축/크기 추정은 패드의 월드 Y 이동, 의자 높이/크기 계산에도 이어진다.

### 수정 방향과 사용자 조치

- 새 메시를 원본 Unity 메시의 로컬 좌표계·단위와 호환되게 만들거나, 새 모델 계층의 변환을 명시적으로 반영하는 B 작업본 구조가 필요하다. 원본 모델/공용 설정 변경이나 검사 삭제로 우회하지 않는다.
- 환자의 실제 머리/발 및 앞/위 방향을 먼저 정하고, 앉은 자세와 패드 앵커/부착 모델/접촉 MeshCollider/의자에 동일한 변환을 적용해야 한다. 월드 AABB의 Y 크기를 키로 가정하지 않는다.
- 이번 구급법 갱신은 실패했다. 단순 재실행·씬에서 마네킹 크기 임의 변경·Content 삭제로 해결할 작업이 아니다. 수정 후 사용자 컴파일/임포트 → 메뉴1 → 검사3 → 씬 저장과 AED 패드/접촉/의자 실기 확인이 필요하다.
- 화생방 메뉴 실행 결과와는 별개다. 현재 B_CBRN 변경을 실패한 구급법 갱신과 함께 되돌리지 않는다.

코드·FBX·씬 수정이나 Unity 실행 없이 문서만 갱신했다.

## 최신 — AED v2 구현보고서 검토와 누운 자세 유지 정정

### 범위 오류: AED는 앉히지 않는다

사용자가 ‘AED는 누워 있는 채로 하는 것이 맞는데 왜 AED까지 앉혔는지’라고 정정했다. 원래 AED 환자는 누운 모델이었다. 에이전트가 서 있는 마네킹 접근성 개선을 AED까지 확대해 프롬프트에 포함한 범위 오류다. 앞으로 AED는 원래 누운 자세를 유지하고, 지혈대·압박붕대의 앉은 자세 개선은 유지한다. 이 정정은 앞선 AED 앉히기 설계·검사·사용자 확인 절차보다 우선한다.

### 실제 코드 대조

- `TrainingFieldSetup.cs:1110`은 여전히 AED에 ApplySeatedAed를 호출한다.
- v2는 JSON의 상체 강체 회전/이동을 읽어 몸체 및 부착 패드 2개의 메시와 접촉 MeshCollider를 교체하고, PadAnchors 부모에 변환을 한 번 적용하며, 의자를 생성한다. 보고서의 처리 방식과 일치한다.
- `TrainingFieldSetup.cs:1652` 이후 검사도 AED를 지혈대·압박붕대와 함께 앉은 기록/의자 필수 대상으로 두고, 추가로 v2 앉은 메시/패드/바닥 정렬을 요구한다. 정상적인 누운 AED를 FAIL로 판단하는 기준이므로 현재 요구와 맞지 않는다.
- 원본 FBX SHA256은 `9f65f411081d757b361997187f789a8f48a1914fc3ffa74e3c1c1892159daca3`, 새 파일은 `78587ebb77b98fbd7bfc9ff085a8917dd3e2eaf8b31102084562524b668dd459`로 JSON 기록과 일치한다. 원본 FBX/환자 프리팹/개별 AED Tutorial의 Git 변경은 없다.
- 이전 단위·축 문제를 해결하려는 코드 경로는 반영됐다. 다만 현재 요구에서는 이 경로를 더 완성할 것이 아니라 AED에서 제외하고 원래 상태를 복구해야 한다. 검토 중 관련 없는 추가 필수 오류를 억지로 분류하지 않는다.

### 저장된 씬도 이미 변경됨

보고서는 Unity 메뉴 미실행 시점의 설명이지만, 현재 작업공간은 그 상태와 다르다. 로컬 Editor.log에는 `seated AED casualty applied (aed-seated-v2)`, `Every box matches`, `Field check after the update: no FAIL items`, `Scene saved: Assets/B/Scene/B_FirstAid.unity`가 있다. 이는 에이전트 실행이 아니라 기존 로그를 읽은 결과다. Play/HMD 성공을 의미하지 않는다.

저장된 B_FirstAid에도 앉은 FBX GUID 참조 4개(몸체·접촉 Collider·패드 2개), PadAnchors 자세 변경, AED FieldChair, aed-seated-v2 기록이 있다. 그러므로 ‘구성 메뉴 미적용’ 또는 ‘적용 함수만 제거하면 끝남’이라고 보고하면 안 된다.

### 필요한 복구 범위

1. AED의 앉은 자세 적용과 앉은 상태를 강제하는 검사/JSON 의존을 제거하고, 기존 누운 환자·패드·접촉 참조를 확인하는 기준으로 돌린다.
2. 저장된 AED 몸체/접촉 MeshCollider와 부착 패드 2개의 메시를 원본으로 복구한다. PadAnchors의 위치와 회전도 원본 프리팹 기준으로 복구한다. 메시만 복구하면 앵커는 앉은 위치에 남는다.
3. AED에 생성한 의자와 AED의 적용 기록만 정리한다. 지혈대·압박붕대 의자·뼈 자세·판정 앵커·공용 기록 컴포넌트는 유지한다.
4. StationRoot/PracticeAnchor/FloorAnchor 및 장비·보드·교육장 배치, 두 운영 씬의 다른 사용자 변경은 보존한다. 씬 전체/프리팹 전체를 되돌리는 복구는 피한다.
5. AED 충전 Paused, timeScale 미사용 보류, 시작 승인·추적 대기·순간이동 차단 등 자세와 무관한 개선은 유지한다. 불필요해진 AED 전용 생성 코드/에셋 정리는 참조를 확인한 뒤 해당 범위에서만 한다.

복구 완료 기준은 누운 AED에서 패드·부착 표시·손 접촉·다시하기가 맞고 메뉴 반복에도 다시 앉혀지지 않는 것이다. 컴파일/메뉴/Play/HMD 실행 확인은 사용자 몫이다. 이번 요청에서는 코드·모델·씬을 수정하거나 실행하지 않고 문서만 갱신했다.

## 최신 — AED 누운 자세 복구본 코드·저장 씬 재검토

### 결론

구현보고서와 실제 RestoreLyingAed/LyingAedProblems, 원본 프리팹, 저장된 B_FirstAid 및 기존 Editor.log를 대조했다. 현재 구성 기준에서 추가 필수 코드 오류는 발견하지 못했다. 앉은 상태 강제 문제를 계속 미해결로 재배정하지 않는다. 에이전트가 Unity를 실행한 것은 아니며 Play/HMD 기능 성공은 확인하지 않았다.

### 복구 코드 확인

- TrainingFieldSetup:1105는 AED에서 RestoreLyingAed를 호출한다. 이전 AED 앉히기·보고서 로딩·좌표 보정·의자 생성 경로와 관련 기호의 C# 잔여 참조가 없다.
- RestoreLyingAed:1282는 몸체/접촉 MeshCollider/부착 패드 2개의 m_Mesh 오버라이드, PadAnchors 및 패드 Transform의 자세 오버라이드만 되돌린다. 환자 루트 배치, 자식 PadAttachAnchor의 미세 조정, Marker 카메라 연결을 통째로 되돌리는 처리는 없다.
- FieldChair 및 TrainingFieldSeatedPose는 환자 프리팹에 씬 오버라이드로 추가된 경우에만 제거한다. 지혈대·압박붕대 쪽 의자와 공용 기록 컴포넌트는 유지한다.
- LyingAedProblems:1326은 원본 FBX의 프리팹 메시와 같은지, 앵커/패드 자세 오버라이드가 없는지, AED 의자/기록이 없는지, 패드 참조 및 접촉 Collider 목록을 읽기 전용으로 확인한다.
- 이전 aed-seated-v2 JSON이나 FBX가 복구에 필수인 경로는 없다. AED 충전 Paused와 timeScale 미사용 보류도 유지된다.

### 보고서의 씬 미적용 설명은 현재 상태와 다름

보고서는 메뉴 미실행·저장 씬 미복구 상태를 설명하지만 현재 로컬 파일/로그는 이미 복구된 상태다.

- Editor.log에 `AED casualty restored to the lying prefab patient`와 몸체/Collider/패드 메시 복구, PadAnchors 위치·회전 복구, 의자·기록 제거 로그가 있다.
- 그 뒤 `Field check after the update: no FAIL items`, B_FirstAid 저장 성공이 있다.
- 별도 검사 출력에도 Station_AED의 `lying as in its prefab` PASS와 최종 `Result: no FAIL items`가 있다. 지혈대·압박붕대의 `casualty seated once`도 PASS다.
- 저장 씬에서 앉은 FBX GUID 및 aed-seated-v2 기록이 사라졌다. 남은 앉은 기록은 지혈대·압박붕대의 rig bones 2개다.
- 원본 환자 프리팹 인스턴스 오버라이드를 B_AED_Tutorial과 비교한 결과, 현재 B_FirstAid 21개/Tutorial 19개이고 차이는 현장 XR 카메라를 연결한 m_Camera 2개뿐이다. 환자 배치와 기존 패드 앵커 미세 조정은 유지된다.
- 원본 FBX SHA256은 기존 기록과 같으며 원본 FBX·환자 프리팹·개별 Tutorial의 Git 변경은 없다.

### 남은 사항

1. 반복 메뉴 실행의 `nothing to restore`, 저장·재열기, Play의 패드 부착·부착 표시·손 접촉·다시하기·두 번째 회차, Simulator/HMD 보류 동작은 이번 로그만으로 성공을 확정하지 않는다. 이미 확인된 첫 복구/구성 검사까지 다시 미실행으로 표기하지 않는다.
2. Assets의 unity/prefab/asset/mat/cs 검색 범위에서 앉은 FBX GUID 참조는 0건이다. 따라서 보고서의 ‘B_FirstAid가 아직 참조하므로 보존’ 사유는 현재 해소됐다. 불필요 에셋 정리는 가능하지만 이번 검토 요청으로 삭제하지 않았다. 지혈대·압박붕대가 쓰는 의자 재질과 공용 기록은 정리 대상이 아니다.

코드·씬·에셋 변경, Unity 실행·스테이징·커밋 없이 Docs/B 검토 기록만 갱신했다.
