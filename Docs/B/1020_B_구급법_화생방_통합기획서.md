## 1. 기획 목적

예비군 교장의 구급법과 화생방 교육을 가상 환경에서 반복 학습할 수 있도록 구현한다. 사용자는 상황을 확인하고, 필요한 장비를 선택·조작하며, 단계별 피드백을 통해 자신의 누락과 잘못된 행동을 확인한다.

B의 확정 담당은 **구급법과 화생방 중 제독**이다. 방독면·보호의 착용은 제독 전후 교육과 연결되는 구현 후보이며, B가 직접 제작할 범위는 팀 협의로 확정한다.

학습 목표는 상황 판단, 도구 선택, 가상 배치 위치, 절차 수행, 누락 방지다. 컨트롤러만으로 실제 압박력·방독면 밀착성·제독 효과를 측정하거나 실제 술기 자격을 인증하지 않는다.

## 3. 사용자 경험과 교육 흐름

```text
과정 진입
 → 조작 안내·교육 목표
 → 상황 제시
 → 단계 안내 / 필요 시 시범
 → 사용자 조작
 → 완료 조건 확인 또는 오류 피드백
 → 다음 단계
 → 수행 결과
 → 재시도 또는 과정 종료
```

- 조작 안내: 잡기·놓기·버튼 조작·지정 위치 배치를 먼저 익힌다.
- 안내 실습: 현재 목표와 필요한 도구를 자막·음성·시각 표시로 안내한다.
- 오류 피드백: 잘못된 도구나 위치를 알려주고 현재 단계에서 수정할 수 있게 한다. 단순 실수마다 과정을 처음부터 재시작하지 않는 안을 기본으로 한다.
- 수행 결과: 완료 단계, 누락 또는 오류, 재학습 항목을 표시한다. 배점·합격선은 교안 확정 후 반영한다.
- 무안내 평가: 승인 시 같은 단계·판정 데이터를 재사용하고 안내 표시 정책만 변경한다.

교육 시간과 이동 방식, 서기·앉기 운영 조건은 미정이다. 첫 프로토타입은 한 작업 공간에서 주요 장비에 접근하는 구성으로 검토한다.

P1은 1차 제작 후보, P2는 후속 후보를 의미한다. 모든 P1을 첫 시연에 동시에 납품한다는 의미는 아니다. 첫 검증 과정은 AED를 제안한다.

### 4.3 보류 범위

실제 압박력·깊이·이완·인공호흡 측정, 실제 방독면 밀착 검사, 전신 착의 추적, 실제 부상자 운반, 자유로운 천·붕대 감기, 전문 제독차·대규모 지역 제독, 제독소 전체 운영은 보류한다. 골절·기도폐쇄·온열질환·탐지 보고의 독립 과정, 멀티플레이, 외부 센서, 서버·학습관리시스템 연동도 현재 기본 범위에 포함하지 않는다.

## 5. 대표 시나리오

아래는 화면·상호작용 구성을 위한 흐름이다. 실제 처치·제독의 세부 순서와 수치는 승인 교안으로 확정한다.

### 5.1 AED 과정 — 공통 시스템 검증용

- 상황: 훈련 중 쓰러진 대원과 AED가 있는 교장.
- 목표: 상태 확인과 도움 요청, 장비 조작 및 부착 상태 확인을 학습.
- 구성: 상황 확인 → 도움 요청 → AED 조작·패드 부착 → 장비 안내에 따른 행동 → 결과.
- 주요 판정: 올바른 패드와 부착 대상, 현재 부착 상태, 단계별 필수 행동.
- 오류 예: 잘못된 부착 위치, 필요한 패드 누락, 부착 후 다시 분리.
- 경계: 전체 CPR 교육은 FA-02와 별도이며, AED 시연을 완전한 소생술 과정으로 표시하지 않는다.

### 5.2 출혈 처치 과정

- 상황: 사지 출혈이 설정된 가상 부상자.
- 목표: 상황에 맞는 도구 선택과 가상 조작 절차 학습.
- 구성: 상태 확인 → 교안에 따른 처치 선택 → 압박붕대 또는 지혈대 조작 → 확인·기록 → 결과.
- 주요 판정: 선택한 도구, 가상 적용 위치, 조임·고정·기록 동작.
- 경계: 직접 압박과 지혈대를 모든 상황에서 동일한 순서로 강제하지 않는다. 실제 지혈 효과는 측정하지 않는다.

### 5.3 개인방호 과정 — 담당 연계 후보

- 상황: 경보와 보호태세 지시가 제시된 교장.
- 목표: 방독면 및 보호장비의 선택·착용·점검 절차 학습.
- 구성: 지시 확인 → 필요한 장비 선택 → 가상 착용·점검 → 결과.
- 표현: 얼굴 앞 배치 후 착용 상태 전환. 머리 뒤 조임과 전신 착의는 아바타 또는 앞쪽 조작 UI 활용.
- 연계: 다른 담당자가 제작할 경우 착용 결과와 다음 과정 진입 정보만 전달받는다.

### 5.4 개인제독 과정 — B 핵심

- 상황: 교육용 표시가 있는 가상 신체 또는 휴대장비와 제독 도구.
- 목표: 대상·도구 선택, 지정 부위 처리, 재오염 방지 학습.
- 구성: 상황·대상 확인 → 도구 선택 → 승인된 처리 행동 → 누락·재접촉 확인 → 도구 회수·결과.
- 표현: 가상 팔·손, 앞쪽 교육용 인체 모델 또는 작업대 위 장비 사용. 실제 사용자 전신 접촉 추적은 요구하지 않는다.
- 판정: 단순 색상 제거율이 아니라 대상·도구·행동·재접촉 조건으로 평가한다.
- 경계: 오염 표시는 교육용 시각화임을 알린다. 화학·생물·방사능에 동일한 도구와 처리법을 일괄 적용하지 않는다.

## 6. 화면·안내·피드백

| 요소 | 표시 내용 | 기본안 |
| --- | --- | --- |
| 과정 시작 | 목표·조작·시작 | 짧은 안내 후 실습 |
| 현재 단계 | 해야 할 행동 | 한 번에 주 목표 하나 |
| 장비 안내 | 대상 강조·위치 표시 | 안내 실습에서 제공 |
| 자막·음성 | 동일 안내 내용 | 자막만 있는 안내도 허용 |
| 오류 | 잘못된 도구·위치·누락 | 짧은 자막, 반복 출력 제한 |
| 결과 | 완료·오류·재학습 항목 | 점수·합격선은 미정 |
| 재시작·종료 | 현재 과정 제어 | 중단·복원 완료 후 재진입 |

자막 배치·글자 크기는 Quest 2 실기에서 가독성과 장비 가림을 확인해 정한다. 음성과 문구의 의미 일치도 콘텐츠 검수에 포함한다.

## 7. 공통 시스템 설계

### 7.1 책임 구조

```text
TrainingDefinition — 교육별 설정 데이터
 └─ Steps: EnterActions / CompletionConditions / ExitActions
                  ↓
TrainingRunner — 시작·단계 진행·종료·재시작
 ├─ TrainingContext — 이번 실행 상태와 기록
 ├─ SceneBindings — 대상 ID와 씬 Object 연결
 ├─ StepActionExecutor — 활성화·Animation·배치·안내
 └─ StepConditionEvaluator ← Interaction 행동·장비 상태

PresentationController
 ├─ SubtitleId → TrainingSubtitles.Get → 자막 상수
 └─ AudioClip → 음성 출력
```

| 구성 | 책임과 경계 |
| --- | --- |
| TrainingDefinition | ScriptableObject에 단계·조건·Action 설정 보관. 실행 결과는 기록하지 않음 |
| TrainingRunner | 현재 교육 1개를 진행. 교육별 이름에 따른 분기 대신 데이터 실행 |
| TrainingContext | 현재 단계·실행 회차·수행 기록. 별도 전역 Manager 없이 Runner 소유 |
| SceneBindings | 대상 ID를 실제 Object·컴포넌트·배치 앵커에 연결 |
| StepActionExecutor | 공통 작업 실행. 장비 고유 처리와 잡기 해제는 장비 측에 요청 |
| StepConditionEvaluator | 일회성 행동, 현재 상태, 유지 조건, 복수 조건 판단 |
| Interaction·장비 컴포넌트 | 감지·부착·회전·버튼·접촉 유지와 장비 상태 관리 |
| PresentationController | 음성·자막 재생·교체·중단. 교육 진행 판단은 하지 않음 |

### 7.2 Object·Animation·Transform 관리

공통 Action은 우선 SetActive, Animator 제어, 지정 앵커 배치, PlayCue로 제한한다. 각 Action에 대상·값·완료 대기 여부를 명시한다. 작업은 기본 순차 실행하며 필요한 시범·안내만 비대기로 시작한다.

- Collider 진입은 감지 정보이며 부착·착용 완료와 동일하지 않다.
- XR 잡기, 물리, Animation, 교육 이동이 같은 Transform을 동시에 제어하지 않는다.
- 잡힌 도구의 강제 배치·비활성화는 XR 선택 해제와 작업 정리 후 수행한다.
- 교육 대상의 On/Off로 Runner·음성·자막 시스템 루트가 함께 꺼지지 않게 분리한다.
- 복수 Collider와 이미 겹친 상태, 비활성화로 이탈 이벤트가 누락되는 상황도 처리한다.

### 7.3 자막 규칙

자막 문구는 **TrainingSubtitles static class의 const string**으로만 선언한다. 교육 Script와 Inspector 에셋에는 동일 문구를 복사하지 않는다.

```text
Cue = SubtitleId + AudioClip
SubtitleId → TrainingSubtitles.Get(id) → 해당 상수 → 표시
```

SubtitleId에는 고정된 값을 부여하고 기존 값 재사용·재번호를 피한다. 조회는 명시적 매핑으로 구성한다. 음성·자막의 재생 요청 ID를 관리해 이전 안내의 완료 신호가 새 자막을 지우지 않게 한다.

### 7.4 전환·취소·복원

- 상태: Idle → Entering → Running → Exiting → 다음 단계 또는 Completed. 중단은 Stopped.
- 조건은 진입 작업 전에 준비하되, 단계 전환은 진입 작업 완료 후 허용한다.
- 일반 안내 중 조작은 허용하는 기본안. 조작 잠금이 필요한 시범 단계는 명시한다.
- 중복 완료 요청은 한 번만 처리한다. 실행 회차·단계 진입 번호가 다른 콜백은 무시한다.
- 정상 완료는 종료 Action 실행. 중단·재시작은 완료 보상 없이 취소·복원한다.
- 복원 대상: 활성 상태, 부모·위치·회전·크기, 변경한 물리 상태, 장비 상태, Animation, 타이머·안내.
- 재시작 중 발생한 장비 이벤트는 평가에 반영하지 않는다. 상세 규칙은 [S5]를 따른다.

### 8.2 통합 인터페이스 제안

전체 앱에서 교육 ID와 필요한 초기 상태를 전달받아 시작하고, 완료 또는 중단 시 교육 ID·종료 사유·수행 요약을 반환하는 구조를 제안한다. B 모듈이 다른 담당자의 씬 로딩이나 공용 XR 설정을 직접 변경하지 않도록 책임을 정한다.

구체적인 호출 방식·데이터 타입·씬 진입점은 팀 합의 전이다. 결과는 우선 실행 중 메모리에서 관리하며 파일 저장·서버 전송은 요구 확정 후 결정한다.

## 13. 협업·변경 원칙

- B 문서만 `Docs/B`에서 작성·수정. A·C 문서는 읽기 전용.
- `AGENTS.md`는 `Docs/B`에 유지한다.
- `Assets`에서는 `Assets/B/**`만 요청 작업 범위 내 생성·쓰기·수정한다. 나머지 전체는 읽기 전용이며, 변경 필요 시 대상·이유·방법을 설명하고 사용자 승인을 기다린다. 경로 비교는 대소문자를 구분하지 않는다.
- B 외부 `.meta`와 `Assets/B.meta`도 읽기 전용이다. Unity 자동 저장·재직렬화·자동 수정으로 이 경계를 우회하지 않는다.
- 패키지 추가·버전 및 XR 설정 변경 필요 시 B 문서로 먼저 제안한다. Optional Validation 경고를 임의 Fix하지 않는다.
- 재사용 계약은 실제 공통 행동에 맞춰 작게 만든다. 요청되지 않은 범용 프레임워크·서버·설정 시스템은 추가하지 않는다.
- 코드 변경은 요청 범위와 기존 스타일에 맞추고, 성공 기준을 확인한 뒤 다음 단계로 진행한다.
