## 5. 잡기·판정·부착 동작

### 5.1 잡기

- 입력은 기존 Starter Assets XR Origin의 XRI 경로(NearFar Interactor, Grip 선택). 키보드 전용 입력 없음.
- XRGrabInteractable: Instantaneous, `selectMode = Single`, `throwOnDetach = false`, 이징·스무딩 없음, `useDynamicAttach`(현재 손 위치·회전에서 잡기 기준 생성 → 손 쪽으로 튀지 않음), `farAttachMode = DeferToInteractor`, 기본 Grab Transformer.
- Rigidbody: Kinematic, 중력 없음, 보간 없음. 놓으면 그 자리에 머문다(K1 방독면과 같은 방식). XRI는 잡는 동안만 Transform을 쓰고 놓을 때 초기 Rigidbody 설정을 복원한다.
- 왼손·오른손 모두 같은 본체를 잡는다. 한 번에 한 손. 다른 손이 곧바로 넘겨 잡으면 XRI가 이전 손 선택을 종료하고 새 손이 잡는다. 이 경우 같은 프레임에 잡기가 다시 시작되므로 놓기 판정·실패 기록을 하지 않는다.

### 5.2 배치 후보(잡고 있는 동안, 매 LateUpdate)

`TourniquetLimbTarget.Evaluate(루트 자세, 장비)`가 데이터로 받은 루트 자세에서 `Point_LimbAttach`(고리 중심)의 자세를 계산해 사지 기준과 비교한다. 잡는 동안에는 현재 Transform 자세를, 놓을 때는 §5.4의 놓기 기준 자세를 넘긴다. 판정 순서:

1. 영역: 판정 자세와(후보가 있으면) 후보 자세 각각에서 장비 판정 부피(§12.2)가 어느 영역 상자와 겹치면 `ForbiddenZone` 또는 `OtherTarget`. 둘 중 하나라도 겹치면 불가.
2. 후보 범위 밖(축 거리 > candidateRange 또는 구간 끝에서 candidateRange 초과) → `OutOfRange`, 미리보기 없음.
3. 축 방향 위치가 허용 구간 밖 → `OutsideAllowedZone`(위치).
4. 고리 중심과 사지 축 거리 > radialTolerance → `OffLimbCenter`(위치).
5. 고리 축과 사지 축 각도 > axisTolerance → `WrongAxis`(방향, 부호 있음: 뒤집힌 고리는 실패).
6. 본체 면(up)과 기준 up의 축 둘레 각도 > rollTolerance → `WrongRoll`(방향).
7. 모두 통과 → `Valid`.

후보 자세 = 고리 중심을 사지 축 위로 투영해 허용 구간 안에 고정한 위치 + 기준 회전, 이를 장비 루트 자세로 환산한 값. 손 추적이 끊기면 `TrackingLost`, 후보 없음.

### 5.3 미리보기

- 잡고 있고, 추적 중이고, 후보가 있을 때만 고스트와 문구를 표시한다. 가능 = 초록 고스트 + "배치 가능", 불가 = 빨강 고스트 + "배치 불가 / 이유".
- 고스트에는 Collider·Rigidbody·Interactable이 없다. 실제 장비·판정 대상과 충돌·잡기 간섭이 없다.
- 후보 이탈·추적 소실·놓기·부착 시 즉시 숨긴다.

### 5.4 부착 확정 시점

**놓기 기준 자세** = 놓는 프레임에 XRI가 갱신을 마친 잡던 interactor의 attach 자세 × 동적 잡기 기준(dynamic grab attach) 기준의 장비 루트 관계. 기본 Grab Transformer가 그 attach로 만들었을 자세와 같다. 근거·흐름은 §12.1.

1. 잡는 동안 잡던 NearFar interactor의 `InteractionAttachController.attachUpdated`를 구독한다. 매 프레임 XRI의 `PreprocessInteractor`(attach 갱신 완료, 선택 해제 전)에서 attach 자세·루트 관계·추적 유효성을 프레임 번호와 함께 표본으로 저장한다.
2. XRI `selectExited` 시점: 선택 취소(`isCanceled`)면 `SelectionCanceled`, 잡던 손이 미추적이면 `TrackingLost`, 이번 프레임·이 손의 표본이 없으면 `ReleasePoseUnavailable`("놓은 자세 확인 불가"). 그 외에는 표본으로 놓기 기준 자세를 계산해 보관만 한다. 구독·표본은 즉시 정리한다. 상태는 즉시 `Unattached`, 미리보기 정리. 장비 Transform·해제 후 interactor attach transform은 판정에 쓰지 않는다.
3. 같은 프레임 `LateUpdate`(실행 순서 100, XRInteractionManager −105의 Late 단계 `Detach` 이후): 다른 손이 이미 잡았으면 아무것도 하지 않는다(보류된 놓기는 새 잡기 시작 때 이미 취소됨). 놓기 기준 자세를 판정해 `Valid`면 부착, 아니면 장비를 놓기 기준 자세로 옮겨 놓고 실패를 기록한다. 판정 자세와 실제 정지 자세가 일치한다.
4. 부착: 속도 제거 → Kinematic·보간 없음 → 판정 결과의 후보 자세로 이동(Transform·Rigidbody 동시) → `throwOnDetach = false`, `interactionLayers = 0`(본체 이동 잡기 잠금) → `TQ_LimbTarget_LeftUpperArm`의 자식으로 이동(로컬 배치 유지) → 상태 `Attached` → `Attached` 이벤트 1회.
5. 실패: 부착·완료 기록 없음. `LastFailure`에 이유 기록, Prefab 초기 물리 설정 유지(Kinematic 여부는 XRI가 복원한 값 그대로), 다시 잡기 가능. 선택 취소·추적 소실은 XRI가 남긴 위치에 그대로 둔다.

부착 후 XRI가 Transform을 다시 쓰는 경로(Drop Transformer)는 기본 Transformer에 없음을 패키지 소스로 확인했다(정적 확인).

|---|---|---|
| `Unattached` | 미부착·잡지 않음 | 시작, 놓기(부착 전·실패) |
| `HeldBlocked` | 잡고 있음·배치 불가 | 잡기 중 판정 ≠ Valid, 추적 소실 |
| `HeldPlaceable` | 잡고 있음·배치 가능 | 잡기 중 판정 = Valid |
| `Attached` | 부착됨 | 유효한 정상 놓기 + 재검사 통과 |

런타임 상태는 직렬화·정적 필드에 남지 않는다. 새 Play 세션은 씬 저장값(미부착)에서 시작한다.

## 12. 정적 검토 지적 수정 (2026-10-29)

### 12.1 수정 A — 놓기 프레임의 최신 자세

원인(XRI 3.4.1 소스 확인):
- `XRInteractionManager.Update`는 `PreprocessInteractors` → 그룹 갱신·`ClearInteractorSelection`(선택 해제) → `ProcessInteractables(Dynamic)` 순서다. 장비 자세 갱신(`PerformInstantaneousUpdate`)은 선택 중일 때만 Dynamic·OnBeforeRender 단계에서 실행된다. 따라서 놓는 프레임에는 해제가 먼저 일어나고 그 프레임의 자세 갱신은 없다. `selectExited`와 같은 프레임 `LateUpdate`의 장비 Transform은 모두 **직전 프레임 렌더 자세**다. 처음 코드의 두 번 검사는 같은 이전 자세를 검사했다.
- `NearFarInteractor.OnSelectExiting`은 마지막 선택이 끝나면 `interactionAttachController.ResetOffset()`(앵커 자식 로컬 자세 초기화)을 호출한다. 매니저 `SelectExit` 순서는 `interactor.OnSelectExiting` → `interactable.OnSelectExiting`(Drop) → `interactor.OnSelectExited` → `interactable.OnSelectExited`(이벤트 후 동적 잡기 기준 반환)다. 장비가 `selectExited`를 받을 때 interactor attach는 이미 offset을 잃었다.

1차 수정의 잔여 문제(이번 수정 대상):
- 1차 수정은 "이번 프레임 컨트롤러 자세 × 직전 LateUpdate의 컨트롤러 기준 장비 관계"였다. NearFar는 `PreprocessInteractor(Dynamic)` → `InteractionAttachController.DoUpdate`에서 attach를 갱신한다. 이 갱신에는 움직임 안정화(앵커 부모가 컨트롤러를 지연 추종), 거리 기반 속도 배율·관성, 조작 입력의 당기기·밀기(`DoPositionUpdate`)·회전(앵커 자식 회전)이 들어 있다. 놓는 프레임에 처리된 이 결과는 컨트롤러 Transform과 이전 관계로는 복원되지 않는다. 컨트롤러를 고정하고 회전·당기기 입력과 Grip 해제를 같은 프레임에 넣거나, 안정화·속도 배율이 작동하는 중에 놓으면 실제 XRI 결과와 다른 강체 추정 자세로 판정됐다.

정보 확보 지점:
- `InteractionAttachController.DoUpdate`는 끝에서 공개 이벤트 `attachUpdated`를 발생시킨다(offset이 없을 때와 있을 때 모두). `DoUpdate` 호출처는 `NearFarInteractor.PreprocessInteractor`(Dynamic)뿐이다. 이 시점은 같은 Update의 선택 해제·`ResetOffset`보다 앞서고, 선택 중이면 interactor·동적 잡기 기준이 모두 유효하다. 공개 이벤트만 사용한다. 패키지 수정·리플렉션·private 접근·상속·추가 `DoUpdate` 호출은 없다.

기본 Grab Transformer와의 대응(`XRGeneralGrabTransformer` 단일 잡기, 위치·회전 추적, 축 제한 없음, 축척 1):
- `OnGrab`에서 offset 회전 = (루트 기준 동적 잡기 기준 회전)의 역, offset 위치 = 동적 잡기 기준 공간에서 본 루트 위치. 잡기점 보정항은 interactor attach 위치를 기준으로 잡아 0이다.
- `UpdateTarget`의 결과는 루트 = interactor attach 자세 ∘ (동적 잡기 기준 공간에서 본 루트 자세)다. 장비는 Instantaneous, 이징·스무딩 없음이라 이 target이 그대로 Transform이 된다.
- 표본의 루트 관계는 같은 프레임의 루트와 `grab.GetAttachTransform(interactor)`(동적 잡기 기준, 루트의 자식이며 잡는 동안 고정)로 계산한다. 이는 Transformer의 offset과 같은 값이다.

수정한 흐름(`TourniquetDevice`):
1. `selectEntered`: 이전 표본을 지우고 이 interactor가 `NearFarInteractor`면 그 `InteractionAttachController.attachUpdated`를 구독한다(구독 전 기존 구독 해제 → 중복 없음).
2. `attachUpdated`(매 프레임, 선택 해제 전): 이 interactor가 장비를 아직 선택 중일 때만 표본을 저장한다. 표본 = {interactor, `Time.frameCount`, 갱신된 interactor attach 자세(`GetAttachTransform`), 동적 잡기 기준 공간의 루트 자세, 손 추적 유효성}. 자세를 읽기만 하고 아무것도 움직이거나 다시 갱신하지 않는다.
3. `selectExited`: 표본의 interactor·프레임이 이번 해제와 같고 추적 유효하며 취소가 아닐 때만 놓기 기준 자세 = 표본 attach ∘ 루트 관계를 계산해 보관한다. 이유 구분: 취소 → `SelectionCanceled`, 해제 시점 또는 표본의 미추적 → `TrackingLost`, 이번 프레임 표본 없음 → `ReleasePoseUnavailable`. 이전 프레임 값으로 성공 처리하지 않는다. 구독·표본은 여기서 정리한다.
4. 같은 프레임 `LateUpdate`(XRI Late 단계 이후): 다시 잡혔으면 무시한다. 놓기 기준 자세를 한 번 판정해 유효하면 후보 자세로 부착(1회)하고, 아니면 놓기 기준 자세에 정지시키고 실패를 기록한다.

수명·순서:
- 첫 잡기: 선택 시작은 같은 Update의 `PreprocessInteractors`보다 뒤라 그 프레임 표본은 없다. 해제는 항상 다음 프레임 이후이므로 그 프레임의 `PreprocessInteractor` 표본이 먼저 생긴다.
- 같은 프레임 손 바꿈: 두 손의 `PreprocessInteractor`가 모두 끝난 뒤 선택 처리 루프에서 이전 손 해제 → 새 손 선택이 연속 호출된다. 새 `selectEntered`가 보류 놓기를 취소하고, 이전 손 구독을 해제하고, 새 손을 구독한다. 표본은 interactor로 구분해 재사용하지 않는다.
- 비활성화·씬 종료: `OnDisable`이 선택을 취소하고(놓기 판정 없음) 구독·표본·보류 정보를 모두 정리한다.
- 근거리·원거리: 둘 다 같은 경로다. 원거리 offset과 그 프레임의 안정화·배율·조작 결과는 표본 attach 자세에 들어 있다. 장비를 손 위치로 끌어오지 않는다.
- `NearFarInteractor`가 아니거나 attach controller가 `InteractionAttachController`가 아닌 interactor로 잡으면 표본이 없어 `ReleasePoseUnavailable`로 부착하지 않는다. Starter Assets XR Origin의 잡기 interactor는 NearFar다(검사 메뉴로 확인).
- 실행 순서 숫자 변경, 한 프레임 대기, 기본 입력 기능 끄기는 쓰지 않았다. 컨트롤러 강체 추정 경로는 제거했다.

### 12.5 남은 근사 한계

- 놓기 기준 자세는 해제 프레임 Update 단계에서 XRI가 계산한 attach 결과다. 그 프레임에 장비가 실제로 그 자세까지 렌더되지는 않았다(XRI가 해제 후 갱신하지 않음). 실패 시 장비를 그 자세로 옮겨 판정 자세와 정지 자세를 맞춘다. 렌더 직전(OnBeforeRender)의 늦은 추적 갱신분은 포함되지 않는다.
- 기본 Grab Transformer 대응은 단일 잡기·위치/회전 추적·축 제한 없음·루트 축척 1·이징/스무딩 없음 전제다. Prefab 설정이 바뀌면 일치하지 않는다(검사 메뉴로 확인).
- NearFar + `InteractionAttachController`가 아닌 interactor로 잡은 경우 놓기 자세를 확보하지 않고 부착하지 않는다.
- 잡는 도중 손 추적이 끊긴 프레임의 표본은 미추적으로 기록된다. 그 프레임에 놓으면 `TrackingLost`다.
- 판정 부피는 상자 근사다. 조임막대 원기둥은 외접 상자라 모서리만큼 크게 판정된다. 밴드 고리는 24구간 다각형이며 실제 밴드 메시(48구간)와 미세하게 다르다. 영역 상자 자체도 피부 형상을 따르지 않는다.
- 판정 부피는 Prefab 루트 축척 1을 전제한다(검사 메뉴로 확인).
