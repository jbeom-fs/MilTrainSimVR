## 2. 잡기 허용 조건

`K1MaskExtraction`이 `XRGrabInteractable`의 선택 필터(`IXRSelectFilter`)로 새 선택만 판정한다. 이미 잡고 있는 손은 계속 통과한다(XRI가 선택 유지 중에도 필터를 재평가하기 때문).

| 상태 | 새 잡기 허용 |
|---|---|
| 꺼내기 전(수납·추출 중) | `carrierLid.IsUnlocked && carrierLid.IsFullyOpen`를 **매 판정 시 현재 값으로** 확인 + 근거리 |
| 완전 이탈 후 | 주머니 상태와 무관, 근거리만 |

- 근거리: 선택하는 인터랙터의 부모 `TrackedPoseDriver`가 추적 중이고, 그 위치가 잡기 기준점에서 `maxHandDistance`(기본 0.25m) 이내. 먼 거리 레이 잡기를 막는다. 추적 판정은 덮개와 같은 함수(`K1CarrierLid.IsTracked`)를 쓴다.
- 미리 누른 입력: 스타터 리그 인터랙터의 선택 방식이 `StateChange`다. XRI 3.4.1 소스 설명상 "상호작용이 가능해지기 전에 누르기 시작한 입력으로는 선택되지 않는다". 닫힌 상태에서 누른 채 기다려도 덮개가 열린 뒤 자동으로 잡히지 않는다. 리그 설정은 바꾸지 않았다.
- 한 손: `InteractableSelectMode.Single`. 다른 손이 잡으면 이전 손이 해제되고 새 손이 현재 위치에서 이어 받는다.

## 3. 잡기 기준점

- 주머니의 `Anchor_MaskPickup`은 주머니 `MaskInteractionFrame` 아래에 있어 방독면을 따라가지 않는다. 그래서 방독면 Prefab 루트 아래에 `MaskPickupPoint`(Transform만)를 만들고, 수납 상태에서 원본 앵커와 같은 위치·방향이 되도록 배치했다.
- 계산: 주머니 FBX의 `Anchor_MaskStored`·`Anchor_MaskPickup`과 방독면 `Anchor_FaceFit` 실제 임포트 값으로 `수납 루트 = MaskStored × FaceFit⁻¹`(수납 배치와 같은 식), `잡기 기준점 = 수납 루트⁻¹ × MaskPickup`.
- `MaskPickupPoint`는 방독면 자식이므로 추출 중·이탈 후에도 방독면을 따라간다. `XRGrabInteractable.attachTransform`과 근거리 판정 기준으로 쓴다. 주머니 안에 고정 조작점은 만들지 않았다.
- 잡기 Collider는 새로 만들지 않고 기존 물리 Collider 5개를 `XRGrabInteractable.colliders`로 지정했다.

## 4. 추출 제어 (완전 이탈 전)

- 단일 경로: `XRGrabInteractable`(Instantaneous)의 유일한 잡기 Transformer가 `K1MaskExtraction`이다. 기본 Transformer 자동 추가 끔. XRI가 계산 결과를 Transform에 한 번 적용하고, 다른 스크립트는 방독면 Transform을 쓰지 않는다.
- 목표 자세 = 수납 자세 + 주머니 위쪽(+Y) × 추출량. 회전과 횡방향 위치는 수납 기준 그대로다. 수납 자세는 Play 시작 시 씬에 저장된 자세를 주머니 기준으로 기억한다.
- 추출량 = 기준 추출량 + (현재 손 − 기준 손)의 주머니 +Y 성분. 0 ~ (완전 이탈 거리 + `extractionOvershoot` 0.03m)로 제한한다.
- 기준은 새 선택마다(같은 손 재잡기·손 전환 포함) 첫 추적 프레임의 손 위치와 현재 추출량이다. 잡는 순간 방독면이 손으로 이동하지 않는다.
- 놓으면 그 위치에 정지한다(kinematic 유지, 던지기 없음, 이징·스무딩 0).
- 추적 소실: 현재 자세를 유지하고 기준을 버린다. 복귀한 첫 프레임이 새 기준이 되어 튀지 않는다.
- 접힌 머리끈·정화통 부착 상태는 손대지 않는다. 방독면 전체가 강체로만 이동한다.

## 5. 덮개 연동

- **추출 시작 조건(2026-10-27 수정)**: 잡은 뒤 다른 손으로 덮개를 닫을 수 있으므로, 잡을 때의 확인과 별도로 수납 구간(추출량 ≤ 1mm)에서 추출 구간으로 넘어가기 직전 프레임마다 `carrierLid.IsUnlocked && carrierLid.IsFullyOpen`를 현재 값으로 다시 확인한다.
  - 만족: 먼저 `K1CarrierLid.HoldOpenAtLeast(현재 열림)`로 닫힘 하한을 건 뒤, 같은 프레임에 추출량을 갱신해 방독면을 움직인다.
  - 불만족: 잡기는 유지하고 방독면은 현재 위치(수납 구간)에 둔다. 손 기준을 버려 다음 프레임에 현재 손 위치·현재 추출량으로 다시 잡는다. 따라서 덮개가 닫혀 있던 동안의 손 이동은 누적되지 않고, 덮개를 다시 완전히 연 뒤에는 그때의 손 위치부터 추출이 이어진다. 강제로 놓거나 처음부터 다시 시작하지 않는다.
- 하한이 걸린 뒤 덮개는 더 열 수는 있지만 그 값 아래로 닫히지 않는다. 손을 놓아도 부분 추출 상태면 하한이 유지된다.
- 추출량이 1mm 이하로 돌아오면(수납 위치 복귀, 허용오차 1mm 유지) 하한을 해제한다. 잡기를 유지한 채 다시 올리면 위 시작 조건을 다시 확인한다.
- 완전 이탈 시 하한을 해제한다.
- 덮개 제어(손잡이 경로·보간·상태 판정)는 바꾸지 않았고, 최종 열림 적용 직전에 하한만 반영한다.
- 하한은 완전 열림(≥0.97 진입, ≥0.93 유지) 상태의 열림 값이므로 0.93 이상이다. 부분 추출 뒤 다시 잡을 때 `IsFullyOpen` 조건이 유지된다.
- 이전 구현은 추출량을 먼저 계산·적용한 뒤 하한을 걸어, 잡은 채 덮개를 닫으면 닫힌 값으로 하한이 걸리고 닫힌 덮개를 통과해 추출될 수 있었다(정적 검토 지적, P2). 위와 같이 수정했다.

## 6. 완전 이탈 판정 근거

- 판정 데이터: 렌더 부품 9개(Part_Buckles, Facepiece, FilterCanister, FilterConnector, FrontAssembly, Harness, Lens_L, Lens_R, TubeAssembly)별 경계 상자. 방독면 루트 로컬 좌표.
- Editor 계산: 방독면 Prefab 사본에 수납 본 자세(수납 배치와 같은 `SolveStoredBoneLocals`)와 BlendShape 값을 적용하고, `Part_Harness`는 `SkinnedMeshRenderer.BakeMesh`로 **변형된 정점**을, 강체 부품은 Mesh 정점을 읽어 부품별 상자를 만든다. SkinnedMeshRenderer 기본 자세 bounds는 쓰지 않는다. 사본은 저장하지 않고 버린다.
- 런타임 판정: 모든 부품 상자의 꼭짓점 8개 × 9개가 입구 평면(`Anchor_ExitPlane`, 법선 = 주머니 +Y)보다 `exitMargin`(기본 0.005m) 이상 위에 있을 때만 완전 이탈. 상자는 실제 형상을 포함하므로 일부 형상이 안에 남았는데 완료되는 일은 없다(보수적). 본 원점·충돌 프록시·이동 거리·루트 통과로 판정하지 않는다.
- 추출 중 방독면 축이 주머니 축과 평행하므로 가장 낮은 꼭짓점 높이 = 실제 최저 정점 높이다. 완료가 늦어지는 양은 `exitMargin`뿐이다.
- 참고 수치: 원본 수납 형상 최저점 z=0.012m, 입구 z=0.254m → 최저점이 입구에 닿는 추출량 약 0.242m, 판정은 약 0.247m. `K1_StoragePose.json`의 0.26m 경로는 참고로만 쓰며(검사 INFO), 완료 판정에 쓰지 않는다.
- 완료는 한 번만: `IsExtracted`가 true가 되는 프레임에 로그 1줄과 `Extracted` 이벤트 1회. 이후 주머니에 다시 넣어도 수납 상태로 돌아가지 않는다.
- 런타임은 `Source~`·JSON을 읽지 않는다.

## 7. 자유 잡기 전환

- 완전 이탈 판정 프레임에 위쪽 제한을 해제하고, 같은 손의 컨트롤러 포즈와 그 프레임의 방독면 자세로 상대 오프셋을 잡는다. 이후 목표 = 컨트롤러 포즈 × 오프셋. 선택을 끊거나 다시 걸지 않으므로 손이 놓이지 않고 위치·회전이 튀지 않는다.
- 이탈 후 놓기: 현재 위치에 정지. 다시 잡기·손 전환: 새 선택 시점의 오프셋으로 이어 잡는다.
- 추적 소실 시 정지·복귀 시 오프셋 재설정은 추출 단계와 같다.
- 중력 낙하·던지기·분실 회수 없음.

## 8. 상태 제공 (`K1MaskExtraction`, 방독면 루트)

| 멤버 | 의미 |
|---|---|
| `CanGrab` | 현재 새 잡기 가능 여부(손 거리 제외): 이탈 후이거나, 수납 상태에서 주머니가 해제·완전 열림 |
| `Extraction` | 주머니 +Y 방향 추출량(m), 0 = 수납. 이탈 후 고정 |

## 12. 사용자 확인 순서

준비: Unity 컴파일 완료, `B_K1_Tutorial` 열기·저장 상태. 결과 로그를 그대로 전달.

1. **컴파일·구성**: Console 컴파일 오류 없음 → 메뉴 3(`Keep existing`).
   기대: 로그에 `Folded mask outline: 9 parts, lowest point …mm below the mouth`, `Mask extraction configured`, `Mask linked to carrier lid and Anchor_ExitPlane`, 이어서 메뉴 4 `Result: no FAIL items.` 메뉴 2도 `Result: no FAIL items.`
   실패: `FAILED`, FAIL, `NOT RUN`.
2. **잡기 차단**: Play. 잠긴 상태·덮개 닫힘·덮개 절반 열림에서 방독면 위쪽을 잡으려 함 → 잡히지 않음. 닫힌 상태에서 버튼을 누른 채 덮개를 다른 손으로 끝까지 연 뒤에도 → 잡히지 않음(새로 눌러야 함).
3. **완전 열림 후 잡기**: 덮개를 끝까지 연 뒤(`Fully open: True`) 방독면 위쪽 고무 부근에서 버튼을 새로 누름 → 잡힘, 잡는 순간 방독면 위치 변화 없음. 0.25m 밖에서 레이로 선택 → 잡히지 않음.
4. **위쪽으로만 추출**: 잡은 채 손을 옆·앞뒤로 움직이고 손목을 돌림 → 방독면은 움직이지 않거나 위아래로만 이동, 회전 없음. 손을 올림 → 주머니 위쪽으로 따라 올라옴. 아래로는 수납 위치 아래로 내려가지 않음.
5. **놓기·재잡기·손 전환**: 중간에 놓음 → 그 높이에 정지. 다시 잡음 → 튐 없이 이어서 추출. 잡은 채 다른 손으로 잡음 → 첫 손 해제, 튐 없이 새 손으로 이어짐.
6. **덮개 닫힘 제한**: 방독면이 조금 올라온 상태(놓은 상태 포함)에서 덮개를 닫으려 함 → 그때 열림보다 더 닫히지 않음. 방독면을 완전히 내려 수납 위치로 되돌리면 → 덮개를 다시 닫을 수 있음.
7. **일부 남음 → 미완료**: 정화통·머리끈 아래쪽이 입구 아래에 남은 높이에서 멈춤 → 완료 로그 없음, 아직 위로만 움직임.
8. **완전 이탈 순간**: 계속 올림 → 모든 부분이 입구 위로 나온 순간 Console `[K1MaskExtraction] Mask fully out of the carrier (extraction ~0.247 m).` 1회. 손에서 떨어지지 않고 위치·회전 튐 없음.
9. **자유 잡기**: 이어서 옆으로 옮기고 돌림 → 손을 따라 자유 이동·회전. 놓음 → 그 자리에 정지(떨어지지 않음). 다시 잡음·손 전환 → 튐 없음. 이후 주머니 상태와 무관하게 잡힘. 주머니 입구에 다시 가져가도 수납 상태로 돌아가지 않고 완료 로그가 다시 나오지 않음.
10. **유지**: 전 과정에서 주머니 본체가 움직이지 않음. 머리끈은 접힌 상태 그대로(펼쳐지지 않음), 정화통 부착 유지.
11. **초기 복원**: Play 종료 → 방독면이 주머니 안 수납 위치, 덮개 닫힘, 표시등 주황. 메뉴 4 `Result: no FAIL items.`(씬 항목 `Saved stored and not extracted` 포함).
12. **재구성**: 메뉴 3(`Keep existing`) 재실행 → `MaskPickupPoint`·`XRGrabInteractable`·`K1MaskExtraction` 각 1개, 메뉴 2·4 `Result: no FAIL items.` 메뉴 1(Prefab `Replace`, 씬 `Keep existing`) 실행 후에도 방독면 잡기 구성·수납·연결 유지, 메뉴 2·4 통과.

### 12.1 추출 시작 조건 수정 확인 (2026-10-27)

컴파일 후 Play. 각 단계 결과와 Console 로그를 그대로 전달.

1. 덮개를 완전히 열고 방독면을 잡되 들어 올리지 않는다. 잡은 채 다른 손으로 덮개를 닫는다(표시등 근처 덮개 끝을 잡아 되돌림). 방독면을 잡은 손을 위로 올린다.
   기대: 방독면이 올라오지 않음. 선택은 유지됨. 실패: 닫힌 덮개를 통과해 올라옴, 선택이 강제로 풀림.
2. 위 상태에서 손을 위로 올려 둔 채, 다른 손으로 덮개를 다시 끝까지 연다(`Fully open: True`).
   기대: 여는 순간 방독면이 손 높이로 튀지 않음. 그 뒤 손을 올리면 현재 위치에서 추출 시작. 실패: 열린 순간 방독면이 한 번에 올라옴.
3. 부분 추출 후 놓는다. 덮개를 닫아 본다.
   기대: 방독면 그 높이에 정지. 덮개는 추출 시작 때 열림보다 닫히지 않음.
4. 다시 잡아 수납 위치까지 내리고 선택을 유지한다. 다른 손으로 덮개를 닫은 뒤 방독면을 다시 들어 올린다.
   기대: 수납 위치까지 내리면 덮개를 닫을 수 있음, 닫힌 상태에서는 추출 차단. 덮개를 다시 완전히 열면 튐 없이 그때 손 위치부터 추출 재개.
5. 정상적으로 완전 이탈시킨다.
   기대: `Mask fully out of the carrier` 로그 1회, 선택 유지, 자유 이동·회전 가능. 이후 덮개를 닫거나 열어도 다시 잡기 가능.
6. Play 종료 후 메뉴 2·4 실행.
   기대: 두 메뉴 모두 `Result: no FAIL items.`

## 13. 미검증·제약

- 컴파일·메뉴·Play·Simulator 조작 결과: 사용자 확인 전.
- 메뉴 3의 외곽 생성 결과(위 11절). 실패 시 앞 단계 저장 변경이 남을 수 있음.
