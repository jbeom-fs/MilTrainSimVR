# 화생방 씬 YAML 고정 배치 — 2026-11-09

사용자 요청에 따라 `Assets/B/Scene/B_CBRN.unity`를 직접 수정했다. 구급법 작업과 같은 수동 YAML 방식이며 자동 배치 도구를 실행하지 않았다. Unity 임포트·컴파일·메뉴·Play·헤드셋 검증은 수행하지 않았다.

## 배치와 환경

기존 B 소유 `B_BarracksShell.prefab`과 `B_FirstAidTable.prefab`을 재사용했다. 구급법 씬과 공용 프리팹·재질·모델 파일은 변경하지 않았다. A/C 원본 반입이나 새 자산 복제도 하지 않았다.

| 대상 | 월드 위치 X, Y, Z (m) | Yaw |
|---|---|---|
| K1 방독면 StationRoot | -1.7, 0, -3.6 | 270° |
| 보호의 StationRoot | 1.8, 0, -3.6 | 90° |
| KD-1 StationRoot | 0.25, 0, -7.0 | 180° |
| EntryAnchor | 0, 0, -0.85 | 180° |
| ExitAnchor | 1.6, 0, -0.7 | 90° |

K1은 왼쪽, 보호의는 오른쪽, KD-1은 안쪽이다. 각 실습 위치 앞의 장비·거울은 가까운 벽 쪽에 놓인다. PracticeAnchor와 FloorAnchor의 로컬 위치·회전, 장비·거울·아바타의 과정 내부 상대 배치는 유지했다.

- EnvironmentRoot 아래 내무반 프리팹 인스턴스 1개를 추가했다. 기준은 원점·회전 0·배율 1이다.
- 기존 TempFloor는 비활성화했다. 기존 PC_Floor·KD1_Floor는 원래 비활성이며 그대로 유지했다. 실제 바닥은 내무반 Shell/Floor다.
- 입구판은 입구의 앞쪽 왼편, 출구판은 오른편에 배치했다. 교육 목록·버튼·씬 전환 참조는 유지했다.
- 과정 이름 표지는 로컬 높이 2.23m, 크기 2.6×0.4m로 방 안에 배치했다.
- B_CBRNFill_1·2 보조 Point Light를 추가했다. 구급법의 보조 광원 설정을 재사용했으며 기존 Directional Light도 유지했다.

## 세 콘텐츠 테이블

| 콘텐츠 | 기존 받침대 | 폭 × 깊이 | 상판 높이 |
|---|---|---|---|
| K1 방독면 | Workbench | 1.20×0.60m | 0.85m |
| 보호의 | PC_Workbench | 0.85×1.30m | 0.85m |
| KD-1 | KD1_Workbench | 1.00×0.60m | 0.80m |

각 기존 받침대의 자식으로 B_TableModel 프리팹 인스턴스를 추가했다. 기존 Transform은 유지하고 새 모델의 폭·깊이·높이를 맞췄다. 하단은 바닥 Y=0이다. 기존 Box MeshRenderer와 BoxCollider 3쌍은 비활성화하고 새 모델의 MeshCollider를 사용한다. 장비의 저장 위치나 교육 복구 지점은 이동하지 않았다.

## 이동 목적지

EnvironmentRoot/B_CBRNWalkable에 TeleportationArea 1개와 목적지용 BoxCollider 7개를 추가했다. 각 Collider 윗면은 Y=0.002m다. Teleport 상호작용 레이어와 윗면 히트 판정을 사용하며, 과정별 기존 실습 TeleportationAnchor도 유지한다.

| 구역 | X 범위 | Z 범위 |
|---|---|---|
| Entry | -0.10~2.05 | -1.20~-0.45 |
| EntryRight | 0.25~0.90 | -2.70~-1.10 |
| Centre | -0.75~0.75 | -5.80~-2.60 |
| Cross | -3.40~3.40 | -5.90~-5.60 |
| WestReturn | -3.40~-1.50 | -8.80~-5.70 |
| EastReturn | 1.50~3.40 | -8.80~-5.70 |
| Rear | -3.40~3.40 | -8.95~-8.65 |

위 값은 순간이동을 허용하는 목적지 범위다. 물리적인 바닥 전체를 순간이동 가능 영역으로 지정한 것은 아니다. 중앙 통로와 안쪽 양옆·뒤편을 돌아오는 구성을 의도했다.

## 정적 검토 결과와 한계

- 기존 씬 문서 21개를 변경하고 새 문서 38개를 추가했다. 모든 기존 MonoBehaviour와 기존 교육 프리팹 인스턴스 문서는 그대로다.
- YAML 중복 fileID·파일 내부 참조·직렬화된 계층 연결을 확인했다. 새 자산 참조 GUID 3개가 프로젝트/패키지에 존재하며 A/C 자산을 직접 참조하지 않는다.
- B 코드와 구급법 씬·기존 환경/테이블 프리팹 및 meta·글꼴 등 143개 파일의 해시가 작업 전과 같다.
- PracticeAnchor·FloorAnchor의 원문을 보존했고, 세 테이블의 계산상 바닥 면적과 상판 높이가 기존 받침대와 일치한다.
- 저장된 LocalArea 사각형은 방 내부에 있고 서로 겹치지 않는다. 목적지 사각형 7개는 서로 연결되며, 각 사각형에 몸 여유 0.25m를 더해도 저장된 실습 범위나 방 경계를 침범하지 않는다.

마지막 항목은 저장된 실습 범위로 검토한 결과다. 실제 Renderer·Collider 형상, 사용자 아바타의 움직임이나 손 이동 전체를 측정한 결과가 아니다. 거울 영상, 재질, 충돌체 요리 결과, 착용·집기·순간이동의 실제 동작은 사용자 실행 전에는 미확인이다.

## 후속 작업 — 거울 외형 모델링

사용자가 11/09 작업 마감 때 거울도 추후 모델링할 항목으로 추가하도록 요청했다. K1_Mirror·PC_Mirror의 프레임·지지대 등 외형을 B 소유 모델로 제작·적용한다. 기존 반사면·카메라·RenderTexture·아바타 제외 설정과 교육 참조는 유지하고, 모델이 몸·손·이동 경로를 가리지 않도록 한다. 오늘은 후속 작업 기록만 추가했으며 모델 제작이나 거울 씬 변경은 하지 않았다.

최신 완료 상태와 다음 순서는 [1109 작업 마감](1109_작업마감_진행상황.md)을 따른다. 사용자의 씬 수정 확인 완료 보고는 보존하고, 아래 순서는 작업 당시 확인 절차로 남긴다.

## 사용자 확인 순서

1. Unity에서 외부 변경을 반영하고 B_CBRN 씬을 다시 연다. 이전 씬 상태가 열려 있다면 그 상태로 덮어 저장하지 않는다. Missing Script·임포트 오류·분홍 재질·누락 모델이 없는지 확인한다.
2. Hierarchy에서 B_BarracksShell 1개, B_CBRNWalkable 1개, 보조 광원 2개, 세 테이블 인스턴스와 TempFloor 비활성을 확인한다. 테이블 상판에 장비가 놓이고 바닥 아래로 모델이 내려가지 않는지 본다.
3. `B/교육장/4. 화생방 검사 (읽기 전용)`를 실행한다. 기존 과정·거울 카메라·아바타·입출구 참조에서 FAIL이 없는지 확인한다.
4. Play에서 입구 정렬과 안내판 가독성을 확인한다. 각 과정 시작 후 장비 집기·착용·중단·복귀를 확인하고, K1 정면/측면 거울과 보호의 거울에 사용자 몸과 장비가 올바르게 나오는지 본다.
5. 중앙·양옆·안쪽 목적지와 실습 앵커 사이를 이동한다. 벽이나 테이블·장비 내부로 도착하거나 돌아 나올 수 없는 위치가 있으면 해당 위치를 기록한다.
6. 출구 버튼으로 구급법 씬 전환을 확인한다. 구급법에서 돌아왔을 때 화생방 입구 정렬이 다시 되는지도 확인한다.

사용자가 씬 수정 확인 완료를 보고한 뒤 생성 기능 삭제를 요청했다. `B/환경/1·2` 자동 반입·기록 기반 검사와 `B/교육장/1·2` 생성·갱신 코드를 제거했다. 자동 반입 도구 4개, 미사용 반입 기록 클래스와 각 meta도 삭제했다. `B/교육장/3·4` 읽기 전용 검사와 교육 런타임은 유지한다. 삭제 작업은 씬·프리팹·글꼴을 변경하지 않았다. 코드 정리 후 Unity 재컴파일·검사 메뉴 실행은 사용자 확인 전이다.

커밋·Push는 하지 않았다. 변경 전 씬의 임시 백업은 `Temp/CodexCbrnYaml/B_CBRN.before.unity`다. Temp는 영구 보관 위치가 아니다.
