# 통합 씬 사용자 피드백과 개선 요구 — 2026-11-06

사용자가 운영 씬 사용 중 6건을 보고하고, 추가로 교육 중단 시 Simulator 정지가 실제 VR에도 영향을 주는지 확인을 요청했다. 사용자 현상 보고와 코드상 근거를 구분한다. 이번 작업은 정적 확인·요구 정리이며 코드·씬을 직접 수정하거나 실행하지 않았다.

## 1. 보호의: 잡아야 할 품목 안내

- 사용자 보고: 첫 단계에서 하의를 잡아야 하지만 어떤 물건인지 표시되지 않아 혼동된다.
- 정적 근거: `ProtectiveClothingTrainingGuide.Instruction:123`~124는 잡기 전 행동 문구만 반환하고 target을 설정하지 않는다. target은 잡은 뒤 131행에서 설정되며 `ShowMarker:182`는 물건이 아니라 사용자 몸의 착용 영역에 링을 표시한다.
- 개선 요구: 현재 단계의 품목 위에 물건을 식별할 표식과 이름을 표시한다. 예: 하의 위 화살표/강조와 ‘하의를 잡으세요’. 잡은 뒤에는 기존 착용 위치 안내로 전환한다. 상의·덧신 좌우·장갑 좌우에도 단계 대상을 일관되게 연결하고 완료·보류·중단·초기화에 맞춰 표시를 정리한다. 실제 착용 판정 크기와 순서는 유지한다.

## 2. 타 과정 체험 불가 패널의 글자 비침

- 사용자 보고: 실습 중 다른 과정의 체험 불가 패널 글자가 현재 과정 패널 뒤에서 보인다.
- 정적 근거: `TrainingFieldSetup.EnsureBlockers`는 별도 Canvas를 만들고 원본 보드보다 sortingOrder를 10 높인다. 다른 실습대의 가림판도 같은 정책이다. UI 배경과 글꼴은 투명 렌더링을 사용하며 현재 글꼴 원본 셰이더는 `TextMeshPro/Distance Field`다. 상태 표식의 Overlay 셰이더가 글꼴에 적용돼 있다고 단정할 근거는 없다.
- 개선 요구: 현재 보드를 뒤의 안내 글자가 뚫고 보이지 않도록 처리한다. 과정 시작 소유권/입력 잠금과 가림판 텍스트 표시를 분리하고, 불필요한 타 과정 안내 중복과 월드 UI 깊이·그리기 순서를 함께 정리한다. sortingOrder만 계속 높이거나 모든 글꼴을 Always/Overlay로 바꾸는 방식은 피한다. 최종 원인과 양안 결과는 사용자 실행으로 확인해야 한다.

## 3. 지혈대: 초록 허용 영역 중심으로 설명 단순화

- 사용자 요구: 빨강·노랑 계열 영역 안내를 제거하고 초록 영역에 배치하라는 문구로 단순화한다.
- 정적 근거: 현 코드의 소개는 ‘초록: 개발용 허용 영역 · 빨강: 금지 영역 · 주황: 다른 부위’다. 사용자 표현의 노랑은 현재 문구상 주황에 해당할 수 있으며 장치 색상은 이번에 보지 않았다.
- 개선 요구: 교육생에게는 초록 허용 영역을 표시하고 해당 위치에 지혈대를 가져가라는 안내를 제공한다. 빨강/주황의 표시와 색상 범례를 제거한다. ‘빨간 밴드 끝’처럼 별도 장비 조작을 가리키는 문구까지 일괄 삭제하지 않는다. 잘못된 부위/허용 영역 밖 배치 차단은 유지한다.

## 4. 직접 압박: 상처 위치 안내 강화

- 사용자 보고: 상처 부위가 잘 보이지 않는다.
- 정적 근거: 기존 `PB_WoundMarker`는 WoundTarget 아래 작은 표시용 원판이다. 교육의 이동 링 `PressureBandageCourseMarker`는 기본 반경 0.035m로 장비 조작점 중심을 따라가며, 상처를 지속적으로 식별시키는 전용 방향 안내와는 다르다.
- 개선 요구: 실제 WoundTarget에 연결한 화살표·윤곽/영역 강조로 드레싱을 가져갈 상처 위치를 명확히 한다. 현재 단계에서 필요한 동안만 표시하고 드레싱/붕대 아래 상처를 과도하게 가리지 않는다. 표시를 키우는 것과 상처·접촉 성공 영역을 키우는 것을 구분한다. 실습 루트 재배치·자세 변경에도 표시와 실제 판정이 일치해야 한다.

## 5. 구급법 마네킹: 앉은 자세와 접근성

**후속 사용자 범위 정정이 우선:** AED 환자는 원래의 누운 자세를 유지한다. 앉은 자세 변경은 서 있던 지혈대·압박붕대 마네킹에 적용한다. 에이전트가 앞선 프롬프트에서 AED까지 포함해 범위를 잘못 확장했다. 아래의 AED 자세 변경 요구와 기존 프롬프트는 이 정정으로 대체한다. AED 충전 보류 등 자세와 무관한 개선은 유지한다.

- 사용자 요구: 서 있는 마네킹 때문에 키에 따라 불편하므로 구급법 마네킹을 앉은 자세로 변경한다.
- 개선 요구: 구급법 실습 대상의 앉은 자세, 지지물/의자, 팔 위치와 손이 닿는 작업 높이를 함께 조정한다. 적용할 각 마네킹의 리그·메시·장비 연결을 확인한다.
- 자세만 변경해서 완료라 하지 않는다. AED 패드 위치/부착 표시, 지혈대 대상/부착 앵커/영역, 압박붕대 상처 프레임/감김 경로/테이프 위치, 환자 접촉 검사와 초기화 위치가 실제 표면을 따라야 한다. 특히 PB WoundTarget은 현재 마네킹 홀더 아래에 있고 감김 경로는 표면에서 측정하는 구조라 포즈 변경 후 정렬/재계산 여부를 확인해야 한다.
- 원본 모델·다른 과정 원본은 보존하고 B 작업본으로 적용한다. 원본 모델 제작·수정이 필요하면 기존 지침대로 Blender를 사용한다. 정지 자세 구성과 런타임 코드 개선 범위를 구분한다.

## 6. 압박붕대 테이프: 근접 자동 부착

- 사용자 요구: 각도 판정이 엄격하므로 적당히 근처에 오면 붙도록 변경한다.
- 정적 근거: `PressureBandageApplication.JudgeTape`는 접촉 중심 거리, 접착면 방향, 기울기, 긴 변의 정렬을 모두 검사한다. 기본 거리 0.03m·기울기 35도·방향 45도이며 현재 성공은 정상 놓기에 연결돼 있다.
- 개선 요구: 테이핑 단계에서 사용자가 잡은 테이프가 지정 목표 근처에 오면 자동으로 올바른 위치·방향에 스냅한다. 앞뒤 면·기울기·긴 변 정렬은 성공 조건에서 제외한다. 근접 허용 거리는 조정 가능한 값으로 두고 실기 접근성으로 맞춘다.
- 현재 단계·올바른 테이프·대상·추적/포커스·실습 중 여부는 유지한다. 보류 중 이동이 재개 직후 자동 성공으로 인정되지 않도록 기존 붕대 끝과 같은 재무장 정책을 새 테이프 경로에도 반영한다. 초기화·완료 요약·문구·Editor 검사도 실제 규칙과 일치시킨다.

## 7. 교육 중단 시 전역 시간 정지 영향

- 사용자 보고: 교육 중단을 누르면 Simulator 작동이 멈춘다. 실제 VR 영향 여부 확인 요청.
- 직접 원인: `TrainingFieldCoordinator.OnStop:397`이 `Time.timeScale=0`을 설정하고 `Resume:452`에서 복구한다.
- 설치 소스 확인:
  - `XRInteractionSimulator.cs:1212`~1214, 1274~1276의 위치 이동은 Time.deltaTime을 곱하므로 정지한다. Simulator 전체 입력 장치가 비활성화되는 것과는 구분한다.
  - `ContinuousMoveProvider.cs:252`, 277의 실제 VR 스틱 이동도 Time.deltaTime에 의존하므로 영향이 있다. 시간 기반 회전/물리·장비 스무딩 경로도 확인 대상이다.
  - Input System의 `TrackedPoseDriver.PerformUpdate:573`~575는 입력된 위치·회전을 반영하며 Time.deltaTime을 이동량에 곱하지 않는다. 실제 HMD·컨트롤러 추적 입력 자체가 전역 시간과 함께 멈추는 구조는 아니다.
  - XRI `UIInputModule.Update`는 계속 처리하고 클릭 시간 계산은 Time.unscaledTime을 사용한다. 따라서 확인 버튼을 조준·클릭할 수 있는 코드 구조지만 실제 HMD 조작 성공을 이번에 검증하지 않았다.
- 결론: Simulator만의 현상이며 실제 VR에는 영향 없다고 보고하면 안 된다. 실제 VR에서도 스틱 이동과 시간 기반 동작은 정지한다. HMD 추적과 UI 입력 경로는 구분해 설명한다.
- 개선 방향: 전역 시간 정지 대신 현재 교육의 입력·진행·판정·시간·물리만 보류한다. 단순히 timeScale=0 한 줄만 제거하면 AED 충전 등 별도 Update와 자유 물리가 진행될 수 있으므로, 장비별 보류 범위를 실제로 확인한다. Simulator의 조작·실제 VR 시점·확인창 입력은 계속 사용할 수 있어야 하고, 계속하기/중단 확정의 기존 상태 보존·재무장은 유지한다.

## 작업 순서와 확인 원칙

권장 순서: 전역 시간 보류/패널 가독성 → 앉은 자세와 판정 정렬 → 보호의 품목·상처 안내 → 지혈대 설명 단순화·테이프 근접 부착. 자세가 바뀌는 대상의 새 표식은 최종 앵커에 연결한다.

사용자 보고는 각각 해당 현상의 실행 증거로 보존한다. 이번 에이전트는 실제 HMD·Simulator에서 재현하지 않았다. 사용자가 명시 요청하기 전에는 구현 프롬프트를 자동 작성하지 않으며, 코드·씬을 직접 수정하지 않는다. 작업 트리의 글꼴·BuildSettings·진행상황 변경은 보존했다.

## 8. 후속 사용자 검증 완료와 PB 감기 완료 후 드레싱 유지 개선

사용자 최신 보고: ‘직접압박에서 붕대감은 뒤로는 드레싱을 잡고있을 필요 없게해줘. 그외에는 검증 완료 문제없음.’ 기존 개선·AED 누운 자세 복구 등 나머지 항목은 사용자 검증 완료 보고로 기록하며 다시 미완료로 배정하지 않는다. 개별 기기·각 예외 경로마다 검증됐다고 확대하지는 않는다.

새 변경 범위는 PB 감기 완료 이후다.

- 완료 시점은 롤붕대 감기 진행률 100%, PressureBandageStage.EndPlacement 진입이다. 테이프 부착 완료(Fixed)까지 기다리지 않는다.
- 그 시점부터 드레싱은 현재 유효한 상처 위치에 안정적으로 유지되어야 한다. 잡고 있던 손을 놓아도 위치가 바뀌거나 감기가 취소되거나 드레싱 유지 안내로 돌아가면 안 된다.
- 사용자는 자유로운 손으로 붕대 끝 배치 → 테이프 고정 → 처치 후 확인을 진행할 수 있어야 한다. 드레싱을 다시 잡을 필요가 없어야 하며, 이미 붕대 아래에 고정된 드레싱을 실수로 잡아 움직이지 않도록 한다.
- 감기 완료 전 직접 압박, 감기 전 확인, 유효 배치 조건은 유지한다. 테이프 단계/근접 판정/재무장·보류 정책도 유지한다.
- 계속하기에는 고정 상태를 유지하고, 중단 확정·다시하기·새 회차에는 드레싱의 원래 위치/잡기 상태를 복구해야 한다.
- UI의 행동 안내·보조 상태 표시도 해당 단계에서 드레싱을 계속 잡으라고 요구하지 않도록 맞춘다. 끝·테이프 조작의 안내가 우선이다.

정적 확인: PressureBandageApplication.CurrentBlock은 이미 드레싱의 잡기 자체가 아니라 IsPlacementValid를 사용한다. 다만 AllowSelect는 Fixed 전까지 드레싱 재잡기를 허용하고 WatchPlacement/FollowDressing은 EndPlacement/Taping에서도 이탈·이동 취소를 수행한다. FixTape에서만 드레싱 선택을 정리하고 재잡기를 막는다. 따라서 단순히 ‘잡기 조건 삭제’로 설명하지 말고 감기 완료 시점의 안정적 고정과 안내·초기화 경계를 함께 다루는 변경이다.

이번 요청에서는 정적 확인과 요구 기록만 수행했다. 코드 직접 작성 금지·명시 요청 시 구현 프롬프트 전달 정책을 유지하며 코드·씬·에셋은 변경하지 않았다.
