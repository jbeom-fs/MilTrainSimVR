## 2. 씬 구성(`PC_Equipment`, 월드 원점)

- XR Origin(Starter Assets) 1개, XR Interaction Manager 1개, Simulator(비활성), EventSystem + XRUIInputModule 1개, Directional Light.
- `PC_Floor`: 10 m 평면, 콜라이더 있음.
- `PC_Workbench`: 사용자 왼쪽, 0.85 × 0.85 × 1.3 m, 상판 0.85 m, 콜라이더 있음.
- `PC_Platform`: 마네킹 받침, 높이 0.3 m, 콜라이더 있음.
- `PC_MannequinRoot`: 받침 위 (0, 0.3, 1.25), Y 180°로 사용자를 향한다.
  - `Mannequin` FBX 인스턴스와 `ProtectiveClothing_Worn` FBX 인스턴스가 **둘 다 로컬 원점·무회전·스케일 1**에 있다.
  - 이동·회전·균일 확대는 이 루트로만 한다.
- `PC_Pickups`: 작업대 상판. 그 아래에 `PC_<Name>_Pickup` 6개가 있다.
  - 배치: 가까운 줄에 장갑 L/R, 가운데 줄에 상의/하의, 먼 줄에 덮개 L/R. 왼쪽(-X)에 L 품목.
- `PC_Board`: 사용자 오른쪽. 안내 한 줄과 [초기화] 버튼. 월드 캔버스 + TrackedDeviceGraphicRaycaster.
- `PC_TargetMarker`: 목표 고리 1개. 처음에는 숨김.

레이아웃·콜라이더 크기·반경은 생성할 때만 정한다. 메뉴를 다시 실행해도 사용자 조정은 유지된다.

마네킹 바인드 자세:
- 씬 인스턴스의 본을 SkinnedMeshRenderer의 `bindposes`로 계산한 바인드 자세에 맞춘다(`renderer.localToWorld × bindpose⁻¹`, 부모부터). 인스턴스 오버라이드로만 저장한다.

- 메뉴 2가 문서와 대조한다(§7).

Worn:
- 각 `<Name>_Worn`은 FBX의 위치 그대로 두고 표시만 전환한다. Attach로 옮기거나 본 아래에 붙이지 않는다.
- 저장 상태는 6개 모두 숨김이다.

Pickup:
- Pickup FBX를 한 번 인스턴스한 뒤 언팩한다.
- `<Name>_Pickup` 메시(Grip·Attach 자식 포함)를 FBX 루트 기준 Transform 그대로 `PC_<Name>_Pickup` 아래로 옮긴다.
- 남은 루트는 삭제한다.

## 4. 재질

- `PC_Shared`(URP Lit, 불투명, 앞면):
  - `_BaseMap` = PC_BaseColor_2K(sRGB)
  - `_BumpMap` = PC_Normal_1K(Normal Map)
  - `_MetallicGlossMap` = 파생 `PC_MetallicSmoothness_1K`(RGB 0, A = 1 − roughness, sRGB 끔). `_SmoothnessTextureChannel` = Metallic Alpha.
  - 키워드 `_NORMALMAP`·`_METALLICSPECGLOSSMAP`
- PC_Roughness_1K는 sRGB를 끄고, 파생 맵은 PNG 파일을 직접 읽어 생성한다. 원본 PNG는 쓰지 않는다.
- 12개 렌더러에 `PC_Shared`를 명시적으로 연결한다. Worn은 인스턴스 오버라이드다.

## 5. 잡기와 자동 착용

잡기:
- 각 Pickup에 다음을 둔다.
  - XRGrabInteractable: Instantaneous, attach = Grip, dynamic attach 끔, Single Select, throw 끔
  - 동적 Rigidbody: 중력, 보간, ContinuousSpeculative
  - BoxCollider 1개
- 어느 손으로든 잡을 수 있다(NearFar 양손).
- Equipment가 6개 grab의 select filter다. 다음 경우에는 잡지 못한다.
  - 한 손이 이미 다른 보호장비를 잡고 있음
  - 초기화 중이거나 초기화 실패
  - 이미 착용함
- 진행 중인 선택은 항상 통과시키므로 손에서 떨어뜨리지 않는다.
- 마네킹에는 콜라이더가 없다. 받침·작업대·바닥에는 콜라이더가 있다.
- 플레이 공간 아래로 1 m 이상 떨어진 Pickup은 작업대 원위치로 되돌린다.

판정:
- 시점: `ProtectiveClothingEquipment.LateUpdate`(실행 순서 50). XRI 3.4.1의 선택 변경과 Instantaneous 이동(XRInteractionManager Update, −105), Late 단계(−105)가 끝난 뒤다.
- 조건(모두 충족):
  - 미착용
  - 지금 선택 중(`isSelected`)
  - 선택 손의 TrackedPoseDriver 추적을 지금 읽은 결과가 유효
  - `Application.isFocused`
  - 초기화 중이 아님
  - `|Attach_<Name>_Pickup − Attach_<Name>_Worn|` ≤ `wearRadius`(월드 m, 기본 0.15, Inspector 조정, 유한·양수 검증)
- 각도·면·기울기·손 방향·놓기·유지시간은 보지 않는다.
- 잡지 않은 소품은 착용되지 않는다. 좌우는 서로 다른 목표이므로 반대쪽 목표에서는 착용되지 않는다.

착용 처리(`Wear`, 한 번):
1. 재진입 가드.
2. 착용 기록을 먼저 남긴다. 그래야 선택 해제 중에도 필터가 즉시 다시 잡기를 거부한다.
3. `CancelInteractableSelection`으로 선택을 해제한다.
4. 속도를 정지하고 kinematic으로 둔다.
5. Pickup을 숨긴다(비활성이라 다시 잡거나 손으로 돌아오지 않음).
6. 해당 Worn을 표시한다.
7. `Version`을 올린다.

선택 해제 콜백에는 착용·놓기·초기화 로직이 없다. 선택 진입 콜백은 안내용 잡은 순서만 기록한다.

조회 API(다음 챕터용, 읽기 전용): `IsWorn(part)`, `WornCount`, `AllWorn`, `Version`, `GuidedPiece`, `HandTracking(piece)`, `IsFaulted`/`FaultReason`, `InputLocked`.

## 6. 안내·표식·초기화

안내 문구는 위에서부터 처음 해당하는 하나만 표시한다.
1. 초기화 실패: "초기화하지 못했습니다. 담당자에게 알려 주세요."
2. 포커스 이탈: "교육 화면으로 돌아오세요."
3. 6개 모두 착용: "모든 보호장비를 착용했습니다."
4. 아무것도 잡지 않음: "착용할 장비를 잡으세요."
5. 안내 대상 손의 추적 소실: "컨트롤러를 시야 안으로 가져오세요."
6. 그 외: "{장비}를 {부위} 표시로 가져가세요." 부위는 상의 몸통, 하의 허리, 장갑 왼손/오른손, 덮개 왼발/오른발.

양손: 두 손에 장비가 있으면 **가장 최근에 잡은 미착용 장비**(`GuidedPiece`) 하나만 안내한다. 문구와 고리는 늘 같은 장비를 가리킨다.

고리:
- 안내 대상 장비의 Worn Attach에 반경 = `wearRadius`인 얇은 반투명 고리 1개를 표시한다. 카메라를 향한다.
- 위 6번 문구일 때만 보인다. 잡은 것이 없거나 추적·포커스가 유효하지 않으면 숨긴다. 6개 목표를 동시에 표시하지 않는다.

초기화(`ResetEquipment`, 보드 버튼):
1. 잠근다.
2. 보호장비 선택을 취소한다.
3. 착용 6개를 해제하고 Worn을 숨긴다.
4. Pickup을 처음 위치·회전·표시·kinematic·중력·속도로 되돌린다.
5. 잡은 순서, 손 드라이버 조회 캐시, 안내 대상을 지운다.
6. `Version`을 올린다.
7. 결과를 검증한 뒤에만 잠금을 푼다.

- 실패하면 `IsFaulted`와 원인이 남고 입력은 잠긴 채다. 버튼은 다시 시도할 수 있다.
- 같은 프레임의 두 번째 요청(양손·연타)은 무시한다. 초기화 중에는 착용을 판정하지 않는다.

### 10.1 초기 설정 검증 실패 시 실제 잡기 차단

- `ProtectiveClothingEquipment.Awake`에서 검증이 실패하면 `BlockGrabsForInvalidSetup`이 다음 대상의 `XRGrabInteractable.enabled`를 끈다.
  - 구성품 배열의 유효 항목(null 항목은 건너뛴다)
  - 그 항목의 `Grab`, 없으면 같은 오브젝트의 grab
  - `PC_Equipment` 아래의 모든 grab

  비활성화된 interactable은 XRI 등록에서 빠지므로 어느 손으로도 선택되지 않는다. 필터 미등록을 잠금으로 보지 않는다.
- 끌 grab을 찾지 못한 구성품과 빈 배열 항목은 오류 로그에 이름·개수로 남긴다(`UnblockableParts`, `BlockedGrabCount`).
- 정상 구성일 때 선택 필터와 선택 구독은 Awake에서 등록하고 OnDestroy에서 해제한다.
  - `canProcess`는 객체가 살아 있으면 항상 참이다.
