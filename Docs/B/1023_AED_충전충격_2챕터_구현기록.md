## 1. 흐름

리듬 분석 완료 → (충격 필요 교육 시나리오 고정) → 충전 진입 전 전원·두 패드·앵커 점유·양손 비접촉 확인 → 충전 → 충전 완료 → 양손 비접촉일 때만 버튼 깜박임·조작 가능 → 새로 시작한 유효 입력 1회 → 입력 순간 재검사 → 방전 확정 → 충격 시행 표시 → 후속 단계 대기.

- 충격 시행 후 `ShockDeliveredAwaitingNext`에서 멈춘다. `ModuleCompleted`·전체 완료·CPR 재개·환자 회복·경련·물리 효과는 없다. 에너지나 의료 효과도 계산·표시하지 않는다.

### 충격 허용 조건 (입력 순간 모두 재확인)

1. 진행 상태가 `AwaitingShockButton`
2. 장비 상태 `Charged`(충전 완료·미방전)
3. 장비 입력 활성(충전 완료 후 비접촉 상태에서 켜짐)
4. 해당 포인터의 누름이 입력 활성 중에 시작됨
5. `AllPadsAttached()` — 전원·서로 다른 두 패드 부착·대응 앵커 점유
6. 입력 순간 `contactMonitor.Evaluate()` 결과가 `Clear`

`PatientContact` 캐시는 표시·로그용이다. 허용 판단에 쓰지 않는다.

## 4. 중복 입력·중단 처리

- 충격 버튼 객체에 `EventTrigger`를 두고 코드에서만 PointerDown·PointerClick을 구독한다. 누름이 입력 활성 중에 시작된 포인터 ID만 기억(armed)한다. 그 ID의 Click만 `ShockPressed`로 보고한다. `Button.onClick`은 쓰지 않는다(Inspector 목록 비움).
- 충전 전·중에 시작한 누름은 기억하지 않는다 → 충전 완료 후 놓아도 충격 없음.
- 입력 활성 상태가 바뀔 때마다(접촉·확인 불가로 잠금, 다시 해제) 기억한 누름을 모두 버린다 → 손을 떼는 것만으로는 시행하지 않는다. 새 누름이 필요하다.
- `TryDischarge()`: 입력 잠금 → 기억한 누름 삭제 → `Discharged` 확정 → 깜박임 종료·라벨 갱신 → `true` 반환(1회 보고). 같은 프레임 두 번째 Click이나 다른 컨트롤러 Click은 잠긴 입력·삭제된 누름 때문에 무시된다.
- 충전 시간은 장비 `Update`에서만 누적한다. 코루틴·Invoke 같은 지연 보고가 없다. 충전 완료는 진행 측이 장비 상태를 매 프레임 읽어 처리한다.
- 컨트롤러 비활성화(7~13): 장비 `Interrupt()`(입력 잠금, 충전 중·충전 완료면 `Interrupted`), `ShockPressed` 구독 해제. 재활성화하면 `InterruptedReloadRequired`가 되고 씬 재로드를 안내한다.
- 장비(또는 AED 객체) 비활성화: 장비 `OnDisable`에서 `Interrupt()`와 트리거 구독 해제. 재활성화해도 `Interrupted`가 유지된다. 진행 측은 다음 프레임에 재로드 필요 상태로 전환한다.
- 깜박임은 `Graphic.enabled` 토글이다. 비활성화 경로에서 객체 활성 상태를 바꾸지 않아 계층 비활성화 중 오류를 피한다.
- 씬 재로드 시 장비 `Awake`가 `Idle`·버튼 비활성·깜박임 OFF·라벨 빈칸으로 초기화한다.

## 9. 정적 검토 결과

- Prefab·씬 YAML: 로컬 fileID 중복 0, 끊긴 참조 0, 부모/자식·GameObject/컴포넌트 목록 불일치 0(스크립트 검사).
- 새 블록은 기존 전원 버튼 블록을 복제해 ID·부모·이름·위치만 바꿨다. EventTrigger 스크립트 GUID는 uGUI 패키지 `.meta`에서 읽었다.
- 코드: 상태별 안내는 해당 상태 분기에서만 설정한다. 분석 단계 안내가 충전·충격 안내를 덮지 않는다. 지연 콜백 없음. 이벤트 구독은 `OnEnable`·`OnDisable`에서 짝을 이룬다.
- 컴파일: Unity를 실행하지 않아 **미확인**. 열린 Editor의 로그에도 이번 변경의 컴파일 기록이 아직 없다.

## 14. 충격 후 마무리 안내 (2026-10-23, 커밋하지 않음)

마감 보충: 이 절의 변경은 `8db52ed`로 커밋되었고 사용자가 검증 완료를 보고했다. 아래 설명의 자동 크기 상한 44pt는 구현 당시 보고와 실제 씬 사이의 차이다. 현재 씬 파일은 최소 24pt·최대 72pt이며, 사용자 화면 검증 완료 이후 추가 수정하지 않았다. 실제 표시 글자 크기가 항상 44pt라고 단정하지 않는다.

사용자 보고: 충격 시행까지의 흐름을 사용자가 직접 확인했다. 아래 변경은 그 이후 정적 검토만 한 상태다.

- `ShockDeliveredInstruction`을 체험 완료와 실제 후속 처치 설명으로 교체했다. 문구 안의 CPR 재개·약 2분 후 재분석·반복·119 인계는 실제 사용법 설명이다. 프로그램은 CPR·타이머·재분석·재충격을 실행하지 않는다.
- 표시 경로는 그대로다: 유효 충격 → `OnShockPressed()`가 안내를 설정 → `ShockDeliveredAwaitingNext`(13). 13에서는 안내를 다시 쓰지 않아 대기 중 유지된다. 덮어쓰는 경우는 기존 정책의 오류(`Faulted`)와 중간 비활성화(재로드 안내)뿐이다. 새 상태·타이머·버튼·패널·`ModuleCompleted` 전환은 없다. 충격 잠금·장비 라벨("충격 시행")은 그대로다.
- 줄바꿈 `\n`을 문구 상수에 넣었다. 글리프 검사가 줄바꿈 제어 문자를 누락 글리프로 보고하지 않도록 `ReportMissingGlyphs()`에서 제어 문자만 제외했다. 상수는 `All`에 그대로 포함된다.
- 씬 최소 조정(`B_AED_Tutorial.unity`): 기존 안내창 900×110(44pt 고정, 넘침 허용)으로는 여러 줄 문구가 패널 밖으로 넘친다. 그래서 `GuidePanel` 높이를 110→320으로 늘렸다(위쪽 고정, 아래로 확장, Canvas 600 안). `InstructionText`는 자동 크기 24~44pt를 켜고 여백(좌우 24, 상하 12)을 넣었다. 짧은 기존 안내는 44pt 그대로이고, 긴 문구만 줄어든다. 월드 기준 패널 아래 끝은 약 1.54m→1.33m로 내려온다.
- 미검증(사용자 확인 필요): 컴파일, 마무리 문구 표시·줄바꿈·한글·글자 크기·잘림, 대기 중 유지, 추가 충격·반복 미실행, 커진 패널이 환자·AED 시야를 가리지 않는지, 기존 단계 안내의 표시 변화.
