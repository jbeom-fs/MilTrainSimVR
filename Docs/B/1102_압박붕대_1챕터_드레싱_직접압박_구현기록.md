## 3. 모델·좌표·기준점 연결

- 래퍼 `PressureBandage_Training`(루트, `PressureBandageKit`·`PressureDressing`) 아래에 `PressureBandage_Basic.fbx` 인스턴스 하나를 위치 0·회전 0·축척 1로 둔다. **부품 회전(FBX 축 변환)은 가져온 값 그대로**이며 0으로 지우거나 재회전·미러하지 않는다. 부품을 재부모하지 않는다.
- 트레이 배치는 래퍼에서 관리한다. 루트 = 트레이 윗면 중심. 모델을 처음 추가할 때만 드레싱·롤·테이프의 **위치만** 슬롯으로 옮긴다(부품 메시 경계 중심을 x/z 슬롯에, 바닥을 y=0에). 슬롯: 드레싱 (−0.11,0,0), 롤 (0.03,0,0), 테이프 (0.14,0,0) m. 이후 사용자가 옮긴 위치는 보존한다. 원본의 제작 확인용 배치는 사용하지 않는다.
- 숨김: `PB_BandageStrip`, `PB_WrapStrip`, `PB_BandageEnd`는 비활성(매 실행 유지). 참조는 `PressureBandageKit`에 남는다.
- 드레싱 조작 구성(시각 메시와 분리):
  - XRI가 실제로 움직일 Transform은 `PB_DressingPad`라서, 그 객체에 `Rigidbody`(Kinematic·중력 없음)와 `XRGrabInteractable`을 추가 컴포넌트로 둔다(FBX 파일·메시·재질 미변경).
  - 잡기 Collider는 별도 자식 `Grab_Dressing`의 BoxCollider. 크기 = 패드 메시 경계 + 윗면 쪽 0.012 m. 생성 시에만 크기 지정.
  - 잡기 기준 `Anchor_DressingGrab`(XRI attach), 접촉 기준 `Anchor_DressingContact`, 유지·압박 기준 `Anchor_DressingPress`를 구분해 사용.
- 방향은 Unity 축 이름을 가정하지 않고 기준점으로 계산한다. 접촉 방향 = Press → Contact 월드 방향. 면 축 = 드레싱 부품 로컬 X/Y(메뉴 2가 로컬 Z가 가장 얇은 축임을 검사).
- Unity의 FBX 좌·우손 좌표 변환으로 기준점 X가 반전되어 읽힐 수 있다. 메뉴 2는 작성값과 X 반전값을 모두 허용하고 어느 쪽인지 보고한다. 실제 Unity 값은 미확인.

## 6. 드레싱 잡기·놓기·배치 보조 정책

- **근거리 잡기만**: `PressureDressing`이 드레싱 `XRGrabInteractable`의 select filter다. 새 잡기는 추적 중인 컨트롤러가 잡기 Collider에서 0.10 m 이내일 때만 허용(원거리 광선 잡기 차단). 이미 잡고 있는 선택은 항상 통과하므로 이 필터가 잡은 드레싱을 놓게 만들지 않는다.
- **소유권**: `selectMode = Single`. 이동 소유자는 한 손뿐이다. 다른 손이 잡으면 XRI가 이전 손 선택을 끝내고 새 손이 이어받는다(같은 프레임 인계). 동적 잡기 기준이라 잡는 순간 손 쪽으로 튀지 않는다. 던지기 없음.
- **놓기·정지**: 놓으면 그 자리에 정지한다(Kinematic, 중력 없음). 어느 손으로든 다시 잡을 수 있다. 놓인 드레싱을 잠그거나 고정하지 않는다.
- **안착 보조(1회)**: 추적 중인 손의 정상 놓기이고, 놓인 자세가 이미 유효 배치이며, 안착 후 자세도 유효할 때만 적용한다. 접촉 중심을 축으로 회전해 접촉면을 피부 평면에 맞추고 법선 방향으로만 이동한다. 상처 위 좌우 위치는 유지한다. 선택 취소·미추적 손의 놓기·무효 자세는 안착하지 않는다.
- 잡고 있는 동안에는 위치를 바꾸지 않는다. 가까이 스쳤다는 이유로 고정·완료하지 않는다. 놓기만으로 유지 상태를 만들지 않는다(유지는 손이 잡고 있을 때만, §8).
- 후속 "유지하는 손을 놓으면 감기 중단"과의 관계: 놓는 순간 한 손 유지(A)가 거짓이 된다. 놓인 드레싱의 배치 유효성은 계속 계산되지만 유지와는 별개다. 따라서 충돌하지 않는다.

## 7. 배치 판정(`PressureBandageWound.Evaluate`)

판정 입력: 접촉 중심 위치, 접촉 방향, 드레싱 면 축 2개, 면 반크기(메뉴 1이 패드 메시에서 매 실행 기록). 순서와 이유(안내판 문구):

1. 상처 중심에서 0.15 m(후보 범위) 밖 → `Away` "상처 위치가 아님"(다른 부위·트레이·공중)
2. 접촉 방향과 피부 안쪽 법선의 각도 ≥ 90° → `WrongFace` "반대 면이 상처를 향함"
3. 각도 > 35° → `Tilted` "드레싱이 기울어짐"
4. 접촉 중심이 피부 평면 위 0.02 m 초과 → `Lifted` "상처 표면에서 떨어짐"
5. 피부 평면 아래 0.02 m 초과 → `TooDeep` "팔 안쪽으로 너무 들어감"(위치 판정일 뿐 압박력 아님)
6. 상처 원(반지름 0.015)이 드레싱 면 안에 다 들어오지 않음 → `NotCovering` "상처를 다 덮지 못함"
7. 모두 통과 → `Valid`

- Collider 접촉을 쓰지 않는다. 지정 상처(씬의 `PB_WoundTarget`) 하나만 판정한다.
- 상태는 색과 함께 문구(유효/무효·이유)로 표시한다.

## 8. 한 손 유지와 두 손 접촉의 정확한 조건

매 `LateUpdate`(XRI Late 단계 이후, 실행 순서 100)에 현재 값으로만 다시 계산한다.

| 상태 | 조건(모두 충족) |
|---|---|
| A. 한 손 유지 `IsHoldValid` | 배치 유효 · 드레싱이 선택됨 · 선택한 손의 `TrackedPoseDriver` 추적 유효 · 그 컨트롤러가 Press 기준점에서 0.12 m 이내 · 앱 포커스 |
| B. 두 손 접촉 `IsTwoHandContactValid` | 배치 유효 · 왼손·오른손 모두 추적 유효 · 두 컨트롤러 모두 압박 영역 안 · 앱 포커스 |

- 압박 영역: Press 기준점 위 원기둥. 면 방향 반지름 0.08 m, 윗면 위 0.16 m, 아래 0.03 m. 두 컨트롤러를 실제로 겹치거나 몸·책상을 누르지 않아도 되도록 위쪽 높이를 둔 VR 축약이다.
- B는 드레싱 선택을 요구하지 않는다(두 번째 손 중복 잡기 불필요). 한 손이 잡고 있어도, 놓인 드레싱 위에 두 손을 대도 된다.
- A와 B는 서로의 조건으로 성립하지 않는다. A가 참이어도 B 진행은 없고, B가 참이어도 A(유지)는 선택한 손이 있어야 한다.
- 추적 판정: 드라이버 없음(`연결 없음`)과 드라이버는 있으나 위치·회전 추적이 아님(`추적 안 됨`)을 구분한다. Transform이 남아 있어도 추적으로 보지 않는다.

## 9. 연속 접촉·역할 인계·추적 소실·포커스

- 연속 접촉 시간 `contactCheckSeconds`(기본 5 s, 개발용 조작 확인 시간)은 `PressureDressing`만 센다. 유한한 양수가 아니면 `TryValidate` 실패로 컴포넌트가 꺼지고 메뉴 2가 FAIL을 기록한다. 안내판은 초가 아닌 비율(%)만 표시한다.
- B가 참인 동안만 증가한다. 끊기는 프레임에 0으로 초기화하고 끊긴 이유를 기록한다(손 이탈/추적 소실/포커스 상실/배치 무효/비활성화). 끊긴 구간을 합산하지 않는다.
- 다시 참이 된 첫 프레임은 시간을 더하지 않고, 한 프레임 최대 0.1 s만 더한다. 추적·포커스 복귀나 긴 프레임으로 한 번에 완료되지 않는다. 위치 이동을 적분하지 않으므로 과거 위치와 새 위치를 이은 순간 이동 계산이 없다.
- 처음 설정 시간에 도달하면 이번 회차 이력 `HasCompletedContactPractice`를 남기고 `ContactPracticeCompleted`를 한 번 발생시킨다. 이력은 현재 상태를 대신하지 않는다. 안내판은 이력을 별도 줄에 표시하고, 완료 문구는 **현재 연속 접촉이 설정 시간에 도달했을 때만**(B 참이고 `ContactProgress` ≥ 1) 지시문에 표시한다(§17.1에서 정정).
- 역할 인계: 좌우 손을 역할에 고정하지 않는다. 같은 프레임 인계는 선택이 이어져 A가 유지된다. 놓은 뒤 다시 잡으면 그 사이 A는 거짓이다. B는 두 손 모두 영역 안이면 어느 손이 잡든 상관없다.
- 비활성화: 파생 상태와 시간을 지우고 XR 선택은 XRI에 맡긴다(강제 해제 없음). 다시 켜지면 현재 선택을 그대로 읽고 시간은 0부터 시작한다.
- 포커스: `Application.isFocused`. 헤드셋 시스템 메뉴 등에서 이 값이 실제로 어떻게 바뀌는지는 미확인이다. 추적 상태도 함께 보므로 추적이 끊기면 포커스와 별개로 멈춘다.

## 10. 상태 안내판

- 줄 구성: 제목 · 가상 조작 안내 · 다음 행동 1개 · 현재 상태(배치·이유 / 드레싱 유지 / 두 손 접촉 / 왼손·오른손 추적과 드레싱 위 여부) · 연속 접촉 비율 · 이번 회차 기록.

## 13. 정적 검토 결과와 미확인 항목

정적 확인(파일 읽기):
- XRI 3.4.1: `XRInteractionManager.CanSelect`가 선택 중에도 interactable select filter를 다시 검사하고 실패하면 선택을 끝낸다 → 필터는 선택 중인 interactor를 항상 통과시킨다. filter 목록은 필드 초기화 시 만들어지고 Awake는 추가만 한다 → 등록 순서와 무관.

- URP Lit: `_Cull` 0 = 양면, `SetMaterialKeywords`가 양면 GI를 맞춤. 뒷면 법선 반전 없음.
- 새 C# 7개 파일의 따옴표·괄호 짝 스크립트 검사 통과. 람다 매개변수·지역 변수 이름 충돌을 수동 점검했다.

## 15. 2챕터에 넘길 상태와 연결 지점

- 읽기 전용 상태(`PressureDressing`): `CurrentCheck`, `IsPlacementValid`, `IsHeld`, `HoldingHand`, `HoldingHandTracking`, `IsHoldValid`(감기 진행 조건 후보), `IsTwoHandContactValid`, `ContactSeconds`, `ContactProgress`, `HasCompletedContactPractice`(이력), `LastContactBreak`·`LastContactBreakTime`, `LeftTracking`·`RightTracking`, `LeftInPressZone`·`RightInPressZone`, `InputFocused`, 이벤트 `ContactPracticeCompleted`.
- 부품·기준점: `PressureBandageKit.PartTransforms`·`AnchorTransforms`(롤 축 `Anchor_RollAxis` 로컬 +Y, 출구 `Anchor_RollExit`, 띠 시작·끝, 끝 고정 `Anchor_EndFix`, 테이프 접촉). 띠 3종은 숨김 상태로 대기.
- 상처 프레임: `PressureBandageWound`(up = 피부 바깥, forward = 손목 쪽). 감기 경로 기준 축은 이 프레임과 마네킹 아래팔 뼈로 만들 수 있다.
- 후속 Runner 연결 시 연속 접촉 시간을 다시 세지 않는다. 과정 연결부가 `HasCompletedContactPractice`(이력)와 현재 상태를 TrainingTarget 상태로 옮기고, Runner HoldState로 같은 유지량을 중복 판정하지 않는다.
- 다시하기·시작 잠금은 아직 없다. 드레싱 초기 자세·이력 초기화 경로는 3챕터 범위에서 설계한다(이번에 미리 만들지 않음).

## 16. 경계 밖 사항과 한계(변경하지 않고 보고)

- 인체 원본 자세 기준이라 상처가 어깨 높이에 가깝다. 자세 변경(뼈 회전)은 하지 않았다.

## 17. 정적 검토 보완 (2026-11-02)

사용자 정적 검토로 지적된 세 가지를 최소 범위로 보완했다. 잡기·안착·배치 판정·접촉 영역·개발용 시간·상처 기본 높이·모델 원본은 바꾸지 않았다. 감기·고정·Runner 등 후속 기능은 추가하지 않았다. 컴파일·메뉴·Play·Simulator 모두 미확인, 미커밋.

### 17.1 현재 접촉 진행과 과거 완료 이력 구분

- 문제: `Instruction()`이 두 손 접촉 유효 시 `HasCompletedContactPractice`(이력)로 완료 문구를 골랐다. 한 번 완료 → 손 이탈(진행 0) → 재접촉하면 진행 0%인데 곧바로 완료 문구가 나왔다.
- 수정(`PressureBandageStatusBoard.cs`): 두 손 접촉이 유효할 때 `ContactProgress >= 1`(기존 공개 상태, `PressureDressing`이 센 현재 연속 접촉 시간 ÷ 설정 시간)이면 완료 문구, 아니면 접촉 유지 문구. 새 상태·타이머는 추가하지 않았다.
- `ContactProgress`는 현재 연속 접촉 시간이 설정 시간 이상일 때만 1이 된다. 이는 `PressureDressing`이 이력을 남기는 조건과 같다. 끊기면 시간이 0이 되므로 재접촉 직후에는 1이 아니다.
- 그대로 유지: `HasCompletedContactPractice`(회차 이력, 기록 줄 표시), `ContactPracticeCompleted` 회차당 1회, 끊김 시 시간 0 초기화, 시간 소유자 `PressureDressing`.
- 표시 캐시: 캐시 키에 지시문 문자열과 진행 %가 포함되어 있어 유지↔완료 문구 전환과 0% 재시작이 바로 다시 그려진다.

### 17.2 상처 판정점과 시각 표식 연결

- 문제: `PB_WoundMarker`가 `PB_WoundTarget`의 형제였고 생성 때만 위치를 맞춰, 판정점을 옮기면 표식이 남았다.
- 최종 구조: `PB_Mannequin/PB_WoundTarget`(판정 전용, `PressureBandageWound`, 자체 렌더러·Collider 없음) 아래에 `PB_WoundMarker`(표시 전용 원판, 렌더러만)를 **자식**으로 둔다. 판정점 이동·회전을 Unity 부모·자식 관계로 따라가며, 매 프레임 복사 코드는 없다. 표식 로컬 위치·회전이 판정점 기준 상대 오프셋이다. 기본값은 피부 법선 방향 0.0015 m, 회전 없음이다(원기둥 위 = 피부 법선).
- 메뉴 1 처리:
  - 새로 만든 경우: 판정점 자식으로 기본 오프셋·지름 0.03 m·`MAT_PB_WoundMarker`로 생성한다.
  - 판정점 아래에 이미 있는 경우: 그대로 유지한다. 사용자 상대 위치·회전·크기·재질을 바꾸지 않는다.
  - 이전 배치(마네킹 묶음 아래 형제)만 있는 경우: 판정점 아래로 옮기고 **기본 오프셋으로 되돌린다**. 이전 배치와 판정점의 차이(mm·도)는 로그로만 남기며 사용자 오프셋으로 고정하지 않는다. 크기·재질은 유지한다.
  - 판정점 아래와 이전 배치에 모두 있는 경우: 판정점 아래 것을 유지하고 이전 것을 삭제해 하나만 남긴다(로그 표시).
  - 같은 위치에 둘 이상: 구성을 중단하고 하나만 남기라고 알린다.
  - 표식·판정점의 Collider는 매 실행 제거한다. Interactable·입력 기능은 없다.
- 판정점 축척을 바꾸면 자식 표식도 함께 커진다. 판정은 축척을 쓰지 않는다. 메뉴 2가 판정점 축척을 INFO로 보고한다.

메뉴 2 변경(`ValidateWoundMarker`, 읽기 전용, 누락 시 FAIL만 기록하고 계속):
- `PB_Training` 아래 `PB_WoundMarker`가 정확히 1개인지.
- 이전 배치(마네킹 묶음 바로 아래)에 표식이 남지 않았는지.
- 판정점이 `PB_Mannequin` 아래 `PB_WoundTarget`이고 자체 렌더러·Collider가 없는지.
- 표식의 부모가 씬의 지정 판정점인지. 다르면 FAIL과 실제 부모 이름을 보고한다.
- 표식이 렌더러만 있고 판정 컴포넌트·Collider·Interactable이 없는지.
- 표식 상대 위치·기울기·크기와 판정점 축척은 INFO로만 보고한다. 사용자 조정을 허용하며 화면 정렬 통과로 표현하지 않는다.

### 17.3 피부 측정 실패 처리 기록 정정

- 이전 §5 서술은 "측정 실패 시 항상 대체 높이로 진행"으로 읽힐 수 있었다. 실제 코드는 `false` 반환일 때만 대체 높이와 WARNING으로 진행한다. `BakeMesh` 등에서 예외가 나면 메뉴 1이 중단된다(§5 정정). Read/Write 비활성만으로 예외가 난다고 확정하지 않는다.
- 예외를 숨기거나 대체 높이로 통과시키는 새 처리는 추가하지 않았다.
