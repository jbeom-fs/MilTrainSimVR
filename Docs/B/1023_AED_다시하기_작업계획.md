# AED 완료 후 다시하기 작업 계획

작성: B · 2026-10-23 (Asia/Seoul)

마감 상태(2026-10-23): 이 계획에 따른 다시하기 구현이 `1c1d57b`로 커밋되었고, 사용자가 검증 완료를 보고했다. 개별 체크리스트·실기 장치·로그 결과는 별도 제공되지 않았다. 에이전트는 실행 검증을 하지 않았다. [구현 기록](1023_AED_다시하기_구현기록.md), [최신 작업마감](1023_작업마감_진행상황.md) 참조. 아래는 구현 전 설계 기준으로 보존한다. 음성 안내·음원 제작은 계속 보류한다.

## 1. 목표와 첫 범위

사용자가 AED 1사이클과 마무리 설명을 확인한 뒤 **다시하기 → 초기 상태 복원 → 시작 화면 → 새 체험**을 VR 안에서 수행하도록 한다.

- 다시하기 버튼은 현재 최종 상태 `ShockDeliveredAwaitingNext=13`에서 표시하는 기본안이다.
- 완료 전 중간 재시작, 종료·메뉴 복귀, 앱 종료, 결과 저장, 음성은 이번 첫 범위에 포함하지 않는다.
- 기존 전원·패드·분석·충격 조건과 마무리 문구를 보존한다.
- 새로운 의료·교육 절차나 반복 CPR/AED 사이클을 만들지 않는다. 사용자가 별도의 새 체험을 시작하는 기능이다.

## 2. 현재 상태와 구현 방향

현재 초기화는 Play 재시작·씬 재로드에 의존한다. 기존 장비에는 전원 OFF·패드/앵커 부착 해제·충전/방전 초기화 기능이 없다. 충격 버튼은 방전 후 잠기며 패드는 앵커에 부모가 변경돼 있다.

첫 방향은 현재 씬 안의 장비별 초기화다. XR Rig·사용자 위치·시야는 유지하고 AED와 교육 진행만 처음으로 되돌린다. 공용 Rig·프로젝트 설정 변경이나 씬 로딩 체계 추가를 선행하지 않는다.

파일 조사에서 `ProjectSettings/EditorBuildSettings.asset`의 씬 목록에는 SampleScene만 보였다. 씬 재로드 방식으로 전환하려면 배포용 씬 등록·팀 통합 방식을 함께 확인해야 한다. 이 계획에서는 그 파일을 수정하지 않고 B 내부 복원으로 범위를 잡는다.

## 3. 복원할 상태

| 구성 | 복원 대상 |
| --- | --- |
| 진행 컨트롤러 | 시작 대기 상태, 현재 패드·분석 시간·접촉 표시 캐시·재접촉 기록·중단 잠금 플래그 |
| AED 전원 | OFF·표시등·라벨·전원 입력 초기 상태 |
| 충격 장비 | Idle·충전 시간 0·입력 잠금·기억한 포인터 삭제·깜박임 OFF·상태 라벨 초기화 |
| 패드 2개 | 부착 상태 해제, 대응 앵커 참조 해제, 손 정보 초기화, 최초 부모·로컬 위치·회전·스케일 |
| 패드 물리·상호작용 | 최초 Rigidbody 설정·잔여 속도 제거, Collider·시각 모델, XR 선택·레이어·throwOnDetach 설정 복원 |
| 부착 앵커 | 점유 해제·인체 부착 패드 OFF·위치/부착 가능 표시 정리 |
| UI | 마무리/다시하기 숨김, 시작 화면·버튼 복원, 이전 강조와 오류 표시 정리 |

초기값은 현재 씬의 실제 초기 상태를 기준으로 보관한다. 사용자 앵커 override·인체 축 반전·MirrorFix 재질·모델 원본을 되돌리거나 다시 구성하지 않는다.

특히 `AedPad.TryAttach()`가 변경하는 부모, Rigidbody의 kinematic/interpolation, XR interactionLayers와 throwOnDetach까지 복원 대상에 포함한다. 위치와 IsAttached만 바꿔 두 번째 체험에서 패드를 못 잡는 상태를 만들지 않아야 한다.

## 4. 처리 순서와 책임

1. 최종 상태에서만 다시하기 입력 접수. 즉시 연속 입력·이전 진행 평가를 잠근다.
2. 충격 입력과 기존 선택·표시를 정리한다. 같은 완료 입력이 새 체험을 자동 시작시키지 않게 한다.
3. 패드·앵커의 부착/점유를 함께 해제하고, 패드가 자기 초기 부모·배치·물리·XR 설정을 복원한다.
4. 전원과 충격 장비가 자기 내부 상태·표시·입력 기록을 초기화한다.
5. 진행 기록·분석 시간·중단 플래그와 UI를 초기화한다.
6. 시작 화면을 표시하고 별도 시작 입력을 기다린다. 원래 시작 시점의 입력 잠금 규칙을 적용한다.

장비별 작은 초기화 동작을 두고 진행 측이 순서를 조정한다. 다른 컴포넌트의 private 상태를 강제로 덮어쓰거나 `Awake`/`OnEnable`을 초기화 함수처럼 호출하지 않는다. 씬 전체 스냅샷·새 범용 Reset 프레임워크는 만들지 않는다.

기존 이벤트 연결은 유지하거나 필요한 범위에서만 정리한다. 다시하기 횟수에 따라 콜백·버튼 이벤트가 중복 등록되지 않아야 한다. 복원 때문에 생긴 장비 이벤트를 새 교육 행동으로 판정하지 않는다.

## 5. UI와 변경 범위

- 완료 안내를 읽은 뒤 선택할 수 있는 다시하기 버튼 1개를 둔다. 기존 마무리 문구를 가리지 않도록 배치한다.
- 기존 XR UI 선택 경로를 재사용한다. 새 EventSystem·입력 모듈은 추가하지 않는다.
- 버튼 문구는 `TrainingSubtitles`에 단일 관리하고 `All`에도 반영한다.
- 후보 경로: `Assets/B/Scripts/AedTutorial/**`, 현재 B AED 씬, 필요한 B 장비 래퍼 연결. 문서는 `Docs/B/**`.
- B 외부 자산·공용 설정·패키지·프로젝트 설정은 변경하지 않는다. 모델·기존 교육 흐름도 최소 변경으로 보존한다.
- 음성 안내 계획은 보류 기록으로 유지한다. 음원 생성·재생 연결은 진행하지 않는다.

## 6. 사용자 직접 확인 기준

| 시작 상태·조작 | 기대 결과 |
| --- | --- |
| 교육 시작부터 충격 전까지 진행 | 다시하기 버튼이 완료 선택지로 미리 나타나지 않음 |
| 충격 시행·마무리 안내 확인 | 다시하기 버튼 표시, 기존 설명 읽기 가능 |
| 다시하기 선택 | 전원 OFF, 패드 원위치·잡는 모델 복귀, 인체 부착 표시 OFF, 충격 라벨·깜박임 초기화, 시작 화면 |
| 시작 전 대기 | 이전 완료·충전·분석 이벤트로 자동 진행하지 않음 |
| 다시 시작해 패드 조작 | 두 패드 모두 다시 잡고 놓아 부착 가능. 이전 앵커 점유 잔류 없음 |
| 두 번째 분석·충전·충격 | 첫 회차와 동일한 판정으로 충격 1회·마무리 안내 도달 |
| 다시하기 연타 | 초기화 1회, 이벤트 중복·자동 시작 없음 |
| 연속 체험 | 매 회차 정상 수행, 장비 중복 생성·위치 튐·이전 상태 잔류 없음 |
| VR 사용자 위치 | 재시작 때문에 사용자 시야·Rig가 불필요하게 이동하지 않음 |

검증은 사용자가 원본 프로젝트에서 직접 수행한다. 에이전트는 정적 검토와 확인 절차만 제공하고 Unity·Simulator·테스트·빌드를 실행하지 않는다. 복제 프로젝트를 만들거나 기존 복제본을 재사용하지 않는다.
