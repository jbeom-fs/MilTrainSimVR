## 1. 범위

- 교육 흐름: 시작 대기 → 상황·도구 확인 → 드레싱 배치 → 직접 압박 접촉 동작 연습 → 감기 전 상태 확인 → 붕대 감기 → 붕대 끝·테이프 고정 → 처치 후 상태 확인 → 최종 확인 → 완료 화면 → 완료 후 다시하기 → 시작 대기.
- 제외: 교육 중 다시하기·재시작 확인창, 교육 선택·복귀 버튼과 허브, 실제 압박력·장력·지혈·혈류 판정, 점수, 영구 저장, 새 모델링.
- 같은 씬 `B_PressureBandage_Tutorial`이 이제 교육 과정 씬이다.
  - 1·2챕터 장비 조작은 교육 시작 뒤 해당 단계에서 할 수 있다.
  - 장비 단독 확인용 안내 방식(안내판이 제목·지시문을 직접 쓰는 방식)은 이 씬에서 꺼진다(§7).

## 3. 교육 단계와 조건

모든 조건은 **State**다. 공통 Runner는 단계에 들어온 프레임과 같은 프레임의 Action을 받지 않는다(`frame <= enteredFrame`). 그래서 단계 전환 때 입력이 누락되지 않도록 연결부가 매 프레임 상태를 갱신한다. HoldState는 쓰지 않는다. 접촉 시간은 계속 `PressureDressing`만 센다.

| 단계 ID | 이름 | 조건(모두 State, 참이어야 함) |
|---|---|---|
| `pb-situation` | 상황·도구 확인 | 상황 확인 |
| `pb-dressing` | 드레싱 배치 | 상황 확인 · 드레싱 배치(현재) |
| `pb-contact` | 직접 압박 접촉 동작 연습 | 상황 확인 · 접촉 연습 수행 |
| `pb-pre-check` | 감기 전 상태 확인 | 위 + 감기 전 확인(현재 적용 시도) |
| `pb-wrap` | 붕대 감기 | 위 + 감기 완료(현재 단계가 끝 배치 이후) |
| `pb-fix` | 붕대 끝·테이프 고정 | 위 + 적용 고정(현재 `Fixed`) |
| `pb-post-check` | 처치 후 상태 확인 | 위 + 처치 후 확인(현재 시도·현재 `Fixed`) |
| `pb-final-check` | 최종 확인 | 7개 요구 모두(드레싱 배치 현재 포함) + 최종 확인 입력 |

- 대상 `pb-equipment`(현재 장비 상태): `dressing-placed`(`IsPlacementValid`), `wrap-complete`, `application-fixed`.
- 대상 `pb-trainee`(이번 회차 기록·입력): `situation-confirmed`, `contact-practiced`, `pre-check-confirmed`, `post-check-confirmed`, `final-confirmed`.
- 드레싱 배치는 현재 상태다. 과거에 한 번 배치했다는 기록으로 통과시키지 않는다. 접촉 이후 단계에는 넣지 않았다. 손을 놓으면 안착은 유지되지만 연습 중 위치가 바뀔 수 있어서다. 최종 확인에서 현재 배치를 다시 요구한다.
- 감기·고정은 장비의 현재 단계(`EndPlacement → Taping → Fixed`)를 그대로 읽는다. UI가 장비를 완료로 만들지 않는다.
- 단계는 누적 조건이다. 앞 조건이 깨지면 이후 단계는 멈추고, 완료가 막힌다.

## 4. 현재 상태·수행 이력·확인 기록의 구분과 무효화

| 구분 | 항목 | 성립 | 철회 |
|---|---|---|---|
| 현재 상태 | 드레싱 배치, 감기 완료, 적용 고정 | 장비가 매 프레임 계산한 값 | 장비 값이 거짓이 되면 즉시 |
| 회차 기록 | 상황 확인 | 확인 버튼(실행 중, 포커스) | 다시하기·새 회차에서만 |
| 회차 기록 | 접촉 연습 수행 | 상황 확인 뒤 `PressureDressing.HasCompletedContactPractice`가 참이 됨 | 다시하기·새 회차에서만 |
| 적용 시도 기록 | 감기 전 확인(3항목) | 항목마다 버튼 1회. 입력 순간 드레싱 배치·한 손 유지·적용 `Ready`·포커스 충족 | 적용 취소(드레싱 이탈·밀림·회전, `CancelCount` 증가)나 장비 초기화 시 |
| 적용 시도 기록 | 처치 후 확인(4항목) | 항목마다 버튼 1회. 입력 순간 적용 `Fixed`·포커스 충족 | 적용 시도가 바뀌거나 `Fixed`가 아니게 되면 |
| 회차·단계 입력 | 최종 확인 | 최종 단계에서 7개 요구 모두 충족일 때만 받음 | 단계 진입 토큰 변경, 완료 전 요구 하나라도 깨짐, Runner가 판정했는데 완료되지 않음 |

- 접촉 연습 기록의 출처: 시작할 때 연습 기록이 거짓이어야 한다. 또 상황 확인 전에는 드레싱을 잡을 수 없다. 그래서 참이 되면 이번 회차의 연습이다. 시작 전·이전 회차의 이력은 새 수행으로 인정되지 않는다.
- 적용 시도는 `(CancelCount, ResetCount)`로 식별한다. 감기 진행·외곽 갱신으로 오르는 표시용 `Version`은 새 시도로 보지 않는다. 그래서 정상 감기 중에는 감기 전 확인이 유지된다.
- 거부된 확인 입력과 최종 확인 입력은 저장하지 않는다. 조건을 복구한 뒤 새로 눌러야 한다.
- 최종 확인과 처치 후 확인은 현재 한 손 유지나 두 손 접촉을 요구하지 않는다. 고정 뒤에는 손을 놓는 것이 정상이다.
- 감기 전 확인만 한 손 유지를 요구한다. 설계 §4의 "한 손으로 드레싱을 유지하면서 다른 손으로 확인"에 따른 것이다.

## 5. 장비 선택 허용 범위와 시작 잠금

`PressureBandageTrainingStart`가 드레싱·롤·끝·테이프 잡기에 select filter 하나를 더한다.
- 장비 자체 필터(한 손 한 부품, 근거리, 단계 제한, 고정 뒤 잠금)는 그대로다. XRI가 모두 적용한다.
- `enabled`·`interactionLayers`는 쓰지 않는다.
- XRI 3.4.1은 선택 중에도 필터를 다시 검사한다. 그래서 이 필터는 진행 중 선택을 항상 통과시켜 부품을 떨어뜨리지 않는다.
- 선택 종료는 장비 초기화(`ResetEquipment`)만 담당한다.

| 시점 | 드레싱 | 롤·끝·테이프 |
|---|---|---|
| 시작 전·초기화 중·고장(Faulted) | 차단 | 차단 |
| 실행 중, 상황 확인 전 | 차단 | 차단 |
| 상황 확인 뒤 | 허용 | 접촉 연습 수행과 현재 시도의 감기 전 확인 뒤에만 허용 |
| Runner 완료 뒤(완료 화면) | 차단 | 차단(요약과 실제 상태가 어긋나지 않게) |

- 롤을 접촉 연습과 감기 전 확인 뒤로 미뤘다. 감기·고정이 먼저 끝나 나중에 접촉 연습을 할 수 없게 되는 상황을 막기 위해서다. 드레싱이 잠기는 것은 고정 뒤뿐이고, 그때는 연습이 이미 끝났다.
- 허용 판정은 현재 Runner 단계 번호가 아니라 기록·현재 상태로 정한다. 그래서 Runner가 뒤 단계에 있어도 적용 취소 뒤 드레싱 재배치 → 감기 전 재확인 → 재감기라는 복구 경로가 열린다.

시작 순서(`PressureBandageStartScreen.OnStartClicked` → `PressureBandageTrainingStart.TryStart`):
1. 버튼을 즉시 끈다. 연속 클릭·양손 입력은 같은 프레임에 버튼이 꺼져 있고 게이트가 이미 대기 상태가 아니라서 무시된다.
2. 안내판 구성요소(상태판·과정 안내·최종 확인·완료)가 실행 중이고 참조가 유효한지 확인한다.
3. 게이트 참조를 확인한다. 장비 초기 상태도 확인한다.
   - 적용 `Ready`, 아무 부품도 선택되지 않음, 드레싱이 상처 위가 아님, 연습 기록 없음, 마지막 장비 초기화 성공
   - 각 잡기에 Interaction Manager 등록
4. 연결부가 새 회차로 Runner를 시작한다. 실제로 `Running`이고 첫 단계인지 확인한다. 아니면 Runner를 정지하고 기록을 지운다.
5. 수락:
   - 그 순간 잡기 입력(그립)이 눌린 손은 놓을 때까지 선택할 수 없다. 시작 입력이 잡기로 이어지지 않는다.
   - 실습 화면이 표시된다.

실패하면 게이트가 Faulted가 되고 장비 잠금이 유지된다. 원인은 Console에 남고, 화면에는 "지금은 교육을 시작할 수 없습니다…"가 표시된다. 화면만 전환하지 않는다.

## 6. 복구와 교육 순서

- 장비의 기존 일시 중단(유지 손 이탈·롤 놓기·추적 소실·포커스)과 적용 취소 정책은 그대로다.
- 과정 안내는 Runner 단계와 별도로 **현재 성립하지 않는 첫 요구**를 기준으로 다음 행동과 표식을 정한다. 예를 들어 Runner가 고정 단계에 있을 때 적용이 취소되면 다음 순서로 안내한다.
  - 취소 안내(4초)
  - 드레싱 재배치
  - 한 손 유지 + "붕대 적용이 취소되어 감기 전 확인을 다시 해야 합니다" + 감기 전 확인
  - 롤 잡기·감기·끝·테이프
- 확인 영역은 지금 필요한 확인(상황 / 감기 전 / 처치 후)을 Runner 단계와 무관하게 보여 준다. 최종 단계에서 요구가 깨진 경우에도 실습 화면으로 돌아가 복구할 수 있다(최종 화면은 7개 요구가 모두 충족일 때만 표시).
- 일반 복구를 전체 교육 초기화로 대신하지 않는다. 교육 중 다시하기는 없다.

| 네 화면(시작·실습·최종 확인·완료) 전환 | `PressureBandageStartScreen`만 |
| 안내 문구(Notice, 안내판 최상위) | `PressureBandageStatusBoard` |
| 실습: 단계 줄(Title)·다음 행동(Instruction) | `PressureBandageTrainingGuide` |
| 실습: 상태 줄(Status·Bandage·Progress·History) | `PressureBandageStatusBoard`(`writesGuidance` 끔, 두 텍스트 참조 없음) |
| 실습: 확인 영역(제목·항목·버튼)과 그 표시 여부 | `PressureBandageTrainingGuide` |
| 최종 확인 화면 텍스트·버튼 | `PressureBandageFinalCheck` |
| 완료 화면 텍스트·다시하기 버튼 | `PressureBandageCompletionPanel` |
| 시작 화면 텍스트·시작 버튼 | `PressureBandageStartScreen` |
| 감기 고리·화살표·경로 점선 표시 여부 | `PressureBandageTrainingGuide`가 `PressureBandageGuide.Suppressed`로 결정. 위치·모양은 기존 장비 표식 그대로 |
| 드레싱·롤·끝·테이프 위치 고리 | `PressureBandageTrainingGuide`가 `PressureBandageCourseMarker` 하나의 대상 지정 |

표식 정책:
- 시작 대기·완료·초기화 중·최종 확인(모두 충족)에는 모든 표식을 숨긴다.
- 감기 표식은 접촉 연습·감기 전 확인 뒤, 고정 전까지만 보인다.
- 위치 고리는 다음 행동 문구가 가리키는 부품과 같다.
  - 드레싱 잡기·재배치 → 드레싱 잡기점
  - 두 손 접촉·한 손 유지 → 드레싱 윗면
  - 롤·붕대 끝·테이프 잡기 → 각 잡기점
  - 테이프를 내려놓아야 할 때·감기 이동 중에는 고리 없음(감기 고리·화살표가 안내)
- 표식에는 Collider·Interactable·UI Graphic이 없다. 안내판에서는 버튼 이미지 4개만 레이를 받는다.

문구:
- 모든 원문은 `TrainingSubtitles` 상수다. UI·Inspector·교육 데이터에 저장하지 않는다(텍스트는 빈 값으로 저장).
- 장비 다음 행동은 1·2챕터 규칙을 재사용한다(`ContactInstruction`, `BandageInstruction`).
- 키보드 안내·클래스명·수치 디버그는 넣지 않았다.

## 8. 의료적 표현 범위

- 시작 화면에 학습 목표와 가상 조작 범위(실제 압박력·장력·지혈 성공·혈류는 판단하지 않음, 제품·교안 미정 기본형)를 표시한다.
- 감기 전 확인 영역 첫 줄에 "직접 압박 동작 연습을 마쳤습니다. 이후 감기 구간은 출혈이 조절된 상태를 가정한 훈련 구간입니다. 실제 지혈 여부는 판단하지 않습니다."를 표시한다.
- 감기 전후 확인은 가상 부상자 상태 카드·응답을 항목별로 확인하는 방식이다.
  - 감기 전: 손 쪽 색·온도·감각.
  - 처치 후: 재출혈과 손 쪽 색·온도·감각을 구분한다.
  - 수치·진단 기준은 만들지 않았다.
  - "컨트롤러로 맥박·온도·혈류를 재지 않습니다"를 함께 표시한다.
  - 정상 적용 한 가지 시나리오이며, 이상 상태 분기는 없다.
- 접촉 연습 진행률은 1챕터대로 비율로만 표시하고 초를 표시하지 않는다. 개발용 시간을 권장 압박 시간으로 제시하지 않는다.
- 완료 화면은 수행 여부 요약과 "실제 압박력·출혈량·혈류·합격 여부는 판단하지 않습니다 … 출혈이 계속되거나 다시 시작되면 재평가가 필요합니다"만 표시한다. 점수는 없다.

## 9. 완료 요약과 완료 후 다시하기

- **요약:**
  - 연결부가 Runner의 `Completed`를 본 프레임에 한 번 만든다(`PressureBandageTrainingSummary`, 메모리만).
  - 항목: 7개 요구의 그 순간 값 + 최종 확인 입력.
  - Runner는 최종 단계 조건이 모두 참일 때만 완료되므로 모두 수행으로 나올 것으로 보이나, 값은 실제로 다시 읽는다. 수집하지 않은 항목을 임의로 성공 처리하지 않는다.
  - 완료 패널은 같은 요약을 한 번만 쓴다. 완료 뒤에는 게이트가 장비 선택을 막아 요약과 실제 상태가 어긋나지 않는다. 장비 적용 상태는 그대로 유지된다.
- **다시하기** (`PressureBandageTrainingReset.TryRetry`, 완료 버튼만 호출):
  1. 중복 차단(`IsResetting`, 버튼 즉시 끔). 게이트 `Resetting`(새 선택·시작 차단). 과정 안내 표식·확인 영역 숨김.
  2. Runner 정지. 연결부가 회차·기록·확인·최종 입력·요약을 잊는다. 이전 회차의 지연 입력은 회차 번호가 달라 받지 않는다.
  3. `PressureBandageApplication.ResetEquipment()`를 호출하고 반환값을 확인한다. 선택 취소, 트레이 배치, 띠·끝·테이프, 드레싱 접촉·이력이 대상이다.
  4. 장비 초기 준비 상태를 다시 확인한다(시작 때와 같은 검사).
  5. 최종 확인·완료 화면 캐시와 버튼을 초기화한다.
  6. 게이트 `WaitingForStart`, 시작 화면 표시. 자동 시작은 없다.
- 유지: XR Origin(사용자 위치·시야), 안내판 자세·레이아웃, 상처·경로 위치와 사용자 조정값. 씬 재로드는 없다.
- 실패하면 게이트 Faulted(장비 잠금 유지)가 되고, 시작 화면에 "장비를 처음 상태로 되돌리지 못해…"가 표시되며 시작 버튼이 꺼진다. Console에 원인이 남는다.

## 10. 기존 장비 코드 변경과 필요성

| 변경 | 필요성 |
|---|---|
| `PressureBandageApplication.CancelCount` | 확인 기록을 적용 시도에 묶기 위함. 표시용 `Version`과 구분해야 정상 감기 중 확인을 지우지 않는다 |
| `RollGrab`·`EndGrab`·`TapeGrab` 읽기 전용 속성 | 시작 게이트가 같은 장비의 잡기인지 검증 |
| `PressureBandageStatusBoard.writesGuidance` | 같은 Title·Instruction을 안내판과 과정 안내가 동시에 쓰지 않도록 |
| `ContactInstruction`·`BandageInstruction` 공개 | 장비 다음 행동 규칙 재사용(문구 중복 방지) |
| `PressureBandageGuide.Suppressed` | 단계 밖·최종 확인·완료에서 감기 표식 숨김 |

장비의 판정·시간·잡기·안착·감기·고정·초기화 순서는 바꾸지 않았다. 장비 어셈블리는 Training·Tutorial을 참조하지 않는다.

## 12. 정적 검토 결과

- 공통 Training 코드를 읽고 확인한 사항:
  - `StartTraining`은 반환값이 없다. 그래서 시작 뒤 `Status == Running`과 첫 단계로 성공을 판정한다.
  - `ReportAction`은 진입 프레임 Action을 거부한다.
  - Runner는 `LateUpdate`(순서 0)에서 단계를 하나씩 판정한다.
  - 공통 Runner는 확장하지 않았다.
- 실행 순서:
  - Runner 0 → 드레싱 100 → 적용 102 → 연결부 104(상태 기록) → 과정 안내 105(장비 표식 억제) → 장비 표식 106 → 상태판·최종·완료 110 → 화면 전환 112 → 과정 고리 120.
  - 버튼 입력은 Update 단계에서 연결부가 바로 상태를 갱신하므로, 같은 프레임 Runner가 판정한다.
- XRI 3.4.1: 선택 중 필터 재검사(진행 중 선택 통과), `XRBaseInputInteractor.selectInput`·`isSelectActive`로 잡기 입력 해제 대기, XRUIInputModule·TrackedDeviceGraphicRaycaster 구성(지혈대와 같은 프로젝트 방식).
- 장비 런타임·Tutorial·메뉴 C# 21개 파일 따옴표·괄호 짝 검사 통과. 이름 충돌·확정 할당·Unity 방식 null 검사(메뉴의 `??` 사용 2건을 `TryGetComponent`로 수정)를 직접 점검했다.
- **컴파일은 실행하지 않아 미확인이다.**

## 13. 남은 제품·교안 미확정 사항과 한계

- 실제 제품·여밈 방식·적용 교안·상처 부위·감기 방향·회전 수·겹침·고정법은 미확정이다. 경로·허용오차·테이프 마감·접촉 시간은 개발값이다.
- 직접 압박(두 손)에서 한 손 유지로의 전환, 감기 전후 확인의 항목·상태 카드 문구는 교육 담당 검토가 필요하다. 정상 적용 한 가지 시나리오다.
- 감기 전 확인은 한 손 유지 중에만 받는다. 실제 교안에서 다른 순서라면 조정 대상이다.
- 2챕터의 개발 확인용 컨텍스트 메뉴 "Reset Equipment (development check)"는 교육과 별개로 남아 있다. 교육 중 호출하면 회차 기록과 장비가 어긋날 수 있다. 교육생 경로가 아니며 개발 확인에만 사용한다.
- 같은 씬이 교육 씬이 되어 1·2챕터 장비만 단독 확인하는 방식(안내판이 장비 안내 직접 표시)은 이 씬에서 쓰지 않는다. 장비 조작 확인은 교육 시작 뒤 해당 단계에서 수행한다.
- 버튼 레이 선택은 NearFar 상호작용기의 UI 레이에 의존한다. 헤드셋·Simulator 실제 동작은 미확인이다.

## 14. 사용자 확인 절차 (모두 미확인)
