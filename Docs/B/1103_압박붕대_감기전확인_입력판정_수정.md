# 압박붕대 감기 전 확인 입력 판정 수정 (2026-11-03)

상태: **코드 수정 완료. 컴파일·메뉴 1/2·Play·Simulator·헤드셋 모두 미확인. 미커밋.** 근거 문제는 [11/02 마감](1102_작업마감_진행상황.md) §2.2. §2.3(③~⑦ Dressing 조건 누락)은 이번 범위가 아니다.

## 1. 문제

- `PressureBandageTrainingLink.CanConfirmCheck`·`TryConfirmCheck`가 `PressureDressing`의 `InputFocused`·`IsPlacementValid`·`IsHoldValid`를 읽었다. 이 값들은 `PressureDressing.LateUpdate`(100)에서 갱신되므로, 버튼 입력 시점에는 직전 프레임 값이다.
- XRI 패키지 순서: `UIInputModule`(-200, Update에서 `DoProcess`) → `XRInteractionManager`(-105, Update에서 선택 해제·선택, Dynamic 처리) → … → LateUpdate. 따라서 버튼 콜백은 같은 프레임의 놓기 처리보다 먼저 실행된다. 입력 순간에 다시 조회해도 그 프레임의 놓기·이탈은 아직 반영되지 않았을 수 있다.

## 2. 변경

| 파일 | 변경 |
|---|---|
| `PressureDressing.cs` | 한 손 유지 판정식 `HoldValid(...)`·`Holder`를 분리했다. `Refresh`와 새 읽기 전용 `IsHoldValidNow`·`IsInputFocusedNow`가 같은 식을 쓴다. 조회는 현재 포커스, 현재 배치(`EvaluateCurrent`), 실제 선택 손, 그 손의 `PressureBandageTracking.Of`, 유지 지점 거리를 읽는다. 컴포넌트가 비활성이면 false다. `contactSeconds`·연습 이력·이벤트·자세·선택은 바꾸지 않는다(`DriverOf` 캐시만 채울 수 있음). |
| `Tutorial/PressureBandageTrainingLink.cs` | 확인 입력 2단계 판정. `PressureInputResult.Pending` 추가. `CanConfirmCheck`은 버튼 표시 보조이며 현재 데이터로 판정한다. 대기 중이면 false. |
| `Tutorial/PressureBandageTrainingGuide.cs` | `OnCheckClicked` 주석만 수정. 동작 변경 없음. |

장비는 Tutorial을 참조하지 않는다. TrainingSubtitles·씬·레이아웃 개정(5)은 바꾸지 않았다.

## 3. 프레임 처리 순서

1. Update(UI 모듈 -200): 확인 버튼 → Guide `OnCheckClicked`(버튼 즉시 비활성) → `TryConfirmCheck`.
   - 이전 프레임에서 남은 대기 입력은 폐기한다(정상 경로에서는 남지 않음).
   - 활성 확인이 아니거나 같은 프레임 대기 입력이 있으면 `Ignored`.
   - 현재 데이터로 조건 불충족이면 `Refused`, 남기지 않음.
   - 충족이면 대기: 실행 토큰(회차·단계 진입), 적용 시도 키(`CancelCount`, `ResetCount`), 확인 종류, 다음 항목 번호, 프레임을 묶는다. `Pending` 반환. 기록하지 않는다.
2. XRI(-105): 같은 프레임 놓기·선택 변경·Dynamic 이동.
3. LateUpdate: Runner(0) → Dressing(100, 안착·프레임 상태·접촉 시간) → Application(102).
4. Link(104) LateUpdate: `Observe()` → `ResolveCheck()`. 아래 중 하나라도 해당하면 폐기한다.
   - 프레임 불일치
   - 실행 중 아님 또는 토큰 변경
   - 적용 시도 변경
   - 활성 확인 또는 다음 항목 변경
   - 현재 데이터 조건 불충족

   모두 통과하면 그때 한 항목을 기록하고 `Observe()`를 실행한다. Runner는 다음 프레임에 판단한다(모두 State).

5. Guide(105) LateUpdate: Link의 대기 입력 처리 이후, 확정된 현재 항목과 조건을 기준으로 안내·확인 카드·버튼 상태를 갱신한다. 기록이 수락되면 다음 항목을 표시하고, 거부·폐기되면 기존 항목 또는 필요한 복구 행동을 표시한다.

결과:
- 입력 시 무효였으면 즉시 거부되므로 같은 프레임 후반에 복구돼도 수락하지 않는다.
- 입력 시 유효했어도 프레임 최종 상태가 무효면 기록하지 않는다.
- 먼저 기록했다가 철회하는 경로는 없다.
- 거부·폐기된 입력은 이후 자동으로 적용되지 않는다.

상황 확인·처치 후 확인도 같은 경로를 쓴다. 항목 수·순서·한 입력당 한 항목은 같고, 기록 시점만 같은 프레임 LateUpdate로 늦춰진다. 최종 확인(`TryConfirmFinal`)은 바꾸지 않았다.

## 4. 폐기

- 같은 프레임 연타·양손 입력: Guide 버튼 비활성 + Link `checkPending` → 두 번째는 `Ignored`.
- 적용 취소: `AttemptKey`가 바뀌어 폐기된다. 기존의 감기 전·후 확인 철회(`Observe`)는 유지된다.
- 다시하기·새 회차: `ClearFacts`(`EndRunForReset`·`TryBeginRun`·회차 변경)에서 폐기된다.
- Link 비활성화: `OnDisable`에서 폐기된다.
- 폐기는 로그 `check input dropped ... a new input is required`로 남긴다. 입력 시 거부는 로그 `check input refused`로 남긴다.

## 5. 유지

- 감기 전 확인 조건(포커스, 유효 배치 + 한 손 유효 유지, 적용 `Ready`, `ActiveCheck == PreWrap`)은 같다. 판정식은 `Refresh`와 공유한다.
- `ActiveCheck`·`ItemCount`·`MarkNext`·적용 취소 철회·최종 확인 재검사와 완료 처리, 연속 접촉 시간 계산 위치(`Refresh`만)는 그대로다.
- Application은 계속 프레임 상태(`IsHoldValid`)를 읽는다. 장비를 강제로 놓게 하거나 선택·자세를 바꾸지 않는다.
