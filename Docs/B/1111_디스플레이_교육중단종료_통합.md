## 2. UI 통합 방식

기존 패널의 객체를 새로 만들지 않고 **같은 객체(fileID)·컴포넌트·색·폰트를 옮겨 재사용**했다. 버튼은 기존 이벤트(StopRequested·ContinueRequested·AbortRequested·EndRequested)로만 보고하고, 코디네이터의 기존 보류·계속·중단·종료 경로를 그대로 쓴다. 별도 중단 상태나 초기화 경로는 추가하지 않았다.

| 부분 | 위치 | 표시 조건 |
|---|---|---|
| 교육 중단 | 과정 보드 Canvas 마지막 자식, 하단 고정 행 왼쪽 (−240, 행 y), 200×60 | 과정 Running이고 확인창이 닫혀 있을 때 |
| 교육 종료 | 같은 Canvas, 하단 행 오른쪽 (240, 행 y), 200×60. 다시하기는 왼쪽 | 과정 Completed이고 확인창이 닫혀 있을 때 |
| 최근 결과 | 같은 Canvas, 하단 행 오른쪽 (240, 행 y), 200×60, 22pt 주황 | 과정 Waiting(시작 화면)이고 이번 방문 결과가 있을 때 |
| 중단 확인창 | 그 과정의 첫 차단 Canvas(디스플레이 4mm 앞, 720×440) 마지막 자식, 720×440 불투명 카드 | 확인창 열림. 이때 차단 Canvas도 함께 켜짐 |

- 행 y: TQ −126(아래 고지문 띠 유지), 나머지 −180. 세 부분은 스크롤 본문 밖에 있어 스크롤 위치와 무관하게 보인다.
- 확인창: 질문 “교육을 중단할까요?”(34pt), 설명(22pt, 확인 중 이 실습만 멈춤 + 중단하면 진행·장비가 처음 상태로 돌아감), 계속하기(−150, −60)·중단하기(150, −60) 240×64. 모두 720×440 안에 있어 스크롤이 없다. 중단하기 직후 나타나는 시작 버튼과 겹치지 않는다(TQ 시작 버튼 상단 −94, 확인 버튼 하단 −92).
- 과정명·안내 문장(상태 줄)은 디스플레이 제목·명판과 중복이라 옮기지 않았다. 외부 패널의 Canvas·배경·제목·상태 객체와 해당 참조(titleText·statusText)는 삭제했다. TrainingFieldStation·코디네이터·과정 링크·차단 연결은 그대로다.
- 외부 상태 줄 중 필요한 예외 안내는 **디스플레이 앞 차단 메시지**로 옮겼다: 다른 과정 진행 중(“{과정} 실습이 진행 중입니다. 그 위치에서 교육 종료 또는 교육 중단을 선택한 뒤 시작하세요.”), 과정 Faulted, 초기화 실패(Running이 아닐 때). 초기화 실패 후에도 Running이면 차단하지 않아 기존처럼 교육 중단을 다시 누를 수 있다.

## 3. 입력 차단과 표시 순서

- 확인창이 열리면 코디네이터가 기존처럼 `SetHeld(true)`·`HoldPhysics()`로 그 과정만 보류한다. 전역 `Time.timeScale`은 바꾸지 않는다. 이동·회전·시점·다른 UI는 계속 동작한다.
- 확인창은 첫 차단 Canvas 안에서 Shade·Message 뒤(나중) 형제라 그 위에 그려지고, 같은 Canvas 레이에서 버튼이 먼저 맞는다. 확인창 배경 Image는 raycastTarget을 켜 디스플레이 전체를 덮는다. 차단 Canvas는 보드보다 4mm 앞이라 기존 차단과 같은 원리로 보드보다 먼저 레이를 받는다. 따라서 뒤쪽 본문 스크롤·단계 버튼·K1 CanvasGroup 본문은 입력을 받지 않는다.
- AED 전원·충격 버튼 차단 Canvas 2개도 확인 중 계속 켜진다(기존 규칙).
- 확인창 개폐는 보드 Canvas와 본문을 끄거나 켜지 않는다. TrainingScrollBody의 맨 위 초기화 조건(페이지 표시·단계 문구 변경)에 해당하지 않으므로 계속하기 후 스크롤 위치가 유지된다.
- 중단 버튼·종료 버튼·결과는 차단 Canvas 밖(보드 안)이라 다른 과정 진행 중에는 차단에 덮인다.

## 6. 사용자 확인 목록

각 항목은 시작 상태 → 조작 → 기대 결과 → 실패 기준 순이다.

1. **컴파일·검사 메뉴**: Unity 재컴파일 → `B/교육장/3`, `B/교육장/4` 실행 → FAIL 없음, TrainingFieldStation 오류 로그 없음. 실패: 컴파일 오류, “stop confirm must be inside the first blocker” 등.
2. **중단 버튼 표시(6개 과정)**: 각 과정 교육 시작 → 진행 화면 하단 왼쪽에 ‘교육 중단’이 항상 보이고 본문 스크롤 끝까지 내려도 가려지지 않음. 시작 전·완료 화면에서는 안 보임. 실패: 본문·단계 버튼·TQ 고지문·TQ 최종 확인·PB 확인 카드·K1 단계 수·KD-1 수행 수/처음부터와 겹침, 시작 전 노출.
3. **확인창 표시와 선택**: 진행 중 교육 중단 → 같은 디스플레이 전체를 덮는 확인창(질문·설명·계속하기·중단하기)이 스크롤 없이 보이고 왼손·오른손 레이 모두로 선택 가능. 디스플레이 밖 창 없음. 실패: 뒤 본문 비침, 버튼이 안 눌림, K1 본문이 위에 보임.
4. **확인 중 차단**: 확인창이 열린 상태에서 뒤 본문 스크롤바 드래그·장비 잡기·AED 전원/충격 버튼 시도 → 반응 없음, 진행·판정·시간 정지. 머리 회전·이동은 가능. 실패: 단계 진행, 장비 판정, 시점 고정.
5. **계속하기**: 본문을 중간까지 스크롤한 상태에서 중단 → 계속하기 → 같은 단계·같은 스크롤 위치·장비 상태 유지, 중단 버튼 재표시. 실패: 스크롤이 맨 위로, 단계 초기화, 장비 튐.
6. **중단 확정**: 중단 → 중단하기 → 해당 과정 시작 화면, 하단 오른쪽 ‘최근 결과: 중단’. 다른 과정 시작 가능, 같은 과정 재시작 정상. 실패: 시작 화면 미복귀, 다른 과정 차단 유지, 장비 미복구.
7. **완료 화면**: 과정 완료 → 요약·다시하기(왼쪽)·교육 종료(오른쪽) 표시, 중단 버튼 없음. 교육 종료 → 시작 화면, ‘최근 결과: 완료’, 입구 목록도 완료. 다시하기 → 기존처럼 재시작. 실패: 허브/씬 이동, 결과 사라짐, KD-1 다시하기 위치 겹침.
8. **다른 과정 사용 중**: 한 과정 진행 중 다른 과정 디스플레이 → 차단 메시지(진행 중 과정명 + 종료/중단 안내), 시작 불가. 실패: 시작 가능, 메시지 잘림.
9. **잔여 요소**: 디스플레이 옆 기존 패널 위치에 화면·투명 입력 영역이 없음(레이 포인터가 빈 공간에서 UI에 걸리지 않음). 실패: 남은 패널·입력 영역.

## 7. 재개 기준

- 외부 FieldPanel은 삭제됐다. 과거 문서·백업의 “디스플레이 옆 현장 안내판” 구성으로 되돌리지 않는다.
- 다음 우선순위: 위 §6 사용자 확인 → 기존 목재 명판 가독성·장비 접근성·스크롤 확인(1110 마감 §4). 거울은 사용자 확인 완료이며 추가 작업 없음.
- 허브 복귀 포털·Walk_Rear 겹침은 계속 사용자 보류다. 스테이징·커밋·Push는 하지 않았다.

## 8. 후속 사용자 요구 — 고지문 제거·단계 확인 버튼 고정 (2026-11-11)

사용자는 검토 내용을 확인한 뒤 지혈대 하단의 “특정 제품의 재현이나 …” 문구 제거와 압박붕대 단계 확인 버튼의 하단 분리를 요청했다. 다른 과정의 동일한 확인 버튼에도 같은 배치 원칙을 적용한다. 이번 기록은 요구사항·정적 조사이며 구현 완료나 §6 전체 실행 통과를 의미하지 않는다.

- **지혈대:** `PrototypeNotice` 고지문과 하단 전용 띠를 교육 디스플레이에서 제거하고, 확보한 높이를 본문과 고정 조작 행에 재배분한다. 현재 `TourniquetStatusBoard`는 noticeText에 문구를 쓰고 필수 참조로 검사하므로, 객체만 삭제하지 않고 연결·검사도 함께 정리해야 한다. 다른 교육 안내를 일괄 삭제하는 요구는 아니다.
- **압박붕대:** 상황·도구, 감기 전, 처치 후 확인에서 재사용하는 `CheckButton`을 스크롤 본문 밖의 하단 오른쪽에 둔다. 왼쪽은 기존 교육 중단이다. 확인 설명·항목은 본문에 유지하고, 확인이 필요한 때만 버튼을 표시한다. 조건 미충족·중단 확인 중에는 입력을 막고, 기존 사실 기록·중복 입력 방지·자동 완료를 유지한다.
- **압박붕대 연결 보완:** `PressureBandageTrainingGuide.SetCheck`는 현재 CheckArea만 표시/숨김하고, TryValidate는 버튼이 CheckArea 내부인지 검사한다. 버튼 분리와 함께 표시 수명·검사 조건을 수정해야 한다. 본문 확인 카드의 스크롤 포커스 대상은 유지한다.
- **지혈대의 동일 유형:** 최종 확인의 `확인 완료`도 같은 하단 오른쪽 위치로 통일한다. 현재 버튼은 이미 스크롤 본문 밖에 있으므로 고지문 제거 후 행 위치·여백을 맞추는 대상이다. FinalCheckPanel 아래의 표시 제어와 기존 판정을 유지한다.
- **나머지 네 과정:** 현재 AED·K1·보호의·KD-1에는 같은 유형의 별도 단계 확인 버튼이 없다. 시작·다시하기·KD-1 처음부터와 AED 전원·충격은 역할이 다른 기존 조작이며, 이번 요구로 단계 확인 버튼을 추가하거나 기기 버튼을 옮기지 않는다.

권장 공통 구성은 **본문 = 설명·확인 항목 / 하단 왼쪽 = 교육 중단 / 하단 오른쪽 = 해당 단계 확인**이다. 완료 시에는 기존 다시하기·교육 종료 구성을 유지한다. 고정 버튼이 본문을 가리거나 화면 전환 직후 다른 버튼과 겹치지 않도록 함께 확인한다.

후속 사용자 확인: 고지문 제거 후 본문 공간, PB 확인 단계별 버튼 노출·조건 해제 시 숨김/차단, 스크롤과 무관한 버튼 접근, 중단→계속하기, 확인 후 다음 항목·단계 진행 및 마지막 자동 완료, TQ 최종 확인·완료 전환. 코드·씬은 이번 요구사항 기록에서 수정하지 않았다.
