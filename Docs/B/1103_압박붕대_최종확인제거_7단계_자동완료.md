# 압박붕대 교육: 최종 확인 단계 제거, 7단계 자동 완료 (2026-11-03)

상태: **코드·데이터 수정 완료. 컴파일·메뉴 1/2·Play·Simulator·헤드셋 모두 미확인. 미커밋.** 이전 작업(거리 SNAP 등)과 폰트·씬·Prefab의 사용자 변경은 미커밋 상태로 보존했다. ③~⑥ Dressing 조건 보완은 별도 후속이다.

## 1. 최종 7단계 흐름

① 상황·도구 확인 → ② 드레싱 배치 → ③ 직접 압박 → ④ 감기 전 확인 → ⑤ 붕대 감기 → ⑥ 끝·테이프 고정 → ⑦ 처치 후 확인 → (자동) 완료 화면

- 단계 줄 예: `3 / 7 · 직접 압박`. 박스 7개 중 현재 단계 하나만 강조하고, 복구 표시도 유지한다.
- 상황·감기 전·처치 후의 항목별 확인 버튼은 유지한다. 최종 확인 화면·안내·버튼은 없다.

## 2. 자동 완료 조건

`PressureBandageTrainingIds.Steps`에서 ⑦ `pb-post-check`의 조건을 `AllRequirements`로 바꿨다. 기존 ⑧이 검사하던 조건에서 `final-confirmed` 하나만 뺀 것과 같다.

| 조건 | 신호 |
|---|---|
| 상황 확인 | `situation-confirmed` |
| 현재 드레싱 배치 | `dressing-placed` |
| 이번 회차 직접 압박 연습 | `contact-practiced` |
| 현재 적용 시도의 감기 전 확인 | `pre-check-confirmed` |
| 감기 완료 | `wrap-complete` |
| 고정 완료 | `application-fixed` |
| 현재 적용 시도의 처치 후 확인 | `post-check-confirmed` |

- 처치 후 마지막 항목은 기존 2단계 판정(입력 순간 → Link LateUpdate 재검사)을 통과해야 기록된다. 대기 중인 입력은 State에 반영되지 않는다.
- 공통 Runner는 다음 프레임에 모든 State가 참이어야 Completed가 된다. 하나라도 거짓이면 진행이 계속되고, Guide가 첫 미충족 요구의 복구 안내를 보인다.
- ①~⑥ 조건은 바꾸지 않았다.

## 3. 삭제·정리한 전용 상태와 참조

| 위치 | 내용 |
|---|---|
| `TrainingIds` | `FinalCheckStep`, `FinalConfirmed`(TraineeSignals에서도), `StepName`의 최종 분기 |
| `TrainingLink` | `TryConfirmFinal`, `CancelConfirm`, `ConfirmPending`, `ConfirmCancelled`, `IsFinalCheckStep`, 확인 대기·철회 토큰과 프레임, `Missing()`, 요약의 `FinalConfirmed`, `PressureInputResult.Accepted`(최종 확인만 사용) |
| `PressureBandageFinalCheck.cs`(+meta) | 파일 삭제. 씬에 남은 컴포넌트는 메뉴 1이 missing script로 제거한다. |
| `StartScreen` | FinalCheck 화면·필드·검증. 화면은 시작·실습·완료 3개 |
| `TrainingReset` | `finalCheck` 필드·`ClearForReset`·검증 |
| `TrainingGuide` | `IsFinalScreen`, 최종 단계 표시. 실습 = 회차 Running |
| `CompletionPanel` | 요약의 "최종 확인" 줄. 7개 요구만 표시한다. |
| `TrainingSubtitles` | `StepFinal`, `ItemFinal`, `ActConfirmFinal`, `ActConfirmFinalAgain`, `FinalAccepted`, `FinalButton`. 시작 설명 "8단계"를 "7단계"로 바꿨다. |
| Setup | Final 패널·텍스트·확인 버튼 사양, ButtonPaths/전환쌍(Start→Check→Retry→Start), 데이터의 FinalConfirmed 조건, 관련 검사·문구 |

- 유지한 것: `PressureCheckKind.PostWrap`, 확인 기록·철회, `PressureInputResult` 나머지 값.
- `PressureBandageTrainingSummary`는 `RunId`와 요구 7개 값만 가진다. FinalConfirmed를 true로 채우는 경로는 없다.

## 4. 완료 화면 표시

1. Runner(실행 순서 0)가 마지막 단계 조건 충족으로 Completed가 된다.
2. 같은 프레임 Link(104)의 `CaptureSummary`가 이번 회차 요약을 한 번 만든다.
3. CompletionPanel(110)이 요약을 쓰고 다시하기 버튼을 켠다.
4. StartScreen(112)이 `Summary != null`일 때 완료 패널을 연다. 단계 행, 확인 카드, 진행률은 실습 패널과 함께 숨겨진다.

UI가 완료 상태를 만들지 않는다. 화면은 한 번에 하나만 활성화된다.

버튼 영역(안내판 단위)은 서로 겹치지 않는다. 그래서 마지막 확인을 빠르게 두 번 눌러도 다시하기가 실행되지 않는다.
- 확인: y -180..-120
- 다시하기: y -241..-189
- 시작: y -97..-33

## 5. 다시하기(기존 `PressureBandageTrainingReset.TryRetry` 재사용)

처리 순서:
1. `LockForReset`: 새 선택·시작·감기 시작을 잠근다.
2. Guide `ClearForReset`: 표식, 확인 카드, 단계 강조, 진행률, 표시 캐시를 지운다.
3. Link `EndRunForReset`: Runner를 정지한다. 기록, 프레임 후반 대기 입력, 회차·시도 키, 요약을 지운다.
4. `Application.ResetEquipment`:
   - XRI 선택을 취소로 해제한다.
   - 드레싱·롤·끝·테이프를 초기 배치·표시로 되돌린다.
   - 감긴 띠·연결 띠 작업 메시를 원래대로 돌린다.
   - 자동 감기 진행·선택 손 기준을 초기화한다.
   - 끝 SNAP 잠금(충돌체)을 풀고 끝·테이프 놓기 대기를 지운다.
   - 직접 압박 시간·이력을 지운다.
5. `TryCheckReady`로 장비가 준비됐는지 확인한다.
6. `CompletionPanel.ClearForReset`
7. `TryReturnToWaiting`
8. `ReturnToStart`: 시작 대기. 자동 시작은 없다.

- 중복 방지: 버튼은 누르는 즉시 꺼진다. `IsResetting` 가드가 있고, 요약이 지워진 뒤에는 버튼이 다시 켜지지 않는다.
- 실패 처리: 시작 게이트 Faulted, 실패 문구, 시작 버튼 꺼짐(기존 처리 그대로).
- 교육 중간에 다시하기는 추가하지 않았다.

## 6. 기존 씬·데이터 갱신

교육 데이터 `PB_PressureBandageTraining.asset`:
- YAML을 직접 7단계로 고쳤다. 기존 ⑦ 블록을 지우고 ⑧ 블록을 `pb-post-check`로 바꿨으며 `final-confirmed` 조건을 뺐다.
- 결과는 메뉴 1의 `ExpectedSteps`와 같은 순서·조건이다. 메뉴 1도 실행할 때마다 다시 쓴다.

메뉴 1(레이아웃 개정 7):
- `Final` 패널(줄·확인 버튼)을 1회 삭제한다.
- `Steps/Box_8` 이후 박스를 삭제하고, 박스 7개 위치를 한 번 다시 배치한다(개정 6 → 7, 박스만).
- 보드의 missing script(옛 FinalCheck)를 제거한다.
- Guide `stepBoxes` 7개와 StartScreen/Reset 참조를 다시 연결한다.
- 수강자 대상 상태를 다시 써서 `final-confirmed`를 제거한다.
- 안내판 위치·회전·다른 배치·감기 영역 값은 쓰지 않는다. 이름으로 찾으므로 다시 실행해도 중복이 생기지 않는다.

메뉴 2:
- 데이터 단계 수 = 박스 수 = 7, 8번째 박스 없음.
- Final 패널·missing script 없음.
- 다시하기 연결(CompletionPanel → Reset → Guide/Completion/StartScreen).
- 저장 상태: 시작 패널만 표시.
- 버튼 3개와 전환쌍 영역 분리, 텍스트 맞춤·광선 대상 3개.

메뉴 1 실행 전 주의:
- 씬에는 아직 박스 8개, `Final` 패널, missing script 컴포넌트가 남아 있다.
- 이 상태에서는 Guide 검증(박스 수 7)에 실패해 교육을 시작할 수 없다.
- 반드시 메뉴 1을 먼저 실행해야 한다.

## 7. 사용자 적용 순서

1. 재컴파일한다. 보드에 missing script 경고가 보일 수 있다.
2. 메뉴 1을 실행한다. 로그에서 Final 패널 삭제, 박스 1개 삭제, missing script 제거, 개정 6 → 7을 확인한다.
3. 메뉴 2를 실행한다.
4. Play/Simulator로 확인한다.
