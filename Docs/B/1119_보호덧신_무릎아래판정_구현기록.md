# 1119 보호덧신 무릎 아래 판정·즉시 착용 구현 기록

- 작성일: 2026-11-19
- 시작 HEAD: `5c50d87` (작업 시작 시 작업 트리 깨끗함)
- 상태: **코드·씬 파일 변경과 정적 대조 완료. 사용자 Unity 컴파일·Play·Quest 2 확인 대기.**
- 후속: 구현 보고서·실제 코드·저장된 세 씬을 재대조했다. 추가 필수 기능 오류는 미발견이다. LateUpdate 판정/표시 순서와 렌더 직전 몸 재계산의 차이를 §3·§9에 명확히 했다. 사용자 실행 결과는 아직 미보고다.
- 범위: 좌우 덧신(OverbootLeft = 4, OverbootRight = 5)만 바꿨다. 상의·하의·장갑의 판정과 교육 순서(하의 → 상의 → 왼/오른 덧신 → 왼/오른 장갑)는 그대로다.
- 정책: 이번 지시로 받은 코드·씬 직접 수정 허가 범위에서만 작업했다. 스테이징·커밋·Push와 Unity 실행은 하지 않았다.
- 보존: 손 모델·장갑 표시 연계, Windows DX11 설정을 유지했다. 작업 중 사용자 Unity가 저장한 변경도 보존했다(§5).

## 1. 바뀐 동작

| 항목 | 이전 | 이후 |
|---|---|---|
| 덧신 판정 중심 | 발 본 아래 `PC_Zone_Overboot_L/R`, 발등·발목 근처(바닥 위 약 0.13 m) | 같은 점을 매 다리 계산 후 **무릎→발목 선의 25% 지점**(무릎 아래 종아리 위쪽)으로 옮김 |
| 덧신 반경 | 0.14 m | **0.25 m** (월드) |
| 덧신 arming | 영역 밖(반경 + armMargin 0.05)을 한 번 확인한 뒤 재진입해야 착용 | **없음.** 잡고 있는 덧신의 PickupAttach가 영역 안이면 그 프레임에 착용 |
| 덧신 "영역 밖으로 조금 떼세요" | 영역 안에서 잡으면 표시 | 표시되지 않음 |

## 2. 코드 변경

### `ProtectiveClothingUserBody.cs`
- 새 직렬화 필드 `overbootShinFraction`을 추가했다.
  - 범위는 `[Range(0,1)]`, 기본값 0.25. 0은 무릎, 1은 발목이다.
  - Inspector에서 Wear zones 바로 아래에 있다.
- `PlaceOverbootZones()`가 판정점을 옮긴다.
  - 계산: `zones[4/5].point.position = Lerp(leg.lower.position, leg.end.position, overbootShinFraction)`.
  - `lower`는 무릎(Mixamo `LeftLeg`/`RightLeg`), `end`는 발목(`LeftFoot`/`RightFoot`)이다. `SolveTwoBone`의 a = 엉덩이, b = 무릎, c = 발목 정의와 같다.
- 호출 위치:
  - `Solve()` 안에서 `SolveLeg` 두 번 직후. LateUpdate order 40과 OnBeforeRender 모두 해당한다.
  - `Awake()`의 `CaptureRest` 직후. 첫 머리 자세를 받기 전에도 무릎 아래에 둔다.
- 모델의 로컬 축이나 바닥 높이는 쓰지 않는다. 같은 프레임에 계산된 무릎과 발목의 월드 위치만 쓴다. 따라서 이동, 회전, 숙임을 따라간다.
- 판정점 Transform은 계속 발 본 아래에 있다. 다만 월드 위치를 매번 절대값으로 다시 쓴다. 씬 뷰(Edit 모드)에는 저장된 이전 발등 위치가 보이고, Play 중에는 무릎 아래에 있다.
- `ZonePoint`와 `ZoneRadius`는 그대로다. 장비 판정(order 50)이 몸 계산(order 40) 뒤에 이 점을 읽으므로, 같은 프레임의 새 위치로 판정한다.
- `TryValidate`에 비율 범위 검사를 추가했다. 0 이상 1 이하이고 NaN이 아니어야 한다.
- 착용 메시, `WornAttach`, 다리 IK, 발 위치 계산은 바꾸지 않았다.

### `ProtectiveClothingEquipment.cs`
- `WearsOnEntry(part)`는 OverbootLeft/Right에서만 true다.
- `TryWear`에서 기존 차단 조건을 모두 통과한 뒤에만 이 분기로 간다. 덧신이면 `distance <= radius`일 때 바로 기존 `Wear(index)`를 부른다.
  - armed와 waitingToClear를 쓰지 않는다. 그래서 "떼세요" 안내가 나오지 않는다.
- 덧신에도 그대로 유지한 기존 차단 조건:
  - 잡혀 있을 때만 판정한다(`Grab.isSelected`).
  - 입력 포커스가 있어야 한다.
  - 교육 단계 Gate의 AllowsWear를 통과해야 한다.
  - 잡은 손의 추적이 Tracked여야 한다.
  - `ZoneTracking`: 몸이 이번 프레임에 계산됐고 머리 추적이 Tracked이며 안정돼 있어야 한다.
  - `GrabBring.BlocksCompletion`: 원거리로 가져오는 중이거나 추적 소실로 정지 유지 중이면 착용하지 않는다.
  - InputLocked: 초기화 중이거나 실패했을 때, 몸이 정지했을 때, 장비가 꺼졌을 때.
  - 이미 착용한 부위와 재진입 방지(`worn`, `wearing`).
  - 기존 초기화와 다시하기 경로.
- 좌우 영역이 겹쳐도 각 덧신은 자기 Part의 영역만 검사한다. 방향, 접근, 유지 시간, 각도, 속도 조건은 추가하지 않았다.
- 상의, 하의, 장갑의 arming과 armMargin은 그대로다.

## 3. 안내 링

- 두 Guide 모두 기존 `ZoneRadius`로 링 크기를, `ZonePoint.position`으로 링 중심을 정한다. 별도 표시 기준점을 만들지 않았다.
  - 장비 Guide는 order 60, 교육 Guide는 order 105다. 둘 다 몸(40)과 장비 판정(50) 뒤에 실행되므로 판정과 같은 위치와 반경을 그린다.
  - 반경이 바뀌면 `!Mathf.Approximately(radius, ringRadius)` 조건으로 링을 다시 만든다.
- 위 위치 일치는 LateUpdate 시점 기준이다. 몸은 기존 `OnBeforeRender → Solve(0)`에서도 다시 계산되고 이번에 덧신 판정점도 함께 옮겨진다. 두 Guide는 렌더 직전 재배치하지 않으므로, 렌더 시점의 최신 판정점과 표시 링이 언제나 완전히 일치한다고 보장하지는 않는다. 정지 시에는 차이가 없을 수 있으며 이동·숙임 중 체감 차이는 미검증이다. 기존 몸/Guide 갱신 구조의 제약으로 구분하고 이번 요청의 추가 필수 코드 오류로 분류하지 않는다.
- `ProtectiveClothingSfx`의 착용음 위치도 `ZonePoint`를 쓰므로, 덧신 착용음은 무릎 아래에서 난다.

| B_CBRN | 0.25 / 0.25 | 0.25 (작업 중 사용자 Unity가 기본값으로 먼저 저장한 줄 유지) |

## 6. 정적 검토 결과 (실행 검증 아님)

- Unity 번들 Roslyn으로 `MilTrainSimVR.B.ProtectiveClothing`과 `…Tutorial` 소스를 scratchpad에 타입 검사 컴파일했다. 오류는 0이고, 경고는 직렬화 필드 CS0649뿐이다.
- 줄끝은 원래 형식을 유지했다. Equipment·Guide는 CRLF, 나머지는 LF이며 섞이지 않았다.
- 추정 위치(1104 기록의 바인드 자세 값에 눈높이 1.6 m 축척 약 0.965를 적용한 계산값):
  - 무릎 약 0.50 m, 발목 약 0.10 m. 중심은 바닥 위 약 0.40 m, 영역 높이는 약 0.15–0.65 m다.
  - 무릎은 영역 안이다(중심에서 약 0.10 m).
  - 서서 손을 늘어뜨린 높이(약 0.75 m)는 대체로 영역 밖이라 무릎 근처까지 조금 내려야 한다.
  - 좌우 무릎 간격이 0.5 m 미만이므로 두 영역은 겹친다(요구대로 허용).
  - 측정값이 아니라 계산값이다.

## 8. 미검증·실기 보정 항목

- **비율과 반경:** 0.25 / 0.25 m가 실제로 편한지, 너무 넓어서 의도치 않게 착용되지는 않는지 확인해야 한다. 조정은 UserBody Inspector의 `overbootShinFraction`과 Wear zones[4]·[5] radius에서 한다. 세 씬을 같은 값으로 맞춘다.
- **좌우 겹침:** 겹치는 구간에서는 잡은 덧신이 자기 쪽으로 착용된다. 사용자가 이를 반대쪽 착용으로 느끼는지 확인이 필요하다.
- **숙임 추정:** 몸을 숙이면 추정 몸 전체가 머리를 따라 앞으로 이동하므로(1104 기록 §3) 링도 실제 무릎보다 앞에 생길 수 있다. 링을 보고 가져가는 전제다.
- **작업대 근접:** 작업대 덧신의 높이와 위치가 무릎 영역(반경 0.25)과 가까우면, 잡는 순간 착용될 수 있다. 요구 ③에 따른 허용 동작이다. 세 씬의 실제 작업대 배치에서 의도와 맞는지는 실행 확인이 필요하다.
- **표시:** 목적 문구의 줄바꿈과 링 크기가 가독성에 주는 영향은 확인하지 않았다.
- **Edit 모드 위치:** 씬 뷰의 `PC_Zone_Overboot_L/R`은 이전 발등 위치에 보인다. 실제 판정 위치는 Play 중에만 무릎 아래다.

2026-11-19 사용자 요청으로 현재 미커밋 소스와 저장된 세 씬을 대조했다. 검토자는 Unity·컴파일러·Play·Simulator·테스트·빌드를 실행하지 않았고 코드·씬은 수정하지 않았다. 이번 후속에서는 이 기록과 Docs/B/AGENTS.md만 갱신했다.

### 9.1 확인한 구현

- `ProtectiveClothingUserBody`는 설정 유효성 및 본 대응 확인 후 `CaptureRest → PlaceOverbootZones`를 수행한다. 매 Solve에서는 좌우 SolveLeg 뒤에 기존 점의 월드 위치를 `Lerp(lower.position, end.position, overbootShinFraction)`로 절대 대입한다. 변위를 누적하거나 착용 메시·다리 본을 판정점으로 이동시키는 코드는 없다.
- `CaptureRest`의 구동 본 목록에는 zone 점이 없고, 착용 모델 본 대응에서도 zone 점을 제외한다. 기존 점이 발 본 아래에 남아 있어도 매 Solve에서 위치를 다시 계산하므로 부모 움직임이 누적되는 경로는 발견하지 못했다.
- `TryWear`는 기존 포커스·교육 Gate·잡은 손/몸 추적·GrabBring 차단을 먼저 검사한다. 그 뒤 Part 4/5만 기존 Wear를 즉시 호출한다. 잡지 않은 장비는 TryWear로 들어가지 않고, 상의·하의·장갑은 기존 armed 분기를 그대로 사용한다.
- `waitingToClear`는 매 LateUpdate에서 초기화되고 덧신은 그 값을 true로 만드는 armed 분기를 건너뛴다. 따라서 기존 두 Guide의 MoveAway 분기에도 덧신이 들어가지 않는 구조다.
- 기존 Wear는 worn 기록 → 선택 취소 → 픽업 정지/숨김 → 기존 착용 메시 표시를 유지한다. 덧신을 무릎에 표시하거나 다른 쪽 슬롯에 기록하는 변경은 없다. 초기화 경로도 변경되지 않았다.
- 세 씬은 각각 UserBody 1개이며 반경 배열은 `[0.15, 0.15, 0.15, 0.15, 0.25, 0.25]`, 비율은 0.25다. 좌우 점 이름과 해당 발 본 부모 연결은 세 씬 모두 일치한다. 다른 장비·손 Renderer 참조를 변경한 diff는 발견하지 못했다.
- B_CBRN 및 B_FirstAid의 허브 포털 z 위치와 폰트 변경은 보고된 기존 사용자 저장분과 구분하고 보존했다. ProjectSettings에는 이번 덧신 작업의 변경이 없다.

### 9.2 판단

**추가 필수 수정 기능 오류는 미발견이다.** 보고서의 판정/링 일치 설명은 §3처럼 LateUpdate 시점으로 한정한다. 렌더 직전 위치 차이를 실행으로 재현하거나 사용성 결함으로 확정한 것은 아니다.

사용자 확인 우선순위는 좌우 무릎 아래 진입과 영역 안 첫 잡기(§7 ①~④), 추적·중단·가져오기 차단(⑥), 착용 위치·초기화 및 다른 부위 회귀 확인(⑦~⑨)이다. 0.25 m 영역의 겹침·작업대 가까이에서 잡자마자 착용·몸 숙임 때 추정 영역 이동은 현재 요구에서 허용한 동작 또는 보정 대상이며, 실행 근거 없이 엄격한 추가 조건을 필수 요구하지 않는다.
