## 3. 다시하기 처리 순서 (`TourniquetTrainingReset.TryRetry`, 한 호출 안에서)

수락 조건: 조정 중 아님, 참조 유효, 시작 게이트 `Started`, `link.Summary != null`(이 과정 회차의 Runner Completed 요약). 버튼은 클릭 즉시 비활성, 조정 중 재진입 차단 → 양손·연속 클릭에도 1회.

1. `trainingStart.LockForReset()` — 게이트 `Resetting`: 새 장비 선택 차단, 시작 거부, 입력 해제 대기 목록 비움.
2. `trainingGuide.ClearForReset()` — 표식 전부 숨김, 문구 캐시 삭제.
3. `link.EndRunForReset()` — Runner `StopTraining`, 시작 회차 0, 장비·교육생 TrainingTarget 상태 false, 확인 pending·cancelled·토큰, 완료 요약 삭제. 이후 `Observe`는 Running일 때만 쓰므로 초기화 중 장비 이벤트를 수집하지 않는다.
4-5. `operation.ResetToInitial()`(기존) — 부품 핸들 선택 취소 → 핸들 보류 해제·참조·놓기 대기 삭제 → `device.ResetPlacement()`(본체 잡기 선택 취소, 표본·후보·놓기 대기 삭제, 최초 부모·로컬 자세·Rigidbody 자세, 보간, 상호작용 레이어, 실패 이유) → 진행량·막대 단계·스트랩·시간 기록 글자·기록값·부착 기준 시계 → 밴드·막대·스트랩·시간 표기면 자세와 작업본 메시 복원 → 핸들 잠금. 취소된 놓기는 판정하지 않는 기존 경로라 새 성공이 생기지 않는다.
   - 확인: 미부착·비선택·진행값 0이 아니면 실패 처리.
6. `finalCheck.ClearForReset()`, `completionPanel.ClearForReset()` — 버튼 비활성, 거부 기록·캐시 삭제.
7. `trainingStart.TryReturnToWaiting()` — 참조·장비 준비(초기·비선택·관리자) 재확인 후 `WaitingForStart`. 장비 선택은 시작 전 잠금 그대로.
8. `startScreen.ReturnToStart()` — 준비 문구·시작 버튼 복원, 시작 패널만 표시.

새 교육은 시작 버튼으로만 시작한다. 다음 `StartTraining()`이 새 회차 번호를 만든다(Runner 회차 번호를 되감지 않음, 리플렉션 없음). 씬 재로드·XR Rig 재생성 없음.

실패(조건 미충족·예외): 게이트 `Faulted`(잠금 유지), 표식 숨김, 시작 패널에 `RetryFailed` 문구와 비활성 시작 버튼, Console에 원인.

### 표시 조건 (텍스트와 같은 기준)

Guide가 행동 문구를 고를 때 쓰는 **안내 대상** = 현재 단계 k, 또는 이번 회차에 도달했다가 무효가 된 앞 단계(복구 문구 대상). 표식은 이 대상의 표식만 켠다.

- 대상 상태가 이미 유효하면 숨김(Runner가 따라잡는 동안 이미 잠긴 부품을 강조하지 않음).
- 배치 대상인데 본체를 잡고 있으면 숨김(기존 미리보기가 안내, 고스트·영역 판정 무변경).
- 이 과정 회차의 실습 단계 Running + 장비 조작 준비일 때만 표시. 시작 대기·최종 확인·완료·중단·다시하기 중·복귀 후 전부 숨김.
- 막대 회전량이 다시 부족하면 문구 `RecoverTurn`과 함께 표식도 막대 끝만(고정부 제외). 회복하면 고정 단계 표식(막대 끝+고정부)으로 복귀.

## 7. 정적 검토

- 공통 Runner: `StopTraining` 후 `StartTraining`은 Running이 아니면 새 Context와 `++runId`; 대상 구독은 해제 후 재등록이라 중복 없음. 지연 `ReportAction`은 토큰 불일치로 거절.
- `ResetToInitial`·`ResetPlacement` 코드 대조: 선택 취소 → 놓기 대기 삭제 순서라 취소된 놓기가 판정·부착되지 않음. Prefab 물리(키네마틱·중력 없음·throwOnDetach 끔)는 부착 시 바꾸는 값과 같아 복원이 필요 없음.
- 게이트 `Resetting`/`Faulted`에서는 `InputAllowed`가 거짓, `TryStart`는 `WaitingForStart`만 수락.
- 화면: 리셋은 한 호출에서 끝나 중간 프레임이 없다. 이후 `StartScreen.LateUpdate`도 시작 화면을 유지.
- 컴파일·IDE 진단 미실행. 변경 C# 파일 따옴표·괄호 짝 스크립트 검사 통과.
- 남은 점: 표식 크기·오프셋·막대 끝 방향(+X)은 헤드셋 미확인. 막대의 다른 끝을 잡아도 회전은 되며, 필요하면 `Marker_WindlassEnd`의 localPoint를 사용자가 조정. 클립 진입 위치는 클립 중심 기준. 다시하기 직후 손이 그립을 누르고 있어도 장비는 시작 전 잠금 상태이고, 시작 뒤에는 기존 입력 해제 대기가 적용된다. 새 스크립트 `.meta`는 Unity 임포트 시 생성.

## 10. 표식 가시성 개선(O 모양) — 2026-11-02 후속

상태: 다시하기·단계 표식은 사용자 검증 완료 보고(미커밋 작업 트리). 이번 가시성 수정은 **코드·메뉴 작성, 정적 검토만. 컴파일·메뉴 1/2·Play·헤드셋 미확인.**

### 코드로 확인한 경로

| 경로 | 확인 결과 |
|---|---|
| 원 닫힘 | 런타임 `Awake`에서 32점 + `line.loop = true`. 씬 저장값 `m_Loop: 0`은 Awake가 덮어써 영향 없음. 마지막-첫 점 연결 누락은 코드상 없음 |
| alignment·회전 | 씬 저장값 `alignment: 1`(TransformZ). `Follow`가 `LookRotation(-facing)`으로 원 평면(XY)을 시청자 쪽으로 돌림. 원이 시청자에 수직이라 회전 때문에 일부만 사라지는 경로는 코드상 없음 |
| 컬링 | 기존 재질 URP Unlit `_Cull = 2`(Back). 링 띠의 감김 방향은 원 전체에서 같으므로 컬링이면 원 전체가 보이거나 사라지며, 일부만 잘리는 원인일 가능성은 낮다(헤드셋 미확인). 방향 의존을 없애려 양면으로 바꿈 |
| 깊이 가림 | 링은 목표점에서 시청자 쪽 1.5 cm, 반지름 1.2~2 cm. Point_Grab은 본체 안쪽 기준점이고 위로 막대·고정부가 있어, 비스듬한 시점에서 원의 일부가 본체·막대 표면 뒤로 들어갈 수 있다. **가장 유력하지만 실행으로 확정하지 않음** |

### 수정

- 전용 셰이더 `Assets/B/Shaders/TQ_GuideMarker.shader`(`B/Tourniquet/GuideMarker`): Unlit, `Cull Off`, `ZWrite Off`, `ZTest LEqual`, 알파 블렌드, Queue Transparent+50, URP Core.hlsl, 단일 패스 인스턴싱 매크로.
- 가림 처리: 정점 깊이만 뷰 공간에서 카메라 쪽으로 `_DepthPull`(기본 0.05 m) 당김. 화면 위치·Target·LocalPoint·towardViewer(1.5 cm)는 그대로. 근평면 너머로는 당기지 않음. `ZTest Always`가 아니다.
- 부작용: 링보다 5 cm 이내 앞에 있는 물체(장비 표면, 해당 부위를 잡은 손, 팔 표면 일부)는 링을 가리지 않는다. 5 cm보다 더 앞에 있는 물체는 계속 가린다. 투명 영역 표시(큐 3000)보다 뒤에 그려 그 위에 보인다.
- `MAT_TQ_GuideMarker`: 메뉴 1이 매번 전용 셰이더로 전환(기존 Unlit 재질도 전환), 색 유지, `_DepthPull`은 처음 전환·생성 때만 0.05로 설정(이후 사용자 조정 보존), renderQueue는 셰이더 값. 새 재질을 만들지 않고 같은 경로를 재사용.
- `TourniquetGuideMarker.Awake`: `alignment = TransformZ`, `useWorldSpace = false`, `loop = true`를 매번 설정.
- 메뉴 1: 기존 표식에도 `useWorldSpace`·`alignment`·`loop`·재질·그림자 설정을 매번 적용. LocalPoint·반지름·선 두께(0.003 m)는 생성 때만(보존). 크기·두께는 바꾸지 않음.
- 메뉴 2: 재질이 전용 셰이더를 쓰는지, `_DepthPull` 범위(0~0.15], 선 설정(로컬·loop·TransformZ) 검사. 정적 구성 검사이며 O 모양·VR 가독성 확인이 아니라고 보고에 표시.

### 사용자 확인 — 모두 미확인

1. 재컴파일 → 메뉴 1 → 메뉴 2: 셰이더 컴파일 오류·`error CS`·검사 예외 없음, 메뉴 1 로그 `MAT_TQ_GuideMarker switched to the marker shader`(두 번째부터 `kept`).
2. 교육 시작 후 본체 표식을 정면·좌우·위아래에서 관찰: 닫힌 O.
3. 밴드·막대·고정부·시간 기록·마감 표식: 조작 위치를 가리키고 부품 움직임 추종.
4. 장비 회전·시점 이동: 반쪽 잘림·깜빡임 없음. 손으로 해당 부위를 잡을 때 링이 손 위에 보일 수 있음(의도된 부작용).
5. 단계 전환·완료·다시하기 후 표시/숨김 기존대로.
6. 레이·잡기 입력 기존대로.
7. 메뉴 1 재실행 후 유지, 표식·재질 중복 없음.
8. 헤드셋(단일 패스 인스턴싱)에서 양쪽 눈 모두 링 표시.

O 모양이 여전히 끊기면 `_DepthPull`을 0.08 정도로 올려 보고, 너무 많이 비치면 낮춘다(재질에서 조정, 메뉴 재실행 시 보존).
