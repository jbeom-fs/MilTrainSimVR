## 1. 목표와 첫 버전 범위

교육생이 지정된 휴대장비와 도구를 준비하고, 안내된 표면을 처리한 뒤 누락을 보완하고 마무리하는 한 회차를 완주하도록 한다.

- 휴대장비 1종·도구 1세트·교육생 1명·작업대 하나를 기본으로 설계한다. 여러 제품 비교·정답 도구 맞히기 시험은 첫 버전에 넣지 않는다.
- Windows PC VR·Quest 2 + Link·양손 컨트롤러를 기존 프로젝트 기준으로 사용한다. 한 손은 장비, 다른 손은 도구를 조작할 수 있고 역할을 바꿀 수 있다.
- K1·보호의 착용 과정과 독립적으로 시작할 수 있는 기능 확인용 과정으로 설계한다. 보호의 과정을 매번 다시 통과해야 시작하는 구조는 두지 않는다.
- 피부 제독·보호의 탈의·제독소 운영·지역/차량 제독·점수·등급·영구 저장·음성은 이번 범위에 넣지 않는다.
- 가상 처리 범위와 절차 수행을 기록한다. 실제 오염 여부·잔류량·제독 효과를 측정하는 시스템으로 표현하지 않는다.

## 3. 전체 흐름

```text
시작 화면
  ↓ 시작
1. 대상 준비 → 2. 도구 준비 → 3. 표면 처리
                                 ↓ 처리 마치기
                            4. 누락 확인·보완
                                 ├ 누락 있음: 해당 부위 처리 ↺
                                 └ 필수 조건 충족
                                      ↓
                                5. 마무리
                                      ↓ 모든 마무리 조건 충족
                              자동 완료·회차 요약
                                      ↓ 다시하기
                                  시작 화면
```

시작 전에는 교육용 잡기·처리 입력을 잠근다. 시작 입력을 놓은 뒤 실습 잡기가 가능하게 해 버튼 누름이 장비 잡기로 이어지지 않게 한다. 완료·초기화 중에도 새 실습 입력을 잠근다.

## 4. 단계별 교육 설계

| 단계 | 교육생 행동 | 화면 안내 예시 | 완료·전환 조건 |
|---|---|---|---|
| 1. 대상 준비 | 지정 장비를 집어 작업받침 위치에 놓기 | ‘장비를 표시된 작업 위치에 놓으세요.’ | 해당 회차에서 지정 장비를 실제 선택했고 유효한 작업 위치에 배치됨 |
| 2. 도구 준비 | 지정 도구를 집고 필요한 준비 동작 수행 | ‘표시된 도구를 준비하세요.’ | 올바른 도구 선택·준비 상태. 개봉 등이 필요한지는 제품 선정 후 결정 |
| 3. 표면 처리 | 장비를 돌려가며 필요한 표면을 도구로 처리 | ‘표시된 부위를 도구로 처리하세요.’ | 교육생의 ‘처리 마치기’ 선택으로 4단계에 진입. 이 선택은 처리 성공을 대신하지 않음 |
| 4. 누락 확인·보완 | 남은 부위를 보고 직접 보완 | ‘남은 표시 부위를 처리하세요.’ | 필수 표면의 유효 처리와 도구/절차 조건이 모두 충족되면 자동으로 5단계 진입 |
| 5. 마무리 | 사용 도구를 지정 위치에 회수하고 장비 정리 | ‘도구와 장비를 표시된 위치에 정리하세요.’ | 교안에 맞춘 회수·정리 조건과 전체 필수 상태를 현재 회차 기준으로 확인 후 자동 완료 |

### 1단계 — 대상 준비

- 대상 이름·목표·이번 과정에서 다룰 범위를 시작 화면에 표시한다. 다시 확인 버튼을 누르게 하지 않고 실제 선택·배치 행동으로 대상 준비를 확인한다.
- 장비는 받침 위치에 놓인 뒤에도 처리 단계에서 다시 집어 회전할 수 있다. 초기 배치 경험과 현재 받침 상태를 구분해, 장비를 들었다는 이유로 교육 처음으로 돌아가지 않는다.
- 장비가 작업 위치 밖으로 떨어지면 ‘장비를 작업 위치로 가져오세요.’로 안내한다. 손이 닿지 않는 위치에는 해당 장비를 시작 트레이로 돌리는 ‘장비 돌려놓기’를 제공한다. 처리 기록은 회차 안에 유지하되 현재 조건을 다시 확인한다. 이 버튼은 제품상 재오염 상태를 해제하지 않는다.

### 2단계 — 도구 준비

- 선택용 잡기 영역과 표면에 사용하는 작용 영역을 구분한다. 손잡이·도구 본체 전체가 처리 면으로 판정되지 않게 한다.
- 준비는 실제 손동작으로 표현할 항목만 둔다. 제품에 없는 개봉·활성화 버튼이나 효과음용 조작을 임의로 추가하지 않는다.
- 도구 선택 중 손을 바꾸거나 놓았다 다시 잡을 수 있다. 도구를 잡았다는 이유만으로 표면 처리 기록을 만들지 않는다.

### 3·4단계 — 처리와 누락 보완

- 3단계는 대략적인 대상 영역과 현재 작업할 부위를 안내한다. ‘처리 마치기’는 교육생이 작업을 끝냈다고 판단하는 한 번의 입력이며, 단계마다 누르는 다음 버튼은 두지 않는다.
- 4단계는 기록된 누락 영역만 더 분명하게 강조한다. 누락이 있으면 그 부위를 처리하고 같은 회차에서 보완한다. 이미 필요한 처리를 마쳤다면 재처리나 추가 확인 버튼 없이 5단계로 이동한다.
- 제품이 표면 처리 순서를 요구하면 해당 순서를 반영한다. 제품 미정 단계에서 앞면·뒷면·손잡이 순서를 정답으로 고정하지 않는다.
- 잘못된 접촉·무효 처리는 해당 부위의 이유와 다음 행동을 짧게 안내한다. 오류 한 번에 전체 초기화·실패 화면으로 보내지 않는다.
- 가상 재접촉 규칙은 교안과 연결된 항목만 사용한다. 규칙 미확정 상태에서는 임의의 ‘다시 오염됨’ 판정을 켜지 않으며, 해당 교육 요소를 구현·검증 완료로 표시하지 않는다.

### 5단계 — 마무리와 완료

- 사용 도구를 아무 트레이에 놓는 것을 회수 완료로 인정하지 않는다. 선정된 구성품별로 지정 목적지를 구분한다. 화면에는 해당 제품에 맞는 ‘회수함/거치대’ 이름을 사용한다.
- 실제로 잡기를 해제하고 지정 위치에 놓은 상태를 확인한다. 손에 든 도구를 목적지에 스치기만 해도 사라지는 방식은 피한다.
- 마지막 필수 배치가 끝나면 자동 완료한다. 별도의 최종 확인 버튼은 추가하지 않는다.
- 유효 처리 상태가 무효화됐다면 정리·완료보다 보완을 우선 안내한다. 도구를 되돌릴 수 없는 회수 상태로 확정하기 전에 필수 상태를 다시 확인한다.
- 제품상 도구 회수가 되돌릴 수 없고 추가 처리가 필요하다면 교안에 맞는 새 도구 사용 경로를 먼저 설계한다. 회수된 도구를 자동으로 되살리는 동작은 넣지 않는다.

## 5. 표면 처리 판정과 시각화

| 항목 | 설계 기준 |
|---|---|
| 표면 기준 | 장비에 붙어 있는 필수 영역·제외 영역을 정의. 장비를 회전해도 표식·처리 기록이 표면을 따름 |
| 진행 기록 | 실제로 유효한 작용 면이 해당 영역에 접촉하고 필요한 동작을 한 경우만 기록. 같은 지점을 반복해 전체 표면 진행을 채울 수 없음 |
| 접근 면 | 장비 반대쪽·가려진 뒤쪽을 관통 접촉으로 동시에 처리하지 않음. 처리할 면이 손에 닿도록 장비를 회전 |
| 추적·포커스 | 입력이 유효할 때만 진행. 소실 중의 이동·복귀 순간의 위치 점프는 처리 경로로 연결하지 않음 |
| 도구 조건 | 준비·작용 면·선택·교안상 사용 가능 상태를 함께 확인. 잘못된 면의 접촉은 진행 없음 |
| 수치 | 거리·각도·이동 표본 간격 등 조작 허용오차는 개발 설정. 실제 약제 양·효능·접촉시간의 정답 수치로 사용하지 않음 |
| 표시 | 미수행·수행·다시 수행 필요를 색과 테두리/기호로 구분. 교육용 표식임을 시작 안내에 명시 |
| 완료율 | 필요하면 ‘수행한 영역 수/전체 영역 수’로 표시. 오염 제거율·실제 안전성 수치로 표시하지 않음 |

첫 버전은 장비별로 정의한 작은 처리 영역들의 수행 여부를 다루며, 범용 오염 유체·화학 반응·자유 표면 도색 시스템은 선행 제작하지 않는다. 도구가 접촉·이동 방식이 아닐 경우 실제 제품 동작에 맞춰 이 절의 판정 방식을 수정한다.

## 6. 양손 조작과 공간 배치

- 정면에는 대상 장비와 작업받침, 한쪽에는 사용 전 도구, 구분된 위치에는 사용 도구 목적지를 둔다. 좌우 고정 역할을 강요하지 않고 양손 조작을 허용한다.
- 다른 손으로 장비를 잡아 돌리거나, 받침 위에서 도구를 사용할 수 있게 한다. 장비 두 손 파지나 장비 고정에 특별한 동작이 필요한지는 모델 선정 후 결정한다.
- 첫 버전은 한 오브젝트에 한 선택 소유자만 둔다. 손 인계 때 입력 기준을 새로 잡아 도구 이동이 갑자기 누적되지 않게 한다.
- 도구를 놓으면 처리는 중단되고 이미 유효하게 수행한 영역은 유지된다. 놓는 것 자체를 도구 회수·제독 실패로 판정하지 않는다.
- 뒤쪽 표면을 보려 과도하게 몸을 숙이거나 장비를 뚫고 손을 넣을 필요가 없도록 잡기점·회전 공간을 확보한다. 구체적인 높이·거리·반지름은 모델과 사용자 조작 확인 후 정한다.
- 월드 고정 안내판은 장비를 가리지 않는 뒤쪽/옆쪽에 둔다. 손에 붙는 긴 안내판이나 강제 시점 이동은 넣지 않는다.

## 7. UI와 오류·복구

UI는 기존 B 교육 방식에 맞춰 단계 박스 5개·현재 행동 한 문장·필요한 보조 안내로 구성한다. 처리 중에만 영역 진행을 보여주고 개발 설정·Collider·교안 설정 누락 같은 내부 설명은 교육생 화면에 내보내지 않는다.

| 상황 | 교육생에게 보이는 동작 |
|---|---|
| 시작 전·완료 후 조작 | 장비 조작 잠금, 시작 또는 다시하기 안내 |
| 도구 준비 누락 | 현재 필요한 도구 부위 강조, 처리 기록 보류 |
| 허용하지 않는 면 접촉 | ‘표시된 처리 면을 사용하세요.’ 등 구체적인 행동 안내, 진행 없음 |
| ‘처리 마치기’ 선택 후 누락 있음 | 남은 부위 강조, 같은 회차에서 보완 |
| 유효 처리 뒤 교안상 재접촉 발생 | 정의된 영향 부위만 무효화·보완 안내. 임의의 전체 확산 연산 없음 |
| 대상·도구가 바닥에 떨어짐 | 줍기 허용. 닿지 않으면 해당 물체 돌려놓기, 회차 기록 보존·현재 상태 재확인 |
| 컨트롤러 추적·앱 포커스 소실 | 새 처리 중지·안내, 복귀 후 새 접촉 기준으로 재개 |
| 정리 목적지 불일치 | 해당 목적지 강조, 손에 든 상태에서 자동 회수하지 않음 |

정상적인 놓기·손 인계·추적 복귀는 전체 다시하기를 요구하지 않는다. 교육 중 전체 ‘처음부터 다시하기’ 버튼은 이번 초안에서 추가하지 않고, 완료 후 다시하기와 물체별 돌려놓기를 제공한다. 교육 중 중단·선택 화면 복귀는 이후 분야별 운영 씬 통합에서 설계한다. 이는 사용자의 영구 제외 지시가 아니라 첫 버전의 범위 제안이다.

## 8. 완료 화면·다시하기

완료 제목: **휴대장비 제독 가상 절차 연습 완료**.

- 이번 대상·도구 이름, 필수 영역 수행, 누락 보완 여부, 사용 도구 회수·장비 정리를 요약한다.
- 점수·합격 등급·실제 제독 성공·무해화 완료 문구는 넣지 않는다. 소요시간을 표시하더라도 합격 제한시간으로 사용하지 않는다.
- 완료 이벤트와 요약은 회차당 한 번만 발생한다. 완료 뒤 장비를 만지거나 도구를 돌려놓아 완료를 반복 발생시키지 않는다.
- 다시하기 → 새 입력 잠금 → 과정 정지·이전 회차 작업 무효화 → 잡고 있는 XRI 선택 종료 → 장비·도구·회수 상태·표식 복원 → 수행 기록·진행률·누락 안내·요약 초기화 → 시작 화면.
- 다시하기 후 자동 시작하지 않는다. 사용자의 XR 위치·시야는 유지하며 씬 재로드를 초기화 방식으로 사용하지 않는다.
- 초기화 실패 시 입력 잠금과 복구 안내를 유지한다. 정상 시작 상태인 것처럼 표시하지 않는다.

## 9. 기존 교육 구조와 연결할 책임

정적 확인 기준: 현재 `TrainingDefinition`은 Action/State/HoldState 조건, `TrainingRunner`는 시작·정지·단계/완료 알림을 제공한다. `TrainingContext`는 앞으로 한 단계씩 진행하며 임의 단계 되감기는 제공하지 않는다.

- 장비/도구 쪽은 잡기·준비·표면 기록·정리 상태를 담당하고, 과정 연결부가 해당 상태를 교육 진행과 연결한다. UI는 이를 읽어 안내한다.
- 대상 선택·준비 경험은 해당 회차 기록, 처리 유효성·도구 사용 가능·현재 정리 여부는 상태로 구분한다. 과거 성공 한 번만으로 최종 완료하지 않는다.
- 처리 → 확인 → 보완 반복은 과정 내부 상태로 설계한다. Runner의 표면 처리 구간 안에 3·4번 화면 흐름을 묶어 필수 조건 충족 후에만 마무리 단계로 넘어가게 할 수 있다. 화면의 5개 교육 단계와 Runner 내부 단계 수는 같을 필요가 없다.
- 마무리 전 처리 상태를 다시 확인한다. 교안 확정 뒤 마무리 도중 되돌아가야 하는 유효성 변화가 가능하다면 해당 구간도 완료 전 복구 상태로 명시하고, 현재 Runner에 되감기가 있다고 가정하지 않는다.
- 시작 입력 해제 대기·현재 단계의 허용 조작·회차 구분·초기화 책임은 기존 보호의/K1 과정의 책임 분리를 참고한다. 기존 장비·공통 Runner를 이번 설계만으로 수정하지 않는다.
- 지연 입력·이전 회차의 처리 보고가 새 회차에 반영되지 않게 한다. 상태 갱신과 단계 판정 순서를 맞춰, 입력 소실·무효 접촉과 같은 프레임에 이전 유효 상태로 완료되지 않게 한다.
- 자막 원문은 추후 해당 과정의 `TrainingSubtitles` static class 상수로 관리한다. 이 문서의 문구는 화면 설계 예시이며 Inspector·데이터에 중복 저장하는 방식은 채택하지 않는다.
- 후속 운영 씬 통합 때 시작·완료·중단·복귀를 외부 연결점으로 제공한다. 지금 공용 허브·전체 앱 전환을 선행 구현하지 않는다.

5. 시작·교육·자동 완료·다시하기를 연결하고 사용자가 확인.
6. 완성 후 화생방 운영 씬에 K1·보호의와 함께 배치하고 선택·복귀 연결.

### 기존 모델과의 차이·후속 제작 범위

| 기존 소품 | KD-1 외형 기준 수정 방향 |
|---|---|
| `DC_KitCase`: 본체+경첩 뚜껑 | 유연한 외포장과 개별 밀봉 포장으로 변경 필요. 색상만 바꾸는 수정으로 해결되지 않음 |
| `DC_Applicator`: 두꺼운 파지부+밝은 작용 면 | 손 삽입/고정 공간이 있는 얇고 어두운 패드로 변경 필요. 실제 손 접촉 관계를 고려하되 기존 손·인체는 재사용 |
| `DC_CollectionBin`: 열린 회수 용기 | KD-1 키트 구성품으로 확인되지 않음. 별도 교육장 소품으로 보존하고 실제 회수 절차는 교안 확정 후 연결 |

후속 모델 구성 후보는 외포장·개별 패킷·꺼낸 패드다. 동일한 개별 패킷 4개는 공유 메시 인스턴스로 구성할 수 있다. 개봉 전/후와 손에 끼운 상태의 구분은 실제 사진·추가 자료를 바탕으로 정한다. 외포장에 경첩을 추가하거나 패드에 단단한 그립을 유지하지 않는다. 기존 원본·FBX·GUID와 다른 과정의 재사용 장비는 보존한다.

### 아직 확인하지 못한 내용

- 신뢰할 만한 실물 실측/제조사 도면에 근거한 패드·개별 포장·외포장의 각 치수와 두께.
- 패드 뒷면·손 삽입구·봉제선·내부 고정 구조의 전체 모습.
- 현행 납품형별 포장 인쇄·색 차이. 2015년 사진을 모든 현행 군 보급형의 동일 규격으로 표시하지 않는다.
- 적용 부대의 현행 교안, 실제 대상 장비의 처리 허용 면·동작·회수 규칙. 공개 소개 글의 동작 설명만으로 교육 판정·횟수·시간을 확정하지 않는다.

참고로 검색한 유통 페이지들의 치수는 구성품 구분과 기준이 불명확해 제작 확정값으로 채택하지 않았다. 이번 범위는 외형 조사·수정 대상 정리이며 모델 수정과 새 구현 프롬프트 작성은 수행하지 않았다.

형상 변경 완료는 공개 실물 자료를 참고한 모델 제작 범위다. 공식 실측 미확보, 뒷면/부착 상세와 상단 9mm 개봉 가정, 정적 손 착용 자세의 제한은 남는다. 현행 군 보급형의 확정 규격·실제 제독 효과·동적 VR 동작 통과로 확대하지 않는다. 참고 사진의 구조와 구성이 반영됐다는 이유만으로 미확정 대상 장비·교안 규칙이 확정되는 것도 아니다.

다음 사용자 확인은 Unity 임포트 뒤 크기·축·URP 재질·상태별 표시·앵커 대응이다. 그 뒤 대상 장비와 표현할 조작을 정해 준비·잡기·개봉·꺼내기 등 기능 범위를 구체화한다. 구현 프롬프트는 요청 시 채팅으로만 전달한다. 현재 원본·FBX·기존 가상 세트와 사용자 변경은 보존한다.

### 15.1 설계에 반영할 내용

- 처리 동작은 단순한 자유 문지르기나 접촉 시간 채우기로 고정하지 않는다. 확인한 군 공식 설명에 따라 패드의 작용 면으로 대상 부위를 두드리는 구조를 우선 설계한다. 접촉·이탈을 구분하고 한곳에 대고 있는 시간만으로 다른 영역 수행이 누적되지 않게 하는 것은 VR 판정 설계안이다.
- 실제 장비 종류의 근거가 생겼으므로 기존 보호장갑을 고정 전시한 대상을 첫 시연 후보로 제안할 수 있다. 방독면도 문헌상 대상 예시이나, 기존 K1의 렌즈·여과기·내부 등 개별 부위를 모두 처리 가능하다고 자동 승인하지 않는다.
- 한 손 조작을 위해 대상은 받침 또는 기존 마네킹에 고정하고 착용한 패드 손만 움직이는 배치를 제안한다. 이는 사용자 편의에 맞춘 VR 배치이며 실제 국군 절차가 원래 한 손 전용이라는 뜻은 아니다.
- 화면의 ‘겉봉투 → KD-1’ 변경을 다음 기능과 함께 수행한다. 아직 명칭이나 처리 코드를 수정하지 않았다.

### 15.2 아직 확인하지 못한 항목

현행 교범 판본, 장비별 필수 부위·제외 부위, 두드림 횟수·힘·속도·면적당 약제량, 장비별 순서, 패드 교체·사용 후 처리의 구체적인 기준은 이번에 찾은 군 관련 자료만으로 확정할 수 없다. 수치 판정은 개발용 허용오차로 구분하고 국군 정답이나 제독 효과 수치로 표시하지 않는다.

따라서 권장 후속 범위는 ‘보호장갑 등 근거 있는 대상 후보 선택 → 지정 부위와 작용 면 두드림 판정 설계 → 가상 수행 영역 표시’다. 새 모델 제작·피부 제독·K1 착용 절차 수정·교육 전체 구현으로 범위를 자동 확대하지 않는다. 이번 작업은 조사·설계 문서 갱신뿐이며 코드·자산 수정과 Unity 실행은 하지 않았다.
