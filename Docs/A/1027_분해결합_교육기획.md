## 2. 교육 흐름

```text
[안내] → (선택) 조정간 안전 확인 → 분해 6단계 → 결합 6단계
      → 기능 점검 → [결과] → 다시 하기 / 메뉴
```

| 구간 | 내용 |
| --- | --- |
| 진입 | 내무반 작업대 앞에서 시작. 작업대 하나에서 끝나므로 이동 기능은 넣지 않는다 |
| 안내 | 패널에 목표와 조작법 표시 (잡기 = 그립, 당기기·밀기). 모드 선택. 시작 버튼 |
| 조정간 안전 확인 | **선택 (미정).** 탄창이 필요 없고 기능 점검의 조정간 조작을 다시 쓰므로 비용이 적다 |
| 분해·결합 | 기존 13단계 (`AssemblySequence`, 분해 5는 2단계로 나뉨) |
| 기능 점검 | 3절 |
| 결과 | 4절 |

## 3. 기능 점검

결합이 끝나면 작업대의 분해용 총을 사격용 총으로 바꾼다. 같은 위치이고 겉모습도 같다 (방법: [재사용 검토 4절](1027_C사격코드_재사용검토.md)). 사용자가 총을 집어 든다.

| # | 단계 | 완료 조건 | 피드백 |
| --- | --- | --- | --- |
| 1 | 총 들기 | 권총손잡이를 잡음 | |
| 2 | 조정간 안전 확인 | 조정간 안전에서 방아쇠를 당겨 격발되지 않음을 확인 (10/27 구체화. 총이 처음부터 안전이라 상태만 보면 바로 넘어간다) | 단계 완료음 |
| 3 | 장전 손잡이 끝까지 당겼다 놓기 | 끝까지 후퇴 → 놓아서 앞으로 복귀 | 노리쇠 후퇴·전진 소리 |
| 4 | 조정간 단발 | 조정간이 단발 | 조정간 소리 |
| 5 | 총구를 위로 향하고 방아쇠 (10/27 변경) | 단발 + 공이치기 젖혀짐 + **총구가 수직 위에서 60° 안** (처음 45°, 10/27 사용자 요청으로 60°) | **"탁"** + 짧은 진동. 탄·반동·총구 화염 없음 |
| 6 | 조정간 안전 | 조정간이 안전 | 완료음 |

- 3을 하지 않고 5를 하면 "탁"이 나지 않는다 (공이치기가 떨어져 있음). 자막으로 3단계를 안내한다.
- 안전 상태에서 방아쇠를 당기면 당겨지지 않는다. 오류음과 자막이 나온다.
- 겨누는 방향: 10/27 사용자 요청으로 **총구가 위를 향할 때만** 통과한다. 위를 향하지 않고 "탁"이 나면 실수로 세고, 장전 손잡이를 다시 당겨 위로 향해 다시 쏜다 (13-6).
- 조정간은 처음에 **잡은 손의 B/Y 버튼**으로 돌린다 (C와 같은 방식). `Part_Selector`를 손으로 돌리는 방식은 나중에 한다.
- 총을 놓쳐 떨어뜨리면 작업대 위 자리로 되돌린다.

## 4. 모드와 결과

| | 학습 모드 | 평가 모드 |
| --- | --- | --- |
| 지금 할 부품 외곽선 | ○ | × |
| 빠지는 방향 화살표 | ○ | × |
| 결합할 때 끼울 자리 (반투명 형상) | ○ | × |
| 패널의 단계 문구 | ○ | ○ (지금 단계 이름만) |
| 순서 오류 자막 | 지금 할 단계를 알려 준다 | "순서가 아닙니다"만 |
| 타이머 표시 | × | ○ |
| 결과 | 시간, 오류 수 | 시간, 단계별 오류 수, 등급 |

- 힌트는 `AssemblySequence.Current`(지금 단계의 부품·종류)를 읽어서 보여 주기만 한다. 판정 로직은 그대로 둔다.
- 등급 기준 시간은 미정이다. 실기로 몇 번 해 본 뒤 정한다.
- 오류는 기존대로 잡을 때마다 한 번만 센다.

## 5. 화면 (작업대 앞 패널)

- 월드 공간 패널 하나. 작업대 맞은편 위쪽에 두어 총을 보면서 읽을 수 있게 한다.
- 표시 내용: 모드, 진행(n/전체), 지금 단계 문구, 자막(오류·안내), 타이머(평가 모드).
- 버튼(시작, 다시 하기, 메뉴)은 레이로 누른다. **부품은 가까이 잡기만 허용하고 레이 잡기는 막는다.**
- 문구는 `AssemblyTexts` 한 곳에 둔다. 팀 공통 자막 방식(B 제안 `TrainingSubtitles`)을 따를지는 아직 미정이다 ([AGENTS.md](AGENTS.md) 6절).

## 7. 진행 — 2번 교육 흐름 관리자 (10/27)

**스크립트**

- `AssemblyTrainingFlow.cs` (신규). 구간: `Intro` → `Assembly` → (`FunctionCheck`) → `Result`.
  - 패널 버튼용 메서드: `StartLearning`, `StartEvaluation`, `Retry`, `ReturnToIntro`.
  - 기능 점검이 끝나면 기능 점검 쪽에서 `CompleteFunctionCheck`를 부른다. → 10/27 5번에서 바꿨다: `FunctionCheckSequence.Finished` 이벤트를 흐름이 듣는다 (`CompleteFunctionCheck` 삭제).
  - 구간이 바뀌면 `StageChanged`를 알린다 (패널·힌트용).
  - 10/27 0단계 정리 이후 구조는 [스크립트 구조 계획 5절](1027_A스크립트_구조계획.md)을 본다. 시험은 에디터 메뉴 `A/시험`으로 한다.
- `AssemblySequence`:
  - 씬 시작 때 자동으로 시작하지 않는다. `Begin()`으로 시작한다.
  - `ResetAll()`은 모든 부품을 끼운 상태로, 본체를 닫힌 상태로 되돌린다.
  - 시작 전과 끝난 뒤에는 부품이 잠기고 오류도 세지 않는다.
  - 완료 결과는 이제 흐름 관리자가 표시한다.
- `AssemblyPart.ResetToSeat()`: 잡고 있으면 손에서 놓게 하고, 끼울 자리의 자식으로 되돌리고, 물리를 멈춘다.
- `AssemblyHinge.ResetClosed()`: 잡고 있으면 손에서 놓게 하고, 0°로 되돌린다.
- `AssemblyTexts`: 안내·결과·모드 문구를 추가했다.

**씬 설정**

- `A_Sandbox`의 `AssemblyController`에 `AssemblyTrainingFlow`를 붙였다.
- 임시 설정 `m_StartOnPlay` = 켬. 패널이 생기기 전 헤드셋 확인용이고, Play하면 학습 모드로 바로 시작한다.
- `m_UseFunctionCheck` = 끔. 기능 점검을 만들기 전이라 결합이 끝나면 바로 결과로 간다.

**확인 (에디터 Play, 헤드셋 없음)**

부품 동작은 손 대신 리플렉션으로 일으켰다.

| 시험 | 결과 |
| --- | --- |
| Play 시작 | `Assembly`·학습 모드, 첫 단계 가스 조절기 |
| 분해 5단계 진행 중 처음으로 (가스 조절기는 물리로 떨어지는 상태) | `Intro`, 부품 5개 모두 끼워짐·자리 복귀·물리 멈춤, 본체 0°, 안내 문구 표시 |
| 평가 모드로 13단계 끝까지 | `Result`, "평가 모드 · 소요 시간 00:30 · 오류 0회" |
| 결과 화면에서 막힘 보고 | 오류로 세지 않음 (0) |
| 다시 하기 | 평가 모드 유지, 첫 단계, 오류 0. 진행 중 막힘 보고는 1로 셈 |
| 콘솔 | 오류 0. 경고는 XR 오디오 장치 경고 2개 (헤드셋 미연결) |

**확인 안 함**

- 헤드셋에서 실제로 잡은 상태로 다시 하기를 눌렀을 때 손에서 놓이는지. `CancelInteractableSelection`을 쓰지만 실기로는 확인하지 않았다.
- 모드별 차이(힌트·타이머·오류 문구)는 아직 없다. 6·7번에서 붙인다.
- 패널 버튼이 없다. 헤드셋 안에서는 시작(자동)만 되고, 다시 하기·처음으로는 3번 패널이 생겨야 할 수 있다.

## 13. 헤드셋 1차 피드백 수정 (10/27)

**사용자 보고**

1. 순서와 상관없이 장전 손잡이를 잡으면 날아가거나 사라진다.
2. 2단계 총기 본체 열기에서 본체가 열리지 않는다.

**원인 (두 증상 공통)**

- XRI 3.4.1 `XRGrabInteractable.Grab()`은 잡는 순간 `m_Transform.SetParent(null)`로 **부모를 떼어 씬 루트로 옮긴다** (패키지 소스 `XRGrabInteractable.cs` 2502~2503줄).
- 장전 손잡이(분해 부품): 끼워진 부품은 끼울 자리 기준 로컬 좌표로 위치를 정한다(`SetOffset`). 부모가 떨어지면 그 로컬 좌표가 월드 좌표로 쓰여 **월드 원점(문 쪽) 근처로 순간이동**했다. 다른 부품도 같았다.
- 본체: 상부 본체가 회전 중심(`HingePivot`)에서 떨어져서, 회전 중심을 돌려도 본체가 따라 돌지 않았다.
- 에디터 시험은 손 대신 메서드로 단계를 진행해서 이 경로(`Grab()`)를 타지 않았다. 사격용 총의 장전 손잡이(`ChargingHandleSlide`)는 처음부터 다시 붙이도록 만들어서 문제가 없었다.

**수정**

- XRI는 `Grab()`(부모 떼기) 다음에 `selectEntered` 이벤트를 낸다. 그래서 잡기 이벤트에서 같은 프레임에 다시 붙인다 (월드 위치 유지).
  - `AssemblyPart.OnGrab`: 끼워진 상태면 끼울 자리(`m_SeatParent`)에 다시 붙인다. 분리된 부품은 그대로 씬 루트에 둔다.
  - `AssemblyHinge.OnGrab`: 회전 중심(`m_Pivot`)에 다시 붙인다.

**확인 (에디터 Play)**

`XRSocketInteractor`를 임시 손으로 만들어 실제 선택(`SelectEnter` → `Grab()`)을 일으키고, 손을 움직였다.

| --- | --- |
| 1단계에서 장전 손잡이 잡기 → 빠지는 쪽으로 5 cm | 부모 `Part_Upper` 유지, 위치 그대로, 움직이지 않음, 오류 1 (순서 아님). 놓아도 그대로 |
| 1단계 가스 조절기 잡기 → 3 cm → 9 cm | 3 cm는 축을 따라 이동(`Moving`), 9 cm에서 분리(`Free`)되고 2단계로. 놓으면 떨어진다 |

### 13-3. 3차 피드백 (10/27)

**1. 밀대뭉치·가스 활대를 가운데를 잡아야만 당겨진다 (보이는 끝부분을 잡으면 안 당겨짐)**

- 원인:
  - 리그의 Near-Far Interactor 정렬 방식이 기본값 `SquareDistance`였다. 이 방식은 **손과 각 부품 중심점(Transform 위치) 사이 거리**로 잡을 대상을 고른다.
  - 그래서 막대 끝을 잡으면 다른 부품(노리쇠 뭉치·밀대뭉치·상부 본체)의 중심이 더 가까워 그쪽이 잡히고, 순서가 아니라 막혔다.
  - 프리팹에 설정한 거리 계산 방식(내부 부품 Collider Volume, 상부 본체 Collider Position)은 이 정렬 방식에서 쓰이지 않았다 ([프리팹 구조](1026_K2C1_프리팹_구조.md) 6절의 가정이 틀렸다).
  - 상부 본체 뒤쪽은 밀대뭉치(z -0.37 ~ -0.128), 가스 활대(-0.351 ~ 0.020), 노리쇠 뭉치(-0.349 ~ -0.237)의 잡기 상자가 겹친다.
- 수정:
  - A 씬 리그 양손 Near-Far Interactor의 `nearCasterSortingStrategy` → **`InteractableBased`** (씬 인스턴스 값만 바꿈, 공용 프리팹은 그대로). 이제 각 부품의 거리 계산을 쓴다.

  - `AssemblySequence.IsActive(AssemblyHinge)`: 열기·닫기 단계인지.
- 사격용 총의 장전 손잡이 우선(Collider Volume)도 이 정렬 방식 변경으로 의도대로 동작하게 된다.

| 총이 누운 채(위에서 90°) 격발 | `NotAimedUp` 실수, 5단계 그대로 |
| 다시 방아쇠 | `HammerDown` 실수 (다시 장전 안내) |

| 장전 → 위에서 30° 기울여 격발 | 통과 → 6단계 |

### 13-7. 조정간 부품 회전 (10/27 사용자 요청)

- 요청: 조정간을 단발·안전으로 바꿀 때 총의 실제 조정간도 돌아가게.
- 수정: `K2C1Rifle`에 `m_Selector`(`Part_Selector`)와 `m_SelectorAngles`를 추가했다. 조정간이 바뀔 때(시작·`SetFireMode`·`ResetState` 포함) 부품을 자기 X축(총 좌우)으로 돌린다. `K2C1_Rifle` 프리팹을 제자리에서 고쳤고 빌더에도 넣었다.
- 회전 중심: 조정간 메시는 원점을 중심으로 앞뒤 대칭인 레버판이다 (두께 11 mm, 길이 38 mm, 높이 18 mm). 그래서 원점을 회전축으로 보았다. 앞쪽 끝(+Z)에 돌기가 있다.
- 각도: 처음에는 임시값(점사 135° 포함)으로 넣었다. 그 뒤 **사용자가 K2C1 조정간 위치를 확정했다 (10/27)**:

> **K2C1 조정간은 세 위치다.** 총의 왼쪽 면(조정간 쪽)을 총구가 왼쪽에 오게 놓고 볼 때 **9시 = 안전, 12시 = 단발, 3시 = 연발.** 점사는 없다.

| 위치 | 시계 방향 | 각도 (`m_SelectorAngles`) | 레버 돌기 |
| --- | --- | --- | --- |
| 안전 | 9시 | 0° | 앞(총구 쪽) |
| 단발 | 12시 | 90° | 위 |
| 연발 | 3시 | 180° | 뒤 |

- 모델 자세(0°)가 9시(안전)였다. 각도는 그대로 맞았다.
- `K2C1Rifle.m_HasBurst`(신규, 기본 끔)를 추가했다. B/Y 순환이 **안전 → 단발 → 연발 → 안전**이 되고 점사를 건너뛴다. 점사 코드와 `FireMode.Burst`는 C 복사본과의 호환을 위해 남겼다.
- 확인: B/Y 4번 → 단발(12시) → 연발(3시) → 안전(9시) → 단발.
- C의 `TempRifle`(시가지 전투)은 점사를 포함해 4단으로 돈다. K2C1에는 점사가 없다는 것을 C에게 알릴지는 사용자가 정한다.
- **논의 필요 (10/27):** 사용자가 찾은 자료에는 K2C1이 기존 K2와 같은 **4가지 모드**(안전 S · 단발 1 · 연발 A · 점사 3)를 지원한다고 되어 있다. 점사는 방아쇠를 당기고 있으면 3발씩 끊어 나간다. **당장은 3위치(점사 없음)를 유지**하고, 점사를 넣을지와 점사 위치의 각도는 이야기한 뒤 정한다.
  - 넣기로 하면 `K2C1Rifle.m_HasBurst`를 켜고 `m_SelectorAngles`의 점사 값(지금 135°, 임시)을 실제 위치로 바꾸면 된다. 순환 순서(안전 → 단발 → 연발 → 점사? 등)도 같이 정한다.

- 확인 (에디터 Play, 총을 세워 왼쪽 면을 임시 카메라로 찍음): 위 표대로 돌고, 레버가 제자리에서 돈다 (중심이 움직이지 않음).
- 손으로 조정간을 돌리는 조작은 아직 없다. 여전히 B/Y 버튼이다.
