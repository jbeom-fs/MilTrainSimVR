# 헤드셋 확인 목록 (분해·결합 3~7번)

작성: A · 2026-10-27
사용자 결정: 구현을 먼저 하고, 헤드셋 확인은 나중에 한 번에 한다. 그때 이 목록을 순서대로 본다.
자세한 내용: [교육 기획](1027_분해결합_교육기획.md) 7~12절

에디터 Play에서는 모두 확인했다. 확인 방법은 메뉴 `A/시험`과 메서드 호출이다. 아래는 **손·헤드셋으로만 확인할 수 있는 것**이다.

## 0. 세션 준비와 진행 순서

### 0-1. 준비

1. Quest 2를 PC에 Link로 연결한다.
   - Meta Quest Link 앱 → 설정 → 일반 → **OpenXR 런타임을 Meta Quest Link로 활성화**.
   - C는 Virtual Desktop으로만 실기를 했다. **A·B 방식인 Link는 팀에서 아직 아무도 확인하지 않았다** (C 10/22 통지).
2. Unity에서 `Assets/A/Scenes/A_Sandbox.unity`를 연다.
3. **씬의 `XR Interaction Simulator`는 꺼진 채여야 한다.**
   - 켜져 있으면 진짜 헤드셋 입력을 지워서 화면이 머리를 따라 같이 돈다 (C 10/22 통지 2절).
   - 10/27 확인: A 씬에서 꺼져 있다 (`active=False`).
4. **눈높이:** 기본 높이(시작했을 때 그대로)로 한다 (사용자 10/27). 높이를 맞춰야 하면 `XR Origin (XR Rig)`의 `SeatedTestHeight`(10/27 추가, 지금 꺼 둠)를 켠다.
   - Play 뒤 머리 추적이 잡히고 1초 뒤 머리 높이를 재서, 눈높이가 **1.6 m**가 되도록 카메라를 올린다. 추적 기준(Floor/Device/Unbounded)과 상관없이 동작한다.
   - 자세를 바꾸면 컴포넌트 우클릭 → `다시 재기`.
   - **서서 할 때는 `m_Seated`를 끈다.** 기획은 서서 하는 것이 기준이다.
   - 콘솔에 `[A] 앉은 테스트 높이: 추적 기준 …`이 찍힌다. Link의 추적 기준을 여기서 알 수 있으니 기록한다.
5. 헤드셋을 쓰고 Play를 누른다.
5. 시작 위치는 작업대 남쪽(z -6.8)이고 북쪽 문 쪽을 본다. 패널은 작업대 너머에 있다.

### 0-3. 막혔을 때

- **레이로 버튼이 안 눌리면:** 다른 사람이 키보드에서 메뉴 `A/시험` → `학습 모드 시작` / `평가 모드 시작` / `다시 하기` / `처음으로`를 누른다. 혼자라면 `AssemblyController`의 `m_StartOnPlay`를 켜고 Play한다.
- **부품이 안 빠지거나 단계가 막히면:** 메뉴 `A/시험` → `지금 단계 완료`로 넘기고, 막힌 단계와 증상을 기록한다.

## 1. 공통 (기존 분해·결합 — 6절 1번)

- [ ] 13단계를 손으로 끝까지 진행할 수 있는가.
- [ ] 내부 부품과 상부 본체 중 어느 쪽이 먼저 잡히는가 (내부 부품 충돌체가 상부 본체 충돌체 안에 있다).
- [ ] 부품 분리 거리, 본체 열림 각도(25°)가 적당한가.
- [ ] 작업대 높이 0.95 m, 통로 폭이 적당한가 (XR 추적 기준이 바닥인지도 확인).
- [ ] 부품을 잡은 채 **다시 하기·처음으로**를 누르면 손에서 놓이는가.

## 2. 패널 (3번)

- [ ] **레이로 버튼을 누를 수 있는가.** XRUIInputModule + TrackedDeviceGraphicRaycaster 구성만 맞췄다.
- [ ] 레이로 부품이 잡히지 않는가. 아직 막지 않았다. 잡히면 막는다.
- [ ] 패널 위치가 적당한가: (0, 1.45, -5.15), 작업대 북쪽, 플레이어는 문 쪽을 본다.
- [ ] 머리줄 글자(30)가 작지 않은가.

## 3. 사격용 총 (4번)

- [ ] 장전 손잡이를 손으로 잡고 당길 수 있는가.
- [ ] 장전 손잡이와 총 몸 중 어느 쪽이 먼저 잡히는가.
- [ ] 양손 잡기 (손잡이 + 앞손).
- [ ] 장전 손잡이·가스 활대가 0.09 m 움직일 때 상부 본체 메시를 뚫고 보이지 않는가.
- [ ] (교범) 행정 0.09 m, 장전 손잡이가 가스 활대와 함께 움직이는지.

## 4. 기능 점검 (5번)

- [ ] 6단계를 손으로 진행: 총 들기, 안전에서 방아쇠, 장전 손잡이, B/Y 단발, 트리거 "탁", B/Y 안전.
- [ ] 분해용 총에서 사격용 총으로 바뀌는 순간 겉모습이 같은가 (물리 때문에 살짝 내려앉을 수 있다).
- [ ] 총을 떨어뜨리면 작업대 위로 돌아오는가.

## 5. 학습 모드 힌트 (6번)

- [ ] 반투명 강조·끼울 자리 형상이 깜박이거나 깨져 보이지 않는가 (같은 메시를 겹쳐 그리는 방식).
- [ ] 화살표(길이 7 cm)가 잘 보이고 방향을 알아볼 수 있는가. 특히 열기·닫기.
- [ ] 기능 점검 단계에도 힌트(장전 손잡이·조정간 강조)가 필요한가.

## 6. 평가 모드·결과 (7번)

- [ ] 결과 글자가 읽히는가. 줄이 많으면 자동으로 최소 22까지 줄어든다.
- [ ] **등급 기준 시간 정하기.** 지금은 임시값으로 우수 3:00·오류 0, 합격 5:00·오류 2. 몇 번 해 본 시간을 보고 Inspector `m_Grade`를 조정한다.

## 7. 남은 구현

- 8번 실제 소리 자산. 지금은 코드로 만든 임시 소리를 쓴다: 오류, 막힘, 철컥, 단계, 사격, 탁, 조정간, 장전 손잡이. 소리 파일을 어디서 구할지 정해야 한다.
