## 3. 복사 vs 참조 — 결정: **필요한 파일만 복사해서 A 것으로 고친다**

**복사를 고른 이유**
- C 코드는 자주 바뀐다 (10/26 하루에 커밋 2번). 참조하면 C의 수정이 A 씬을 깨뜨릴 수 있고, A는 C 폴더를 고칠 수 없다.
- A에 필요한 동작(공이치기, 장전 손잡이, 탄창 없는 시작)은 `TempRifle`의 본체를 고쳐야 들어간다. 참조로는 넣을 수 없다.
- `TempRifle`은 C의 `Gunfire`·`IHittable`·`MuzzleFlash`·`RifleRecoil`에 묶여 있다. 참조하면 시가지 전투 코드 전체에 의존하게 된다.

**복사의 단점**
- C가 버그를 고쳐도 A에 자동으로 들어오지 않는다. 그래서 파일 머리에 원본 경로와 커밋을 적어서 나중에 비교할 수 있게 한다.
- 비슷한 총 코드가 두 벌이 된다. 앱을 통합할 때 공용으로 합칠지 그때 C와 정한다.

**복사 규칙**
1. **`.meta` 파일은 복사하지 않는다.** `.meta`를 같이 복사하면 GUID가 겹쳐 Unity가 한쪽 GUID를 새로 만든다. 이때 C 프리팹이 A 스크립트를 가리키는 등 참조가 꼬일 수 있다. `.cs`만 복사하고 Unity가 새 `.meta`를 만들게 한다.
2. **namespace를 바꾼다.** `MilTrainSimVR.UrbanCombat` → `MilTrainSimVR.A.Rifle`. 같은 namespace에 같은 클래스가 둘이면 컴파일 오류(CS0101)가 난다.
3. **클래스 이름도 바꾼다.** 예: `TempRifle` → `K2C1Rifle`. namespace가 달라도 Add Component 메뉴에 같은 이름이 둘 뜨면 헷갈린다.
4. **프리팹은 복사하지 않는다.** `C_K2C1.prefab`·`C_TempRifle.prefab`은 C 스크립트를 가리킨다. A는 `K2C1.prefab`의 Variant를 새로 만든다.
5. 파일 머리 주석: `원본: Assets/C/Scripts/TempRifle.cs (커밋 a1a51ac, C 이주석). A가 복사해 고침.`
6. C에게 복사한 사실과 목록을 `Docs/A`에 공지한다.

**복사할 것 (위치: `Assets/A/Scripts/Rifle/`)**

| 원본 | 복사본 | 바꿀 것 |
| --- | --- | --- |
| `TempRifle.cs` | `K2C1Rifle.cs` | 공이치기 상태, 처음 탄 수, `Gunfire` 호출 제거 (또는 A 쪽 작은 이벤트) |
| `MuzzleFlash.cs` | `MuzzleFlash.cs` | namespace만 |
| `RifleRecoil.cs` | `RifleRecoil.cs` | namespace만 |
| `IHittable.cs` | `IHittable.cs` | namespace만 |

- `ImpactEffects`는 사로에서 탄흔이 필요할 때 복사한다. `PracticeTarget`·`TargetRange`는 복사하지 않고 사로 표적지를 따로 만든다.
- 복사는 **기능 점검 구현을 시작할 때** 한다.
- **10/27 복사함.**
  - 원본 4개는 기준 커밋 `a1a51ac` 이후 바뀌지 않았다.
  - `IHittable`·`MuzzleFlash`·`RifleRecoil`은 줄바꿈을 무시하고 비교하면 namespace 한 줄만 다르다.
  - `K2C1Rifle`에서는 `Gunfire` 호출을 지웠다. A 씬에는 적이 없어서 대신할 이벤트도 두지 않았다.
  - `.meta`는 복사하지 않았다.

## 4. 기능 점검에서 총을 드는 방법 — 제안: **총 교체**

결합이 끝나면 작업대의 분해용 총(`K2C1_Assembly`)을 끄고, 같은 위치·회전에 사격용 총(`K2C1.prefab`의 A Variant + `K2C1Rifle`)을 켠다.

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| **총 교체 (권장)** | 분해용과 사격용 스크립트가 섞이지 않는다. 사격용 총을 사로에서 그대로 쓴다 | 바꾸는 순간 부품 상태가 같아야 한다. 결합이 끝났으면 모두 끼워진 상태라 겉모습이 같다 |
| 분해용 총에 전체 잡기 추가 | 오브젝트가 하나 | 부모 잡기와 부품 잡기가 겹친다. XRI는 자식 콜라이더를 부모 잡기에 묶을 수 있어서 콜라이더 목록을 하나하나 지정해야 한다 |

## 5. 확인 안 함

- `TempRifle`을 헤드셋으로 직접 쏴 보지 않았다 (C의 커밋 설명과 코드만 봤다).
- 장전 손잡이 실제 동작: K2는 장전 손잡이가 오른쪽에 있고 노리쇠와 함께 뒤로 움직인다고 보고 -Z 슬라이드로 잡았다. 교범으로 확인 필요.
