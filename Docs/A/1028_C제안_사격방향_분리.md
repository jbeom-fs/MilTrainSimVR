# C 제안 — 탄이 나가는 방향을 한 자리에서 정하기

작성: A · 2026-10-28
대상: C (조준 역할 분담: 직접 들고 쏘기 보정 = C, 조준 확대 모드 = A)
상태: **제안 — C와 나중에 한 번에 확인한다** (사용자 10/28: 코드 충돌 문제는 이미 C에게 전달됨)

## 1. 알리는 것 — 조준선 측정값

K2C1 모델에서 직선을 쏴서 잰 값 (총 루트 기준, m). C의 직접 조준 보정에도 필요하다.

| 점 | 측정 | 기존 위치 표시 (추정) |
| --- | --- | --- |
| 가늠자 구멍 가운데 | (0, 0.156, 0.0205) | `Anchor_RearSight` (0, 0.155, 0.020) |
| 가늠쇠 끝 | (0, 0.1465, 0.5336) | `Anchor_FrontSight` (0, 0.155, 0.525) |
| 총구 | (0, 0.09, 0.729), 앞 +Z | `Anchor_Muzzle` 그대로 |

- **조준선이 총열보다 1.06° 아래로 기운다.** 조준선으로 25 m를 정확히 겨누면 총열(지금 판정 직선)은 약 40 cm 위를 향한다. 사로 헤드셋 확인에서 거의 안 맞은 주원인이다 (손떨림보다 크다).
- A는 `K2C1.prefab`의 `Anchor_RearSight`·`Anchor_FrontSight`를 위 측정값으로 옮긴다 (이름 그대로). C가 이 두 점을 쓰고 있으면 값이 바뀐다.

## 2. 문제 — 같은 총 코드가 두 벌

- A의 `K2C1Rifle`은 C의 `TempRifle`을 복사해 고친 것이다 ([재사용 검토](1027_C사격코드_재사용검토.md)). 두 파일 모두 `Shoot()` 안에서 탄 방향을 `m_Muzzle.forward`로 바로 정한다.
- 이제 탄 방향을 바꾸는 쪽이 둘이다: C의 직접 조준 보정, A의 확대 모드. 각자 `Shoot()`을 고치면 두 총이 더 갈라지고, 한 총에 둘을 같이 쓸 때 서로 덮어쓴다.

## 3. 제안 — 총은 "탄 방향을 물어보는 자리" 하나만 둔다

```csharp
// 총이 쏘기 직전에 묻는다. 줄 직선이 없으면 false — 총은 원래대로 총열 방향으로 쏜다
public interface IShotLine
{
    bool TryGetShotLine(out Vector3 origin, out Vector3 direction);
}
```

- 총(`Shoot`)은 연결된 `IShotLine`에 물어보고, 주면 그 직선으로, 안 주면 지금처럼 총구 앞 방향으로 판정한다. 벽 속 총구 검사·탄도선·효과는 그대로.
- **A 확대 모드:** 확대 모드일 때만 조준선(가늠자 → 가늠쇠) + 흔들림으로 직선을 준다.
- **C 직접 조준 보정:** 같은 약속으로 보정한 직선을 준다.
- 둘을 같이 쓸 때 순서: 확대 모드가 켜져 있으면 확대 모드, 아니면 직접 조준 보정, 둘 다 없으면 총열. (작은 "고르는" 컴포넌트 하나로 묶거나, 확대 모드가 꺼져 있을 때 다음 것에 넘긴다.)

## 4. A가 지금 하는 것 / 하지 않는 것

- A는 자기 복사본(`Assets/A/Scripts/Rifle/K2C1Rifle.cs`)에만 이 자리를 만든다. `Assets/C` 파일은 고치지 않는다.
- 인터페이스 이름·위치는 C와 확인할 때 바꿔도 된다. 공용 위치로 옮길지(두 벌 → 한 벌)는 팀 결정이다.

## 5. 함께 확인할 것 (나중에 한 번에)

1. C가 이 약속을 같이 쓸지, C 보정 방식은 무엇인지 (조준선 기울기 보정만? 손 보정?).
2. 앞손 트리거: A는 확대 모드의 숨 참기로 쓴다. C에서 앞손 트리거를 다른 데 쓰는지.
3. `Anchor_RearSight`·`Anchor_FrontSight` 값 변경이 C 쪽에 문제 없는지.
4. 사격 코드를 공용 한 벌로 합칠지.
