## 2. 폴더·namespace·asmdef

```text
Assets/A/Scripts/
  Common/      MilTrainSimVR.A.Common     소리·진동·임시 신호음, 작업대 패널
  Rifle/       MilTrainSimVR.A.Rifle      사격용 K2C1 (C 코드 복사본), 장전 손잡이, 조정간
  Assembly/    MilTrainSimVR.A.Assembly   분해·결합, 교육 흐름, 기능 점검, 힌트
  Range/       MilTrainSimVR.A.Range      사로 사격 (나중에)
Assets/A/Editor/  MilTrainSimVR.A.Editor  시험용 메뉴 (에디터 전용)
```

- asmdef 이름은 namespace와 같게 한다. `Rifle`·`Range`는 만들 때 추가한다.
- 의존 방향은 **`Common` ← `Rifle` ← `Assembly`·`Range`** 한쪽으로만 둔다. `Editor`는 `Assembly`를 참조한다.
- A asmdef는 C 코드(`Assembly-CSharp`)를 참조할 수 없다. 그래서 C 코드를 쓰려면 복사해야 한다 ([재사용 검토](1027_C사격코드_재사용검토.md)).
- 스크립트를 옮길 때는 `.meta`와 함께 옮겨 GUID를 유지한다. 그래야 씬에 붙은 컴포넌트가 끊기지 않는다.

## 3. 호출 규칙

- 위 → 아래는 메서드 호출, 아래 → 위는 이벤트로 알린다.
  - 흐름 → 순서·기능 점검: `Begin`, `ResetAll`.
  - 부품 → 순서: 지금처럼 `Report*`.
  - 순서 → 흐름: `StepChanged`, `OrderError`, `Finished`.
- 패널은 표시만 한다. 무엇을 표시할지는 흐름 관리자가 정한다. 그래서 순서(`AssemblySequence`)는 글자를 모른다.
- 소리·진동은 조작에 바로 붙는 피드백이라 순서·총이 `TrainingFeedback`을 직접 부른다.
- 문구는 `AssemblyTexts`·`RifleTexts`에만 둔다. 팀 공통 자막 방식이 정해지면 옮긴다.
- 한 파일에 한 클래스, 파일 이름은 클래스 이름과 같게 한다. 주석은 한국어로, 이유 위주로 쓴다.

**지금 구조**

```text

  TrainingFeedback.cs       소리·진동·임시 신호음 (AssemblyFeedback 에서 옮김)
```

**바뀐 것**

| 대상 | 내용 |
| --- | --- |

| `AssemblyTrainingFlow` | 단계 문구, "분해 완료" 안내, 순서 오류 문구를 이벤트를 받아서 표시한다. 문구와 표시 시간은 전과 같다 |
