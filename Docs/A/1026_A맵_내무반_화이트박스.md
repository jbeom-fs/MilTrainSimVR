# A 맵 — 내무반 화이트박스 배치

작성: A · 2026-10-26

분해·결합 공간(`Room_Assembly`)을 실제 군 내무반 구조로 바꾼다. 이번에는 화이트박스 상자로 배치만 잡았다. 침대·관물함 모델은 나중에 교체한다. 구조는 실제 내무반을 따르고, 치수는 임시값이다.

## 1. 기준

- 작업대(`Desk/Table`, 2.1 × 1.0m, 윗면 0.95m, 중심 z -5.8)와 총은 **그대로** 두고 기준으로 썼다.
- 북쪽 벽(z = 0, 사로 쪽)의 문도 그대로 두었다.

## 3. 침대·관물함 (`Room_Assembly/Barracks/West`, `East`)

양쪽 벽을 따라 문 쪽부터 **관물함 → 침대** 4쌍씩 놓았다 (번호 1 = 문 쪽). 맨 남쪽 침대는 남쪽 벽에 닿는다.

| 물건 | 크기 (벽 방향 × 벽에서 나온 길이 × 높이) | 재질 |
| --- | --- | --- |
| `Bed_1~4` | 0.9 × 2.0 × 0.45m | `WB_Bed` (올리브) |
| `Locker_1~4` | 0.8 × 0.6 × 1.9m | `WB_Locker` (밝은 회색) |

- 한 쌍 간격 1.7m. 줄 범위 z -2.4 ~ -9.2, 줄 가운데(z -5.8)가 작업대다. 스케치처럼 2번 침대와 3번 관물함 사이 높이다.
- 침대는 머리를 벽에 붙이고 발끝(x ±2.0)이 통로를 향한다. 발끝과 작업대 사이 통로는 0.95m다.
- 문 쪽 관물함 앞(z 0 ~ -2.4)은 비어 있는 입구 공간이다.
- 상자마다 BoxCollider가 있다 (떨어진 부품, 플레이어가 부딪힘).

## 4. 그대로 둔 것

## 6. 침대·관물함 간격 조정 (10/27, 사용자 요청)

- 침대 모델(폭 0.99 m)이 화이트박스보다 넓어서 관물함이 침대 머리판을 덮었다 → 겹치지 않게 간격을 넓혔다.
- **한 쌍 간격 1.7 → 1.81 m** (관물함 0.8 + 침대 0.99 + 틈 1 cm × 2).
- 방 크기와 작업대는 그대로 두었다. 맨 끝 침대를 남쪽 벽(z -9.2)에서 5 mm 띄우고 문 쪽으로 쌓았다. 그래서 문 쪽 입구 빈 공간이 2.4 → **약 1.97 m**로 줄었다 (첫 관물함 끝 z -1.965). 방을 남쪽으로 늘리는 방법도 있지만 방 치수는 사용자가 정한다.

| 쌍 | 관물함 z (중심) | 침대 z (중심) |
| --- | --- | --- |
| 1 (문 쪽) | -2.765 ~ -1.965 (-2.365) | -3.765 ~ -2.775 (-3.270) |
| 2 | -4.575 ~ -3.775 (-4.175) | -5.575 ~ -4.585 (-5.080) |
| 3 | -6.385 ~ -5.585 (-5.985) | -7.385 ~ -6.395 (-6.890) |
| 4 | -8.195 ~ -7.395 (-7.795) | -9.195 ~ -8.205 (-8.700) |

- 서쪽·동쪽이 같다 (x만 거울 대칭). 침대·관물함 상자끼리 겹침 0 (스크립트로 검사).
- 줄 가운데가 z -5.58로, 작업대 중심(-5.8)과 22 cm 어긋난다.
- 관물함은 아직 화이트박스(0.6 × 0.8 × 1.9 m)다. 모델이 들어와 폭이 바뀌면 같은 방식(관물함 폭 + 0.99 + 0.02)으로 다시 맞춘다.

### 8-1. 줄눈 격자 추가 (10/27, 사용자 요청: 정사각형 격자가 있는 실제 바닥 사진처럼)

- 이미지 한 장 = **타일 한 장 (인조석 300각, 0.3 × 0.3 m)** 으로 바꾸고, 가장자리에 **줄눈(폭 약 3 mm, 회색)** 을 코드로 그려 넣었다. 반복하면 정사각형 격자가 된다. 이미지 이음새가 줄눈에 가려져서 8절의 이음새 문제도 함께 해결된다.
- 줄눈이 살짝 파인 홈처럼 보이게 `Floor_Normal.png`(노멀 맵, OpenGL)를 만들어 `Floor.mat`에 연결했다.
- 반복 = 가로 8 ÷ 0.3 ≈ 26.7, 세로 9.2 ÷ 0.3 ≈ 30.7. 방 크기가 0.3 m로 나누어떨어지지 않아 한쪽 끝 타일이 잘린다 (실제 바닥처럼).
- 원본(줄눈 없는 테라조)은 `Models/Floor/Source~/TerrazzoTile.png`에 보관했다 (Unity가 읽지 않는 폴더). 타일 크기·줄눈 폭·색을 바꿔 다시 만들 때 쓴다.
- 확인: 눈높이·낮은 시점 캡처에서 격자가 보이고, 이미지 경계선은 보이지 않는다.
- **10/27 수정 (사용자: 격자가 너무 촘촘함 → 4칸이 1칸 크기로):** 타일 한 변 0.3 → **0.6 m**. 원본이 이음새 없는 이미지가 아니라 넉 장을 이어 붙이면 타일 안에 줄이 생기므로, 원본 한 장을 2배(512 → **1024 px**)로 늘려 타일 한 장으로 썼다. 그래서 돌 조각도 2배(약 0.9 → 1.8 cm)가 됐다. 줄눈 폭 3 mm는 그대로다. 반복 = 8 ÷ 0.6 ≈ 13.3, 9.2 ÷ 0.6 ≈ 15.3. `Floor_BaseColor`·`Floor_Normal` 모두 1024².

## 9. 벽 텍스처 (10/27)

| 항목 | 값 |
| --- | --- |
| 파일 | 사용자가 넣은 `Tile_DefaultMaterial_AlbedoTransparency·MetallicSmoothness·Normal.png` (1024², 셋 다 필요해서 지운 파일 없음) → `Models/Wall/Textures/Wall_BaseColor·MetallicSmoothness·Normal.png` (GUID 유지). `Materials/Wall.mat` (작업대 재질 복사, URP Lit) |
| 가져오기 | 다른 모델과 같음 + 반복(Repeat), 비등방 8 |
| 이음새 | 경계 차이 0.08 ≈ 안쪽 0.09 → 이음새 없는 이미지다 (바닥 원본과 달리 그대로 반복해도 된다). 줄눈 없는 고운 반점 마감 |
| 크기 | **이미지 한 장 = 1 m** (가정). 바꾸려면 `Editor/WallUvBuilder.cs`의 `k_TileMeters`를 고치고 메뉴를 다시 누른다 |
| 적용 | `Room_Assembly/Shell/Wall_*` 6개 (서·동 9.6 m, 남 8.4 m, 북 문 양옆 4.6 m ×2, 문 위 1.2 × 0.8 m) |

- **벽 메시를 바꿨다.** 벽은 Cube를 크기대로 늘린 상자라서, 기본 Cube 메시는 면마다 텍스처를 한 번씩 늘린다 → 벽마다 무늬 크기가 달라진다.
  - 메뉴 `A/만들기/조립실 벽 (m 단위 UV + 벽 재질)`(`Editor/WallUvBuilder.cs`)이 벽마다 실제 크기(m)대로 UV를 넣은 상자 메시를 만들어 바꾸고 `Wall.mat`을 입힌다. 재질 하나로 모든 벽의 무늬 크기가 같다.
  - 메시는 `Models/Wall/Meshes/WallBox_{가로}x{높이}x{깊이}.asset` 4개다 (같은 크기 벽은 같이 쓴다). 노멀 맵용 접선도 계산한다.
  - 꼭짓점 범위는 Cube와 같은 ±0.5라서 크기·위치·부딪힘 상자(BoxCollider)는 그대로다.
  - **벽 크기를 바꾸면 메뉴를 다시 누른다.**
- 확인: 면 방향 검사에서 뒤집힌 삼각형 0 (처음 만든 메시는 12개가 모두 뒤집혀 있어서 감기 방향을 고쳤다). 캡처에서 벽에 텍스처가 고르게 보인다.
- 남쪽 벽의 옛 안내판 화이트박스(`GuideBoard`)와 사로(`Room_Range`) 벽·바닥은 아직 화이트박스다.

- **가정 (사용자 확인 필요):** 창 아래 높이 1.0 m (창 1.0 ~ 2.0 m), 중심 x ±1.95 (벽 조각 간격이 1.8 m로 같게).
