# 빛줄기(광선) 보이게 하기 — 방법 정리

11/02 사용자 질문: 조명이 표적지로 내리쬐는 **빛 기둥이 공중에 보이게** 하고 싶다 (그림: 위에서 사다리꼴로 퍼지는 노란 빛 안에 표적이 있음). "Fake Light"라고 알고 있던 것이 무엇인지, 어떤 방법이 있는지 나중에도 쓸 수 있게 정리했다.

프로젝트 기준: Unity 6000.3, **URP 17.3**, PC VR(Quest Link). Shader Graph는 URP에 딸려 있어 바로 쓸 수 있다. `PC_RPAsset`에 Depth Texture·Opaque Texture·HDR이 이미 켜져 있다 (공용 설정이라 바꾸지 않는다).

## 0. 먼저 알아둘 것 — Light 컴포넌트는 공기를 비추지 않는다

- Unity의 Light(스포트 등)는 **물체 표면만** 밝힌다. 빛이 지나가는 공중(먼지, 연기)은 그리지 않는다. 그래서 지금 사격장 표적 조명도 표적판과 바닥만 밝고 빛 기둥은 안 보인다.
- 빛 기둥이 보이려면 **공중에 무언가를 따로 그려야** 한다. 방법은 둘이다.
  - **가짜(fake)**: 빛 모양의 반투명 메시를 놓는다 → 흔히 말하는 "Fake Light", "Fake Volumetric", "Light Shaft", "God ray mesh"
  - **진짜(volumetric)**: 공기(안개)를 광선 추적(raymarch)해서 계산한다
- **Light Cookie**는 빛이 표면에 맺히는 모양(창살 무늬 등)을 바꿀 뿐, 공중 빛 기둥은 만들지 않는다.
- 실제로는 **진짜 Light(표면 밝히기) + 가짜 빛 기둥(눈에 보이는 광선)**을 같이 쓴다. 빛 기둥은 그림일 뿐 아무것도 밝히지 않는다.

## 1. 가짜 빛 기둥 메시 (Fake Volumetric) — 추천

원뿔(또는 위가 좁은 원뿔대) 메시를 스포트 조명 자리에 같은 각도로 놓고, **더하기(Additive) 반투명 셰이더**로 그린다.

셰이더에서 하는 일 (Shader Graph, URP **Unlit**, Surface = Transparent, Blend = Additive, 양면, 그림자 X):

| 할 일 | 방법 | 효과 |
|---|---|---|
| 끝으로 갈수록 옅게 | UV의 V(길이 방향)나 정점 색으로 알파를 1 → 0 | 빛이 멀어지며 흩어지는 느낌 |
| 가장자리 옅게 | **Fresnel**(시선과 표면 법선의 각) — 정면은 진하고 옆 테두리는 옅게 | 딱딱한 원뿔 테두리가 사라지고 부드러운 기둥처럼 보임 |
| 바닥·표적과 만나는 곳 부드럽게 | **Depth Fade**(Scene Depth − 픽셀 깊이) — 다른 물체에 가까우면 옅게 | 바닥을 뚫고 들어간 자국(딱딱한 선)이 안 보임. Depth Texture 필요(이미 켜져 있음) |
| 가까이 가면 옅게 | 카메라와의 거리로 알파 줄이기 | VR에서 빛 기둥 안에 머리가 들어가면 화면이 뿌옇게 되는 것 방지 |
| (선택) 먼지 느낌 | 노이즈 텍스처를 천천히 흘려 알파에 곱하기 | 살아 있는 빛 |

- 장점: **가볍다**(투명 메시 하나). VR·Single Pass Instanced에서 문제없음(Shader Graph가 알아서 처리). 모양·색·진하기를 마음대로 조절. 대부분의 게임이 이 방식.
- 단점: 빛을 가리는 물체를 모른다 — 표적판 뒤쪽 빛 기둥이 표적 그림자로 끊기지 않는다. 각도에 따라 납작해 보일 수 있다(Fresnel·이중 원뿔로 줄인다).
- 크기 맞추기: 원뿔 꼭짓점 = 조명 자리, 높이 = 조명에서 바닥까지 거리, 밑면 반지름 = 높이 × tan(스포트 바깥 각도 / 2).
- 손으로 짠 셰이더(HLSL)를 쓰면 VR Single Pass Instanced용 매크로(`UNITY_VERTEX_INPUT_INSTANCE_ID`, `UNITY_VERTEX_OUTPUT_STEREO` 등)를 직접 넣어야 한다 → Shader Graph를 권한다.
- 검색어: `fake volumetric light unity`, `light shaft shader graph`, `volumetric light cone fresnel depth fade`

## 2. 축 고정 빌보드(카드) — 아주 가볍게

빛 기둥 그림(위가 밝고 아래로 퍼지며 옅어지는 사다리꼴 텍스처)을 판 하나에 붙이고, **빛의 축을 중심으로만** 카메라 쪽으로 돈다.

- 장점: 메시·셰이더가 가장 간단. 그림을 그대로 쓸 수 있다(사용자 그림 같은 모양).
- 단점: VR은 양쪽 눈 시차가 있어 판이 납작하게 느껴질 수 있다. 축 방향에서 내려다보면 사라진다. 사격장처럼 늘 한쪽에서 보는 곳에는 쓸 만하다.
- 판을 2~3장 십자로 겹치면 돌리지 않아도 된다(가장 싼 방법).

## 3. 먼지 입자 (Particle System) — 1·2에 덧붙이기

빛 기둥 안에만 아주 작은 밝은 점(먼지)을 천천히 떠다니게 한다. 모양(Shape) = Cone, 각도·길이를 스포트와 같게.

- 빛 기둥이 "공기 중의 빛"으로 훨씬 진짜같이 느껴진다. 사격장(화약 연기·먼지)과 잘 맞는다.
- 입자 수를 적게(수십 개) 두면 VR에서도 부담이 작다.

## 4. 진짜 볼류메트릭 (Volumetric Fog / Light)

공중의 안개를 광선 추적해 빛이 지나가는 곳을 계산한다. 물체가 빛을 가리면 빛 기둥에 그림자 줄이 생긴다(가장 사실적).

- **URP에는 HDRP처럼 기본 제공되는 볼류메트릭 안개가 없다.** 직접 Renderer Feature로 만들거나 에셋을 쓴다.
- 쓸 만한 에셋 (Asset Store, 유료):
  - **Volumetric Light Beam** (Tech Salad) — 스포트 하나마다 빛 기둥. 사실상 1번을 잘 만든 것 + 선택적으로 진짜 볼류메트릭. URP·VR 지원. 이 용도에 가장 가깝다.
  - **Volumetric Fog & Mist 2** (Kronnect), **Buto** (OccaSoftware) 등 — 방 전체 안개 + 조명 반응
- 단점: **무겁다** — VR은 두 눈 × 고해상도 × 90 Hz라 광선 추적 비용이 크다. 보통 해상도를 낮춰 계산하고 흐리게 한다.
- 이 프로젝트 규칙: 패키지·에셋 추가, 렌더러(Renderer Feature) 같은 공용 설정 변경은 직접 하지 않고 `Docs/A`에 먼저 제안한다 (AGENTS.md 3절).

## 5. 화면 효과 God Ray (Screen-space) — 이 용도엔 비추천

화면에서 밝은 곳을 기준으로 방사형 흐리기를 해 빛살을 만든다(해가 구름 사이로 비칠 때 같은 효과). 해처럼 화면 안의 광원에는 좋지만, 위에서 내리쬐는 스포트 조명 기둥에는 맞지 않는다. VR에서는 화면 효과가 두 눈에서 어긋나 보이기 쉽다.

## 6. 같이 쓰면 좋은 것

- **어두운 배경**: 빛 기둥은 주변이 어두울수록 잘 보인다. 지금 사격장은 환경광을 0.15로 낮춰 둬서 잘 맞는다.
- **Bloom**(Post-processing Volume): 조명 자리(발광체)가 번져 보이게. HDR이 켜져 있어 쓸 수 있다. Volume은 씬에 두는 것이라 A 씬 안에서 해결할 수 있다.
- **조명 기구 모델**: 빛 기둥 꼭짓점에 작은 스포트 등 모델과 발광 재질을 두면 "어디서 나오는 빛"인지 분명해진다.

## 7. 정리 — 무엇을 고를까

| 방법 | 보기 | 비용(VR) | 만들기 | 비고 |
|---|---|---|---|---|
| 1. 가짜 원뿔 메시 | 좋음 | 낮음 | Shader Graph 하나 + 원뿔 메시 | **추천**. 가리는 물체 표현 X |
| 2. 축 빌보드 | 보통 | 매우 낮음 | 텍스처 하나 | 그림 그대로 쓰기 좋음 |
| 3. 먼지 입자 | 1·2 보강 | 낮음 | Particle System | 같이 쓰기 |
| 4. 진짜 볼류메트릭 | 가장 좋음 | 높음 | 에셋/직접 개발 | 팀 제안 먼저 |
| 5. 화면 God Ray | 해에 적합 | 중간 | 후처리 | 이 용도 X |

**사격장 표적 조명에는 1번(+ 원하면 3번)을 권한다.** 지금 표적 조명 7개(`Room_Range/Lights_Temp/Light_Target1~7`: 높이 4.3, z 28, 표적 가운데로, 바깥 20°)의 자리·방향·각도를 그대로 읽어 원뿔을 만들면 Light와 빛 기둥이 항상 맞는다. 원뿔 메시는 에디터 코드로 만들어 `Assets/A/Models`에 저장하고, 재질은 `Assets/A/Materials/Range`에 둔다 — 공용 설정·패키지 변경 없이 A 폴더 안에서 끝난다.

## 8. 사격장에 적용 (11/02) — 1번 가짜 원뿔 메시

- 셰이더 `Assets/A/Shaders/LightShaft.shader` (`MilTrainSimVR/A/LightShaft`): Shader Graph 대신 손으로 짠 URP Unlit이다 (코드로 만들기 쉬워서). 더하기, 양면, 깊이 쓰기 없음. VR Single Pass Instanced 매크로를 넣었다. 위 표의 길이·테두리(Fresnel)·Depth Fade·카메라 가까이 옅게를 모두 한다.
- 재질 `Assets/A/Materials/Range/Range_LightShaft.mat` — **진하기·색은 여기서 고친다** (다시 지어도 덮어쓰지 않음). 값: Intensity 0.3(전체 진하기), Edge Softness 2(클수록 테두리가 더 옅고 기둥이 가늘어 보임), Length Fade Power 1.2(클수록 끝이 빨리 옅어짐), Depth Fade 0.3 m(바닥·표적과 만나는 곳을 흐리는 폭), Camera Fade 0.3~1.5 m.
- 원뿔: `LightShaftBuilder.Attach(light, 최대 길이)`가 스포트 조명에 자식 `Shaft`로 붙인다. 꼭짓점 = 조명 자리(반지름 5 cm), 방향 = 조명 앞, 각도 = 조명 바깥 각도, 길이 = 바닥까지. 메시는 `Assets/A/Models/LightShaft/LightShaft_길이x반지름.asset`.
- 사격장 표적 조명 7개(`Lights_Temp/Light_Target1~7`)에 붙였다 — 길이 4.49 m, 끝 반지름 0.84 m. `사격장 형광등` 메뉴가 조명을 지을 때 같이 짓는다.
- 렌더로 확인: 어두운 사격장에서 표적마다 빛 기둥이 보이고, 바닥에 빛 원이 맺힌다. 셰이더 오류 없음. 헤드셋에서 두 눈 모두 맞게 보이는지는 확인 필요하다.
- 다른 곳에 쓰려면: 스포트 Light에 `LightShaftBuilder.Attach(light, 길이)`를 부르거나, `Shaft` 오브젝트를 복사해 다른 스포트의 자식으로 둔다 (각도가 다르면 메시를 다시 만든다).
- 먼지 입자(3번)는 아직 안 했다.
- **수정 (11/02 사용자: 수직으로, 먼지 추가, 살짝 약하게)**
  - 표적 조명과 빛 기둥을 **수직**(아래로 90°)으로 바꿨다. 자리는 z 28.6(표적 0.4 m 앞, 높이 4.3)이다. 표적 바로 위(z 29)에 두면 앞면에 빛이 안 닿아서 조금 앞에 두었다. 각도는 바깥 24°·안쪽 16°로 넓혀 빛 가장자리가 표적판 앞면을 스치게 했다. 조명 세기 25는 그대로다. 빛 기둥 길이는 4.3 m(바닥까지)이다. 렌더로 확인: 기둥이 곧게 서고, 표적판 앞면도 보일 만큼 밝다.
  - 빛 기둥 진하기(`Range_LightShaft.mat` Intensity) 0.3 → **0.2** (셰이더 기본값도 0.2).
  - **먼지(3번)**: 조명마다 자식 `Dust`(Particle System)를 붙였다. 빛 기둥과 같은 원뿔 부피(ConeVolume, 반각 12°, 길이 기둥의 90%) 안에서 생긴다. 크기 6~14 mm, 수명 8초, 동시에 최대 40개, 처음부터 차 있음(Prewarm), 느린 Noise로 떠다니고 나타났다 사라진다. 재질 `Range_LightDust.mat`(URP Particles/Unlit, 더하기) + 동그라미 텍스처 `Range_LightDust.png`. 먼지 색·개수는 `LightShaftBuilder`의 `k_Dust*` 값으로 바꾼다. 재질은 다시 지어도 덮어쓰지 않는다.
  - 먼지는 Light를 받지 않고 스스로 빛나는 점이다 (빛 기둥 안에서만 생겨서 빛을 받는 것처럼 보인다).
- **수정 2 (11/02 사용자: 옆면 줄 없애기, 덜 퍼지게, 더 약하게)**
  - 옆면의 세로 줄은 두 가지가 원인이었다. ① 32조각의 꼭짓점 법선을 섞어 테두리 옅기를 구해서 조각마다 밝기가 달랐다. ② 어두운 그라데이션이 8비트에서 계단(밴딩)으로 보였다. 고친 것: 셰이더가 **법선을 픽셀마다 원뿔 축에서 다시 구한다**(조각 경계 없음). **디더링**(`InterleavedGradientNoise`, ±0.5/255)을 넣었다. 조각 32 → 96. 렌더로 확인: 줄이 안 보인다.
  - 빛 기둥 원뿔만 조명보다 좁혔다: `IndoorRangeBuilder.k_TargetShaftAngle` = **14°** (`LightShaftBuilder.Attach`의 세 번째 인자). 바닥 쪽 반지름 0.96 → 0.58 m이다. 먼지도 같은 원뿔 안에서 생긴다. 실제 조명은 24° 그대로라, 바닥에 맺히는 빛 원이 빛 기둥 끝보다 조금 넓다.
  - 빛 기둥 진하기 0.2 → **0.15** (재질·셰이더 기본값). 안 쓰게 된 원뿔 메시 2개는 지웠다.
