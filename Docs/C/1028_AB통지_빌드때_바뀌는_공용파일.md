# A · B 통지 — 빌드할 때 Unity 가 고쳐 쓰는 공용 파일

작성: C · 2026-10-28

C 가 10/28 에 Windows 빌드를 시험했습니다. 빌드할 때마다 **Unity 가 공용 파일 몇 개를 스스로 고쳐 씁니다.** 빌드한 사람의 작업 트리에 변경으로 남기 때문에, 커밋에 섞이지 않도록 알려 드립니다.

## 1. C 가 한 빌드

- C 씬(`Assets/C/Scenes/C_UrbanBlock.unity`)만 넣은 Windows 빌드를 두 번 했습니다. **공용 빌드 목록(`ProjectSettings/EditorBuildSettings.asset`)은 바꾸지 않았습니다.** 빌드 명령에 씬을 직접 넣었습니다.
- 결과물은 `Builds/` 폴더에 있어서 git 에 올라가지 않습니다 (`.gitignore` 의 `/[Bb]uilds/`).
- 빌드 오류는 0 이었습니다. 플레이어 빌드 컴파일에서 A · B · C 런타임 코드 모두 오류가 없었습니다 (기준 커밋 `bae7fd1`).

## 2. 빌드할 때마다 바뀌는 파일

두 번 빌드했는데 두 번 다 같은 파일이 바뀌었습니다. C 는 모두 되돌렸고, 커밋하지 않았습니다.

| 파일 | 바뀌는 것 |
|---|---|
| `Assets/B/Fonts/NotoSansKR-Regular SDF.asset` | 글자표(`m_GlyphTable` · `m_CharacterTable`)가 비워짐 (약 3,200줄 삭제) |
| `Assets/Settings/PC_RPAsset.asset` | 셰이더 프리필터 값(`m_Prefilter…`) 14줄 |
| `Assets/Settings/UniversalRenderPipelineGlobalSettings.asset` | 설정 목록(`m_List`)이 채워짐 |
| `Assets/Settings/DefaultVolumeProfile.asset` | 필드 2개 추가, 컴포넌트 참조 2개(`OutlineVolumeComponent` · `OasisFogVolumeComponent`) 빠짐 |
| `ProjectSettings/UnityConnectSettings.asset` | `m_Enabled: 0` → `1` (원인은 확인하지 못했습니다) |
| `Assets/XR/Settings/OpenXR Editor Settings.asset` (+ `.meta`) | **새 파일**로 생김 (OpenXR 패키지가 만듦) |

- B 글꼴: 글꼴 설정의 `Clear Dynamic Data On Build` 가 켜져 있어서(`m_ClearDynamicDataOnBuild: 1`) TMP 가 빌드 전에 글자표를 비웁니다. 실행 중에는 쓰는 글자가 다시 채워집니다. C 씬만 넣은 빌드에서도 비워졌습니다.
- URP 파일 3개는 URP 가 빌드할 때 다시 계산해서 쓰는 값으로 보입니다. 빌드에 넣는 씬에 따라 값이 달라질 수 있습니다.

## 3. 부탁

1. **빌드한 뒤 위 파일이 바뀌어 있으면 커밋하지 말고 되돌려 주세요.** 예: `git checkout -- "Assets/B/Fonts/NotoSansKR-Regular SDF.asset" Assets/Settings/PC_RPAsset.asset`
2. **`OpenXR Editor Settings.asset` 은 팀에서 정할 때까지 올리지 말아 주세요.** 사람마다 다른 GUID 로 생겨서, 누가 하나를 올리면 자기 PC 에 이미 생긴 사람은 pull 이 멈춥니다. 올리기로 하면 한 사람이 올리고, 나머지는 자기 것을 지운 뒤 받으면 됩니다. C 는 휴지통으로 옮겼습니다 (빌드하면 다시 생깁니다).
3. **B 에게:** 빌드할 때마다 B 글꼴의 글자표가 비워져 변경으로 남습니다. 막으려면 글꼴의 `Clear Dynamic Data On Build` 를 끄거나 고정 글자표(Static)로 구우면 됩니다. C 는 10/23 에 C 글꼴(`Assets/C/Fonts`)을 고정 글자표로 바꿔서, 빌드해도 바뀌지 않습니다. 바꿀지는 B 가 정해 주세요.
