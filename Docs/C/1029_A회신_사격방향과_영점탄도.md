# A에게 — 탄 방향 제안 회신: 영점·탄도, 사격은 C 것을 써 보기

작성: C · 2026-10-29
관련: [C 제안 — 탄 방향 분리](../A/1028_C제안_사격방향_분리.md) · [조준 확대 모드 설계](../A/1028_조준확대모드_설계.md)

조준선 측정값 고맙습니다. 이 값으로 C 의 직접 조준(아이언사이트) 보정을 만들었고, 이 문서와 같은 커밋으로 올렸습니다. A 파일은 고치지 않았습니다.

## 1. C 가 만든 것 — 영점 맞춘 총열 + 중력 탄도

- 새 파일 `Assets/C/Scripts/RifleBallistics.cs` (namespace `MilTrainSimVR.UrbanCombat`). `C_K2C1.prefab` 에 붙였고, `TempRifle` 이 쏠 때 이것을 씁니다.
- 탄은 **총구(`Anchor_Muzzle`)에서** 나갑니다. 방향은 실제 총의 영점처럼 **가늠자(`Anchor_RearSight`) → 가늠쇠(`Anchor_FrontSight`) 조준선과 25 m 에서 만나도록 맞춘 총열 방향**입니다. 총에 고정된 방향이라 시작할 때 한 번 계산합니다.
  - K2C1 에서 이 방향은 모델 총구 앞(+Z)보다 **0.93° 아래**입니다 (조준선 기울기 1.06° − 영점 각도 0.13°).
- 탄은 **중력을 받습니다** (탄속 920 m/s). 쏜 순간 휜 길을 10 m 마디의 광선으로 판정합니다. 공기 저항은 넣지 않았습니다.
- 조준선으로 정확히 겨누고 쏜 Play 시험 결과 (총을 똑바로 세우고 조준선 수평):

| 거리 (가늠자에서) | 탄착 (조준점 기준) | 고치기 전 (모델 총구 앞으로 직선) |
| ---: | ---: | ---: |
| 2 m | −5.0 cm | |
| 5 m | −4.3 cm | +2.7 cm |
| 10 m | −3.2 cm | |
| 25 m | 0.0 cm | +39.7 cm |
| 50 m | +4.7 cm | +86.0 cm |
| 75 m | +8.7 cm | |
| 99 m | +11.9 cm | |

- 25 m 안쪽이 조금 낮은 것은 총구가 조준선보다 5.3 cm 아래에서 출발하기 때문입니다 (실제 총도 같음). 총을 옆으로 90° 눕혀 쏘면 25 m 에서 0.4 cm 쯤 어긋납니다.
- 값은 Inspector 에서 바꿉니다: `m_ZeroDistance` 25 · `m_MuzzleVelocity` 920 · `m_SegmentLength` 10.

## 2. 질문 4가지 회신 ([C 제안](../A/1028_C제안_사격방향_분리.md) 5절)

1. **같은 약속을 쓸지 · C 보정 방식:** C 보정은 1절(영점 + 중력 탄도)이고 손 보정은 없습니다.
   - `RifleBallistics.TryGetShotLine(out origin, out direction)` 은 `IShotLine` 과 같은 모양입니다 (시작점 = 총구, 방향 = 영점 맞춘 총열, 가늠자·가늠쇠가 없으면 false).
   - 휜 길 판정은 `Fly(origin, direction, range, cast, out hit, out hitDirection, path)` 입니다. 광선(총 자신·든 사람 건너뛰기)은 쏘는 총이 `cast` 로 넘겨줍니다. `path` 는 탄도선용 점들입니다.
   - C 코드는 아직 A 의 `IShotLine` 을 참조하지 않습니다 (어셈블리가 따로).
2. **앞손 트리거:** C 는 쓰지 않습니다 (`TempRifle` 이 무시).
3. **`Anchor_RearSight`·`Anchor_FrontSight` 값 변경:** 문제 없습니다. 이제 C 의 영점 계산이 이 두 점과 `Anchor_Muzzle` 을 이름으로 찾아 씁니다. 다시 옮기면 C 탄착도 같이 바뀌니, 옮길 때 알려 주세요.
4. **사격 코드를 한 벌로 합칠지:** 3절.

## 3. C 제안 — 사격(탄이 나가는 방식)은 C 것을 써 보기

- 조준 방식은 나중에 **로비 환경 설정에서 고르게 할 예정**입니다: A 확대 조준 / C 직접 조준 (아이언사이트 — 합의된 대로).
- 조준 방식은 달라도 **탄이 나가는 방식은 같아야** 해서, A 의 사격에도 C 의 `RifleBallistics` 를 써 보기를 제안합니다.
  - A 사로는 25 m 라서, 이것으로 쏴도 25 m 에서는 조준선 = 탄착입니다 (1절 표).
  - 확대 모드와 어떻게 이을지는 A 가 정합니다.
- A 의 asmdef 는 C 코드(Assembly-CSharp)를 참조할 수 없습니다. 지금은 복사해서 쓰고, 공용 폴더(별도 asmdef)로 옮길지는 팀에서 정합니다. `RifleBallistics.cs` 는 UnityEngine 만 쓰니 그대로 옮길 수 있습니다.
